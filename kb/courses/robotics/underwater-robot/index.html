    水下机器人系统¶

    前两页里，机器人脚下踩的都是硬地面：有 GPS、有无线电、有空气。 一旦把它放进水里，这些前提一个都不剩： 信号传不远、看得见却摸不着定位、还得随时和浮力较劲。 这一页讲的就是这批「在水里干活」的机器人： 它们靠什么浮、靠什么看、又靠什么在三维的水里走出该走的轨迹。

    这一页的主线

    水下机器人的一切特殊性，都来自水的三种性质： ① 密度大（于是浮力成了主角，而不是配角）； ② 吸收电磁波（于是声学几乎是唯一能远距离用的感知手段）； ③ 有阻力、有流（于是速度要用续航换、航线会被推偏）。 这一页就按这三条走：先讲它们怎么「站住」（一）→ 再讲它们怎么「看见」（二）→ 最后讲它们怎么「走对」（三）。

    水下机器人不是「潜到水里的无人机」

    无人机最大的三个依赖 —— GPS 定位、无线电通信、空气动力学 —— 水下全部失效。换成水下，你得用声波定位和通信（慢、窄、还受多径干扰）、 用浮力来配平（配不好就一头扎底或浮出水面）、 用水动力来算运动（阻力随速度平方涨、还带耦合）。 本页三节会用 5 段实跑代码把这些「换了之后差在哪」逐个量化。

    一、水下机器人概述¶

    1.1 水下为什么是「另一个世界」：五个反常¶

    把一台机器放进水里，有五件事和陆上反着来：

    陆上 / 空中 水下
    定位 GPS 直接给经纬度 电磁波进不了水，没有 GPS
    通信 无线电、带宽大、延迟低 只能靠声波，带宽窄、延迟大、易受多径干扰
    支撑 靠轮子/机翼「顶」着重力 靠浮力托着，重力与浮力几乎相等
    感知 相机、激光雷达好用 光被吸收散射，几米外就糊了，远距离只能靠声
    运动 空气阻力小，可近似忽略 水的密度是空气的 800 倍，阻力、惯量、耦合都不能忽略

    这五条里，第一条和第二条是「致命」的 —— 它们不是「性能差一点」， 而是「这项能力干脆没有」。后面两节（传感器、控制）本质上都是这两条的补救办法。

    1.2 家族图谱：ROV、AUV、UUV 与滑翔机¶

    水下机器人按「有没有人和它连着」分成两大类，中间还有过渡形态：

    类别 全称 有没有缆 谁在决策 典型任务
    ROV 遥控潜水器（Remotely Operated Vehicle） 有缆（脐带） 人在船上实时遥控 深海作业、采样、检修
    AUV 自主水下航行器（Autonomous Underwater Vehicle） 无缆 自己按预编程/自主决策 大范围测绘、搜索
    UUV 无人水下航行器（Unmanned Underwater Vehicle） — — 统称（含 ROV 与 AUV）
    水下滑翔机 Glider 无缆 自主 长时序海洋观测

    差别不只是「有没有缆」，而是「决定权在谁手里」：

    • ROV 有缆 → 供电和通信都不受限，人在回路里看着屏幕操作，能干细活； 代价是缆绳拖拽、活动范围受缆长限制。
    • AUV 无缆 → 自由、隐蔽、范围大，但通信几乎中断： 只能在下潜前把任务编好，浮上水面（或偶尔）才通信。 它必须自己扛住一切 —— 这正是它和「本章前面那些机器人」最大的不同。

    一句话记住分工

    ROV 是「有线的手术刀」，AUV 是「断线的信鸽」。 前者靠人，后者靠自主 —— 而「自主」在水下的难度， 正是因为它连「我在哪」都很难确定（见第二节）。

    1.3 六个自由度与「浮力驱动」¶

    水下机器人是六自由度刚体：三个平动

    • 纵荡 \(x\)（surge，前进/后退）
    • 横荡 \(y\)（sway，左右平移）
    • 升沉 \(z\)（heave，上浮/下潜）

    加三个转动：

    • 横滚 roll（绕 \(x\) 轴）
    • 纵倾 pitch（绕 \(y\) 轴）
    • 偏航 yaw（绕 \(z\) 轴）

    陆上移动机器人常常受非完整约束（不能横着走），水下机器人没有这个限制 —— 它可以横荡、可以原地转。代价是：六个方向都得有推进器去管（见 3.2 节）。

    「上浮下潜」有两种完全不同的做法

    一种是推进器垂直推（升沉自由度，靠推力）； 另一种是改变净浮力（进水/排水、抛载），让它自己浮或沉。 水下滑翔机走的是第二条路：不带垂直推进器， 靠改变浮力 + 机翼把「沉一点、浮一点」变成斜向滑翔， 于是几乎不耗推进能量，可以漂几个月 —— 代价是极慢。 这提醒我们：自由度的实现方式，决定了这台机器人的整个性格。

    1.4 静力平衡：浮力、重力与配平¶

    阿基米德原理：物体受到的浮力等于排开水的重力

    \[ B = \rho V g, \qquad W = m g \]

    其中 \(\rho\) 是水的密度、\(V\) 是排水体积、\(m\) 是整机质量。净浮力 \(F = B - W\) 决定生死：

    净浮力 状态 后果
    \(F \gt 0\) 正浮力 一直往上浮，收不住
    \(F = 0\) 中性浮力 悬停在任意深度（目标状态）
    \(F \lt 0\) 负浮力 一直往下沉，坐底

    配平就是给机器人加压载（配重），把 \(F\) 调到 0（工程上常留极小的正浮力， 这样故障时能自动上浮）。所需压载质量为

    \[ m_{\text{压载}} = \frac{B}{g} - m = \rho V - m \]

    关键是它正比于水的密度 \(\rho\)：换个海区（淡水 ↔ 海水），配平就变了。

"""第17章 代码1：水下机器人的静力平衡——浮力、重力与压载配平。"""
G = 9.81                      # 重力加速度 m/s^2
M_DRY = 45.0                  # 干重（不含压载）kg
VOL = 0.048                   # 排水体积 m^3


def statics(rho):
    r"""浮力 B = rho*V*g，净浮力 F = B - m*g，配平所需压载 = B/g - m。"""
    B = rho * VOL * G
    W = M_DRY * G

    二、水下机器人传感器系统¶

    2.1 水下没有 GPS：定位链靠什么¶

    陆上定位一句话：「接收 GPS + 轮式里程计 + IMU」。 水下这三样都不能照抄：GPS 进不来、轮子不存在、里程计测不准（水里有流）。

    于是水下定位变成「多传感器拼出来的一条链」，各管一段尺度：

    传感器 管什么尺度 原理 / 特点
    IMU / 惯导 INS 短时、连续 积分加速度/角速度 → 会漂，必须被纠正
    深度计 单维、很准 测静水压 → 深度，升沉方向最可靠的量
    DVL（多普勒测速仪） 速度 向海底发声，用多普勒频移测对地速度
    罗盘 / 磁力计 航向 易受电机与船体磁场干扰
    USBL / LBL（基线定位） 绝对位置 靠声与母船/海底应答器测距测向
    CTD（温盐深） 环境 测声速剖面，给声学定位做修正

    注意这条链的分工：INS 连续但会漂，DVL/USBL 不漂但不连续 —— 两者互补，正好用卡尔曼滤波合起来（和 同时地图构建与定位 里那套是同一个套路）。

    2.2 声学是唯一能远距离用的「眼睛」¶

    光在水里衰减极快（十几米就见底），声波却能跑几公里到几十公里。 所以水下「看得远」的手段只有声学：

    • 主动声呐：自己发声、听回声 → 能测距，但暴露自己；
    • 被动声呐：只听不发声 → 隐蔽，但不知道距离（只知道方位）。

    水声的「数学」这一页不重复 —— 它已经在本库海洋声学里讲透了：

    • 声呐方程：发射 − 传播损失 + 目标强度 ≥ 门限这本分贝账本；
    • 海水的声学特性：声速怎么随温盐压变化（→ 声线怎么弯）；
    • 海洋中的声传播理论：为什么有声道、有会聚区；
    • 海洋环境噪声：决定「听得多清」。

    这一页只做一件事：把那个方程代进真实数字，看它能算出多远。

    2.3 从声呐方程到作用距离¶

    声呐方程的核心是把增益与损失放在同一把尺子（分贝）上相加减。 主动声呐要求「回声级」超过「噪声级 + 检测阈」：

    \[ SL - 2\,TL + TS \;\ge\; NL - DI + DT \]

    把与距离无关的项挪到一边，得到回声余量（figure of merit）：

    \[ 2\,TL \;\le\; \underbrace{SL + TS - NL + DI - DT}_{\text{FOM}} \]

    而传播损失由几何扩展 + 吸收两部分组成：

    \[ TL(r) = 20\lg r_{\text{m}} + \alpha(f)\, r_{\text{km}} \]

    其中 \(\alpha(f)\) 是吸收系数（dB/km），随频率快速上升（Thorp 经验公式）。 于是「能走多远」就变成：找一个 \(r\)，让 \(TL(r)\) 刚好等于 FOM 的一半。

import math


def alpha_thorp(f_khz):
    r"""Thorp 吸收系数（dB/km），f 单位 kHz。"""
    f2 = f_khz ** 2
    return 0.11 * f2 / (1 + f2) + 44 * f2 / (4100 + f2) + 2.75e-4 * f2 + 0.003


def tl(r_km, f_khz):
    r"""传播损失 TL = 20 lg r(m) + alpha*r(km)：球面扩展 + 吸收。"""
    return 20.0 * math.log10(r_km * 1000.0) + alpha_thorp(f_khz) * r_km


def solve_range(threshold_db, f_khz, hi=200.0):
    r"""二分求 TL(r) = threshold 的距离（km）。"""
    lo = 1e-4
    for _ in range(200):
        mid = 0.5 * (lo + hi)
        if tl(mid, f_khz) < threshold_db:
            lo = mid
        else:
            hi = mid
    return 0.5 * (lo + hi)

    2.5 把声学量变成状态：水下定位与 SLAM¶

    声呐给的是距离/方位这种「几何观测量」，要变成位姿还得靠状态估计：

    • 单信标 + 方位角 → 只能定一个方向（且洋流一推就偏）；
    • 多信标测距（LBL） → 三角/多边定位出绝对位置；
    • DVL + INS 组合 → 短时不漂，长时间靠 USBL 回一次「绝对位置」纠偏；
    • 水下 SLAM → 没有先验地图时，边建图边定位 —— 与 同时地图构建与定位 完全同构， 只是观测从「激光/视觉」换成「声学」。

    水下估算的「三重困难」

    ① 观测稀疏：声呐更新率低，一秒几次甚至更少； ② 观测有偏：多径、声速剖面误差会让「测距」系统性偏大/偏小； ③ 约束缺失：没有 GPS 的绝对锚点，误差只能靠偶尔浮上水面或已知应答器拉回来。 所以水下定位的第一原则是：能不漂就别让它漂（多用互补、少依赖积分）。

    三、水下机器人运动规划与控制¶

    3.1 水动力：阻力、附加质量与耦合¶

    水下运动方程比陆上「难一层」，因为水会反过来拖着机器人走：

    • 阻力：\(F_d = \tfrac12 \rho C_d A v^2\)，随速度平方增长；
    • 附加质量（added mass）：机器人加速时要把周围的水也「带着动」， 等效惯量比自身质量大（有时大几十个百分点）；
    • 耦合：横着动会影响转向、转向会产生侧向力 —— 六个自由度互相串， 不像陆上轮式那样「一个轮子管一个方向」。

    为什么水下机器人「不敢快」

    阻力 \(\propto v^2\)，而推进功率 \(P = F_d v / \eta \propto v^3\) —— 速度翻一倍，功率要涨八倍。下一小节会把这条算成一张表。

    3.2 推进器配置决定可控自由度¶

    「六个自由度都要管」意味着至少要有六个能独立出力的推进器（欠驱动时更少）。 能不能管住，取决于推进器怎么摆，这件事可以用一个矩阵精确判断。

    把每个推进器的推力方向 \(d_i\) 和它相对质心的位置 \(r_i\) 写成分配矩阵的一列：

    \[ \text{col}_i = \begin{bmatrix} d_i \\[2pt] r_i \times d_i \end{bmatrix} \in \mathbb{R}^{6}, \qquad B = [\,\text{col}_1\ \ \text{col}_2\ \ \cdots\ \ \text{col}_n\,] \]

    那么可控自由度的个数 = \(B\) 的秩， 推不动的方向个数 = 6 − 秩（对应 \(B\) 的零空间）。

    • 秩 = 6：完全驱动，每个方向都能独立控制；
    • 秩 < 6：欠驱动，缺的那几个方向再聪明的算法也补不回来。

import numpy as np

def thruster(pos, direction):
    r"""一个推进器：分配矩阵的一列 = [d; r x d]（6 维：3 力 + 3 矩）。"""
    d = np.asarray(direction, float)
    d = d / np.linalg.norm(d)
    r = np.asarray(pos, float)
    return np.concatenate([d, np.cross(r, d)])


def report(name, cols):
    M = np.column_stack(cols)
    rank = np.linalg.matrix_rank(M, tol=1e-9)
    sv = np.linalg.svd(M, compute_uv=False)
    print("%-20s 推进器 %d | 秩 %d | 可控自由度 %d | 不可控方向 %d"
          % (name, len(cols), rank, rank, 6 - rank))
    print("     奇异值：" + "  ".join("%.3f" % x for x in sv))
    return M

    \[ t = \frac{E}{P} \propto \frac{1}{v^3} \]

"""第17章 代码4：水动力阻力、推进功率与续航——速度是「用续航换的」。"""
RHO = 1025.0        # 海水密度 kg/m^3
CD = 0.30           # 阻力系数（简化，按迎流面积）
AREA = 0.080        # 迎流面积 m^2
ETA = 0.55          # 推进器总效率
E_BATT = 3.6e6      # 电池能量：1 kWh = 3.6e6 J


def drag(v):
    r"""阻力 F = 0.5*rho*Cd*A*v^2。"""
    return 0.5 * RHO * CD * AREA * v * v


def power(v):
    r"""推进功率 P = F*v/eta。"""
    return drag(v) * v / ETA


print("水下机器人阻力与推进功率")
print("rho=%.0f  Cd=%.2f  A=%.3f m^2  eta=%.2f  电量=1 kWh"
      % (RHO, CD, AREA, ETA))
print()
print(" 速度(m/s)   阻力(N)   推进功率(W)   续航(h)")
print(" --------   -------   -----------   -------")
for v in [0.5, 1.0, 1.5, 2.0, 2.5, 3.0]:
    P = power(v)
    print("   %4.1f     %7.2f     %9.1f     %6.2f" % (v, drag(v), P, E_BATT / P / 3600.0))
print()

    3.6 水下路径规划：三维、流场与避障¶

    水下路径规划和陆上（见 机器人运动规划）相比，多了三件事：

    1. 是三维的：要同时决定 \(x, y, z\)，而不只是平面路径；
    2. 有流场：洋流会平移路径，规划时要知道「流的方向和大小」；
    3. 能量是主成本：因为 \(P \propto v^3\)，往往「慢而直」比「快而绕」更省， 目标函数常写成总能量而不是总路程。

    一个反直觉的规划结论

    在有横流时，直线未必最省能量 —— 让航线顺着流走远一点，可能比「迎着流抄近路」更省。 这和陆上「最短路径」的直觉完全不同：水下的距离，是要用能量来度量的。

    3.7 路径跟踪：LOS 制导与横流¶

    规划出路径后，还要沿它走。最常用的制导律是视线制导（LOS）： 从当前位置朝路径上前方一个前视点看，把「看过去的方向」当作期望航向：

    \[ \psi_{\text{des}} = -\arctan\!\frac{e_y}{\Delta} \]

    其中 \(e_y\) 是横向偏差、\(\Delta\) 是前视距离。再用一个航向环 \(\dot\psi = k(\psi_{\text{des}} - \psi)\) 把航向拧过去。

    问题来了：如果有横流 \(c_y\)，机器人必须斜着顶才不会被推走 （\(\sin\psi = -c_y/v\)）。而 LOS 是比例型的：它只在有偏差时才产生「修正方向」—— 于是稳定下来时，一定留下一个不为零的横偏。这就是稳态误差。

    解法：给制导律加积分项，让「长期存在的偏差」被积分器扛住， 等价于在线估计并前馈补偿那股未知的横流：

    \[ \psi_{\text{des}} = -\arctan\!\frac{e_y + k_i \!\int e_y\,dt}{\Delta} \]

import math

V = 1.0          # 前进速度 m/s
K_PSI = 2.0      # 航向环增益
DELTA = 10.0     # 前视距离 m
DT = 0.02
T_END = 120.0


def simulate(ki, cy, psi0=0.0):
    r"""跟踪直线 y = 0：

    制导 psi_des = -atan2(e_y + ki*integ, Delta)；横流 cy 垂直压向航线。
    返回 (终点 x, 终点 y)。
    """
    x, y, psi, integ = 0.0, psi0, 0.0, 0.0
    for _ in range(int(T_END / DT)):
        e_y = y
        integ += e_y * DT
        psi_des = -math.atan2(e_y + ki * integ, DELTA)
        psi_dot = max(-1.0, min(1.0, K_PSI * (psi_des - psi)))
        x += V * math.cos(psi) * DT
        y += (V * math.sin(psi) + cy) * DT
        psi += psi_dot * DT
    return x, y

    例题 1：为什么「淡水中配平」的船，入海就浮起来¶

    问：用 1.5 节的模型（干重 45 kg、排水体积 0.048 m³、\(g = 9.81\)）， 解释为什么淡水中配平的机器人进入海水后会多出上浮趋势。 工程上该怎么处理？

    解答

    先算淡水。 浮力 \(B = \rho V g = 1000 \times 0.048 \times 9.81 = 470.9\) N， 重力 \(W = 45 \times 9.81 = 441.5\) N， 净浮力 \(F = 470.9 - 441.5 = +29.4\) N（已经是正浮力）， 要中性得压 \(B/g - m = 48.0 - 45.0 = 3.00\) kg 压载。

    再算海水。 密度换成 \(1025\)，浮力涨到 \(482.7\) N， 配平压载变成 \(4.20\) kg —— 比淡水多了 1.20 kg。

    多出来的这 1.2 kg 就是问题所在。 如果船是按淡水配平的（压了 3.00 kg），进海后压载不够， 净浮力变成 \(482.7 - 441.5 = +41.2\) N（约 +4.2 kgf）， 机器人会持续上浮、收不住。

    怎么处理？ 三条：

    1. 按密度最大的海域配平，让它在别的海域偏重（便于用少量压载向上补）；
    2. 配置可调压载/浮力系统（注排水、抛载、可变体积），不把压载一次焊死；
    3. 温度也会掺一脚：海水密度还随温度、盐度变，所以余量要留得比「淡水↔海水」这一档还宽一点。

    一句话：浮力正比于水的密度，而密度是环境的属性 —— 所以「配平」天生就是一件「要随环境重算」的事。

    例题 2：为什么「多装两个推进器」不一定多一个自由度¶

    问：3.3 节里，配置 B 是「4 个水平推进器 + 2 个垂直推进器」， 秩只有 5（缺横滚）。请解释为什么加了垂直推进器，横滚仍然控不了。 要控横滚，推进器该怎么摆？

    解答

    先看横滚需要什么。 横滚是绕 \(x\) 轴的力矩 \(M_x\)。 推进器对质心产生的力矩是 \(M = r \times F\)（\(r\) 是推进器到质心的位置向量， \(F\) 是它的推力）。

    再看 B 的布局。 两个垂直推进器的位置是 \((\pm c,\,0,\,0)\)、 推力方向 \((0,0,1)\)。算一下力矩：

    \[ r \times d = (\pm c,\,0,\,0) \times (0,\,0,\,1) = (0,\ \mp c,\ 0) \]

    只有绕 \(y\) 的分量（纵倾），绕 \(x\)（横滚）的分量是 0 —— 因为这两个推力都落在 \(x\) 轴上，力臂在横向上等于 0，推不出「滚」。

    所以 B 的秩是 5：水平组给 3 个（纵荡、横荡、偏航）， 垂直对给 2 个（升沉、纵倾），合起来 横滚缺位。

    怎么改？ 把垂直推进器左右分开摆： 位置改成 \((\pm a, \pm b, 0)\)（如配置 C 的四个垂直推进器装在 xy 四角）。 这时 \(r \times d = (-b,\,a,\,0)\) 一类的分量出现， \(M_x\) 和 \(M_y\) 都能出，秩升到 6，横滚就控住了。

    一句话：能不能控一个方向，看的是「有没有力臂」， 不是「推进器够不够多」—— 同向、同轴的推力堆再多也补不出缺的那一维。

    例题 3：为什么被动声呐听的距离远得多¶

    问：2.4 节的实跑里，同样 \(20\) kHz、\(SL=200\)、\(NL=60\)、\(DI=20\)、\(DT=10\)， 主动作用距离约 \(1.07\) km、被动约 \(15.95\) km。请解释这 15 倍差在哪。 为什么潜艇更看重被动？

    解答

    先写两个判据。 都用「距离无关项 ≥ 距离相关项」的形式：

    \[ \text{主动：}\; 2\,TL \le SL + TS - NL + DI - DT = 130\ \text{dB} \;\Rightarrow\; TL \le 65\ \text{dB} \]
    \[ \text{被动：}\; TL \le SL - NL + DI - DT = 150\ \text{dB} \]

    第一处差异：往返 vs 单程。 主动的 \(TL\) 要乘 2（去 + 回）， 所以同样的 \(TL\) 门限，主动只允许单程损失 \(65\) dB，被动允许 \(150\) dB —— 门限差了一倍还多。

    第二处差异：目标反射损失。 主动还多一项 \(TS = -20\) dB （目标把声能散掉了一大半），被动没有这一项。

    两项一叠加：\(150\) vs \(65\)，门限差了 \(85\) dB。 而 \(TL = 20\lg r_{\text{m}} + \alpha r_{\text{km}}\)，在 \(20\) kHz（\(\alpha = 4.134\) dB/km）下， \(85\) dB 的门限差主要被吸收项吃掉（对数项涨得很慢）， 于是距离从 \(1.07\) km 拉到 \(15.95\) km（约 15 倍）。

    为什么潜艇重视被动？ 因为它面对的是同一个方程的另一面： 主动发声 = 把自己的位置告诉了所有人（暴露）；被动只听 = 不暴露， 而且还能听得更远。「隐蔽」和「听远」在被动这里是一回事。

    一句话：主动是「开手电找人」，被动是「在黑暗里听脚步」—— 后者看得（听得）更远，还不会被发现。

    例题 4：为什么水下机器人「跑不快」¶

    问：3.5 节的表里，速度从 \(1\) 到 \(2\) m/s，功率涨到 \(8\) 倍、续航掉到 \(1/8\)。 请从阻力与功率的关系说明这个「立方律」，并解释它如何影响路径规划。

    解答

    第一步：阻力是平方律。 迎流阻力 \(F_d = \tfrac12 \rho C_d A v^2 \propto v^2\)。 速度翻倍，阻力变 4 倍。

    第二步：功率再乘一个速度。 推进功率 \(P = F_d v / \eta \propto v^2 \cdot v = v^3\)。 所以速度翻倍，功率变 \(4 \times 2 = 8\) 倍 —— 这就是实跑里 \(22.4 \to 178.9\) W 的来源。

    第三步：续航按能量除以功率。 给定电量 \(E\)，续航 \(t = E/P \propto 1/v^3\)。 功率涨 8 倍，续航就掉到 \(1/8\)：\(44.7 \to 5.6\) h。

    对路径规划的影响： 「时间最短」和「能量最省」会给出完全不同的路径。 因为能量 \(\propto v^3\)，稍微降一点速就能省下大量电能， 于是最优策略常常是「用更慢的速度、走更长一点的路」； 再叠加 3.6 节的流场，最优航线甚至可能故意绕路去借流。

    一句话：陆上把「路程」当成本，水下得把「能量」当成本 —— 而能量对速度是三次方敏感的，所以「慢」在水下是一种策略，不是缺陷。

    Q1 请说明 ROV 与 AUV 在「有没有缆绳」之外的本质区别。 为什么「无缆」会让 AUV 的控制问题比 ROV 难得多？

    提示

    想一想：断掉缆绳，供电和通信分别会变成什么样？ AUV 还能像 ROV 那样「人看着屏幕实时纠错」吗？

    解答

    本质区别是「决定权在谁手里」。 ROV 有缆，人在船上实时遥控，出问题人立刻纠正； AUV 无缆，必须自己在无人干预下完成任务 —— 这叫自主，它才是 ROV 与 AUV 的分水岭（缆绳只是表象）。

    为什么无缆让控制难得多？

    1. 通信几乎中断：声通信带宽窄、延迟大、易断， 传不了实时图像，更做不到「连续遥控」。 → AUV 只能预编程 + 有限的自主决策，容错必须做在自己身上。
    2. 没有人在回路纠错：组合导航（INS/DVL）会漂， 一旦定位错了，AUV 不会有人喊停 —— 它得自己估计「我可能错了」并处理。
    3. 能量封闭：全部电量在船上，没有额外供给，任何「绕路找一找」都得自己付电费。

    一句话：ROV 的难点在「机械与操作」，AUV 的难点在「估计与自主」—— 把缆绳剪断，剪掉的是人，剩下的事全归控制器。

    Q2 一台水下机器人干重 \(60\) kg、排水体积 \(0.060\) m³。 在海水（\(\rho = 1025\) kg/m³、\(g = 9.81\) m/s²）中， 它的净浮力是多少？要中性浮力需加多少压载？ 如果把 \(0.004\) m³ 的浮力材料（密度近似 0）装到它身上，又能少加多少压载？

    提示

    \(B = \rho V g\)；净浮力 \(F = B - mg\)； 装浮力材料相当于增大排水体积但不增重。

    解答

    第一步：净浮力。 \(B = 1025 \times 0.060 \times 9.81 = 603.3\) N； \(W = 60 \times 9.81 = 588.6\) N； \(F = B - W = +14.7\) N（正浮力，会上浮）。

    第二步：中性浮力所需压载。 \(m_{\text{压载}} = B/g - m = 61.5 - 60 = 1.5\) kg。

    第三步：加浮力材料的影响。 排水体积增加 \(0.004\) m³，浮力变成 \(B' = 1025 \times 0.064 \times 9.81 = 643.5\) N。 中性所需压载变成 \(643.5/9.81 - 60 = 65.6 - 60 = 5.6\) kg， 比原来多了 \(5.6 - 1.5 = 4.1\) kg。

    也就是说：加浮力材料不是「少加压载」，而是「多加压载」 —— 它把整机的浮力余量顶高了，你得用更多压载把它压回到中性。 （等价地：\(0.004\) m³ 浮力材料贡献的浮力 \(= 1025 \times 0.004 \times 9.81 = 40.2\) N， 约合 \(4.1\) kg 的「反向配重」。）

    一句话：浮力材料的价值不在「省压载」，而在「把重心/浮心位置调对」—— 它让你能在保持中性浮力的同时，把浮心抬到重心上方。

    Q3 在 3.7 节的 LOS 制导里，为什么纯比例制导在横流下一定留下稳态横偏， 加积分后却能压到接近 0？请用「持续外扰」这个角度解释， 并说明这和前面哪一页的哪条结论是同一件事。

    提示

    问自己：稳态时，机器人是垂直对着航线的吗？它必须斜多少才能顶住横流？ 这个「斜」需要 LOS 主动产生吗？

    解答

    为什么纯比例一定留偏。 有横流时，机器人必须斜着顶才能不被推走： \(\sin\psi = -c_y/v\) ⇒ \(\psi = -\arcsin(0.30/1.0) = -0.3047\) rad。

    但纯比例 LOS 是 \(\psi_{\text{des}} = -\arctan(e_y/\Delta)\)： 它只有在 \(e_y \neq 0\) 时才输出一个非零的期望航向。 要让 \(\psi_{\text{des}} = -0.3047\)，就必须有 \(e_y = \Delta\tan(0.3047) = 3.145\) m —— 于是横偏「被迫」停在 \(3.145\) m 不动了（实跑正好是这个数）。

    换句话说：那个用来顶横流的「斜角」，是靠一个固定的横向偏差「换」来的。

    为什么积分能消掉。 加积分后 \(\psi_{\text{des}} = -\arctan\!\big[(e_y + k_i\!\int e_y\,dt)/\Delta\big]\)。 稳态时 \(e_y \to 0\)，但积分项 \(\int e_y\,dt\) 停在一个非零值上， 单独把期望航向顶到 \(-0.3047\)。 于是「那个斜角」由积分器提供，不再需要靠偏差提供 —— 横偏归零。

    从信号的角度看，积分器本质上是在在线辨识并补偿那股持续外扰（横流）。

    同一件事： 这正是 机器人的位置控制 里 「纯 P 一定有稳态误差、加积分才消得掉」那条结论 —— 只是当时的干扰可能是摩擦、重力分量，这里换成了横流， 规律完全一样：比例控制对付不了不肯消失的干扰，积分才能。

    Q4 为什么水下机器人「定位」比陆上难？请说明 INS、DVL、USBL、深度计 各自提供什么信息、各自的短板，以及为什么需要组合使用。

    提示

    每一路传感器，问两个问题：它测的是什么量？、它是「连续但会漂」还是「不漂但不连续」？

    解答

    难在「没有绝对锚点 + 观测稀疏且有偏」。 陆上有 GPS 直接给绝对位置； 水下电磁波进不去，只能靠声学和惯性，各有各的病。

    各路传感器的分工与短板：

    传感器 提供什么 短板
    INS 连续的位置/姿态/速度 积分会漂，时间越长越离谱
    DVL 对地速度（多普勒） 需要海底反射，离底太高或海底太软就失灵
    USBL 绝对位置（相对母船/应答器） 更新慢、依赖声传播、有量测偏差
    深度计 深度（静水压） 只给升沉一维，别的啥也不给
    罗盘 航向 易受电机/船体磁干扰

    为什么必须组合？ 因为它们的误差性质是互补的：

    • INS 连续但会漂；USBL/DVL 不漂但不连续（或需要外部条件）；
    • 深度计在一维上又准又稳，正好给升沉方向做「绝对约束」；
    • 于是用卡尔曼滤波把「连续的预测」和「偶尔的绝对修正」合起来 —— INS 在两次 USBL 之间负责平滑，USBL 一到就把累积的漂移拉回来。

    这和 同时地图构建与定位 里「滤波 = 预测 + 校正的反复拉锯」是同一套框架， 只是观测换成了声学量。也正因为每个传感器都会坏、会偏， 水下定位的第一原则是：多传感器冗余、别让积分独裁。

    小结¶

    要记住的 为什么重要
    水的三性质：密度大 / 吸收电磁波 / 有阻力和流 分别决定了「配平」「声学感知」「能耗」三件大事
    ROV 有缆靠人、AUV 无缆靠自主 剪断缆绳，剪掉的是「人在回路」，剩下全归控制器
    六自由度：纵荡、横荡、升沉 + 横滚、纵倾、偏航 且没有非完整约束，六个方向都要有推进器管
    浮力 \(B = \rho V g\)、净浮力 \(F = B - W\) 中性浮力是目标，工程上常留极小正浮力
    配平压载 \(= \rho V - m\)，正比于水的密度 淡水↔海水差 1.2 kg（实跑）—— 配平随环境变
    水下没有 GPS，定位靠 INS + DVL + USBL + 深度计 各路误差性质互补：连续会漂 vs 不漂不连续
    声学是唯一能远距离用的感知手段 光衰减太快；声呐分主动（暴露）与被动（隐蔽）
    主动判据 \(2TL \le SL + TS - NL + DI - DT\) 往返 + 反射损失，所以近；实跑约 1.07 km
    被动判据 \(TL \le SL - NL + DI - DT\) 单程、无反射损失，实跑约 15.95 km（约 15 倍）
    吸收系数 \(\alpha(f)\) 随频率暴涨 20 kHz 已达 4.134 dB/km（1 kHz 仅 0.069）
    可控自由度 = 分配矩阵的秩 4 水平→3、+2 垂直→5、+4 垂直→6（实跑）
    缺的不是「推力」而是「力臂」 同轴推力再多也补不出缺的那一维（B 缺横滚）
    阻力 \(F_d \propto v^2\)、功率 \(P \propto v^3\) 速度翻倍，功率 ×8、续航 ÷8（实跑）
    规划的成本是能量不是路程 因为 \(P \propto v^3\)，「慢而直」常比「快而绕」更省
    LOS 制导：纯 P 在横流下留稳态横偏 实跑 3.145 m = \(\Delta\tan(\arcsin(c_y/v))\)，与理论吻合
    加积分把横偏压到 ≈ 0 积分器「在线补偿持续外扰」—— 与位置控制同一条原理

    四条最容易出错的地方：

    1. 把「水下机器人」当成「潜到水里的无人机」 —— GPS、无线电、气动全部失效； 感知要靠声、定位要靠组合导航、运动要考虑浮力与水动力。
    2. 以为配平是「一次调好、到处能用」 —— 压载正比于水的密度； 淡水配平、入海就多出约 1.2 kg 上浮余量（实跑）。配平必须随海域留余量、留可调手段。
    3. 以为「推进器越多、能控的方向越多」 —— 能控多少由分配矩阵的秩定； 加了两个同轴的垂直推进器，秩只从 3 到 5，横滚仍然控不了（缺的不是推力，是力臂）。
    4. 在持续外扰下用纯比例控制，还指望没有静差 —— 横流下 LOS 的稳态横偏 \(3.145\) m 不是「调得不好」，而是比例控制的必然； 想消掉就要积分（或前馈），这和位置控制里「纯 P 有稳态误差」是同一条原理。
