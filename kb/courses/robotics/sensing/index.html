    机器人的传感系统与信息融合¶

    前面几页把「要出多大力」算清楚了，但控制器还有一个前提没解决： 它得先知道现在是什么状态 —— 关节转到哪了、末端在哪、手上有没有碰到东西。 这些信息不会自己出现，全靠传感器测出来。 这一页沿着「内部传感器 → 外部传感器 → 信息融合」这条线， 讲清机器人感知的三个问题：测什么、怎么测、多路信号怎么合成一份可信的估计。

    一、机器人为什么离不开传感器¶

    1.1 控制闭环里缺的那一环¶

    一个机器人要动起来，闭环里至少有三个问题要回答，而这三个问题的答案全在测量里：

    问题 需要的量 谁来测
    我现在在什么位置？ 关节角、末端位姿、速度 内部传感器
    周围有什么？ 距离、形状、颜色 外部传感器
    我碰到了什么？接触多大力？ 接触力 / 力矩 力传感器（内 / 外部）

    没有传感器的机器人是「瞎子」：它只能按固定的指令走（开环）， 一旦有负载、有摩擦、有偏差，就会越走越偏。

    1.2 内部传感器 vs 外部传感器¶

    这是机器人传感最常用的一种分类，分界线是「量的是机器人自己，还是环境」：

    内部传感器 外部传感器
    测什么 机器人自身的状态 外部环境 / 目标的信息
    典型器件 编码器、测速机、IMU、关节力矩传感器 距离传感器、力/力矩传感器、相机、触觉
    信息性质 多为一维、结构化（角度、角速度） 多为高维、非结构化（图像、点云）
    数据量 小 大（视觉每秒几十 MB）
    典型用途 伺服控制（我动到哪了） 感知决策（外面什么样）

    一句话：内部传感器管「我在哪」，外部传感器管「世界什么样」。

    记住这条主线

    这一页的四节，是同一件事的四个层次： 先看清感知的地位（一）→ 内部传感器测自己（二）→ 外部传感器测环境（三）→ 把多路信号融合成一份估计（四）。 贯穿始终的只有一个问题：如何得到一份可信、够准、够快（实时）的状态估计。

    1.3 传感器给的是「带噪声的数」，不是「真值」¶

    必须先立一个观念：任何传感器测出来都带误差。 误差分两类，后面所有融合方法都围绕它们展开：

    · 系统误差（有偏）：每次都往同一个方向偏 —— 陀螺的零漂、编码器的安装偏心、 超声测距受温度影响。可以用标定减小，但很难彻底消除； · 随机误差（噪声）：每次都不一样，均值为零 —— 相机的像素噪声、加速度计的热噪声。 单次测不准，但可以用多次平均、多路融合压下去。

    所以「一个传感器够不够」这个问题，答案通常是「不够」 —— 这正是第四节融合的由来。

    二、内部传感器：测量机器人自己¶

    2.1 位置：编码器¶

    关节「转了多少」是最基本的状态量，主力器件是光电编码器，分两种：

    · 增量式编码器：码盘上一圈刻线，转动时输出 A、B 两路正交方波。 靠数脉冲个数得相对位移，A、B 的相位先后判断转向。 输出只有「增量」，上电后不知道绝对位置 —— 所以机器人开机要先「回零」（找机械原点）； · 绝对式编码器：码盘上每一位都带唯一的编码， 上电立刻读出绝对角度，不需要回零 —— 代价是码盘更复杂、更贵。

    正交倍频：A、B 两相的上升沿和下降沿都能计数， 一圈能数出 4 倍于刻线数的脉冲 —— 这就是所谓「4 倍频」，免费提高分辨率。

    分辨率由三个数决定：

    \[ \text{每转计数} = \text{刻线数} \times \text{倍频数} \times \text{减速比} \]

"""第9章 代码1：内部传感器 —— 编码器分辨率 + 「差分测速」在低速时为何失真。"""
import numpy as np

# 增量式光电编码器：1000 线码盘 × A/B 两相正交 4 倍频 × 50 减速比
lines, quad, gear = 1000, 4, 50
cpr = lines * quad * gear                # 每转总计数 counts/rev
res_rad = 2 * np.pi / cpr                # 角度分辨率

dt = 1e-3
N = 2000
t = np.arange(N) * dt

print("编码器 %d 线 × %d 倍频 × 减速比 %d" % (lines, quad, gear))
print("每转计数 = %d counts/rev，角度分辨率 = %.4f° = %.3e rad"
      % (cpr, np.degrees(res_rad), res_rad))
print("采样周期 %.0f ms；每 1 个计数 = %.4f rad/s 的速度台阶" % (dt * 1e3, res_rad / dt))
print()
print("真实速度(rad/s)  每步走过(计数)  差分均值  差分标准差")
for omega in (0.5, 0.1, 0.02):
    theta_true = omega * t
    counts = np.round(theta_true / res_rad)     # 量化到整数计数
    theta_meas = counts * res_rad
    omega_hat = np.diff(theta_meas) / dt        # 位置差分测速
    print("      %7.2f %13.2f %10.4f %11.4f"
          % (omega, omega * dt / res_rad, omega_hat.mean(), omega_hat.std()))

    编码器 1000 线 × 4 倍频 × 减速比 50
每转计数 = 200000 counts/rev，角度分辨率 = 0.0018° = 3.142e-05 rad
采样周期 1 ms；每 1 个计数 = 0.0314 rad/s 的速度台阶

真实速度(rad/s)  每步走过(计数)  差分均值  差分标准差
         0.50         15.92     0.5000      0.0087
         0.10          3.18     0.1000      0.0121
         0.02          0.64     0.0200      0.0151

    读这张表，两个结论：

    1. 分辨率非常高：\(1000 \times 4 \times 50 = 20\) 万个计数/转， 角度分辨率 \(0.0018°\) —— 这就是编码器能称霸位置测量的原因；
    2. 差分测速「低速失准」：均值一直很准（\(0.5000 / 0.1000 / 0.0200\)）， 但标准差几乎不变（约 \(0.009 \sim 0.015\) rad/s）—— 到了 \(0.02\) rad/s 那一行，噪声已经和真实速度（\(0.0200\)）一样大了，估计值基本不可用。

    原因是「量化」：位置本身是离散的整数计数， 速度 = 位置差 ÷ 时间，除一个很小的 \(\Delta t\)，就把量化误差放大了。 速度越低，每步跨过的计数越少（最后一列：\(0.64\) 个计数/步）， 「有的步跳 1 个计数、有的步不跳」的抖动就越显眼 —— 这就是低速测速的经典难题。

    工程对策：加长差分窗口（多步平均）、用测速发电机、或把编码器和 IMU 融合 （这正是第四节要做的事）。

    低速测速为什么要融合

    编码器差分在低速时量化噪声大，IMU 的陀螺在短时很好但长期漂移 —— 两者刚好互补。所以高性能伺服常常编码器给位置、陀螺给瞬时速度， 再用卡尔曼滤波合成 —— 传感器融合不是「凑数」，是取长补短。

    2.3 速度与加速度：测速机 与 IMU¶

    · 测速发电机（tachometer）：直接输出与转速成正比的模拟电压， 响应快、无量化 —— 缺点是有纹波、要额外占一根轴； · 惯性测量单元（IMU）：一个模块里打包了 三轴加速度计（测比力，含重力）和三轴陀螺仪（测角速度）， 常见型号还会再配三轴磁力计（俗称"九轴"）； IMU 是所有移动平台（无人机、水下机器人、手机）姿态解算的核心。

    IMU 的两个坑：

    · 陀螺积分会漂：角速度积分成角度，零漂会随时间线性累积 —— 积一分钟就偏出去； · 加速度计含重力：它测的是「比力」，静止时也能读出 \(1g\)， 不能直接把读数当运动加速度，必须先减去重力分量。

    这正是「IMU + 其他传感器」融合的动机（见第四节）。

    2.4 力 / 力矩 与 方位¶

    · 关节力矩传感器：贴在关节输出轴或谐波减速器上（应变片原理）， 直接测「关节现在受了多大力矩」—— 有了它，就能做力矩控制、碰撞检测、拖动示教； · 方位传感器：磁力计（指南针，测绝对航向）、倾角计、GNSS（室外绝对位置）。 它们的特点是绝对、无累积误差，但噪声大、更新慢， 正好和 IMU 互补 —— 又是融合。

    三、外部传感器：测量周围环境¶

    3.1 距离传感器¶

    「离障碍物有多远」是最基础的环境信息，主要靠主动测距（自己发波、收反射）：

    器件 原理 量程 优缺点
    超声波 声波飞行时间 0.2–5 m 便宜；受温度影响、波束角大、更新慢
    红外三角测距 反射光斑在 PSD 上的位置 0.1–1 m 便宜、近距准；远距差、受光照影响
    激光三角 同理，用激光 0.1–1 m 光斑小、精度高；量程短
    激光雷达（LiDAR） 激光飞行时间 / 相位 数米–数百米 精度高、扫描成点云；贵、怕雨雾
    ToF 相机 调制光相位差 0.5–10 m 一次成像出深度图；多径干扰

    共同点：都是「发出去 → 等回来 → 用时间 / 几何反算距离」， 所以都受反射率、环境光、介质（水 / 空气）影响。

    3.2 力 / 力矩传感器（外部）¶

    装在末端（腕部）的六维力 / 力矩传感器：同时测三个方向的力 \(F_x, F_y, F_z\) 和绕三个轴的力矩 \(M_x, M_y, M_z\) —— 各维通常独立标定。

    用途：装配（轴孔对准）、打磨（恒力跟踪）、协作机器人（碰撞即停）。 它是第十章「力控制」的直接输入，也是机器人「手感」的来源。

    3.3 视觉：机器人最重要的外部传感器¶

    视觉信息量最大：能同时给出位置、形状、颜色、纹理。 本课程在第十三章会系统展开，这里只用一个最小的例子看清视觉测距的本质 —— 双目。

f = 1000.0        # 焦距（像素）

print("双目相机：焦距 f = %.0f px，基线 B = %.2f m，视差噪声 σ_d = %.1f px"

    3.4 触觉 与 其他¶

    · 触觉阵列：一片柔性压力敏感阵列，给出「接触在哪、多大、什么样」的分布图， 用于抓取的稳定判断（滑移检测）； · 接近觉：电容 / 红外，在真正碰上前几厘米就感知到，用于减速； · 听觉 / 嗅觉：特定场景使用（异常声音、气体泄漏检测），非通用。

    四、信息融合：把多路信号合成一份可信的估计¶

    4.1 为什么必须融合¶

    回到第二节的两个坑：编码器低速测速差、陀螺长期漂移。 再想想一、二节的所有传感器 —— 它们几乎都满足同一个规律：

    · 一种传感器，总有自己的「盲区」：要么量程不够，要么噪声太大，要么会漂； · 不同传感器的盲区往往不重叠：一个的弱点正是另一个的强项。

    信息融合就是「用多个不完美，换一个更完美」 —— 把多路冗余、互补的信息合成一份比任何单路都准的估计。

    4.2 最简单的融合：按「可靠度」加权¶

    假设有两个独立的估计 \(x_1,\,x_2\)，误差标准差分别是 \(\sigma_1,\,\sigma_2\)。 要让合成估计的方差最小，就该给准的更大权重：

    \[ \hat{x} = w_1 x_1 + w_2 x_2,\qquad w_i = \frac{1/\sigma_i^2}{\sum_j 1/\sigma_j^2} \]

    合成后的标准差是：

    \[ \sigma_{\text{fused}} = \frac{1}{\sqrt{1/\sigma_1^2 + 1/\sigma_2^2}} \]

    记住这个式子：它告诉你融合一定不比最好的单路差， 而且多一路就多一分信息（分母里的项越多，\(\sigma_{\text{fused}}\) 越小）。

    4.3 卡尔曼滤波：带时间维度的融合¶

    上面的加权只处理同一时刻的多路量测。但传感器的信息是随时间来的， 而系统的状态是有规律地演化的（下一步大概在哪，可以预测）。 卡尔曼滤波（Kalman filter） 就是把这两件事结合起来：

    1. 预测：用动力学 / 运动模型，把上一步的估计推到这一步（\(\hat{x}^-,\ P^-\)）；
    2. 更新：拿这一步的量测来修正预测 —— 修正的力度由卡尔曼增益 \(K\) 决定。
    \[ K = \frac{P^-}{P^- + \sigma_{\text{meas}}^2},\qquad \hat{x} = \hat{x}^- + K\,(z - \hat{x}^-),\qquad P = (1-K)P^- \]

    \(K\) 的物理意义非常好懂：它是「该信预测多一点，还是信量测多一点」的开关 ——

    · 量测噪声 \(\sigma_{\text{meas}}\) 很大（传感器很烂）→ \(K \to 0\) → 基本信预测； · 量测很准 → \(K \to 1\) → 基本信量测。

    预测 - 更新 - 再预测 循环下去，就得到一条又平滑、又跟得上变化的估计。

"""第9章 代码3：信息融合 —— 一维卡尔曼滤波把两路传感器合成一份更准的估计。"""
import numpy as np

rng = np.random.default_rng(1)

# 真值：一条缓慢变化的位置曲线（模拟机械臂关节角的缓慢运动）
N, dt = 400, 0.01
t = np.arange(N) * dt
x_true = 1.0 + 0.1 * np.sin(2 * np.pi * 0.1 * t)

# 两路独立传感器：内部编码器（准）、外部视觉（糙）
sig1, sig2 = 0.02, 0.04
z1 = x_true + rng.normal(0, sig1, N)
z2 = x_true + rng.normal(0, sig2, N)


def kalman_fuse(z_list, sig_list, q=1e-6):
    """一维卡尔曼滤波：状态 = 位置。每步对多路量测依次做更新。"""
    x_hat = z_list[0][0]
    P = sig_list[0]**2
    xs = np.empty(len(z_list[0]))
    for k in range(len(xs)):
        P = P + q                              # 预测（随机游走）
        for z, sig in zip(z_list, sig_list):
            K = P / (P + sig**2)               # 卡尔曼增益
            x_hat = x_hat + K * (z[k] - x_hat)  # 更新
            P = (1 - K) * P
        xs[k] = x_hat
    return xs


rmse = lambda a: np.sqrt(np.mean((a - x_true)**2))
e1 = kalman_fuse([z1], [sig1])
e2 = kalman_fuse([z2], [sig2])
ef = kalman_fuse([z1, z2], [sig1, sig2])

print("两路传感器：σ1 = %.2f m（内部编码器），σ2 = %.2f m（外部视觉）" % (sig1, sig2))
print("理论上限：σ_fused = 1/√(1/σ1² + 1/σ2²) = %.4f m"
      % (1 / np.sqrt(1 / sig1**2 + 1 / sig2**2)))
print()
print("只用传感器1          RMSE = %.4f m" % rmse(e1))
print("只用传感器2          RMSE = %.4f m" % rmse(e2))
print("融合两路（卡尔曼）   RMSE = %.4f m" % rmse(ef))

    两路传感器：σ1 = 0.02 m（内部编码器），σ2 = 0.04 m（外部视觉）
理论上限：σ_fused = 1/√(1/σ1² + 1/σ2²) = 0.0179 m

只用传感器1          RMSE = 0.0083 m
只用传感器2          RMSE = 0.0117 m
融合两路（卡尔曼）   RMSE = 0.0069 m

    读最后三行：

    · 单用编码器，RMSE \(=0.0083\) m；单用视觉，\(=0.0117\) m； · 融合后 \(=0.0069\) m —— 比最好的那一路还小。

    这就是融合的价值：不是「取一个折中」，而是「取长补短、去伪存真」。

    （注意一处细节） 表头的理论上限 \(0.0179\) m 是「同一时刻两路量测」的最优融合方差； 而卡尔曼滤波还额外利用了时间上的连续性做平滑（过程噪声很小， 相当于对估计做了低通），所以实际 RMSE 还能低于这个静态上限 —— 「用了历史信息」是卡尔曼比单点加权更聪明的地方。

    融合的三种典型场景

    ① 冗余：两路测同一件事（编码器 + 视觉都测位置）→ 用加权 / Kalman 降噪； ② 互补：各自的频段不同（陀螺高频好、加速度计低频好）→ 用互补滤波； ③ 递推：状态随时间演化（移动机器人定位、SLAM）→ 用 Kalman / EKF / 粒子滤波。 判断用哪种，先问「这两路信息是冗余、互补、还是递推的」。

    例题 1：编码器分辨率与「回零」¶

    某关节用增量式编码器：码盘 2500 线、A/B 正交 4 倍频、减速比 100。 (1) 求每转计数与角度分辨率；(2) 为什么这类机器人开机要先「回零」？

    解答

    (1) 分辨率。 直接套公式：

    \[ \text{每转计数} = 2500 \times 4 \times 100 = 10^6\ \text{计数/转} \]
    \[ \text{角度分辨率} = \frac{360°}{10^6} = 3.6\times10^{-4}\,° \approx 6.3\times10^{-6}\ \text{rad} \]

    即百万分之一圈 —— 这就是工业机器人能高精度定位的底气之一。

    (2) 为什么回零。 增量式编码器只输出「转了多少」的脉冲，计的是一个相对量。 上电瞬间，它不知道「当前是第几个计数」，只知道「从此刻起又转了几个」。

    所以必须先运动到机械原点（撞限位或找零位标记）， 把计数器清零，之后所有角度才有绝对参照。

    一句话：增量式测「变化量」，绝对式测「绝对量」； 要绝对定位，增量式就必须先回零。

    例题 2：为什么「位置差分」测速在低速时不可靠¶

    本页实跑里，真实速度 \(0.02\) rad/s 时，差分测速的标准差已经和速度本身相当。 用量化误差的观点解释这个现象。

    解答

    根子在「位置是离散的」。 编码器位置只能取 \(\dots,\ k\Delta\theta,\ (k+1)\Delta\theta,\ \dots\) 这些离散值， 量化误差最大有半个计数 \(\Delta\theta/2\)。

    速度用差分估计：\(\hat{\omega} = \dfrac{\theta_{k+1}-\theta_k}{\Delta t}\)。 于是位置上的量化误差，被除以一个很小的 \(\Delta t\) 传到了速度上：

    \[ \delta\omega \sim \frac{\Delta\theta}{\Delta t} \]

    本页例子中 \(\Delta\theta/\Delta t = 0.0314\) rad/s，这就是速度估计的「台阶」。

    为什么速度越低越糟：真实速度 \(0.5\) rad/s 时，每步跨过近 \(16\) 个计数， 量化误差被「平均」掉一大半；而 \(0.02\) rad/s 时每步只有 \(0.64\) 个计数 —— 有时跳 1 格、有时不动，差分值在 \(0\) 和 \(0.0314\) 之间乱跳， 噪声自然和真实速度差不多大了。

    一句话：量化台阶 \(\Delta\theta/\Delta t\) 是个常数， 速度越接近它，相对误差越大 —— 低速测速必须靠融合或加长窗口。

    例题 3：双目视觉的误差为什么随距离平方增长¶

    由 \(z = fB/d\) 出发，推导 \(\sigma_z\) 与 \(z\) 的关系， 并解释「为什么远距离测距必须加大基线」。

    解答

    第一步：对 \(d\) 求导（误差传播）。 视差测量误差 \(\sigma_d\) 传到深度上：

    \[ \frac{\partial z}{\partial d} = -\frac{fB}{d^2} \;\Longrightarrow\; \sigma_z \approx \left|\frac{\partial z}{\partial d}\right|\sigma_d = \frac{fB}{d^2}\,\sigma_d \]

    第二步：把 \(d = fB/z\) 代回去，换成 \(z\) 的函数：

    \[ \sigma_z = \frac{fB}{(fB/z)^2}\,\sigma_d = \frac{z^2}{fB}\,\sigma_d \;\Longrightarrow\; \boxed{\ \frac{\sigma_z}{z} = \frac{z}{fB}\,\sigma_d\ } \]

    相对误差正比于 \(z\)（本页实跑：\(0.5 \to 5\) m，相对误差 \(0.1\%\to1.0\%\)，正好十倍）。

    为什么加大基线有用：看分母 —— \(\sigma_z \propto \dfrac{1}{fB}\)。 基线 \(B\) 和焦距 \(f\) 越大，深度误差越小。这就是 车载双目基线做得比手机宽、远距测距用长焦的原因。

    代价：基线 / 焦距一大，视场变窄、近距离容易「看不到同一块区域」 —— 又是一个「量程 vs 精度」的取舍。

    一句话：三角测距的精度上限由「\(fB\)（基线 × 焦距）」定， 误差随距离平方涨 —— 想看得远，就得把「两个眼睛」分得开。

    例题 4：卡尔曼增益在「信预测」和「信量测」之间怎么选¶

    写出卡尔曼增益 \(K = \dfrac{P^-}{P^- + \sigma_{\text{meas}}^2}\)，讨论两种极端情形。

    解答

    增益在 \(0\) 和 \(1\) 之间，由预测的不确定度 \(P^-\) 和量测噪声 \(\sigma_{\text{meas}}\) 的比值决定。

    情形一：量测很烂（\(\sigma_{\text{meas}}\) 很大）。 分母被 \(\sigma_{\text{meas}}^2\) 主导，\(K \to 0\)：

    \[ \hat{x} = \hat{x}^- + K(z-\hat{x}^-) \to \hat{x}^- \]

    修正项几乎为零 —— 基本忽略量测，只信模型预测。

    情形二：量测很准（\(\sigma_{\text{meas}}\to 0\)）。 分母只剩 \(P^-\)，\(K \to 1\)：

    \[ \hat{x} \to \hat{x}^- + 1\cdot(z-\hat{x}^-) = z \]

    —— 直接采用量测。

    一般情形：谁更可信，就更听谁的 —— \(K\) 就是那个自动配好的权重。 而且 \(P^-\) 会随预测步长变大（越推越不确定）， 所以预测隔得越久，\(K\) 越大、越愿意相信新量测 —— 这非常符合直觉。

    一句话：卡尔曼增益 = 「预测 vs 量测」的自动权重， 由两者的不确定度之比实时算出，不需要人工调。

    Q1 内部传感器和外部传感器，本质区别是什么？各举两例。

    提示

    想：这个量，量的是「机器人自己」还是「外部环境」？

    解答

    本质区别：测的是机器人自身的状态，还是外部环境 / 目标的信息。

    · 内部：编码器（关节角）、测速机（关节速度）、IMU（姿态角速度 / 加速度）、 关节力矩传感器 —— 管「我在哪、我多快」； · 外部：距离传感器、六维力传感器、相机、触觉阵列 —— 管「世界什么样」。

    一句话：内部传感器闭环给自己（伺服），外部传感器感知给决策（导航 / 抓取）。

    Q2 增量式编码器和绝对式编码器，为什么后者「开机不用回零」？

    提示

    想：它们的输出是「增量」还是「绝对位置」？

    解答

    因为绝对式编码器输出的就是「此刻的绝对角度」，而非「转了多少」。

    增量式只数脉冲，丢电就丢位置 —— 上电必须回零重建参照； 绝对式的码盘每一位都有唯一编码，任何时刻读出来的就是绝对位置， 断电再上电也照样知道自己在哪。

    代价：绝对式码盘结构复杂、价格高、位数受限于编码位数。

    一句话：增量式记「变化量」（要回零），绝对式记「绝对量」（免回零）。

    Q3 两个独立估计，标准差分别是 \(0.04\) 和 \(0.03\)，最优融合後的方差是多少？ 融合比单用最好的那一路好在哪？

    提示

    套公式 \(\sigma_{\text{fused}} = 1/\sqrt{1/\sigma_1^2 + 1/\sigma_2^2}\)。

    解答
    \[ \sigma_{\text{fused}} = \frac{1}{\sqrt{\frac{1}{0.04^2}+\frac{1}{0.03^2}}} = \frac{1}{\sqrt{625+1111}} \approx 0.024 \]

    单用最好的那一路是 \(0.03\)，融合后 \(0.024 < 0.03\)。

    好在哪：融合永远不比单路差 —— 每加入一路独立信息， 分母就多一项，方差只会变小。这就是「多传感器优于单传感器」的数学表述。

    一句话：独立信息可以「叠加」，误差按 \(1/\sigma^2\) 累加， 所以多一路、准一分。

    Q4 陀螺仪短时很准却会漂，加速度计不漂却很吵。它们为什么是「互补」的？ 融合的思路是什么？

    提示

    想：一个的强项在短时间（高频），另一个的强项在长时间（低频）。

    解答

    因为两者的误差正好落在不同的「频段」上。

    · 陀螺：短时间里积分很准（高频信息好），但零漂会随时间累积， 长时间不可信（低频差）； · 加速度计：长期看不发散（低频好，重力方向恒定），但噪声大、抖动（高频差）。

    融合思路（互补滤波）：把陀螺高通（保留其快速变化）、 加速度计低通（保留其长期稳定），再相加 —— 得到「短时跟得快、长时不漂」的姿态。

    更严谨的做法是卡尔曼滤波：把陀螺当「预测」（积分状态）， 加速度计当「量测」（修正漂移）—— 本页 4.3、4.4 讲的正是这件事。

    一句话：互补 = 取各自擅长的频段，合起来覆盖全频段。

    小结¶

    要记住的 为什么重要
    内部传感器测自己，外部传感器测环境 一条线分清所有传感器
    传感器输出带噪声：系统误差（偏）与随机误差（噪） 所有融合方法的出发点
    增量式记「变化量」（要回零），绝对式记「绝对量」（免回零） 关系到开机流程与成本
    每转计数 = 刻线数 × 倍频 × 减速比 编码器分辨率的计算式
    差分测速的量化台阶 \(= \Delta\theta/\Delta t\)（常数） 所以低速测速不可靠
    陀螺会漂、加速度计含重力 IMU 必须和其他传感器融合
    双目测距 \(z = fB/d\)，残差 \(\sigma_z \propto z^2\) 近准远差是所有三角法的通病
    融合权重 \(w_i \propto 1/\sigma_i^2\) 越准越被信；这就是「最优加权」
    \(\sigma_{\text{fused}} = 1/\sqrt{\sum 1/\sigma_i^2}\) 融合永远不比单路差
    卡尔曼增益 \(K = P^-/(P^-+\sigma_{\text{meas}}^2)\) 「信预测还是信量测」的自动权重
    卡尔曼 = 预测 + 更新 循环 用上时间维度，比单点加权更强
    实跑：单路 \(0.0083/0.0117\)，融合 \(0.0069\) m 融合确实比最好的一路还准

    四条最容易出错的地方：

    1. 把传感器读数当真实值 —— 任何读数都有系统 / 随机误差，先问「偏多少、抖多少」
    2. 以为「分辨率高 = 精度高」 —— 分辨率是「最小刻度」，精度还受安装偏心、量化、标定影响
    3. 用位置差分数值直接当速度 —— 低速时量化噪声会淹没真实速度（本页实跑已证）
    4. 只信一种传感器 —— 每种都有盲区；冗余 / 互补的信息不融合就浪费了
