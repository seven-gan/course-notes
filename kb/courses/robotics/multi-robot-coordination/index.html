    多机器人的协调与控制¶

    前面十几页，主角始终只有一个机器人： 它有自己的关节、自己的传感器、自己的控制器，出了问题自己扛。 但它有三个绕不过去的天花板：看得不够远、扛得不够重、坏一次就全停。 自然界的答案很早就写好了 —— 蚂蚁、蜜蜂单个都很笨， 凑在一起却能完成蚁穴、蜂巢这种「个体根本做不完」的工程。 这一页讲的就是机器人版的同一件事： 当一群机器人要一起干活时，它们凭什么配合、又靠什么保证不出乱子。 主线是四步：先说清「为什么」和「难在哪」（一）→ 再给它建模（二）→ 然后逐个攻破三类典型任务：搜集（三）、队形（四）、围捕（五）。

    这一页的主线

    多机器人系统的一切，都绕着一个词转：协调（coordination）。 多出来的机器人不是「白得的算力」—— 它们各有一双眼睛、各拿一个主意， 还没有公共的坐标系、没有统一的时间、通信还受限制。 所以这一页反复问同一个问题：「信息在谁手里、决定由谁来做」。 三、四、五节就是三种答案：把任务分出去（分配）、把位置凑起来（队形）、 把目标围住（围捕）—— 而它们的底层工具，其实只有两样： 图 / 拉普拉斯矩阵，和指派问题。

    「多机器人」不是「多装几个」

    最常见的误解，是以为「一台不够就上两台，两台不够就上四台」， 于是性能就翻倍。可惜协调本身是要花钱的： 多一台机器人，就多一条要协商的链路、多一份要融合的信息、 多一次可能撞车的风险。本页第一节会用一个最简单的模型把这件事量化 —— 你会看到 台数翻倍，完成时间并不会减半。 多机器人买到的是分布性、并行性、容错性和灵活性， 而这些好处只有在协调做对的前提下才拿得到。

    一、多机器人系统：为什么「多个」比「一个」强¶

    1.1 生物社会的启示：个体的局限，群体的能力¶

    蚂蚁、蜜蜂这类生物的个体能力（感知、通信、动作）都很有限， 但由它们组成的群体却能完成相当复杂的任务。 机器人研究从这里借来一个基本判断：

    复杂任务未必需要一个「很强的个体」，也可以由一群「很弱的个体」通过交互自发完成。

    这句话里有两个关键词，后面会反复出现：

    • 交互 —— 个体之间、个体与环境之间要有信息的交换；
    • 自发（自组织） —— 秩序的来源不是某个中央指挥，而是局部的规则。

    1.2 四个好处：分布、并行、容错、灵活¶

    多机器人系统比单机器人系统多出来的能力，教材归纳成四条。它们不是同一件事， 而是四种不同的「多」：

    好处 说的是什么 典型场景
    空间分布式 多台同时工作在作业空间的不同位置 搬运大物体：单台要造得又大又强、成本高；多台便宜的可以协调完成
    并行性 任务可分解为若干可独立的子任务，同时处理 大面积搜索、多目标监测
    容错能力强 各台的功能相互重叠，一台坏了可由任务重新分配来弥补 危险环境作业、长期值守
    灵活性好 改变机器人数量即可适应任务规模 订单量涨落、地形变化

    这四条里，「并行」和「容错」是最容易被误解的两条， 所以 1.5 节会专门把它们算成数字。

    1.3 多机器人 ≠ 多装几个：三件「消失的东西」¶

    单机器人的世界里，有三样东西是默认存在的，多机器人系统里它们全部消失：

    单机器人 多机器人
    坐标系 一个车身系，自己的位姿就是全部 每台有自己的局部坐标系，没有天然的公共原点
    时间 一个采样节拍，传感器与控制同步 各有各的时钟，通信还有延迟
    信息/决策 所有状态都在一个控制器里 状态分散在各台手中，决策也是分布做的

    这三条一消失，「控制」这个问题的性质就变了： 它从一个单体的优化问题，变成一个分布式的、带通信约束的问题。

    于是产生了一系列单机没有的毛病，后面会逐个遇到：

    • 不能只看一步：每台都做局部最优的选择，整体可能很差（第三节的「贪心」）；
    • 误差会串起来：一台的估计错误会通过交互传给邻居（第四节的「链式放大」）；
    • 会挤成一团：每台都朝同一个目标冲，反而堵住了彼此（第五节的「围捕」）。

    1.4 有意识型与无意识型；三种协调结构¶

    教材把「协调是怎么来的」分成两大类：

    • 无意识型（自组织）：整体行为不是由全局控制产生的， 而是靠个体间局部的交互自发涌现出协调、有序的状态 —— 蚂蚁、蜜蜂是典型例子。
    • 有意识型：个体之间有共同的目标，相互配合、协同工作； 系统有明确的协调机制，可对交互进行推理，必要时协商。 它又分两种：任务相关（task dependent）的协调（为完成任务）和 情形相关（situation dependent）的协调（同一任务因环境变化而改用不同形式）。

    按「协调控制行为的执行者在系统中分布到什么程度」，协调结构分三种：

    结构 谁做决定 优点 缺点
    完全集中的协调 主控机器人完全控制从属者，靠内部规划器保证协调 系统简单，协商开销小 不适用于动态、开放的环境
    集中与分布相结合 机器人组成层次结构，上层对下层有部分控制 折衷 层次间的通信成为瓶颈
    完全分布的协调 各台地位平等，靠各自的推理机制或相互交互，必要时协商 可扩展、抗单点失效 协商开销大，不保证全局最优

    「完全集中」看起来最省事，但它最脆

    把所有决定都交给一台主控，短期内的确让系统变简单了： 不用协商、不用一致，直接下令就行。代价是两条： 主控一坏，整个系统停摆；环境一变，主控的全局模型立刻过期。 这也正是多机器人系统的价值所在 —— 它天生是分布的， 所以「怎么让分布的东西还能协调」才是这一页真正的主题。

    一句话总结这一节： 多机器人的难点不在于「多」，而在于「没有中央、信息不全、还得一起把事办成」。

"""第16章 代码1：多机器人系统的两个基本收益——并行省时间、冗余抗故障。"""
from math import comb

D = 1000.0      # 任务总工作量（单位：单机·步）
Q = 0.20        # 单台机器人在任务期间发生故障的概率（各台独立）


def stats(n):
    r"""n 台并联：可用台数 k ~ B(n, 1-Q)。"""
    p_ok = 1.0 - Q
    p = [comb(n, k) * p_ok ** k * Q ** (n - k) for k in range(n + 1)]
    p_fail = p[0]                                   # 全挂
    e_k = sum(k * p[k] for k in range(n + 1))       # 期望可用台数
    # 期望完成时间：只在「没有全挂」的条件下统计（k 台平分工作量）
    e_t = sum(p[k] * D / k for k in range(1, n + 1)) / (1.0 - p_fail)
    return p_fail, e_k, e_t


print("多机器人系统：并行（省时间）与冗余（抗故障）")
print("任务工作量 D = %.0f 单机·步；单机故障概率 Q = %.2f（各台独立）" % (D, Q))
print()

print(" ------  ---------   ------------    --------------    ----------")

    二、多机器人系统的模型¶

    要把「一群机器人」当成一个可以分析的对象，得先有模型。 这一节分三步：先写单台的运动，再写它们之间「谁能看见谁」，最后写它们怎样互相影响。

    2.1 单台机器人：轮式移动机器人的运动学¶

    多机器人系统里最常见的个体是轮式移动机器人。它不能横向平移， 所以状态是「位置 + 朝向」三个量，记作 \((x,\,y,\,\theta)\)， 控制量是前进速度 \(v\) 和转向角速度 \(\omega\)：

    \[ \begin{aligned} \dot x &= v\cos\theta \\ \dot y &= v\sin\theta \\ \dot\theta &= \omega \end{aligned} \]

    怎么读这三行：前两行说「车头朝哪，就往哪走」—— 速度的方向被朝向 \(\theta\) 锁死了； 第三行说「转向是自己给的」。这种「速度方向 = 朝向」的约束，叫非完整约束， 它正是轮式机器人不能横着挪的数学表达。

    单看一台，这是一个普通的非线性系统。多机器人的问题是：当有 \(n\) 台这样的小车时，怎么描述整体？

    2.2 把 \(n\) 台拼起来：通信拓扑与拉普拉斯矩阵¶

    最直接的办法是「打包」：把 \(n\) 台的状态摞成一个长向量 \(\boldsymbol x = [x_1, y_1, \theta_1, \dots, x_n, y_n, \theta_n]^{\mathsf T}\)。 这解决了「描述」，但没解决「关系」—— 谁跟谁有影响，这个信息不在状态里。

    描述「谁跟谁」的工具是图。记 \(G = (V, E)\)：

    • 顶点 \(V = \{1, 2, \dots, n\}\) 是机器人；
    • 边 \(E\)：\((i, j) \in E\) 表示 \(i\) 能直接获得 \(j\) 的信息（通信或感知）。

    把这张图写成矩阵，有两个层次：

    \[ A_{ij} = \begin{cases} 1, & (i,j) \in E \\ 0, & \text{否则} \end{cases} \qquad D = \operatorname{diag}\Big(\textstyle\sum_j A_{1j}, \dots, \sum_j A_{nj}\Big) \qquad L = D - A \]
    • \(A\) 叫邻接矩阵：一行有几个 1，就是「这台能看见几台」（图的基础见 图与邻接矩阵）；
    • \(D\) 叫度矩阵：对角线上是每台的「邻居数」；
    • \(L\) 叫拉普拉斯矩阵，它是这一节的主角。

    拉普拉斯矩阵有两个必须记住的性质：

    \[ L\,\boldsymbol 1 = \boldsymbol 0 \qquad\text{（每一行的元素加起来等于 0）} \]
    \[ L \succeq 0 \qquad\text{（半正定，所有特征值} \ge 0\text{）} \]

    为什么行和为 0？ 因为 \(L = D - A\)，而 \(D\) 的对角元正是 \(A\) 那一行的和。 把每一行减去自己的和，自然得 0 —— 这条性质后面会直接推出「平均值守恒」。

    它的特征值从小到大排成 \(0 = \lambda_1 \le \lambda_2 \le \dots \le \lambda_n\)。 其中 \(\lambda_1\) 一定是 0（对应特征向量 \(\boldsymbol 1\)）， 而 \(\lambda_2\) 只有在图「连通」时才大于 0，所以 \(\lambda_2\) 有个专门的名字： 代数连通度（特征值的计算见 特征值与特征向量）。

    2.3 一致性：为什么「跟着邻居走」会收敛到平均¶

    现在给每台一条最简单的协调规则：向邻居的平均位置靠拢。

    \[ \dot x_i = \sum_{j \in \mathcal N_i} a_{ij}\,(x_j - x_i) \]

    其中 \(\mathcal N_i\) 是 \(i\) 的邻居集合，\(a_{ij}\) 是边权（这里取 0/1）。 怎么读这条式子：\(i\) 的速度 = 「邻居的位置与我之差」的加权和 —— 拉我的人越多、拉得越远，我动得越快。

    把 \(n\) 条式子写在一起，就得到一个惊人的简单形式：

    \[ \dot{\boldsymbol x} = -L\,\boldsymbol x \]

    推导（只差一步，但这一步很关键）： 第 \(i\) 个分量是 \(\sum_j A_{ij}(x_j - x_i) = \sum_j A_{ij}x_j - \big(\sum_j A_{ij}\big)x_i\)。 第一项是 \(A\boldsymbol x\) 的第 \(i\) 行，第二项是 \(D\boldsymbol x\) 的第 \(i\) 行， 合起来就是 \((A - D)\boldsymbol x = -L\boldsymbol x\)。

    下面两个结论都从 \(L\boldsymbol 1 = \boldsymbol 0\) 直接掉出来。

    结论一：平均值守恒。

    \[ \frac{d}{dt}\left(\frac{1}{n}\boldsymbol 1^{\mathsf T}\boldsymbol x\right) = \frac{1}{n}\boldsymbol 1^{\mathsf T}\dot{\boldsymbol x} = -\frac{1}{n}\big(\boldsymbol 1^{\mathsf T} L\big)\boldsymbol x = -\frac{1}{n}\big(L\boldsymbol 1\big)^{\mathsf T}\boldsymbol x = 0 \]

    怎么读：每台都在「往外给」，但给出去的总量恰好等于收进来的总量， 所以整体平均一动不动。

    结论二：只要图连通，所有 \(x_i\) 会收敛到那个平均值。 因为误差 \(\boldsymbol e = \boldsymbol x - \bar x \boldsymbol 1\) 满足 \(\boldsymbol 1^{\mathsf T}\boldsymbol e = 0\)， 它落在 \(\boldsymbol 1\) 的正交补里；在这个子空间上 \(-L\) 的最大特征值是 \(-\lambda_2 \lt 0\)， 所以 \(\boldsymbol e(t) \to \boldsymbol 0\)，收敛速度由 \(-\lambda_2\) 决定： \(\lambda_2\) 越大收敛越快。

    一致性的是与非：它不「选」共识，只是「算」共识

    两条容易被忽略的推论： ① 共识值不是协商出来的，是初值决定的。 平均值守恒意味着 不管用什么拓扑、跑多久，最终值一定是初始值的平均。 想让它变成别的数，必须给系统外部输入（例如加一个「领航者」的偏置项）。 ② 拓扑只决定「快慢」，不决定「结果」。 换成链、环、星形、完全图， 收敛的终点都一样，差别只在 \(\lambda_2\) 决定的收敛速度。 这恰好是 2.5 节实跑要验证的事。

    2.4 四种常见的体系结构¶

    一致性只是「协调规则」的一种。教材与文献里还有几种经典结构，各有取舍：

    结构 核心想法 优点 缺点
    领航-跟随 一台是领航（有目标），其余按固定相对位姿跟它 简单、易实现 领航一坏就群龙无首；误差沿跟随链放大
    虚拟结构 把整个队形看成一个刚性刚体，每台追自己的那个「刚体上的点」 队形保持精度高 需要统一的队形描述，灵活性差
    基于行为 每台由若干基本行为（避障、聚合、保持距离）加权合成 行为可叠加、反应快 权重难调，无法保证收敛
    图 / 一致性 用通信图 + 局部规则，让某个量（位置、朝向）达成一致 可扩展、有理论保证 需要连通性，共识值受初值限制

    这四种不是互斥的：工程里常见的是「用图结构描述相对关系， 用领航给队形一个基准，用行为法处理避障」。

"""第16章 代码2：一致性模型 dx/dt = -L x —— 拉普拉斯矩阵与通信拓扑。"""
import numpy as np


def adjacency(kind, n):
    """通信拓扑的邻接矩阵：a_ij = 1 表示 i 能与 j 直接通信。"""
    A = np.zeros((n, n))
    if kind == "链":
        for i in range(n - 1):
            A[i, i + 1] = A[i + 1, i] = 1.0
    elif kind == "环":
        for i in range(n):
            A[i, (i + 1) % n] = A[(i + 1) % n, i] = 1.0
    elif kind == "星形":
        for i in range(1, n):
            A[0, i] = A[i, 0] = 1.0
    elif kind == "完全图":
        A = np.ones((n, n)) - np.eye(n)
    return A


def simulate(A, x0, dt=0.01, tol=1e-3, tmax=200.0):
    """欧拉积分 dx/dt = -L x，返回 (步数, 末态, 平均位置)。"""
    n = A.shape[0]
    L = np.diag(A.sum(axis=1)) - A
    x = x0.astype(float).copy()
    mean = x.mean()
    for step in range(1, int(tmax / dt) + 1):
        x = x - dt * (L @ x)
        if np.max(np.abs(x - mean)) < tol:
            return step, x, mean
    return int(tmax / dt), x, mean


n = 5
x0 = np.array([5.0, 1.0, 4.0, 2.0, 3.0])
print("一致性模型：%d 台机器人交换“邻居的位置”，最终收敛到初始平均" % n)
print("初值 x0 =", x0.astype(int).tolist(), " → 初始平均 =",
      int(x0.mean()), "（这个平均值守恒，谁也没法改）")
print()
print(" 通信拓扑   代数连通度λ2    收敛到 1e-3 所需步数    末态（应全等于平均）")
print(" --------  -------------   -------------------    --------------------")
for kind in ("链", "环", "星形", "完全图"):
    A = adjacency(kind, n)
    L = np.diag(A.sum(axis=1)) - A
    lam = np.sort(np.linalg.eigvalsh(L))
    steps, x, mean = simulate(A, x0)
    print("  %-6s     %8.3f          %8d              [%.3f %.3f %.3f %.3f %.3f]"
          % (kind, lam[1], steps, *x))
print()
print("λ2（代数连通度）就是“收敛快慢”的刻度：")
print("  链 0.382 最慢（信息要一站一站传），完全图 5.000 最快（人人直连）。")
print("所有拓扑的末态都收敛到同一个平均 3.000 —— 一致性算法不需要“领导”，")
print("只要通信图连通，共识值就由初值唯一决定。")

    三、多机器人合作搜集：把任务分出去¶

    3.1 搜集：搜索 + 收集¶

    搜集（foraging）指的是：把散落在未知（或部分未知）环境中的物体 找到并运送到指定区域。教材指出自然界的蚂蚁、蜜蜂的觅食活动本身就是一种搜集行为， 机器人搜集在工程上对应着垃圾收集、扫雷等任务。

    关键是它天然包含两个阶段：

    1. 搜索（Search） —— 找到空间中还没有被发现的待搜集物；
    2. 收集（Collect） —— 把已经找到的物体运到指定区域。

    这两件事对机器人的要求完全不同：搜索要的是跑得快、看得广； 收集要的是装得下、拿得住。于是有了一个很有启发的分工：

    机器人类型 工具 特点
    铲型机器人 带铲铲工具 一次能携带两个被搜集物，但传感范围小
    夹型机器人 装夹型工具 一次只能拿一个，但传感距离远

    教材还提到两条很实际的规则： 机器人不需要知道其他机器人在任意时刻的行为， 而如果别的机器人出现在它的传感范围之内，就当作移动的障碍物处理。 —— 这是一种典型的「降低耦合」的设计：不去理解别人，只去躲开别人。

    3.2 任务分解与任务分配¶

    教材特别强调：任务分配和任务分解密不可分。

    • 任务分解：把系统要完成的任务，按任务本身的特性、控制要求以及资源配置， 拆成若干子任务；
    • 任务分配：决定由谁来完成这些子任务。

    为什么分配这么难？因为「谁最适合干这个子任务」事先并不知道， 必须在一群符合要求的机器人里挑，这本身就是一个耗时的搜索过程。 影响分配效果的因素也很多：单体的认知能力、行为能力、通信能力、 任务本身的特性，以及机器人群体形成的社会结构。

    3.3 分配问题的数学形式：指派问题¶

    把最简单的情形写下来：\(n\) 台机器人、\(n\) 个任务， 机器人 \(i\) 完成任务 \(j\) 的代价是 \(c_{ij}\)（比如距离）。 要求一台一个、一个一台，让总代价最小：

    \[ \min_{x_{ij} \in \{0,1\}} \sum_{i=1}^{n}\sum_{j=1}^{n} c_{ij}\,x_{ij} \qquad\text{s.t.}\qquad \sum_{j=1}^{n} x_{ij} = 1,\quad \sum_{i=1}^{n} x_{ij} = 1 \]
    • 第一个约束：每台机器人只接一个任务；
    • 第二个约束：每个任务只被一台接走。

    这就是运筹学里的指派问题，它是一个整数规划 —— 看上去像线性规划，但「\(x_{ij}\) 只能取 0 或 1」这条约束让它的可行域不再连续， 所以不能直接套用连续优化那套（拉格朗日乘子法在这里只能帮我们放宽问题、给出下界）。 幸运的是，指派问题有一个特别高效、而且保证最优的解：匈牙利算法， 它的复杂度是多项式级的，\(n\) 稍大也能算得动。

    3.4 三种分配机制：预定义、涌现式、市场¶

    教材里给出了一条「分配由谁决定」的谱系：

    机制 谁来决定 特点
    预先规定的分配 系统设计者事先定好 简单可预测，但不适应环境变化
    涌现式分配（emergent allocation） 机器人在任务过程中，依据实时获得的外部与内部信息自己选择子任务 整个系统呈现不断变化的分配状态；不需要中央
    市场 / 投标机制 通过投标（能力、位置、代价）竞争任务 分布式、可扩展；能力不足时还能「联合投标」

    涌现式分配还有个很妙的生物界原型：受蚂蚁沿路留下化学物质的启发， 有的策略让「带路」机器人在通往被搜集物的途中给同伴留下记号， 后来的机器人顺着记号走 —— 这里的「记号」就是一份共享的环境记忆。

    教材用搜集任务把三种算法做了对照：

    算法 任务怎么分 特点
    同构算法 任务不分解，从搜索到收集由每台单独完成 简单；但擅长搜索的被迫去做收集，能力错配
    异构算法 分解成「搜索」与「收集」两个子任务，任何时刻每台只选其一 按环境状况切换子任务，分工自然涌现

    「每台都做局部最优的选择」会毁掉全局

    这是 1.3 节说过的第一个毛病，现在可以讲清楚了。 贪心分配的每一步都无可指摘：选当下最短的那一对，谁也说不出错。 但它一旦选中，就把一台机器人和一个任务同时锁死， 于是后面被迫去走远路 —— 局部最优的叠加，不等于全局最优。 3.5 节会用两个例子把这件事量化：一个 2×2 的手算例子， 和 500 次随机实验的统计。

"""第16章 代码3：任务分配——贪心（局部最优） vs 匈牙利算法（全局最优）。"""
import numpy as np
from scipy.optimize import linear_sum_assignment


def greedy(C):
    """贪心：把所有 (机器人, 任务) 对按代价排序，从小到大“先到先得”。"""
    pairs = sorted(((C[i, j], i, j) for i in range(C.shape[0])
                    for j in range(C.shape[1])))
    used_r, used_t, assign = set(), set(), {}
    for cost, i, j in pairs:
        if i in used_r or j in used_t:
            continue
        used_r.add(i)
        used_t.add(j)
        assign[i] = j
    return assign


def costs(C):
    g = greedy(C)
    cg = sum(C[i, j] for i, j in g.items())
    rows, cols = linear_sum_assignment(C)      # 匈牙利算法：全局最优
    return cg, float(C[rows, cols].sum())


# ---------- 一个“贪心会栽跟头”的两机器人两任务小例子 ----------
C0 = np.array([[1.0, 2.0],
               [1.0, 100.0]])
cg0, co0 = costs(C0)
print("例：2 台机器人、2 个任务，代价矩阵（行=机器人，列=任务）")
print("        任务0   任务1")

print(" 机器1  %5.1f  %6.1f" % (C0[1, 0], C0[1, 1]))

print("      总代价 %.1f —— 比贪心少走 %.1f。\n" % (co0, cg0 - co0))

# ---------- 随机扫描：贪心平均差多少 ----------
rng = np.random.default_rng(16)
N, TRIALS = 6, 500
ratios, worse = [], 0
for _ in range(TRIALS):
    P = rng.uniform(0.0, 10.0, (N, 2))
    Q = rng.uniform(0.0, 10.0, (N, 2))
    C = np.linalg.norm(P[:, None, :] - Q[None, :, :], axis=2)
    cg, co = costs(C)
    ratios.append(cg / co)
    worse += (cg > co + 1e-9)
ratios = np.array(ratios)
print("随机扫描 %d 个实例（%d 台机器人 / %d 个任务，代价=直线距离）：" % (TRIALS, N, N))
print("  贪心严格更差的实例：%d / %d（%.0f%%）" % (worse, TRIALS, 100.0 * worse / TRIALS))
print("  总代价比值 贪心/最优：平均 %.4f，最坏 %.4f" % (ratios.mean(), ratios.max()))
print()
print("结论：贪心只保证“每一步局部最优”，整体却没有保证——")
print("随机实例里 %d%% 都严格更差，平均多走 %.1f%%，最坏多走 %.1f%%；"
      % (100.0 * worse / TRIALS, 100 * (ratios.mean() - 1), 100 * (ratios.max() - 1)))
print("上面那个 2×2 例子更极端（101 对 3，差 30 多倍）。要“保证最优”，")
print("就得把分配当成一个整体的组合优化问题来解（匈牙利算法）。")

    四、多机器人队形控制¶

    4.1 队形怎么描述：位置，还是距离¶

    「保持队形」这句话，在数学上有两种写法，差别很大：

    • 绝对位置描述：给每台指定它在某个公共坐标系里的目标位置。 问题：公共坐标系从哪来？GPS 不是哪儿都有。
    • 相对描述：只规定彼此之间的几何关系。它又分两种最常用的：
    • 距离-距离（\(l\)-\(l\)）：规定 \(i\) 与邻居 \(j\)、\(k\) 的距离；
    • 距离-方位（\(l\)-\(\psi\)）：规定 \(i\) 相对 \(j\) 的距离 \(l\) 和方位角 \(\psi\)。

    怎么读：\(l\)-\(l\) 只要测距（例如 UWB、激光），\(l\)-\(\psi\) 还要测方向（例如视觉、罗盘）。 相对描述的好处是「不需要全局坐标系」 —— 这与 1.3 节说的「公共坐标系消失了」正好对上。 代价是：只知道相对关系，整个队形可以整体平移/旋转而不被察觉 —— 这和 SLAM 里的规范自由度是同一个数学现象。

    4.2 四种队形控制方法¶

    方法 每台的目标从哪来 优点 缺点
    领航-跟随 相对领航（或前一台）的 \(l\)-\(\psi\) 结构简单，不需全局信息 领航失效即崩；误差沿链放大
    虚拟结构 刚体队形上的固定点 队形精度高 需要统一的队形描述；不灵活
    基于行为 若干基本行为的加权合成 反应快、易叠加 权重难调，无收敛保证
    图 / 一致性 由通信图与局部规则共同决定 可扩展、有理论保证 需连通性；收敛慢

    4.3 教材里的链型排列：三类机器人与三步问题¶

    教材用一个很具体的任务来展开队形问题：多机器人码头货物装卸 —— 机器人要排成链型队列，把货物一站一站地「Robot-to-Robot」传下去。 它按信息完备程度把机器人分成三类：

    类型 拥有什么信息 结果
    I 类：信息不完全 只有局部感知，靠个体间交互与个体-环境交互 能完成任务，但系统效率低
    II 类：信息相对完全 有一定范围的通信能力，把各自不完整的局部信息综合起来 能形成相对完整的理解，较有效地规划行为
    III 类：信息完全 有全局目标，已知地图与各目标点位置，有自己的坐标 可以实现一个有效的群体，但现实中很难获取全部信息

    最后教材给出一句很实在的结论： 从实际角度，「局部感知 + 必要的通信」是一种较好的选择。

    教材进一步把这个问题拆成三步，这三步几乎是所有队形任务的通用骨架：

    1. Search（搜索） —— 机器人怎样在整个工作区域内搜索，找到各个目标点？如何提高搜索效率？
    2. Sub-group Making（分子群） —— 搜索完成后，怎样构造协调的子群？
    3. Coordination（协调） —— 子群内各台怎样协调各自的动作？

    对最简单的 I 类机器人，教材给了五条假定，写得非常具体，值得抄下来当模板：

    1. 机器人可以在工作空间的任意方向上以速度 \(v\) 移动，\(0 \le v \le v_{\max}\)；
    2. 能够识别各个目标点；
    3. 具有避障功能；
    4. 有一定范围的传感能力，能感知有限范围内其他机器人的状态；
    5. 能根据其他机器人的状态改变自己的状态。

    对信息更全的 III 类机器人，教材还给出了「链型队列的优化」办法： 在各目标点连成的线上等距分布一些点，让系统去占据它们； 每台机器人的期望位置取为它到「连接首尾两台的直线」的垂足， 若该位置不可达（有障碍）就在附近另找一个 —— 这样每台可以自主规划自己的期望位置， 整个队列就被逐步「拉直」了。

    链型队形的两个结构性毛病

    ① 逐级跟随 = 误差逐级放大。 每台只盯住自己的前一台， 前一台的估计误差就被当成真值抄了下来，再叠加自己的噪声 —— 误差像随机游走一样顺着链条往下传，队形越长，末端越飘（4.4 节实跑）。 ② 领航是单点故障。 领航一坏，整个队形失去基准。 这两点的应对都指向同一个方向：不要只依赖「邻居的当前位置」， 要引入信息共享与全局优化 —— 这正是 III 类机器人（和一致性方法）的价值。

"""第16章 代码4：链式领航-跟随队形控制——误差沿链条逐级放大。"""
import numpy as np

rng = np.random.default_rng(16)

M = 6            # 机器人总数：1 个领航 + 5 个跟随
L_DES = 1.00     # 相邻两台之间的期望间距（m）
K_GAIN = 1.20    # 跟随控制增益
SIG = 0.030      # 每步的位置扰动（模拟轮子打滑、定位噪声）
DT = 0.01
STEPS = 6000
R_C, OMEGA = 4.0, 0.40          # 领航走半径 4 m 的圆，角速度 0.40 rad/s


def leader(t):
    """领航的真值位姿与速度（匀速圆周）。"""
    th = OMEGA * t
    r_hat = np.array([np.cos(th), np.sin(th)])
    h = np.array([-np.sin(th), np.cos(th)])       # 航向 = 切线方向
    return R_C * r_hat, h, r_hat


pos = np.zeros((M, 2))
pos[0], _, _ = leader(0.0)
for i in range(1, M):                            # 跟在后面一字排开，留一点初始偏差
    pos[i] = pos[0] - i * L_DES * np.array([0.0, 1.0]) + rng.normal(0, 0.15, 2)

ideal_err = np.zeros((STEPS, M))                 # 各台相对“理想队形点”的位置误差
for t in range(STEPS):
    tt = t * DT
    pL, hL, r_hat = leader(tt)
    pos[0] = pL
    ideal_err[t, 0] = 0.0
    for i in range(1, M):                        # 逐级跟随：目标 = 前一串的后方 L_DES 处
        target = pos[i - 1] - L_DES * hL
        # 前馈：理想队形点自身的运动速度（圆周上既有切向、也有径向前馈）
        v_ff = R_C * OMEGA * hL + i * L_DES * OMEGA * r_hat
        pos[i] += (K_GAIN * (target - pos[i]) + v_ff) * DT \
            + SIG * np.sqrt(DT) * rng.normal(0, 1, 2)
        ideal_err[t, i] = np.linalg.norm(pos[i] - (pL - i * L_DES * hL))

burn = STEPS // 2                                # 先丢掉前半段（过渡过程）
e = ideal_err[burn:, :].mean(axis=0)
print("链式领航-跟随队形控制：1 个领航 + %d 个跟随，期望间距 %.2f m" % (M - 1, L_DES))
print("领航沿半径 %.1f m 的圆周走；跟随增益 k=%.2f，每步扰动 σ=%.3f" % (R_C, K_GAIN, SIG))
print()
print(" 跟随级数    相对理想队形的误差(m)    相对第 1 级放大")
print(" --------   ---------------------    --------------")
for i in range(1, M):
    print("   第%d级            %8.4f             %6.2f×" % (i, e[i], e[i] / e[1]))
print()
print("队形误差沿链条单调放大：从第 1 级的 %.4f m 涨到第 %d 级的 %.4f m（%.1f 倍）。"
      % (e[1], M - 1, e[M - 1], e[M - 1] / e[1]))
print("每一级只能看到“前一级现在在哪”，前一级的误差就被当成真值抄了下来，")
print("再叠加自己的扰动 —— 误差像随机游走一样顺着链条往下传。")
print("这正是链型队形必须靠信息共享 / 全局优化（而不只是逐级跟随）来纠偏的原因。")

    五、多机器人围捕¶

    5.1 围捕问题与捕获条件¶

    围捕（encirclement / pursuit）是教材给的第三个典型任务： 一群机器人去围住一个（或多个）入侵的移动目标。

    • 逃逸者（evader）：与移动机器人相似，数量可能不止一个； 它可以随机运动，也可以根据自身传感器获取的信息智能决策、力求逃脱追捕。
    • 追捕者（pursuer）：由多台机器人组成，通过局部交互加快任务完成。

    什么叫「捕获」？ 教材的定义很干脆：

    当某个 evader 不能动弹（例如被机器人围住或被堵住等），表明该 evader 被捕获； 当环境中所有 evader 都被捕获，任务完成。

    把这句话翻成可判定的条件，需要两个量： 包围半径 \(r_c\) 和方位角的最大间隙 \(\Delta\theta_{\max}\)。

    \[ \underbrace{d_i \le r_c\ \ \forall i}_{\text{人人贴住包围圈}} \qquad\text{且}\qquad \underbrace{\max_k \Delta\theta_k \le \Delta_{\max}}_{\text{方位铺满一圈，没有缺口}} \]

    怎么读：\(d_i\) 是第 \(i\) 台到逃逸者的距离，\(\Delta\theta_k\) 是相邻两台的方位角之差。 第一个条件防「离太远」，第二个条件防「挤在一侧」。 只有两个条件同时满足，逃逸者才真的动不了 —— 任何一个方向留着缺口，它就从那里跑掉。

    教材还提到一类很典型的配置：一群地面机器人 + 一个监控机器人（例如无人机）。 无人机负责探测 evader，地面机器人负责捕捉 —— 这是把「搜索」和「捕捉」分工到不同平台上。

    5.2 局部坐标系与范围传感器模型¶

    教材对围捕任务的设定有一个关键前提：机器人只有自己的局部坐标系， 它基于周围环境独立决策，靠机器人之间的局部交互来加快任务完成。

    每台机器人用的传感器模型叫范围传感器模型 \(S_{\text{range}}\)： 一共 9 个传感器，每个的探测区域是一个扇形， 箭头方向表示机器人当前的运动方向；机器人能感知每个扇形区域内是否有障碍以及相应距离。 另外还假设机器人与 evader 的视觉范围一致，能区分队友和 evader —— 所以看到 evader 时不会把它当障碍物躲开。

    怎么读这个模型：它把「周围一圈」量化成 9 个扇区的有无 + 距离。 这是一种非常「便宜」的表示 —— 不需要建图、不需要坐标， 只要「哪边有东西、多远」。围捕、避障这类反应式任务，用这种表示就够了。

    5.3 追捕者的四个状态¶

    教材给追捕者设计的是一个有限状态机，按当前掌握的信息切换四种行为：

    状态 什么时候进入 做什么
    搜索 evader 还没被发现 在区域内搜索
    追逐 看到了 evader，但时机还不成熟 朝理想位置运动，并避免与队友相互干扰
    捕捉 认为可以捕捉了 压上去，并持续一段时间 step_catch；超时说明它可能已经跑出包围，要重新分析形势
    预测 追逐中 evader 突然脱离视野 在 step_predict 时间内按它此前的位置预测其运动；再超时就要重新搜索

    追捕状态里有一条很值得琢磨的规则：避免相互干扰。 当 \(R_i\) 与 evader、以及附近另一台机器人 \(R_i^{\min}\) 构成的角度 \(\varphi_{\min}\) 小于阈值（约 \(2\pi/3\) 或 \(2\pi/(N_{\Gamma_i}+1)\)）时， \(R_i\) 不再朝 evader 直冲，而是绕到另一个方位去 —— 也就是有意识地把自己挪开一点，好让包围圈铺得开。

    「每台都朝目标直冲」会毁掉围捕

    这是 1.3 节说的第三个毛病。直冲在直觉上无可指摘： 离目标最近的方向当然是最快的方向。但把它放进多台的语境里就出问题了： 所有人都朝同一个点冲，最后会挤在同一侧，围圈上留下一个大缺口， 逃逸者就从缺口跑掉。更要命的是这个缺口不会自己消失 —— 因为对每一台来说，直冲永远是它的局部最优。 解法也很直白：把「站到圆周上的哪个方位」当成一次任务分配（第 3.5 节）， 每台奔向自己认领的那个方位，而不是奔向同一个点。

    5.4 逃逸者的策略¶

    教材对 evader 的设计同样简单而有效：假定 evader 跟机器人采用同样的传感模型。 当它没看到任何机器人或静态障碍时，它随机运动； 一旦看到了，它就应当力求安全，尽力逃脱机器人的围捕。

    怎么读：逃逸者的策略是两段式 —— 「看不见人 → 随便逛」（相当于搜索机会）， 「看见人 → 往安全的方向跑」。5.5 节实跑里把它写成一个更明确的规则： 朝「1 秒后离最近追捕者最远」的那个方向跑。

"""第16章 代码5：多机器人围捕——各跑各的“直冲”为什么合不了围。"""
import numpy as np

N = 5                    # 追捕者台数
R_C = 1.20               # 包围半径：追捕者只许“围”，不许扑进这个圈
V_P, V_E = 1.00, 0.50    # 追捕速度 / 逃逸速度
DT = 0.02
TMAX = 60.0
GAP_OK = 2 * np.pi / N * 1.5          # 判定“围住”：最大角度间隙 ≤ 1.5 个理想间隔
DIRS = np.array([(np.cos(a), np.sin(a))
                 for a in np.linspace(0, 2 * np.pi, 72, endpoint=False)])


def run(encircle):
    """encircle=False：各自朝逃逸者直冲；True：奔向自己认领的围捕点。

    返回 (合围时刻或 None, 各追捕者到逃逸者的距离, 方位角(度), 最大角度间隙(度))。
    """
    r = np.random.default_rng(16)
    ev = r.uniform(0.0, 8.0, 2)
    P = r.uniform(0.0, 8.0, (N, 2))
    # 一开始就按方位“认领”围捕点，此后不再改：形成一个固定的合围分工
    rank = np.argsort(np.argsort(np.arctan2(P[:, 1] - ev[1], P[:, 0] - ev[0])))
    for step in range(int(TMAX / DT)):
        # --- 逃逸者：朝“1 秒后离最近追捕者最远”的方向跑 ---
        cand = ev + V_E * 1.0 * DIRS
        dmin = np.array([np.min(np.linalg.norm(P - c, axis=1)) for c in cand])
        ev = ev + V_E * DT * DIRS[np.argmax(dmin)]
        # --- 追捕者 ---
        if encircle:
            ang = 2 * np.pi * rank / N
            tgt = ev + R_C * np.stack([np.cos(ang), np.sin(ang)], axis=1)
            dirv = tgt - P
        else:
            dirv = ev - P                       # 都朝同一个点冲
        nn = np.linalg.norm(dirv, axis=1)
        nn[nn < 1e-9] = 1.0
        P = P + V_P * DT * dirv / nn[:, None]
        # 贴到包围圈就停住，不许扑进去（否则“围”变成“撞”）
        d = np.linalg.norm(P - ev, axis=1)
        for i in range(N):
            if d[i] < R_C:
                u = P[i] - ev
                P[i] = ev + R_C * u / (np.linalg.norm(u) + 1e-12)
        # --- 判定：人人都在圈上，且方位铺满一圈 ---
        dd = np.linalg.norm(P - ev, axis=1)
        a = np.sort(np.arctan2(P[:, 1] - ev[1], P[:, 0] - ev[0]))
        gap = np.degrees(np.diff(np.concatenate([a, a[:1] + 2 * np.pi])).max())
        if dd.max() <= R_C * 1.15 and np.radians(gap) <= GAP_OK:
            return step * DT, dd, np.degrees(a), gap
    return None, dd, np.degrees(a), gap

    例题 1：为什么「多机器人」能提升可靠性，却不能线性提升速度¶

    问：用 1.5 节的模型（\(D=1000\)、\(Q=0.2\)）， 解释为什么 \(n=8\) 时提速只有 6.16 倍（小于 8）， 而全挂概率却从 20% 掉到几乎为 0。

    解答

    先看速度。 台数 \(n=8\)、单台故障率 \(Q=0.2\) 时， 可用台数 \(k\) 服从二项分布 \(B(8, 0.8)\)，期望 \(E[k] = 8\times 0.8 = 6.4\) 台。

    但这还不是全部 —— 完成时间是 \(D/k\)，而 \(1/k\) 不是线性函数， 由詹森不等式，\(E[1/k] \gt 1/E[k]\)（\(1/k\) 是凸函数）。 所以实际速度还要再打一点折扣。表里 6.16 倍正是这个数： \(8 \times (1 - \text{故障带来的损失}) \approx 6.16\)。

    直觉：故障把活重新分配给了活着的机器。 一台挂了，它那份活不是「消失」，而是压给剩下的 —— 于是系统的平均速度永远低于「按台数」的线性外推， 而且 \(Q\) 越大，差得越多。

    再看可靠性。 全挂只有一种可能：8 台全部故障， 概率 \(Q^{8} = 0.2^{8} = 2.56\times 10^{-6}\)。

    为什么它掉得这么快？ 因为要求「每一台都坏」， 而各台是独立的，概率要相乘。指数衰减就是这么来的。

    一句话：并行买的是「时间」，冗余买的是「保险」，两者不能互相替代。 一个系统想又快又稳，就要同时具备这两样 —— 这也是真实多机器人系统通常既要求「分工」又要求「备份」的原因。

    例题 2：一致性为什么收敛到「初值的平均」¶

    问：对 \(\dot{\boldsymbol x} = -L\boldsymbol x\)，证明 \(n\) 台的位置最终收敛到 初值的平均 \(\bar x_0\)。如果给每台再加一个相同的常数输入 \(b\) （即 \(\dot{\boldsymbol x} = -L\boldsymbol x + b\boldsymbol 1\)），结果会怎样？

    解答

    第一步：平均值守恒。 记 \(\bar x(t) = \frac1n \boldsymbol 1^{\mathsf T}\boldsymbol x(t)\)。 由 \(L\boldsymbol 1 = \boldsymbol 0\)：

    \[ \frac{d\bar x}{dt} = \frac1n \boldsymbol 1^{\mathsf T}\dot{\boldsymbol x} = -\frac1n \boldsymbol 1^{\mathsf T} L \boldsymbol x = -\frac1n (L^{\mathsf T}\boldsymbol 1)^{\mathsf T}\boldsymbol x = 0 \]

    （最后一步用了 \(L^{\mathsf T} = L\) 和 \(L\boldsymbol 1 = \boldsymbol 0\)。） 所以 \(\bar x(t) \equiv \bar x_0\) —— 平均值一步都不动。

    第二步：图连通则全体一致。 令误差 \(\boldsymbol e = \boldsymbol x - \bar x_0\boldsymbol 1\)。 因为 \(\boldsymbol 1^{\mathsf T}\boldsymbol e = 0\)，\(\boldsymbol e\) 始终落在 \(\boldsymbol 1\) 的正交补里。 在这个子空间上，\(-L\) 的特征值是 \(-\lambda_2, \dots, -\lambda_n\)，全都 \(\le -\lambda_2 \lt 0\) （图连通时 \(\lambda_2 \gt 0\)）。于是 \(\boldsymbol e(t) \to \boldsymbol 0\)， 即 \(\boldsymbol x(t) \to \bar x_0 \boldsymbol 1\)。

    收敛速度由 \(-\lambda_2\) 决定：\(\lambda_2\) 越大，衰减越快。

    加上 \(b\boldsymbol 1\) 会怎样？ 平均值不再守恒：

    \[ \frac{d\bar x}{dt} = \frac1n \boldsymbol 1^{\mathsf T}(-L\boldsymbol x + b\boldsymbol 1) = 0 + \frac1n \cdot b \cdot n = b \qquad\Rightarrow\qquad \bar x(t) = \bar x_0 + bt \]

    怎么读：共同的输入 \(b\) 让整体均值以速度 \(b\) 匀速漂移， 而个体差异（\(\boldsymbol e\)）照样按 \(\lambda_2\) 衰减到 0 —— 也就是说，系统很快「一致」，但一致到这个正在漂移的均值上。

    一句话：一致性只能「统一」现有信息，不能「创造」新信息。 想改变共识值，必须从外部给输入（这正是「领航者」在多机器人系统里的角色）。

    例题 3：指派问题里，贪心为什么必然会错¶

    问：用 3.5 节那个 \(2\times 2\) 的例子，一步一步说明贪心是怎么被带偏的； 再解释为什么「随机实验里 82% 都更差」和「少数情况下一样好」并不矛盾。

    解答

    第一步：看代价矩阵。

    \[ C = \begin{bmatrix} 1 & 2 \\ 1 & 100 \end{bmatrix} \]

    第二步：贪心的执行过程。 把所有 \((i,j)\) 对按代价排序： \(c_{00}=1 \lt c_{10}=1 \le \dots\)（两个 1.0 按字典序，先取 \((0,0)\)）。

    1. 取 \(c_{00} = 1\)：把机器 0 和任务 0 同时锁死；
    2. 下一个候选 \(c_{10} = 1\) 被跳过 —— 因为任务 0 已经被占；
    3. 下一个 \(c_{01} = 2\) 被跳过 —— 因为机器 0 已经被占；
    4. 最后只剩 \(c_{11} = 100\)。

    总代价 \(1 + 100 = 101\)。

    第三步：全局最优。 换一种配法：机器 1 去任务 0（\(1\)）、机器 0 去任务 1（\(2\)）， 总代价 \(1 + 2 = \mathbf{3}\)。

    差在哪？ 贪心在第 1 步做了一个局部正确的选择（它确实选了全局最小的一对数）， 但这个选择同时消耗了两个资源（一台机器人 + 一个任务）， 于是把机器 1 和任务 1 「绑」在了一起 —— 而这一对恰好是最贵的那一对（100）。

    第四步：为什么 82% 更差、却不是 100%？ 随机实例里，很多时候「最近的搭配」正好也是最优搭配： 例如每台机器人都恰好有一个明显最近的、且互不冲突的任务， 这时贪心和匈牙利给出的就是同一个方案（比值 \(=1\)）。 但只要出现「争抢同一个任务」，贪心就会被带偏 —— 500 次实验里，这种情况占了 82%，平均多走 8.7%，最坏多走 54.7%。

    一句话：贪心的错不是「经常算错」，而是「没有保证」 —— 它能给你答案，但不告诉你这个答案离最优有多远。 多机器人系统里，这种「没有保证」往往是不能接受的。

    例题 4：链型队形的误差为什么会逐级放大¶

    问：4.4 节里，每台跟随者都只制造一点点扰动（\(\sigma = 0.030\)）， 为什么误差会从第 1 级的 0.0271 m 一路涨到第 5 级的 0.0901 m？ 请从「信息流」的角度解释，并给出至少两种抑制办法。

    解答

    为什么会放大：误差被「当成真值」往下传了。

    看跟随者的目标公式：\(p_i^{\text{target}} = p_{i-1} - l_d\,h\)。 它的输入是前一台的实际位置 \(p_{i-1}\)，而不是前一台的理想位置。 而 \(p_{i-1}\) 本身已经带着它自己的误差：

    \[ p_{i-1} = p_{i-1}^{\text{理想}} + \varepsilon_{i-1} \qquad\Rightarrow\qquad p_i^{\text{target}} = p_i^{\text{理想}} + \varepsilon_{i-1} \]

    也就是说，第 \(i\) 台把第 \(i-1\) 台的误差当成了自己的「理想」， 在这个基础上再加上自己的新扰动 \(\varepsilon_i'\)：

    \[ \varepsilon_i \approx \varepsilon_{i-1} + \varepsilon_i' \]

    这正是随机游走的递推式：方差逐级累加， 标准差大约按 \(\sqrt{i}\) 增长 —— 所以链越长，末端越飘。实跑里第 5 级是第 1 级的 3.3 倍，量级上完全吻合 （\(\sqrt{5} \approx 2.24\)，再叠加增益有限带来的残余误差）。

    抑制办法（至少两种）：

    1. 扩大信息视野 —— 让每台不只看到前一台， 还看到更靠前的若干台（甚至看到领航）。 这就把「链」变成了「带捷径的图」，误差不再单线累积。 教材里 II 类机器人（有一定通信能力）用的就是这个办法。
    2. 引入绝对参照 / 全局优化 —— 让每台偶尔获得一个不来自邻居的绝对位置 （地标、GNSS），或者让全队周期性地对队形做一次全局最小二乘修正。 这等于给随机游走加了一个「回拉」的弹簧，误差不会无界累积。
    3. （补充）提高增益 + 前馈：把增益 \(k\) 调大能压小单级误差， 加前馈能消掉系统性的跟踪滞后 —— 但它们治不了「累积」这个病根， 只能把整体基数压低。

    一句话：链式结构把「每台的误差」串成了一条随机游走； 要打断它，就得让信息不只沿一条线流。

    自测¶

    Q1 教材把多机器人系统按「协调是怎么来的」分成有意识型和无意识型两类。 请各举一个机器人系统的例子，并说明它们在「谁来做决定」上的根本区别。

    提示

    想想蚁群是靠什么保持队形的，再看看「一个主控发指令、其余照做」的系统。

    解答

    无意识型：靠自组织。 整体行为不是由全局控制产生的， 而是靠个体间局部的交互自发涌现出协调、有序的状态 —— 例如一群做「聚集 / 分散」的简单机器人： 每台只有「离邻居太近就退、太远就靠」这一条局部规则， 整体却没商量就出现了疏密均匀的分布。 蚂蚁、蜜蜂是自然界的同类例子。

    有意识型：靠显式的协调机制。 个体之间有共同的目标， 相互配合、协同工作，系统会对交互进行推理，必要时协商。 例如「一台主控机器人规划路径、其余按指令搬运」的搬运系统。

    根本区别在于「决定权在谁手里」： 无意识型里没有一个地方写着「整个群体该怎样」，秩序是从局部规则涌现的； 有意识型里存在显式的协调机制或协商过程，个体知道「我们要一起完成什么」。

    一句话：无意识型是「规则产生秩序」，有意识型是「目标驱动协商」。

    Q2 4 台机器人排成一条链（1—2—3—4），用一致性规则 \(\dot x_i = \sum_{j \in \mathcal N_i}(x_j - x_i)\) 协调。请写出这个图的邻接矩阵 \(A\)、度矩阵 \(D\) 和拉普拉斯矩阵 \(L\)， 并说明为什么 \(\lambda_1 = 0\) 对应的特征向量是 \(\boldsymbol 1\)。

    提示

    链上每个顶点只有左右两个邻居（端点只有一个）； \(L = D - A\) 的每一行加起来是多少？

    解答

    邻接矩阵（对称，1 表示相邻）：

    \[ A = \begin{bmatrix} 0 & 1 & 0 & 0\\ 1 & 0 & 1 & 0\\ 0 & 1 & 0 & 1\\ 0 & 0 & 1 & 0 \end{bmatrix} \]

    度矩阵（每台有几个邻居）：\(D = \operatorname{diag}(1, 2, 2, 1)\)。

    拉普拉斯矩阵 \(L = D - A\)：

    \[ L = \begin{bmatrix} 1 & -1 & 0 & 0\\ -1 & 2 & -1 & 0\\ 0 & -1 & 2 & -1\\ 0 & 0 & -1 & 1 \end{bmatrix} \]

    为什么 \(\lambda_1 = 0\)、特征向量是 \(\boldsymbol 1\)？ 直接乘一下：

    \[ L\boldsymbol 1 = \begin{bmatrix} 1\cdot1 + (-1)\cdot1 + 0 + 0\\ -1 + 2\cdot1 + (-1)\cdot1 + 0\\ 0 + (-1)\cdot1 + 2\cdot1 + (-1)\cdot1\\ 0 + 0 + (-1)\cdot1 + 1\cdot1 \end{bmatrix} = \begin{bmatrix} 0\\0\\0\\0 \end{bmatrix} \]

    怎么读：\(L\) 的第 \(i\) 行，是把 \(D\) 的第 \(i\) 个对角元（该台的邻居数） 减去 \(A\) 第 \(i\) 行的所有元素（也是邻居数）—— 两者天然相等，所以行和恒为 0， \(\boldsymbol 1\) 就是特征值 0 的特征向量。 这条性质对任何图都成立，正是「一致性保持平均值」的数学根源。

    （另外，\(L\) 半正定、对称，所以特征值都是非负实数； 只要图连通，除 0 以外的特征值都严格为正。）

    Q3 3 台机器人和 3 个任务，代价矩阵为

    任务 0 任务 1 任务 2
    机器 0 1 10 10
    机器 1 10 1 10
    机器 2 10 10 1

    问：贪心算法给出的分配是什么？它是不是最优？如果把机器 2 那一行的任务 2 代价由 1 改成 100， 贪心会变吗？最优解会变吗？

    提示

    先按代价从小到大排一遍，注意「先到先得」会锁死哪些资源。

    解答

    第一问：贪心给出什么？ 三对代价为 1 的格子是 \((0,0)\)、\((1,1)\)、\((2,2)\)，它们互不冲突。 贪心按字典序先取 \((0,0)\)（锁死机器 0、任务 0）， 再取 \((1,1)\)（锁死机器 1、任务 1）， 最后 \((2,2)\)（锁死机器 2、任务 2）。 总代价 \(1+1+1 = 3\)。

    它是不是最优？ 是。这个矩阵的「对角」恰好就是最优搭配， 任何换法都会把某台推到代价 10 的格子上，总代价只会变大。 所以这个实例里贪心和最优一样好 —— 这也说明贪心并非总是错的。

    第二问：把 \(c_{22}\) 改成 100，贪心会变吗？ 不会。 贪心的排序变成 \(c_{00}=1, c_{11}=1, \dots, c_{22}=100\)。 前两步不变（\((0,0)\)、\((1,1)\) 照样互不冲突）； 第三步只剩机器 2 与任务 2 可选，只能付 100。 贪心给出的仍是「对角」方案，总代价 \(1+1+100 = 102\)。

    最优解会变吗？ 会。 现在对角搭配不再是好方案了： 机器 2 无论去哪个任务都要付 10（因为 \(c_{20}=c_{21}=10\)）， 于是可以「错位」：机器 0 → 任务 1（10）、机器 1 → 任务 2（10）、机器 2 → 任务 0（10）， 总代价 \(10+10+10 = \mathbf{30}\)，比 102 小得多。

    一句话：贪心的行为在「局部结构」没变时就不会变， 但全局最优会因为一个元素的改动而整体重排 —— 这正是「局部规则」和「全局优化」的本质差别。

    Q4 在 5.5 节的围捕实验中，为什么「各自直冲」跑满 60 s 也没能合围？ 请用「最大方位间隙」这个量解释，并说明「认领围捕点」为什么能解决它。

    提示

    问自己：如果 5 台机器人都朝逃逸者直冲，它们的方位角会趋向什么？

    解答

    为什么直冲合不了围。 每台追捕者的目标是「逃逸者所在的那一个点」。 大家朝同一个点冲，几何上就必然越冲越挤： 方位角全部收敛到同一个值附近，于是相邻方位角之差里， 总有一个「缝隙」大到包住剩下所有方位 —— 实跑里这个最大方位间隙是 360.0°。

    360° 意味着什么？意味着5 台追捕者几乎在同一方位上， 剩下的 359° 全是空档。逃逸者只要往任意一个空档方向跑，就脱身了。 而且这个缺口不会自动消失：对每一台来说，直冲永远是它的局部最优， 没有任何机制会派一台去「补那个缺」。

    为什么「认领围捕点」能解决。 它把问题换掉了：追捕者的目标不再是「逃逸者那一个点」， 而是包围圈上属于自己的那一个方位。 这等价于把「谁站哪个方位」当成一次任务分配（第 3.3 节的指派问题）， \(N\) 个方位正好分给 \(N\) 台 —— 于是每个人朝不同的方向运动， 方位角自然铺开。

    实跑结果：最大方位间隙从 360.0° 压到 107.6°， 合围时间 16.28 s；5 台机器人整整齐齐贴在半径 1.20 m 的包围圈上。

    一句话：「都朝目标」是单体的直觉，「各就各位」才是多体的解法 —— 合围要的不是「最快靠近」，而是「不留缺口」。

    小结¶

    要记住的 为什么重要
    多机器人的优势：分布、并行、容错、灵活 但它们只有在协调做对时才拿得到
    多机器人 = 没有公共坐标系、没有统一时钟、信息分散 问题的性质从「单体优化」变成「分布式协调」
    无意识型（自组织） vs 有意识型（任务相关 / 情形相关） 决定「协调从哪来」
    协调结构：完全集中 / 分层 / 完全分布 完全集中最简单，但不适用于动态开放环境
    提速小于台数 \(N\)；全挂概率 \(\approx Q^{N}\) 并行买时间、冗余买保险，两者不可替代
    通信拓扑用图描述：\(A\)、\(D\)、\(L = D - A\) 关系信息不在状态向量里，必须单独建模
    \(L\boldsymbol 1 = \boldsymbol 0\) ⇒ 一致性保持平均值 共识值由初值决定，不能靠算法「造」出来
    \(\lambda_2\)（代数连通度） 决定收敛速度 实跑：链 1624 步 vs 完全图 149 步（10.9 倍）
    图不连通（\(\lambda_2 = 0\)）⇒ 永远不全体一致 「连通性」是多机器人协调的硬前提
    任务分解 + 任务分配密不可分 先拆子任务，再决定谁来干
    指派问题：\(\min \sum c_{ij}x_{ij}\)，一机一任务 匈牙利算法保证最优，贪心不保证
    贪心实跑：82% 实例更差，平均多走 8.7% 「每一步局部最优」≠「整体最优」
    队形两种描述：绝对位置 vs 相对距离/角度 相对描述不需要全局坐标系（但留规范自由度）
    链式跟随：误差逐级放大（0.0271 → 0.0901 m） 前一台的误差被当成真值抄了下去
    教材三类机器人：信息不完全 / 相对完全 / 完全 结论：局部感知 + 必要通信是现实选择
    围捕判定：人人贴圈 + 方位铺满（无缺口） 只看「距离」会漏掉「缺口」
    直冲实跑：最大方位间隙 360.0°，60 s 合不了围 「都朝目标」是单体直觉，「各就各位」是多体解法

    四条最容易出错的地方：

    1. 把「多机器人」当成「多装几个」 —— 台数翻倍，完成时间不会减半（实跑 \(n=8\) 只提速 6.16 倍）； 更糟的是，多出来的协调开销（协商、通信、避碰）还没算进去。 加机器人之前先问清楚：我要的是「快」，还是「稳」。
    2. 以为一致性算法能「协商出」一个共识值 —— 它只是保持初值的平均（\(L\boldsymbol 1 = \boldsymbol 0\)）。 想改变共识值，必须从外部给输入。同样，拓扑只决定快慢，不决定结果。
    3. 在分配问题上用贪心还心安理得 —— 贪心每步都对，整体却没保证： 500 次随机实验里 82% 严格更差，最坏多走 54.7%； 而「一机一任务」这类型问题本来就有保证最优的多项式算法（匈牙利）。
    4. 把「朝目标最快靠近」当成通用策略 —— 围捕里它让所有人挤在同一侧， 留下 360° 的缺口；队形里它让误差顺着链条一路抄下去。 多体系统的目标常常不是「靠近」，而是「铺开」或「一致」。
