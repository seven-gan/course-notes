    浮点数与误差¶

    数值计算的第一课不是「怎么算」，而是：

    计算机里的数不是实数 —— 它们只有有限个，且分布不均匀。

    不理解这一点，就会把「算出来一个数」误当成「算对了」。

    一句话抓住核心：三个必须记住的量

    量 双精度值 含义
    机器精度 \(\epsilon\) \(2.22\times10^{-16}\) 相邻可表示数的最大相对间隔
    单位舍入误差 \(u = \epsilon/2\) \(1.11\times10^{-16}\) 一次舍入的最大相对误差
    可表示数个数 \(2^{64}\)（含符号/指数） 有限，所以必有舍入 ✗

    最重要的推论：

    \[ 1+10^{-16} = 1 \quad\text{（在双精度下）} \]

    不是「近似等于」，而是「完全相等」 —— 因为 \(10^{-16}\) 小于相邻两个可表示数的间隔。

    这条性质带来两类后果：

    类型 例子
    灾难性抵消 两个相近的大数相减，有效数字全丢 ✗
    停滞 迭代增量小于精度时，迭代「卡住」

    本页的主线：从表示 → 到舍入 → 到抵消 → 到条件数。

    一、浮点数的表示¶

    IEEE 754 格式¶

    一个双精度浮点数由三部分组成：

    \[ x = (-1)^{s}\times(1.f)_{2}\times2^{e-1023} \]
    部分 位数 作用
    符号 \(s\) \(1\) 正负
    指数域 \(11\) 决定「数量级」（阶码）
    小数域 \(f\) \(52\) 决定「有效数字」

    关键点：精度由小数域的位数决定，与数量级无关 ✓

    \[ \text{相对精度}\approx2^{-53}\approx1.11\times10^{-16} \]

    「有效数字」的概念与它的实际含义

    双精度提供约 15–17 位十进制有效数字：

    \[ 52\log_{10}2+1\approx16.7\ \text{位} \]

    注意「有效数字」的含义：

    量 有效数字
    \(1.234567890123456\) \(16\) 位 ✓
    \(1.234567890123456\times10^{300}\) 仍是 \(16\) 位 ✓
    \(1.234567890123456\times10^{300}+1\) 加法丢失了 \(1\) ✗

    为什么大数加小数会丢失：

    \(10^{300}\) 附近的间隔是：

    \[ 2^{-52}\times2^{\text{阶码}}\approx1.1\times10^{-16}\times10^{300}=1.1\times10^{284} \]

    所以 \(+1\) 完全落在间隔之内，被舍入掉 ✗

    工程含义：

    操作 危险性
    累加器初始值很大，增量为小量 增量可能被「吃掉」✗
    大数间相减 灾难性抵消
    尺度差异大的求和 需要排序或Kahan 求和 ✓

    一个经典的工程教训：金融计算用整数（分）而非浮点数 —— 因为 \(0.1+0.2\neq0.3\) 会造成累积误差

    特殊的「数」¶

    值 表示 产生方式
    \(+\infty\) 指数全 1、小数域 0、符号 0 溢出、\(1/0\)
    \(-\infty\) 同上，符号 1 负溢出
    NaN 指数全 1、小数域非 0 \(0/0\)、\(\infty-\infty\)
    \(+0\) / \(-0\) 全 0 下溢、\(1/(-\infty)\)
    次正规数 指数全 0、小数域非 0 极小值（精度降低）

    工程要点：

    现象 诊断
    结果为 NaN 出现了 \(0/0\) 或 \(\infty-\infty\) ✗
    结果为 inf 溢出或除零
    结果突然变成 \(0\) 可能下溢（次正规数仍可用，但精度差）

    一个重要的实践规则：

    \[ \text{NaN}\neq\text{NaN} \quad\text{（在 IEEE 754 中）} \]

    所以不能用 x == NaN 判断，必须用 isnan(x) ✓

    二、舍入：为什么「精确」是不可能的¶

    舍入规则¶

    IEEE 754 默认用「舍入到最近，遇中取偶」（round to nearest, ties to even）。

    情形 规则
    不在正中 取最近的
    恰在正中（平局） 取「偶数尾数」的那个 ✓

    「遇中取偶」为什么比「四舍五入」好

    「四舍五入」（逢五进一）的偏差：

    情形 偏差方向
    \(1.5\to2\) \(+0.5\)
    \(2.5\to3\) \(+0.5\)
    多次求和 系统性偏高 ✗

    「遇中取偶」的偏差：

    情形 结果
    \(1.5\to2\) \(+0.5\)
    \(2.5\to2\) \(-0.5\)
    多次求和 偏差相互抵消 ✓

    这就是「无偏舍入」的含义 —— 它在统计上更公平

    工程含义：大量数据的求和，误差不会系统性累积

    一个实用推论：若做大量求和，误差的增长是「随机游走」而非「线性」：

    误差模型 增长方式
    有偏舍入 \(\propto n\)（线性）✗
    遇中取偶 \(\propto\sqrt n\)（随机游走）✓

    所以 \(n\) 项的求和误差约 \(\sqrt n\,\epsilon\) 而非 \(n\epsilon\) （这是「为什么求和误差没那么可怕」的定量解释。）

    0.1 不是 0.1¶

    这是最著名的例子：

    \[ 0.1\ \text{（十进制）} = 0.0001100110011\ldots\ \text{（二进制，循环）} \]

    二进制无法有限表示 \(0.1\)（因为 \(0.1 = 1/10\)，分母含因子 5）

    所以：

    \[ 0.1+0.2-0.3 = 5.551115123125783\times10^{-17}\neq0 \]

    原因：三个数各有舍入误差，相减后残差暴露出来

    「哪些十进制小数能被精确表示」的判据

    规则：分母的质因数只有 2 的分数才能用有限二进制表示。

    数 分母质因数 二进制精确？
    \(0.5 = 1/2\) \(\{2\}\) ✓
    \(0.25 = 1/4\) \(\{2\}\) ✓
    \(0.125 = 1/8\) \(\{2\}\) ✓
    \(0.1 = 1/10\) \(\{2,5\}\) ✗
    \(0.2 = 1/5\) \(\{5\}\) ✗
    \(1/3\) \(\{3\}\) ✗

    工程含义（非常实用）：

    场景 建议
    需要精确的十进制运算 用整数或 decimal 类型 ✓
    累加大量小数 注意误差累积
    浮点数相等比较 用容差而非 == ✓

    正确的比较方式：

    \[ \lvert a-b\rvert<\varepsilon_{\text{tol}} \quad\text{（而非 }a = b\text{）} \]

    容差怎么选：

    情形 容差
    一般 \(10^{-12}\) 或 \(10^{-9}\)
    涉及大数运算 相对容差 \(\lvert a-b\rvert\leq\varepsilon\lvert a\rvert\) ✓
    需要严格相等 改用整数/有理数表示

    注意「相对容差」的重要性：

    若 \(a\approx10^{10}\)，则绝对误差 \(10^{-6}\) 意味着相对精度 \(10^{-16}\) —— 这已经是机器精度极限 ✓ 所以绝对容差在这里是过严的 ✗

    三、灾难性抵消¶

    什么是灾难性抵消¶

    定义：两个相近的数相减，结果的相对误差被极度放大。

    为什么：

    设 \(a\approx b\)，令 \(c = a-b\)（很小）。

    输入有相对误差 \(\epsilon\) → 绝对误差约 \(\epsilon\lvert a\rvert\)：

    \[ (a+\delta_a)-(b+\delta_b) = c+(\delta_a-\delta_b) \]

    结果的相对误差：

    \[ \frac{\lvert\delta_a-\delta_b\rvert}{\lvert c\rvert}\approx\frac{2\epsilon\lvert a\rvert}{\lvert a-b\rvert} \]

    放大因子：

    \[ \boxed{\ \frac{\text{结果相对误差}}{\epsilon}\approx\frac{2\lvert a\rvert}{\lvert a-b\rvert}\ } \]

    放大因子的含义：相近程度决定损失程度

    \(\lvert a-b\rvert/\lvert a\rvert\) 放大因子 损失的有效数字
    \(10^{-1}\) \(20\) 约 \(1\) 位
    \(10^{-5}\) \(2\times10^{5}\) 约 \(5\) 位 ✗
    \(10^{-10}\) \(2\times10^{10}\) 约 \(10\) 位 ✗✗
    \(10^{-16}\) \(\to\infty\) 全部丢失 ✗✗✗

    规律：抵消掉 \(k\) 位有效数字，就损失 \(k\) 位精度

    双精度只有 16 位 → 抵消掉 16 位就什么都不剩 ✗

    这是一个「相对的」概念：

    情形 是否危险
    \(a=10^{10}\)、\(b=10^{10}-1\) 危险（抵消 10 位）✗
    \(a=1.5\)、\(b=1.2\) 安全（只抵消 1 位）✓
    \(a=1\)、\(b=-1\)（异号相加） 安全（不相近）✓

    注意「相减」是形式上的 —— 「正数加负数」同样是抵消

    经典例子：\(1-\cos x\)¶

    数学上：当 \(x\to0\) 时，

    \[ \frac{1-\cos x}{x^{2}}\to\frac12 \]

    数值上：当 \(x\) 很小时，\(\cos x\approx1\)，所以 \(1-\cos x\) 是两个相近数相减 ✗

    具体数据（用双精度计算）：

    \(x\) \(\cos x\)（双精度） \(1-\cos x\) \(\dfrac{1-\cos x}{x^{2}}\) 真值
    \(10^{-4}\) \(0.999999995\) \(5.0000\times10^{-9}\) \(0.5\) \(0.5\)
    \(10^{-6}\) \(0.9999999999995\) \(5.0\times10^{-13}\) \(0.5\) \(0.5\)
    \(10^{-8}\) \(1.0\) \(0\) \(0\) ✗ \(0.5\)

    在 \(x = 10^{-8}\) 处，结果完全错误（给 0，真值是 0.5） ✗

    「如何避免抵消」的三种手段（这是本页最实用的部分）

    手段 1：代数恒等变形（首选）

    用半角公式把 \(1-\cos x\) 改写：

    \[ 1-\cos x = 2\sin^{2}\frac{x}{2} \]

    验证：由 \(\cos x = 1-2\sin^{2}(x/2)\) 立即得到

    改写后的效果：

    \(x\) 原式 改写后
    \(10^{-8}\) \(0\) ✗ \(2\times(5\times10^{-9})^{2} = 5\times10^{-17}\) ✓

    正确的商：

    \[ \frac{2\sin^{2}(x/2)}{x^{2}} = \frac{2\times(5\times10^{-9})^{2}}{10^{-16}} = \frac{5\times10^{-17}}{10^{-16}} = 0.5 \;\checkmark \]

    原因：改写后不再有「相近数相减」

    手段 2：用级数展开（当变形困难时）

    \[ 1-\cos x = \frac{x^{2}}{2}-\frac{x^{4}}{24}+\frac{x^{6}}{720}-\cdots \]

    对小 \(x\) 直接用前两项

    手段 3：提高精度（最后手段）

    用扩展精度（如 long double、Decimal）或Kahan 求和。

    代价：慢、不通用 ✗

    三种手段的对比：

    手段 效果 代价 适用
    代数变形 最好 ✓ 需要推导 有恒等式可用时
    级数展开 好 需要判断截断点 有小参数时
    提高精度 好 慢 ✗ 前两者不可行时

    工程建议：先想办法变形，而不是先提高精度

    因为变形是「零成本」的（计算量甚至更少）， 而提高精度要付出成倍的代价。

    同类问题的处理表（值得记住）：

    表达式 危险 安全的写法
    \(1-\cos x\) \(x\) 小时 \(2\sin^{2}(x/2)\)
    \(\sqrt{x+1}-1\) \(x\) 小时 \(\dfrac{x}{\sqrt{x+1}+1}\)
    \(e^{x}-1\) \(x\) 小时 expm1(x) ✓
    \(\ln(1+x)\) \(x\) 小时 log1p(x) ✓
    二次方程求根 判别式相近 用 \(x_1x_2 = c/a\) ✓

    注意最后一行的「二次方程」 —— 它是工程中最常见的抵消来源之一：

    \[ x = \frac{-b\pm\sqrt{b^{2}-4ac}}{2a} \]

    当 \(b^{2}\gg4ac\) 时：

    \[ \sqrt{b^{2}-4ac}\approx\lvert b\rvert \]

    所以其中一个根会抵消 ✗

    安全的做法：先算不抵消的那个根，再用韦达定理

    \[ x_{1}x_{2} = \frac{c}{a} \]

    求另一个

    这就是「为什么数值库的二次方程求解器会做这个处理」 —— 它是必须的，不是「优化」。

    四、条件数与数值稳定性¶

    问题的条件数¶

    定义：输入的相对扰动被放大多少倍。

    \[ \kappa = \frac{\text{输出相对变化}}{\text{输入相对变化}} \]

    关键区分（这一对概念最容易混）：

    概念 归属 能否通过换算法改善
    条件数 问题本身 ✗ 不能（问题的固有性质）
    稳定性 算法 ✓ 能（换算法即可）

    「条件数 vs 稳定性」的经典类比

    概念 类比
    条件数差 「用放大镜看模糊的照片」—— 照片本身模糊 ✗
    算法不稳定 「照相机抖了」—— 拍的时候出了问题 ✗

    两者的组合决定最终精度：

    \[ \text{最终误差}\approx\text{条件数}\times\text{算法的稳定性}\times\epsilon_{\text{mach}} \]

    四条重要推论：

    推论 1：条件数差的「好算法」也救不了精度

    若 \(\kappa = 10^{12}\)，即使算法绝对稳定， 相对误差也至少 \(10^{12}\times10^{-16} = 10^{-4}\) ✗

    含义：这时应该「改问题」（如重新标定、正则化），而不是「换算法」

    推论 2：条件数好的「坏算法」可能也够用

    这就是「为什么朴素高斯消元在温和问题上没问题」

    推论 3：条件数可以「事后估计」

    大多数求解器会返回条件数的估计 —— 应该检查它

    推论 4：条件数定义了「解的可信位数」

    \[ \text{可信位数}\approx16-\log_{10}\kappa \]

    具体数值：

    \(\kappa\) 可信位数
    \(10^{0}\) \(16\) 位 ✓
    \(10^{6}\) \(10\) 位 ✓
    \(10^{12}\) \(4\) 位 ⚠
    \(10^{16}\) \(0\) 位（全不可信） ✗

    工程含义（一个实用的自检）：

    若求解器报「矩阵接近奇异」，或解出来明显不合理， 先看条件数 —— 它决定了「还能信多少位」

    向量/矩阵的情形¶

    矩阵的条件数：

    \[ \kappa(A) = \lVert A\rVert\lVert A^{-1}\rVert \]

    含义：解 \(A\boldsymbol{x} = \boldsymbol{b}\) 时，\(\boldsymbol{b}\) 的相对扰动被放大多少倍。

    重要性质：

    性质 说明
    \(\kappa(A)\geq1\) 恒成立
    \(\kappa(A^{T}A) = \kappa(A)^{2}\) 「正规方程使条件数平方」 ✗

    「(ATA) = (A)2」为什么是一个重要警告

    实际问题：最小二乘的正规方程 \(A^{T}A\boldsymbol{x} = A^{T}\boldsymbol{b}\)

    若 \(\kappa(A) = 10^{8}\)（已经不罕见）

    \[ \kappa(A^{T}A) = 10^{16} \]

    这已到双精度极限 → 正规方程算出完全错误的结果 ✗

    举例：希尔伯特矩阵 \(H_n\)（\(h_{ij} = 1/(i+j-1)\)）

    \(n\) \(\kappa(H_n)\) \(\kappa(H_n^{T}H_n)\)
    \(4\) \(1.5\times10^{4}\) \(2.3\times10^{8}\)
    \(8\) \(1.5\times10^{10}\) \(2.3\times10^{20}\) ✗
    \(12\) \(1.8\times10^{16}\) 溢出 ✗

    所以用正规方程解 LS 问题时， \(n\) 稍大就会完全失败 ✗

    正确做法：用 QR 或 SVD —— 它们不形成 \(A^{T}A\)

    方法 条件数
    正规方程 \(\kappa(A)^{2}\) ✗
    QR \(\kappa(A)\) ✓
    SVD \(\kappa(A)\) ✓

    这就是「数值计算」模块的下一节为什么讲 QR 与 SVD」 —— 它们不是「更高级的选项」，而是「正确性的必要保证」

    工程实践建议：

    情形 做法
    \(n\) 很小、条件数良好 正规方程可以 ✓
    不确定 默认用 QR 或 lstsq ✓
    需要处理秩亏 SVD（加截断）✓

    「默认用 QR」的成本很低（计算量约为正规方程的 2 倍）， 而收益是避免灾难性错误

    五、典型例题¶

    例题 1：手算 \(\sqrt{2}\) 的浮点表示与相对误差¶

    求 \(\sqrt{2}\) 的双精度表示（符号、阶码、尾数），并计算相对误差。

    思路

    先求 \(m = \operatorname{round}(\sqrt2\times2^{52})\)，再拆成阶码与尾数。

    解答

    第一步：定阶

    \[ 1<\sqrt2<2 \implies \sqrt2 = 1.f\times2^{0} \]

    所以阶码域：

    \[ e = 0+1023 = 1023 = \text{0x3FF} \]

    第二步：求尾数

    需要算出 \(\sqrt2\) 的小数部分的前 52 位：

    \[ \sqrt2 = 1.0110101000001001111001100110011111110011101111001101\ldots \]

    前 52 位：

    \[ f = 0110101000001001111001100110011111110011101111001101 \]

    第三步：组装

    域 值
    符号 \(0\)（正）
    阶码 \(1023\)（\(=\text{0x3FF}\)）
    尾数 上式 52 位

    按十六进制读：0x3FF6A09E667F3BCD

    第四步：相对误差

    双精度的 \(\sqrt2\) 实际值：

    \[ \sqrt2_{\text{float}} = 1.4142135623730951\ldots \]

    真值：

    \[ \sqrt2 = 1.41421356237309504880168872420969807856967\ldots \]

    绝对误差：

    \[ \lvert\Delta\rvert\approx9.7\times10^{-17} \]

    相对误差：

    \[ \frac{\lvert\Delta\rvert}{\sqrt2}\approx6.84\times10^{-17}\approx\frac{u}{1.6} \]

    其中 \(u = \epsilon/2\approx1.11\times10^{-16}\) 是单位舍入误差。

    结果：相对误差约 \(6.8\times10^{-17}\) —— 约等于单位舍入误差 \(u\)

    「误差是机器精度的几分之一」说明什么

    双精度的相对误差理论上界是 \(u = \epsilon/2\approx1.11\times10^{-16}\)

    实际误差 \(6.84\times10^{-17}\) 比上界 \(u\) 还小一点 —— 因为：

    原因 说明
    舍入是「取最近」 误差不超过半个间隔（即 \(u\)）
    \(\sqrt2\) 的尾数恰好落在可表示点较近处 运气好 ✓
    遇上「正中平局」才可能达到上界 概率极低

    含义：\(\epsilon\) 是「最坏情况」而非「典型情况」

    工程含义：

    用途 应取的界
    严格误差分析（保证正确性） 用最坏情况 \(\epsilon\) ✓
    估计典型精度 用 \(\epsilon/2\) 或更小
    大量运算的累积误差 \(\propto\sqrt n\,\epsilon\)（随机游走）

    这就是「为什么实际算出来的精度常比理论界好」 但做安全设计时必须用最坏界。✓

    例题 2：灾难性抵消的实际规模¶

    用双精度计算 \(\sqrt{x+1}-1\)，\(x = 10^{-8}\)。与原式、安全写法比较。

    思路

    比较两种算法；再与真值 \(x/(\sqrt{x+1}+1)\) 对照。

    解答

    第一步：真值

    \[ \sqrt{1+10^{-8}}-1 \]

    用泰勒展开：\(\sqrt{1+t} = 1+\frac t2-\frac{t^{2}}{8}+\cdots\)，\(t = 10^{-8}\)：

    \[ \approx\frac{10^{-8}}{2}-\frac{10^{-16}}{8} = 5\times10^{-9}-1.25\times10^{-17} \]

    真值 \(\approx4.9999999875\times10^{-9}\)

    第二步：直接计算（双精度）

    \[ \sqrt{1+10^{-8}} = 1.000000005 \]

    双精度能表示 \(1+10^{-8}\) 吗：

    间隔 \(\epsilon\approx2.22\times10^{-16}\)，而 \(10^{-8}\gg\epsilon\) 所以 \(1+10^{-8}\) 可表示，但只有约 8 位有效数字。

    \[ \sqrt{1+10^{-8}}\approx1.0000000049999999 \]

    相减：

    \[ 1.0000000049999999-1 = 4.9999999\times10^{-9} \]

    相对误差：

    \[ \frac{\lvert4.9999999\times10^{-9}-4.9999999875\times10^{-9}\rvert}{4.9999999875\times10^{-9}}\approx2\times10^{-8} \]

    损失了约 8 位有效数字 ✗

    第三步：安全写法

    \[ \sqrt{x+1}-1 = \frac{x}{\sqrt{x+1}+1} \]
    \[ = \frac{10^{-8}}{1.000000005+1} = \frac{10^{-8}}{2.000000005}\approx4.9999999875\times10^{-9} \;\checkmark \]

    相对误差 \(\approx\epsilon\) 量级（只损失 1 位）

    第四步：对比总结

    方法 结果 相对误差
    直接相减 \(4.9999999\times10^{-9}\) \(\approx2\times10^{-8}\) ✗
    有理化 \(4.9999999875\times10^{-9}\) \(\approx10^{-16}\) ✓

    精度差了 \(10^{8}\) 倍

    「抵消了多少位」如何估算

    公式（本例题的情形）：

    \[ \text{损失位数}\approx\log_{10}\frac{\lvert\sqrt{1+x}\rvert}{\lvert\sqrt{1+x}-1\rvert} \]

    代入 \(x = 10^{-8}\)：

    \[ \log_{10}\frac{1}{5\times10^{-9}}\approx\log_{10}(2\times10^{8})\approx8.3 \]

    损失约 8 位 ✓ 与实测相符。

    一般规律：损失位数 ≈ 结果比输入小多少个数量级

    情形 结果/输入 损失位数
    \(\sqrt{1+x}-1\)，\(x=10^{-4}\) \(5\times10^{-5}\) \(4\) 位
    同上，\(x=10^{-8}\) \(5\times10^{-9}\) \(8\) 位 ✗
    同上，\(x=10^{-16}\) \(5\times10^{-17}\) \(16\) 位（全丢） ✗✗

    实用判据：

    若「结果的量级 ÷ 输入的量级」小于 \(10^{-15}\)，这个算法不可用 ✗ —— 必须改写。

    工程意义（这个判据很实用）：

    场景 是否需改写
    传感器标定的偏差量（\(\ll\) 量程） 需要 ⚠
    差分信号处理 需要 ⚠
    常见的「相对变化」计算 需要 ⚠

    补救手段：先减去「标称值」，再用小量运算 （这就是「去均值」在数值上的价值。）

    例题 3：验证「遇中取偶」的无偏性¶

    用 10000 个随机数验证「遇中取偶」的舍入误差均值趋近于零。

    思路

    生成均匀随机数，舍入到有限位，统计误差的均值与标准差。

    解答

    方法：把 \([0,1)\) 上的随机数舍入到 \(k\) 位十进制小数， 统计「舍入误差」\(e_i = \tilde x_i-x_i\)。

    对「逢五进一」（四舍五入）：

    \[ E[e]\approx+\frac{1}{2}\times10^{-k}\times P(\text{恰在五})>0 \]

    理论上：若小数部分均匀，则误差在 \([-0.5,0.5]\times10^{-k}\) 上均匀分布 → 均值应为 0

    但「逢五进一」破坏了这一点：

    小数第三位 \(x_3\) 四舍五入的动作 误差
    \(<5\) 舍 负 ✓
    \(=5\)（恰中） 进 正 ✗
    \(>5\) 进 正 ✓

    「恰在五」时总是取正误差 → 引入正偏差 ✗

    「遇中取偶」的修正：

    情形 动作
    小数第三位 \(=5\) 且后面全零（真平局） 取使末位为偶的那个 ✓
    其余 同四舍五入

    这样「真平局」时正负误差各半 → 偏差抵消

    定量结论：

    舍入方式 误差均值（理论）
    逢五进一 \(\approx\frac{1}{2}\times10^{-k}\times P(\text{平局})>0\) ✗
    遇中取偶 \(0\) ✓
    截断（向零取整） \(-0.5\times10^{-k}\) ✗

    注意「截断」的偏差最大 —— 它恒为负 ✗

    工程含义：

    应用 影响
    大量数据的求和 截断的偏差累积成 \(\propto n\) ✗
    随机数生成 需无偏
    累加器 用遇中取偶或 Kahan ✓
    定点 DSP 常用「舍入」而非「截断」✓

    实际效果的量级：

    若 \(n = 10^{6}\) 个数，每个误差 \(\sim10^{-k}\)：

    舍入方式 总误差
    遇中取偶（无偏） \(\sim\sqrt{10^{6}}\times10^{-k} = 10^{3}\times10^{-k}\) ✓
    截断（有偏） \(\sim10^{6}\times10^{-k}\) ✗

    相差 1000 倍 ✓ —— 这就是「无偏舍入很重要」的定量说明。

    例题 4：Kahan 求和的实际收益¶

    把 \(n = 10^{6}\) 个数（数值为 \(0.1\) 与少量大数混合）求和， 比较朴素求和与 Kahan 求和。

    思路

    朴素求和的误差 \(\propto\sqrt n\,\epsilon\)；Kahan 求和几乎无累积误差。

    解答

    问题设定：\(10^{6}\) 个 \(0.1\)。

    真值：

    \[ 10^{6}\times0.1 = 10^{5} \]

    朴素求和：

    \[ S = 0.1+0.1+\cdots+0.1\quad\quad\text{（}10^{6}\text{ 次）} \]

    每一步都引入舍入误差：

    累加到 累加值的量级 单步误差
    早期 \(10^{0}\) \(\sim10^{-17}\)
    中期 \(10^{3}\) \(\sim10^{-13}\)
    后期 \(10^{5}\) \(\sim10^{-11}\)

    后期每步误差极大（因为累加值大）✗

    总误差（随机游走模型）：

    \[ \sim\sqrt{10^{6}}\times10^{-11}\approx10^{-8} \]

    相对误差：

    \[ \frac{10^{-8}}{10^{5}} = 10^{-13} \]

    结果：朴素求和的相对误差约 \(10^{-13}\)（损失约 3 位）—— 尚可接受

    但若 \(n\) 更大（如 \(10^{9}\)）：

    \(n\) 相对误差
    \(10^{6}\) \(10^{-13}\) ✓
    \(10^{8}\) \(10^{-12}\)
    \(10^{10}\) \(10^{-11}\) ⚠
    更差的情形（大数在前） 可能损失大半精度 ✗

    Kahan 求和的做法：

    关键思想：每步把「舍入丢失的部分」记下来，下一步补回去 ✓

    算法（伪代码）：

    步骤 操作
    1 \(y = x_i-c\)（先减掉上一步的补偿）
    2 \(t = S+y\)（真正的累加）
    3 \(c = (t-S)-y\)（算出这一步丢了多少）
    4 \(S = t\)

    第 3 步的作用：\((t-S)\) 与 \(y\) 的差就是「加法丢失的部分」

    效果：

    方法 误差增长
    朴素求和 \(\propto\sqrt n\,\epsilon\)
    Kahan 求和 \(\propto\epsilon\)（几乎与 \(n\) 无关） ✓

    代价：每步多 3 次浮点运算（约慢 2–4 倍）。

    「什么时候值得用 Kahan 求和」

    值得用的场景：

    场景 理由
    \(n\) 极大（\(>10^{7}\)） 朴素误差明显 ✗
    数值量级差异大 小量易被吃掉 ✗
    累加是关键路径 精度要求高
    混合了正负数 抵消风险大 ⚠

    不值得用的场景：

    场景 理由
    \(n\) 小（\(<10^{4}\)） 朴素已够 ✓
    数值同量级、同号 误差小 ✓
    性能瓶颈 慢 2–4 倍 ✗
    输入本身有噪声（如测量值） 数据精度才是瓶颈 ✓

    最重要的一条是最后一行：

    若输入数据只有 3 位有效数字，把它求和到 16 位毫无意义 ✗

    工程判断原则：

    \[ \text{数值精度只需匹配「输入数据的精度」} \]

    这避免了「过度工程」

    另外两种实用的替代方案：

    方案 做法 效果
    排序后求和 从小到大累加 改善明显 ✓
    分块求和（pairwise） 两两配对再合并 误差 \(\propto\log n\) ✓
    Kahan 带补偿累加 几乎无误差 ✓

    「排序后求和」几乎零成本（若数据本来就要排序）， 而且效果出奇地好 —— 这是最实用的建议

    无人系统自主决策与优化 · 数值鲁棒性¶

    • 卡尔曼滤波的协方差更新容易出现矩阵失去正定性的问题（数值病态）→ 实践中需用 Joseph 形式或平方根滤波

    • 学习率与损失尺度的配合本质上是对数值范围的把控
    • 梯度裁剪部分是为了防止溢出的实用手段

    • 定点 DSP 的舍入方式直接影响滤波器的累积误差（例题 3）
    • IIR 滤波器的直接型实现在窄带时系数敏感 → 需用级联/并联结构
    • FFT 的误差增长为 \(O(\sqrt{\log N}\,\epsilon)\)
    • 自适应滤波器的累加器常用 Kahan 或延长字长

    • 手眼标定的方程 \(AX = XB\) 常常病态 → 需条件数检查

    • 四元数归一化是防止数值漂移的标准操作

    七、自测¶

    Q1 判断：\(0.1+0.2 = 0.3\) 在双精度下成立。

    提示

    \(0.1\) 与 \(0.2\) 都不能被二进制有限表示。

    解答

    不成立。

    实际结果：

    \[ 0.1+0.2 = 0.30000000000000004 \]

    与 \(0.3\) 的差：

    \[ 5.551115123125783\times10^{-17} \]

    为什么：

    \(0.1\) 与 \(0.2\) 在二进制中都是无限循环小数 ✗ 所以它们各自有舍入误差，相加后误差未被抵消

    具体数值（双精度）：

    数 双精度值 相对误差
    \(0.1\) \(0.1000000000000000055511\ldots\) \(+5.55\times10^{-17}\)
    \(0.2\) \(0.2000000000000000111022\ldots\) \(+5.55\times10^{-17}\)
    \(0.1+0.2\) \(0.3000000000000000444089\ldots\) ——
    \(0.3\) \(0.2999999999999999888978\ldots\) \(-3.70\times10^{-18}\)

    注意「两个误差方向相同」：\(0.1\) 与 \(0.2\) 都偏大 → 和也偏大 ✗

    这个「微小的荒谬」引出三条实践规则：

    规则 说明
    不要用 == 比较浮点数 用容差 ✓
    需要精确十进制用整数/Decimal 如金融计算 ✓
    累加大量小数要留意 误差会累积

    正确的比较：

    \[ \lvert a-b\rvert<\varepsilon_{\text{tol}}\quad\text{（容差取 }10^{-12}\text{ 或相对容差）} \]

    注意「相对容差」的重要性：对 \(a\approx10^{10}\) 的数， 绝对误差 \(10^{-6}\) 已经是机器精度极限， 此时绝对容差 \(10^{-12}\) 永远无法满足 ✗

    Q2 判断：条件数大的问题，换一个更稳定的算法就能解决。

    提示

    条件数属于「问题」还是「算法」？

    解答

    不对。条件数属于问题本身，换算法无法改善。

    两个概念的归属：

    概念 属于 换算法能改善？
    条件数 \(\kappa\) 问题 ✗ 不能
    稳定性 算法 ✓ 能

    误差的分解：

    \[ \text{最终相对误差}\lesssim\kappa\times(\text{算法稳定性因子})\times\epsilon_{\text{mach}} \]

    所以若 \(\kappa = 10^{12}\)：

    \[ \text{误差}\geq10^{12}\times1\times10^{-16} = 10^{-4} \]

    即使用绝对稳定的算法，也只能保证 4 位有效数字 ✗

    「可信位数」的公式：

    \[ \text{可信位数}\approx16-\log_{10}\kappa \]
    \(\kappa\) 可信位数 判断
    \(10^{0}\) \(16\) 完美 ✓
    \(10^{4}\) \(12\) 很好 ✓
    \(10^{8}\) \(8\) 可用 ✓
    \(10^{12}\) \(4\) 勉强 ⚠
    \(10^{16}\) \(0\) 完全不可信 ✗

    条件数差的正确应对：

    手段 说明
    改问题 重新标定、改变量、加正则 ✓
    加正则（岭回归） 降低有效条件数 ✓
    提高精度（如四倍精度） 昂贵，但有效 ⚠
    接受低精度 若工程上够用 ✓

    关键区分（一个实用的判断流程）：

    观察 结论
    换稳定算法后精度改善 问题是算法不稳定 ✓
    换算法后精度不变 问题是条件数差 ✗
    精度已到 \(\kappa\epsilon\) 量级 继续优化算法是徒劳的 ✗

    工程含义：先算条件数，再决定投入方向

    Q3 某累加器要加 \(10^{6}\) 个约为 \(10^{-3}\) 的数， 但累加值已经达到 \(10^{6}\)。会有什么问题？

    提示

    比较「\(10^{-3}\)」与「\(10^{6}\) 附近的浮点间隔」。

    解答

    加法的增量会被完全舍掉 —— 累加器「停止增长」。

    量化分析：

    \(10^{6}\) 附近的浮点间隔：

    \[ \epsilon\times10^{6}\approx2.22\times10^{-16}\times10^{6} = 2.22\times10^{-10} \]

    而被加数是 \(10^{-3}\)。

    比较：

    \[ 10^{-3}\gg2.22\times10^{-10} \]

    所以增量大于间隔 —— 这部分没问题

    但要注意「后续更细的增量」：

    增量大小 是否被吃掉
    \(10^{-3}\) 不会（\(\gg10^{-10}\)）✓
    \(10^{-9}\) 会被部分舍掉 ⚠
    \(10^{-11}\) 完全被吃掉 ✗

    所以真正的危险是「增量远小于当前累加值的间隔」的情形：

    \[ \frac{\text{增量}}{\text{累加值}}<\epsilon\approx2.22\times10^{-16} \]

    这正是「停滞」的判据

    「停滞」的实际表现：

    在迭代算法中（如梯度下降、Newton 法）：

    现象 原因
    损失不再下降 更新量 \(<\epsilon\times\)参数值 ✗
    迭代「卡住」 数值停滞
    与理论收敛不符 可能是数值极限，不是算法问题 ✓

    工程诊断与对策：

    诊断 对策
    更新量 \(\approx\epsilon\times\)参数 已达数值极限，可以停止 ✓
    损失有噪声地波动 正常（随机梯度）
    突然出现 NaN 溢出或除零，需查

    对策（若确实需要继续改善）：

    方法 说明
    中心化（减去均值） 减小累加值 → 提高相对精度 ✓
    分块累加 每块内部累加，再合并 ✓
    Kahan 求和 补偿丢失部分 ✓
    提高精度 最后手段 ⚠

    「中心化」是最实用的建议：

    若数据在 \(10^{6}\) 附近波动，改为「减去 \(10^{6}\) 后累加」

    这在「去均值」的统计计算中就是标准做法 —— 它同时改善了数值稳定性

    Q4 为什么「\(\kappa(A^{T}A) = \kappa(A)^{2}\)」对最小二乘很重要？

    提示

    正规方程用的是 \(A^{T}A\)。

    解答

    因为最小二乘的正规方程会「平方」条件数，使本来可用的问题变得不可用。

    正规方程：

    \[ A^{T}A\boldsymbol{x} = A^{T}\boldsymbol{b} \]

    条件数：

    \[ \kappa(A^{T}A) = \kappa(A)^{2} \]

    具体后果（以希尔伯特矩阵为例）：

    \(n\) \(\kappa(H_n)\) \(\kappa(H_n^{T}H_n) = \kappa^{2}\) 结果
    \(4\) \(1.5\times10^{4}\) \(2.3\times10^{8}\) 可用 ✓
    \(8\) \(1.5\times10^{10}\) \(2.3\times10^{20}\) 溢出 ✗
    \(12\) \(1.8\times10^{16}\) —— 完全失败 ✗

    关键观察：\(n = 8\) 时 \(\kappa\) 已是 \(10^{10}\)（勉强可用）， 但平方后 \(10^{20}\) 远超双精度极限（\(10^{16}\)） ✗

    所以「正规方程在 \(n\) 稍大时就不可用」

    正确做法：

    方法 条件数 代价
    正规方程 \(\kappa^{2}\) ✗ 最低
    QR \(\kappa\) ✓ 约 \(2\) 倍
    SVD \(\kappa\) ✓ 约 \(5\)–\(10\) 倍

    为什么 QR/SVD 不平方条件数：

    因为它们不形成 \(A^{T}A\)

    QR：把 \(A = QR\) 分解（\(Q\) 正交、\(R\) 上三角）， 然后解 \(R\boldsymbol{x} = Q^{T}\boldsymbol{b}\)。

    正交变换不改变条件数（\(\lVert Q\rVert = 1\)）

    \[ \kappa(A) = \kappa(QR) = \kappa(R) \]

    所以 QR 保持了原问题的条件数

    工程建议（可直接照做）：

    情形 做法
    不确定 用 np.linalg.lstsq（内部是 SVD）✓
    已知条件数良好、\(n\) 小 正规方程可以
    \(n>10\) 且矩阵可能病态 必须用 QR 或 SVD ✓
    需要秩亏处理 SVD（截断小奇异值）✓

    成本对比（\(n\) 个参数、\(m\) 个样本）：

    方法 复杂度
    正规方程 \(O(mn^{2}+n^{3})\)
    QR \(O(mn^{2})\)
    SVD \(O(mn^{2})\)（常数更大）

    QR 的代价只是「常系数约 2 倍」 —— 相对于「避免完全错误的答案」，这个代价极小

    一句话：不要用正规方程解最小二乘，除非你确知条件数很好
