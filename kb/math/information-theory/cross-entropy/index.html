    交叉熵与 KL 散度¶

    这一页讲两个量——它们的关系是：

    交叉熵 = 熵 + KL 散度

    这是机器学习中最重要的等式之一 —— 它解释了「为什么用交叉熵做损失」。

    三个量的关系图（记住这张图）

    \[ \underbrace{H(p,q)}_{\text{交叉熵}} = \underbrace{H(p)}_{\text{真实分布的熵（常数）}} + \underbrace{D_{KL}(p\|q)}_{\text{KL 散度（要最小化）}} \]
    量 含义 训练中是否可变
    \(H(p)\) 真实数据的不确定性 不变（数据定了）
    \(D_{KL}(p\;\lvert\;q)\) 模型分布与真实的差距 可优化
    \(H(p,q)\) 交叉熵损失 可优化

    关键推论：因为 \(H(p)\) 是常数，所以

    \[ \text{最小化交叉熵} \iff \text{最小化 KL 散度} \]

    训练损失为什么用交叉熵：它与 KL 只差一个常数， 但计算更简单（不需要知道 \(p\) 的完整形式， 只需样本）✓

    一、KL 散度¶

    定义（离散）：

    \[ \boxed{\ D_{KL}(p\|q) = \sum_x p(x)\log\frac{p(x)}{q(x)} = E_{x\sim p}\left[\log\frac{p(x)}{q(x)}\right]\ } \]

    读法：「\(p\) 相对于 \(q\) 的 KL 散度」。

    含义：用分布 \(q\) 去近似真实分布 \(p\) 时的「信息损失」。

    性质 内容 说明
    非负 \(D_{KL}(p\;\lvert\;q)\geq0\) 来自 Jensen 不等式或 Gibbs 不等式
    为零 \(D_{KL} = 0\iff p = q\)（几乎处处） 完全一致时无损失
    不对称 \(D_{KL}(p\;\lvert\;q)\neq D_{KL}(q\;\lvert\;p)\) 所以不是「距离」 ✗
    不满足三角不等式 —— 也不是度量

    KL 散度不是「距离」——这是最重要的提醒

    数学上「距离」（度量）需要三条：

    要求 KL 是否满足
    非负 ✓
    为零当且仅当相同 ✓
    对称 ✗ 不满足
    三角不等式 ✗ 不满足

    所以 KL 是「散度」（divergence），不是「距离」（distance）。

    具体例子：设 \(p = (0.9,0.1)\)、\(q = (0.5,0.5)\)

    \[ D_{KL}(p\|q) = 0.9\log_2\frac{0.9}{0.5}+0.1\log_2\frac{0.1}{0.5} = 0.9\times0.848+0.1\times(-2.322) \]
    \[ = 0.763-0.232 = 0.531\ \text{比特} \]
    \[ D_{KL}(q\|p) = 0.5\log_2\frac{0.5}{0.9}+0.5\log_2\frac{0.5}{0.1} = 0.5\times(-0.848)+0.5\times2.322 \]
    \[ = -0.424+1.161 = 0.737\ \text{比特} \]

    两者的值不同（0.531 vs 0.737） ✗ 所以不对称。

    为什么这很重要：用哪个方向做优化，结果完全不同。

    方向 名称 行为
    \(D_{KL}(p\;\lvert\;q)\)（\(p\) 在前） 前向 KL 「零避免」（zero-avoiding）
    \(D_{KL}(q\;\lvert\;p)\)（\(q\) 在前） 反向 KL 「零强迫」（zero-forcing）

    这两种行为在后面「JS 散度」一页详述（涉及变分推断的模式选择问题）。

    KL 散度的信息论解释¶

    \[ D_{KL}(p\|q) = H(p,q)-H(p) \]

    含义：「用错误的分布 \(q\) 编码 \(p\) 的数据时， 平均多花的比特数」 ✓

    这个「多花比特」的解释非常实用

    设定：真实数据服从 \(p\)，但你知道的（或模型的）分布是 \(q\)。

    熵编码的长度：

    使用的分布 平均码长
    真实分布 \(p\) \(H(p)\)（最优）
    错误分布 \(q\) \(H(p,q)\)（更长）

    多花的部分：

    \[ H(p,q)-H(p) = D_{KL}(p\|q) \;\checkmark \]

    工程含义：

    场景 \(D_{KL}\) 的意义
    数据压缩 用错模型的压缩效率损失
    机器学习 模型与真实分布的差距
    模型选择 比较不同模型的「失配程度」

    这就是「为什么最小化交叉熵 = 最小化模型失配」的严格解释。

    二、交叉熵¶

    定义：

    \[ \boxed{\ H(p,q) = -\sum_x p(x)\log q(x) = E_{x\sim p}\left[-\log q(x)\right]\ } \]

    读法：「\(p\) 与 \(q\) 的交叉熵」。

    注意不对称性：

    位置 作用
    \(p\)（前） 用在加权（期望）上
    \(q\)（后） 用在 log 里

    所以 \(H(p,q)\neq H(q,p)\) —— 与 KL 一样不对称 ✓

    三者关系¶

    \[ H(p,q) = H(p)+D_{KL}(p\|q) \]

    验证：

    \[ H(p)+D_{KL}(p\|q) = -\sum p\log p+\sum p\log\frac{p}{q} \]
    \[ = -\sum p\log p+\sum p\log p-\sum p\log q = -\sum p\log q = H(p,q) \;\checkmark \]

    机器学习中的用法¶

    关键转换：训练时 \(p\) 是数据分布，\(q\) 是模型分布。

    但 \(H(p)\) 与模型参数无关（数据固定），所以：

    \[ \min_\theta H(p,q_\theta) \iff \min_\theta D_{KL}(p\|q_\theta) \]

    实践中直接用交叉熵，因为：

    原因 说明
    计算更简单 只需 \(-\log q(y)\)，不需要 \(p\) 的完整形式
    等价性 与 KL 只差常数
    数值稳定 避免 \(p\log p\) 中 \(p=0\) 的处理

    交叉熵损失的两种常见形式（与标签类型对应）

    形式 1：one-hot 标签（硬标签）

    若真实标签是 one-hot（只有一个类为 1）：

    \[ H(p,q) = -\sum_{c}p_c\log q_c = -\log q_{y} \]

    其中 \(y\) 是真实类别。

    所以简化成「负对数似然」：

    \[ \mathcal{L} = -\log q_y \]

    含义：只惩罚「真实类别的预测概率」 ✓

    这就是「分类交叉熵」的实现形式（与「最大似然估计」一页完全一致）。

    形式 2：软标签（label smoothing / 知识蒸馏）

    真实标签是分布 \(\boldsymbol{p}\)（不是 one-hot）：

    \[ \mathcal{L} = -\sum_c p_c\log q_c \]

    用途：

    场景 说明
    标签平滑 把 one-hot 改成 \((1-\varepsilon, \varepsilon/(K-1),\dots)\)
    知识蒸馏 用教师模型的软输出作为 \(p\)
    软标签学习 标注不确定时的概率标签

    为什么软标签有用：

    好处 说明
    防止过度自信 模型不会追求「概率 = 1」
    更好的泛化 平滑的标签提供了更多信息
    缓解过拟合 相当于正则化

    三、交叉熵与最大似然（第三次确认这个等价关系）¶

    这是本知识库第三次给出这个结论（「最大似然估计」一页、 「Logistic 与 Softmax 导数」一页、这里）—— 因为它是最重要的桥梁。

    设定：\(n\) 个独立样本，真实标签 \(y_i\)，模型预测 \(q_\theta\)。

    负对数似然：

    \[ -\ell(\theta) = -\sum_i\log q_\theta(y_i) \]

    交叉熵（用经验分布 \(\hat p\)）：

    \[ H(\hat p,q_\theta) = -\sum_c\hat p_c\log q_\theta(c) = -\frac{1}{n}\sum_i\log q_\theta(y_i) \]

    两者只差常数因子 \(n\) ✓ 所以

    \[ \min H(\hat p,q_\theta) \iff \max\ell(\theta) \]

    三次出现这个结论的位置（便于回顾）

    页面 切入点
    最大似然估计 从「伯努利/多项分布的 MLE」推出交叉熵
    Logistic 与 Softmax 导数 从「gradient = s−y 的极简形式」侧面说明
    交叉熵与 KL 散度（本页） 从「交叉熵 = 熵 + KL」给出信息论依据

    三个视角，同一个结论：

    \[ \text{交叉熵损失} = \text{负对数似然} = \text{模型失配（KL）} \]

    这说明「交叉熵」这个选择不是经验性的，而是有理论基础的最优选择 ✓

    为什么不用 MSE（复习「梯度」视角）¶

    损失 梯度（softmax 输出层） 训练表现
    交叉熵 \(\boldsymbol{s}-\boldsymbol{y}\)（极简） 收敛快 ✓
    MSE 含 \(s_i(1-s_i)\) 因子 饱和时梯度消失 ✗

    信息论的补充解释：

    视角 交叉熵的优势
    梯度 梯度形式简洁，不饱和
    信息论 正确度量「分布差异」（\(D_{KL}\)）
    统计 等价于最大似然（有效估计）

    三个视角都指向交叉熵 —— 它不是「习惯」，而是最优选择。

    四、KL 散度的方向问题（实用要点）¶

    问题：\(D_{KL}(p\;\lvert\;q)\) 与 \(D_{KL}(q\;\lvert\;p)\) 哪个更好？

    答案：取决于目标 —— 两者的行为不同。

    方向 名称 优化时的行为 适用
    \(\min_q D_{KL}(p\;\lvert\;q)\) 前向 KL \(q\) 要覆盖 \(p\) 的所有支撑 需要「不遗漏」时
    \(\min_q D_{KL}(q\;\lvert\;p)\) 反向 KL \(q\) 会集中在 \(p\) 的某个峰 需要「精确」时

    前向 KL 的「零避免」与反向 KL 的「零强迫」

    关键差别来自「KL 的定义中谁做权重」。

    前向 KL：\(D_{KL}(p\;\lvert\;q) = \sum_x p(x)\log\frac{p(x)}{q(x)}\)

    权重是 \(p(x)\) —— 所以关键约束是：

    \[ \text{若 }p(x)>0\text{，则不能让 }q(x)\to0 \]

    （否则 \(\log\frac{p}{q}\to\infty\)，KL 爆炸。）

    后果：\(q\) 会覆盖所有 \(p\) 有质量的地方 —— 这叫「零避免」（zero-avoiding）✓

    反向 KL：\(D_{KL}(q\;\lvert\;p) = \sum_x q(x)\log\frac{q(x)}{p(x)}\)

    权重是 \(q(x)\) —— 关键约束变成：

    \[ \text{若 }q(x)>0\text{，则不能让 }p(x)\to0 \]

    后果：\(q\) 会主动避开 \(p\) 接近零的区域， 可以集中在一个峰上 —— 这叫「零强迫」（zero-forcing）✓

    图示化的差别（\(p\) 是双峰分布）：

    方向 \(q\) 的形状
    前向 KL 铺开覆盖两个峰（可能因此变得很宽）
    反向 KL 只锁定一个峰（忽略另一个）

    这解释了两件重要事实：

    事实 原因
    变分推断（VI）常用反向 KL 想要「紧的」近似（锁定主要模式）
    MLE / 交叉熵是前向 KL \(D_{KL}(p_{\text{data}}\;\lvert\;q_\theta)\)，\(p\) 在前

    变分推断为什么接受「只锁一个峰」：

    代价 好处
    忽略其他模式（欠拟合） 计算上可行（不需要覆盖全部）
    —— 近似更「锐利」，便于推断

    一句话：前向 KL「不能漏」，反向 KL「要精确」。

    五、典型例题¶

    例题 1：计算交叉熵与 KL 散度¶

    设真实分布 \(p = (0.5, 0.5)\)，模型分布 \(q = (0.9, 0.1)\)。 求 \(H(p)\)、\(H(p,q)\)、\(D_{KL}(p\;\lvert\;q)\)，并验证三者关系。

    思路

    逐个算，再用 \(H(p,q) = H(p)+D_{KL}\) 验证。

    解答

    第一步：\(H(p)\)

    \[ H(p) = -0.5\log_2 0.5-0.5\log_2 0.5 = 0.5+0.5 = 1\ \text{比特} \]

    第二步：交叉熵 \(H(p,q)\)

    \[ H(p,q) = -0.5\log_2 0.9-0.5\log_2 0.1 \]

    （\(\log_2 0.9 = -0.152\)、\(\log_2 0.1 = -3.322\)）

    \[ = 0.5\times0.152+0.5\times3.322 = 0.076+1.661 = 1.737\ \text{比特} \]

    第三步：KL 散度

    \[ D_{KL}(p\|q) = 0.5\log_2\frac{0.5}{0.9}+0.5\log_2\frac{0.5}{0.1} \]
    \[ = 0.5\times(-0.848)+0.5\times2.322 = -0.424+1.161 = 0.737\ \text{比特} \]

    第四步：验证关系

    \[ H(p)+D_{KL}(p\|q) = 1+0.737 = 1.737 = H(p,q) \;\checkmark \]

    结果汇总：

    量 值
    \(H(p)\) \(1.000\) 比特
    \(H(p,q)\) \(1.737\) 比特
    \(D_{KL}(p\;\lvert\;q)\) \(0.737\) 比特

    工程解读：模型「多花了 0.737 比特」 —— 即用错模型的编码效率损失约 74%（相对于最优的 1 比特）。

    这个例子说明了「交叉熵为什么总是 ≥ 熵」

    \[ H(p,q)\geq H(p) \]

    等号当且仅当 \(q = p\) ✓

    理由：\(H(p,q) = H(p)+D_{KL}(p\;\lvert\;q)\)，而 \(D_{KL}\geq0\)。

    实用含义：

    观察 解读
    交叉熵非常接近熵 模型很好 ✓
    交叉熵远大于熵 模型差 ✗
    交叉熵 = 熵 完美拟合
    交叉熵 < 熵 不可能（除非计算错误或过拟合）

    实践用法：把「熵」当作交叉熵损失的理论下界 —— 这给出了「还能改进多少」的参考。

    注意过拟合的例外：在训练集上交叉熵可以低于真实数据的熵 （因为模型可能「记住」了训练样本的标签，比真实分布更「确定」）。 这就是为什么要在验证集上评估。

    例题 2：KL 散度的不对称性¶

    承上题。求 \(D_{KL}(q\;\lvert\;p)\)，并与 \(D_{KL}(p\;\lvert\;q)\) 比较。

    思路

    交换 \(p\) 与 \(q\) 的角色，重新计算。

    解答

    计算 \(D_{KL}(q\;\lvert\;p)\)：

    \[ D_{KL}(q\|p) = 0.9\log_2\frac{0.9}{0.5}+0.1\log_2\frac{0.1}{0.5} \]
    \[ = 0.9\times0.848+0.1\times(-2.322) \]
    \[ = 0.763-0.232 = 0.531\ \text{比特} \]

    对比：

    方向 值
    \(D_{KL}(p\;\lvert\;q)\)（\(p\) 在前） \(0.737\)
    \(D_{KL}(q\;\lvert\;p)\)（\(q\) 在前） \(0.531\)
    差异 \(0.206\)

    两者不同 ✓ 所以 KL 不是距离

    为什么不同（直观解释）：

    方向 权重 关键约束
    \(D_{KL}(p\;\lvert\;q)\) \(p = (0.5,0.5)\)（分散） \(q\) 不能在小概率处太小 → 被迫覆盖
    \(D_{KL}(q\;\lvert\;p)\) \(q = (0.9,0.1)\)（集中） 主要看大权重处 → 更宽容

    具体点数：

    • \(D_{KL}(p\;\lvert\;q)\) 中 \(0.5\times\log_2\frac{0.5}{0.1} = 1.161\)（大惩罚： 因为 \(p\) 在第二项上有 0.5 的质量，而 \(q\) 只给 0.1）
    • \(D_{KL}(q\;\lvert\;p)\) 中对应项 \(0.1\times\log_2\frac{0.1}{0.5} = -0.232\) （小权重，所以影响小）

    所以「\(p\) 更分散时，用 \(q\) 编码它的代价更大」 ✓

    这个不对称性在实践中的后果

    训练时的方向是固定的：

    \[ D_{KL}(p_{\text{data}}\|q_\theta) \]

    真实分布在前（因为要用数据做期望） —— 这是前向 KL（零避免）。

    这带来一个实际现象：生成模型倾向于「覆盖」数据的所有模式。

    现象 解释
    GAN 早期易「模式崩塌」（只生成少数模式） 但用 JS/其它目标
    MLE 训练的模型不会漏掉模式 前向 KL 的零避免性质
    代价：可能生成一些「边缘」样本 为了覆盖而牺牲精确性

    若要「只精确锁定主要模式」（放弃覆盖）， 则应优化反向 KL —— 这是变分推断的做法。

    实践选择指南：

    目标 方向 例子
    不遗漏数据模式 前向 标准 MLE 训练（分类、密度估计）
    精确近似某个目标 反向 变分推断、某些强化学习
    需要对称 用 JS 散度 GAN 的原始目标

    例题 3：one-hot 标签的交叉熵简化¶

    设三分类任务，真实标签为第 2 类（one-hot：\(\boldsymbol{y} = (0,1,0)\)）， 模型预测 \(\boldsymbol{q} = (0.1, 0.7, 0.2)\)。 求交叉熵损失。

    思路

    one-hot 时只有一项非零。

    解答

    用定义（3 项）：

    \[ H(p,q) = -\sum_c p_c\log q_c \]
    \(c\) \(p_c\) \(q_c\) 项
    1 \(0\) \(0.1\) \(0\times(\cdots) = 0\)
    2 \(1\) \(0.7\) \(-\log_2 0.7\)
    3 \(0\) \(0.2\) \(0\)

    只有一项非零：

    \[ H(p,q) = -\log_2 0.7 \]

    计算（用自然对数换算，因为 ML 中常用 nat）：

    \[ -\ln 0.7 = 0.357\ \text{nat} \]

    或者用比特：

    \[ -\log_2 0.7 = 0.515\ \text{比特} \]

    结果：损失约 \(0.357\) nat（或 \(0.515\) 比特）

    这就是实现中的形式：

    1
    loss = -log(q[y_true])   # 只取真实类别的预测概率

    对比「预测完美」的情形（\(q = (0,1,0)\)）：

    \[ -\log_2 1 = 0 \]

    损失为零 ✓

    对比「预测完全错误」（\(q = (0.4,0.05,0.55)\)）：

    \[ -\ln 0.05 = 3.00\ \text{nat} \]

    损失很大 ✓

    为什么 one-hot 简化成「负对数概率」很有用

    计算效率：

    形式 计算量
    完整交叉熵 \(O(K)\)（\(K\) 个类别）
    one-hot 简化 \(O(1)\)（只需查一次）✓

    数值稳定性：

    问题 说明
    \(0\times\log 0\) one-hot 中 \(p_c = 0\) 的项直接跳过，避免了这个约定

    实现时的注意事项：

    错误做法 正确做法
    先算 softmax 再取 log 用 log-softmax（数值稳定）
    -log(0) → -inf 加极小值 \(\varepsilon\) 或用 log-sum-exp

    这就回到「Logistic 与 Softmax 导数」一页讲过的数值稳定技巧： 减去最大值后再算指数。

    工程提醒：框架中的 CrossEntropyLoss 通常内部做 log-softmax —— 所以传入的是 logits（未归一化的分数），不要自己先做 softmax ✗ （否则会「双重归一化」，导致梯度错误。）

    例题 4：KL 散度与模型选择¶

    某数据集的真实分布未知。两个候选模型给出不同的预测分布：

    样本 真实类型 模型 A 的 \(q\) 模型 B 的 \(q\)
    1 类 1 \(0.8\) \(0.6\)
    2 类 2 \(0.6\) \(0.9\)
    3 类 1 \(0.7\) \(0.5\)

    （表中的 \(q\) 是「真实类别的预测概率」。）

    用交叉熵比较两个模型。

    思路

    交叉熵 = 各项 \(-\ln q\) 的平均。

    解答

    模型 A 的交叉熵：

    \[ \mathcal{L}_A = -\frac13\left(\ln 0.8+\ln 0.6+\ln 0.7\right) \]

    逐项：

    样本 \(q\) \(-\ln q\)
    1 \(0.8\) \(0.223\)
    2 \(0.6\) \(0.511\)
    3 \(0.7\) \(0.357\)
    \[ \mathcal{L}_A = \frac{0.223+0.511+0.357}{3} = \frac{1.091}{3} = 0.364\ \text{nat} \]

    模型 B 的交叉熵：

    样本 \(q\) \(-\ln q\)
    1 \(0.6\) \(0.511\)
    2 \(0.9\) \(0.105\)
    3 \(0.5\) \(0.693\)
    \[ \mathcal{L}_B = \frac{0.511+0.105+0.693}{3} = \frac{1.309}{3} = 0.436\ \text{nat} \]

    比较：

    模型 交叉熵 结论
    A \(0.364\) 更好 ✓
    B \(0.436\) 较差

    结论：模型 A 更优（交叉熵更小）

    一个需要注意的细节：样本数少时不可靠

    本例题只用 3 个样本 —— 结论可能是偶然的。

    模型 B 的问题：它在样本 3 上预测 \(0.5\)（很没把握）， 这一个「差样本」把平均拉高了。

    观察 说明
    A 的预测更「平稳」（0.6–0.8） 交叉熵更均匀
    B 的预测波动大（0.5–0.9） 有一个很差 → 惩罚大

    工程实践：

    做法 理由
    用验证集（足够大） 减小偶然性
    用平均交叉熵（而非总和） 便于跨数据集比较
    多次训练取平均 减小初始化随机性

    交叉熵作为模型选择准则的理论依据：

    它与KL 散度单调对应（差一个 \(H(p)\) 常数）， 而 KL 正是「模型失配」的度量 ✓

    这也解释了「为什么用交叉熵而非准确率」：

    指标 优点 缺点
    准确率 直观 对置信度不敏感（0.51 与 0.99 都算对）
    交叉熵 反映置信度质量 数值不易直观理解

    举例（同样的准确率）：

    情形 准确率 交叉熵
    高置信且正确（预测 0.99） 都正确 小 ✓
    低置信但正确（预测 0.51） 都正确 大 ✗

    所以在「模型校准」场景，交叉熵比准确率更能反映真实质量 ✓

    六、自测¶

    Q1 设真实分布 \(p = (0.25, 0.75)\)，模型分布 \(q = (0.5, 0.5)\)。 求 \(H(p)\)、\(H(p,q)\)、\(D_{KL}(p\|q)\)。

    提示

    先算两个熵，再用「交叉熵 = 熵 + KL」核对。

    解答

    第一步：\(H(p)\)

    \[ H(p) = -0.25\log_2 0.25-0.75\log_2 0.75 = 0.25\times2+0.75\times0.415 \]
    \[ = 0.5+0.311 = 0.811\ \text{比特} \]

    第二步：交叉熵

    \[ H(p,q) = -0.25\log_2 0.5-0.75\log_2 0.5 = 0.25\times1+0.75\times1 = 1.0\ \text{比特} \]

    （因为 \(q\) 均匀，\(-\log_2 0.5 = 1\)。）

    第三步：KL 散度

    \[ D_{KL}(p\|q) = H(p,q)-H(p) = 1.0-0.811 = 0.189\ \text{比特} \]

    验证（用定义）：

    \[ D_{KL}(p\|q) = 0.25\log_2\frac{0.25}{0.5}+0.75\log_2\frac{0.75}{0.5} \]
    \[ = 0.25\times(-1)+0.75\times0.585 = -0.25+0.439 = 0.189 \;\checkmark \]

    结果：

    量 值
    \(H(p)\) \(0.811\)
    \(H(p,q)\) \(1.000\)
    \(D_{KL}(p\;\lvert\;q)\) \(0.189\)

    解读：模型 \(q\) 是均匀的，而真实数据偏向第二类（0.75）。 用均匀模型编码的代价是每个样本多花 \(0.189\) 比特 ✓

    注意「交叉熵 ≥ 熵」：\(1.0 > 0.811\) ✓ 等号只在 \(q = p\) 时成立。

    Q2 判断：\(D_{KL}(p\|q) = D_{KL}(q\|p)\) 总是成立。

    提示

    用上一页的数值例子。

    解答

    不对。KL 散度不对称。

    反例：\(p = (0.5,0.5)\)、\(q = (0.9,0.1)\)

    方向 值
    \(D_{KL}(p\;\lvert\;q)\) \(0.737\) 比特
    \(D_{KL}(q\;\lvert\;p)\) \(0.531\) 比特

    两者不同 ✗

    为什么不对称（结构上的原因）：

    \[ D_{KL}(p\|q) = \sum_x \underbrace{p(x)}_{\text{权重}}\log\frac{p(x)}{q(x)} \]
    位置 作用
    前面的分布 提供权重（期望的基准）
    后面的分布 出现在 log 里（被用来编码）

    两个角色不同，所以交换后有变化 ✓

    具体的点数分析：

    项 \(D_{KL}(p\;\lvert\;q)\) \(D_{KL}(q\;\lvert\;p)\)
    第一项权重 \(0.5\)（分散） \(0.9\)（集中）
    第二项权重 \(0.5\) \(0.1\)

    因为 \(p\) 更分散，它在「小概率区域」（第二项）上仍有 \(0.5\) 的质量 → 那里 \(\log\frac{0.5}{0.1} = 2.322\) 的大惩罚被乘以 \(0.5\) → \(D_{KL}(p\|q)\) 更大 ✓

    工程后果：

    方向 优化时的行为
    前向（\(p\) 在前） 零避免：\(q\) 要覆盖 \(p\) 的所有支撑
    反向（\(q\) 在前） 零强迫：\(q\) 可集中于 \(p\) 的某个峰

    所以要明确「用哪个方向」 —— 结果完全不同。

    Q3 为什么训练的损失函数用交叉熵，而不是直接用 KL 散度？

    提示

    想想 KL 里需要什么信息。

    解答

    因为交叉熵不需要知道真实分布的完整形式，只需样本。

    对比两者的计算需求：

    量 公式 需要什么
    KL \(\sum_x p(x)\log\frac{p(x)}{q(x)}\) \(p(x)\) 的显式形式 ✗
    交叉熵 \(-\sum_x p(x)\log q(x)\) 只需在样本点上算 \(q\) ✓

    关键差别：KL 里的 \(\log p(x)\) 项需要知道真实分布 —— 但训练时我们只有样本（不知道数据的真实密度）✗

    展开验证：

    \[ D_{KL}(p\|q) = \underbrace{\sum_x p(x)\log p(x)}_{-H(p)}-\underbrace{\sum_x p(x)\log q(x)}_{H(p,q)} \]

    第一项 \(-H(p)\) 与模型无关（数据固定）→ 优化时可忽略 → 只剩交叉熵 ✓

    所以「用交叉熵」是「用 KL」的等价简化：

    \[ \min_\theta D_{KL}(p\|q_\theta) \iff \min_\theta H(p,q_\theta) \]

    工程上的三个好处：

    好处 说明
    只需样本 用经验分布 \(\hat p\) 代替 \(p\)
    计算便宜 只需 \(-\log q(y)\)
    数值稳定 避开 \(p=0\) 时的 \(0\log 0\)

    一句话：交叉熵是「可在样本上直接算」的那个量 ✓

    Q4 什么是「标签平滑」？它为什么能防止模型过度自信？

    提示

    想想把 one-hot 的 \(1\) 换成略小于 \(1\) 的值。

    解答

    标签平滑：把 one-hot 标签替换为「接近 one-hot 但不过分极端」的软标签。

    具体做法（\(K\) 类，平滑参数 \(\varepsilon\)）：

    \[ p_c = \begin{cases}1-\varepsilon, & c = y\text{（真实类）}\\ \dfrac{\varepsilon}{K-1}, & c\neq y\end{cases} \]

    例（\(K=3\)、\(\varepsilon = 0.1\)）：

    类别 one-hot 平滑后
    真实类 \(1.0\) \(0.9\)
    其它 \(0\) \(0.05\)
    其它 \(0\) \(0.05\)

    为什么防止过度自信：

    若模型预测完美（\(q_y = 1\)），交叉熵：

    标签类型 损失
    one-hot \(-\log 1 = 0\) ✓
    平滑后 \(-(0.9\log 1+0.05\log 0+\cdots)\to\) 需避免 \(\log0\)

    实际上：模型无法让损失真正为零，因为平滑标签要求 「其它类的概率是 \(0.05\)」而不是 \(0\)。

    所以要最小化损失，模型被迫满足：

    \[ q(\text{其它类})\approx0.05 > 0 \]

    即不能把概率全部堆到一个类上 ✓

    效果总结：

    方面 影响
    置信度 不会过度自信（防止 \(q\to1\)）
    泛化 通常更好（相当于正则化）
    校准 概率更接近真实频率
    知识蒸馏 与此同源（用教师的软输出）

    代价：

    代价 说明
    训练损失不会到零 因为有「故意的」混淆
    需要调 \(\varepsilon\) 通常 \(0.05\)–\(0.2\)

    工程提示：标签平滑是「免费的改进」 —— 一行代码，常能带来可观的泛化提升（尤其在数据量不大时）。
