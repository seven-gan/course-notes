    05 Series 与 DataFrame¶

    这一页解决一个问题：让「一张有列名的表」变成一个能整体运算的对象。

    上一页之前的 NumPy 把「一堆数」变成了能整体运算的对象，这一步很关键。 可是真实的数据几乎不会以「一堆数」的形式出现。 它是一张表：有列名、有行号，而且每一列的类型还不一样—— 站点名是文字，温度是小数，湿度是整数，是否超标是「真/假」。

    把这样一张表塞进 NumPy 会立刻出事：为了容纳文字， 整张表会被统一提升成字符串类型，于是所有数字都变成文字， 求平均、排序、画图全部失效。

    pandas 就是为这张表而生的。它给出两个结构：

    结构 一句话定义 类比
    Series 带标签的一维数组 一列数据 + 一列行标
    DataFrame 带行标和列名的二维表 一张 Excel 工作表

    学完这一页，你将能够：

    能力 具体表现
    选对结构 知道什么时候用 Series、什么时候必须用 DataFrame
    造出数据 从列表、字典、NumPy 数组都能构造，并主动指定 index
    看懂表 shape / dtypes / info / describe 一眼说出表长什么样
    取准数据 [列]、loc、iloc 四种取法不再混用
    说出差别 看到两列相加，先问「标签对得上吗」，而不是「位置对得上吗」

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    NumPy 相加是按位置，pandas 相加是按标签 后者会自动对齐，对不上的位置补 NaN 顺序不同反而算对了，顺序相同也可能算出 NaN
    loc 与 iloc 的切片右端 前者含右端，后者不含右端 少一行或多一行，而且不报错
    df[列] 与 df[[列]] 前者给 Series，后者给 DataFrame 下一步调用的方法不存在，或者形状突然多一维

    这三条都能靠一个动作当场查出来： 打印 type() 与 shape。 本页会把这两个自查手段用在每一个知识点上

    一、为什么需要 pandas¶

    1.1 用 NumPy 存这张表会怎样¶

    先看一个具体场景。某城市在河边、路口、公园各设了监测站， 三月的记录长这样：

    站点 温度 湿度 是否超标
    A 21.5 45 否
    B 22.8 52 否
    A 19.4 61 否

    这张表有三个特点，也正是它「难处理」的原因：

    特点 说明
    列有名字 「温度」这一列和「湿度」这一列要做不同的事
    列的类型不同 文字、小数、整数、真假值混在一张表里（这叫异构）
    行有标号 每一行是一条记录，要能按记录取数

    NumPy 的 ndarray 只满足第三条。前两条它都不管： ndarray 里所有元素的类型必须一致，而且没有列名这个概念。

    把上面那张表原样交给 NumPy，会发生什么：

    1.3 两者的分工¶

    任务 用谁 原因
    矩阵乘法、解方程、特征值 NumPy 同质数值、连续内存，专为数值计算优化
    大规模向量化运算（几百万个纯数字） NumPy 更快、更省内存
    读写 CSV / Excel、按列名选列 pandas 有列名、有行标、能装字符串
    缺失值、混合类型、按列统计 pandas 每列独立类型，缺值有专门表示 NaN
    画图前的数据整理 pandas 整理成表之后交给绘图库
    建模前的特征矩阵 两者配合 pandas 整理 → .to_numpy() → NumPy 计算

    一句话概括：NumPy 管「数值」，pandas 管「表格」。 两者不是替代关系，pandas 的底层就是一列一列的 NumPy 数组。

    二、Series：带标签的一维数组¶

    2.1 四种创建方式¶

    Series 就是「一列数据」再加上「每个元素的名字」。 最常用的四种造法：

    写法 数据从哪里来 默认 index
    pd.Series([...]) 一个列表 0, 1, 2, ...

    「不报错」才是它危险的地方

    如果你以为 pandas 也按位置相加，这段代码会给你一张看似正常的表， 里面却有三分之二是缺值。

    1. 两个 Series 相加前，先比一下标签集合： print(a.index.difference(b.index)) —— 打印出「a 有而 b 没有」的标签， 空结果才说明能安心相加。
    2. 相加之后立刻查一次： print(result.isna().sum()) —— 非零就说明有对不上的位置。

    2.4 与 NumPy 的完整对比¶

    把两种结构的差别集中成一张表，值得抄下来：

    对比项 np.ndarray（一维） pd.Series
    元素类型 全体必须一致 一致（单个 Series 内部仍要统一）
    有没有标签 没有，只有位置 每个元素都有标签
    相加对齐方式 按位置 按标签
    标签不匹配 不可能（形状必须兼容） 补 NaN，不报错
    选一个元素 a[0] s["a"] 或 s.iloc[0]
    切片右端 不含 s["a":"c"] 含右端，s.iloc[0:2] 不含
    有没有名字 没有 有 name
    缺值表示 要自己约定（如 -1、nan） 统一用 NaN，且有 isna() 等配套工具
    与对方的关系 —— s.values 给出 ndarray，pd.Series(arr) 转回来

    最后一行是关键：两者可以互相转换。 所以正确的用法不是「二选一」，而是各管一段： 用 Series 做「按名字取数、对齐、统计」， 用 .values 交给 NumPy 做「大规模数值计算」。

    • .round(2) —— 不加的话浮点数会打印出十几位小数 （如 21.975000000000001），既难读，又容易随版本变化而不同。 给数值列做任何输出前，先 round。
    • 只留数值列 —— 文字列会被自动排除。

    describe() 默认会悄悄跳过文字列

    表里有「站点」这种文字列时，df.describe() 的输出里看不到它， 这不是出错，是默认行为（只统计数值列）。

    想让文字列也出摘要，加一个参数： df.describe(include="all") 会把文字列也统计进来 （给出 unique / top / freq 三行）， df.describe(include="object") 则只看文字列。

    容易被误读的一点：count 是非空值个数，不是总行数。 若某列有缺值，count 会比 len(df) 小， 而 mean / std 都是基于 count 个值算的， 分母不等于总行数。看到 count 不等就说明有缺值。

    • 我需要包含右端 → loc
    • 我在做「取前 n 行」这种数学上的半开区间 → iloc

    三条避免它的规则

    2. 从 df 切出子表后要改它，加一次 .copy()：

    删行（按标签） df.drop(index=[0, 2]) df.drop([0, 2], axis=0)
    删行的简写 df.drop([0, 2]) —— （axis 默认是 0，即行）

    为什么推荐 columns= / index=：axis=0 和 axis=1 差一个数字， 看代码时很容易看漏；而 columns= 一眼就知道在删列。

    drop 默认不改原表

    df.drop(columns=["编号"]) 返回新表，df 原封不动。 这正是上面那段代码最后一行输出的意义。

    要保留结果，必须接住它：写成 df = df.drop(columns=["编号"])。

    忘了接住 → 你以为删掉了，后面却报 「列已存在」或「列不存在」，而且看起来毫无道理。

    判断依据：绝大多数 pandas 方法都返回新对象， 不动原表。这是刻意的设计（见第八节）， 所以「df = 前缀接住返回值」要成为条件反射。

    八、inplace 的取舍¶

    早期 pandas 的教程里到处是 inplace=True：

    1
2
3
    df.drop(columns=["编号"], inplace=True)
df.sort_values("温度", inplace=True)
df.reset_index(drop=True, inplace=True)

    现代 pandas 更推荐「返回新对象 + 重新赋值」：

    1
2
3
    df = df.drop(columns=["编号"])
df = df.sort_values("温度")
df = df.reset_index(drop=True)

    原因有四条，每条都是实际踩过的坑：

    原因 说明
    inplace 经常并不真的「原地」 很多操作内部照样要造新数组，只是最后把结果搬回原对象，省不下内存，还可能更慢
    inplace=True 返回 None 写 df = df.drop(..., inplace=True) 会把 df 变成 None，后面全线报错
    方法链被切断 df.drop(...).sort_values(...).reset_index(...) 一气呵成，中间插一个 inplace 就得拆成四行
    新功能不提供 inplace assign、insert 这类方法根本没有 inplace 参数，强行用会报 TypeError

    再补一条更实际的理由：「返回新对象」让每一步都可以单独检查。

    1
2
3
    df = df.drop(columns=["编号"])        ← 这一行之后 print(df) 看看对不对
df = df.assign(温差=df["温度"] - 20)  ← 再看一次
df = df.sort_values("温差", ascending=False)

    每一步都是「赋值 → 立刻检查 → 再往下」， 中间任何一步出错都能被当场定位。 而一长串 inplace=True 操作是改同一个对象， 出了问题你只能从头一行行加 print 找，这也是本页 （以及那个反复提到的「分步检查」）一贯的主张。

    inplace=True 的 None 陷阱

    想做的事 错误写法 正确写法
    删列 df = df.drop(columns=["a"], inplace=True) df = df.drop(columns=["a"])
    排序 df = df.sort_values("温度", inplace=True) df = df.sort_values("温度")
    降级行标 df = df.reset_index(drop=True, inplace=True) df = df.reset_index(drop=True)

    左边那三种写法都不会报错，df 会安静地变成 None， 然后在你下一次用 df[...] 时抛出 AttributeError: 'NoneType' object has no attribute ...。 报错位置离病根很远，所以特别难查。

    一句话规则：同一行里不要同时出现 df = 和 inplace=True。

    如果已经写了 inplace=True，就不要再接返回值， 把 df.drop(columns=["编号"], inplace=True) 单独写成一行即可。

    但更好的做法是干脆不用它，改写成本节开头那种「接住返回值」的形式。

    十、常见陷阱汇总¶

    前面各节零散提到的问题，这里集中成几张表。这几张表值得单独存下来。

    10.1 五个最常踩的坑¶

    陷阱 现象 原因 正确做法
    链式赋值无效 df[df["a"] > 1]["a"] = 9 之后原表没变 中间产生了临时对象，赋值落在临时对象上 df.loc[df["a"] > 1, "a"] = 9

    SettingWithCopyWarning 控制台出现警告，改的到底是谁说不清 你正在一个「可能是副本、也可能是视图」的对象上赋值 想改原表用 loc；想改副本先 .copy()
    默认索引与 set_index 的区别 取数要写 df[df["站点"] == "B"] 默认行标 0, 1, 2 没有含义 df.set_index("站点") 后可以直接 loc["B"]

    例题 4：Series 与 NumPy 数组相加¶

    题目：把一个 Series 和一个 np.array 相加，会发生什么？ 如果一个 Series 的标签只有对方的一部分，又会怎样？

    思路

    这里是两套规则的交界处，值得单独想清楚：

    • Series + ndarray：长度相同时，ndarray 会被当成 「按位置对齐」的伙伴 —— 因为 ndarray 没有标签， pandas 只能按位置把它贴上去。
    • 两个 Series 相加：按标签对齐，对不上的补 NaN。

    所以同一个 + 运算符，遇到有标签和没标签的对象，行为是不同的。 这正是本题要点出来的地方。

    np.array([1, 2, 3]) 按位置 x=11、y=22、z=33，全部有效
    Series([1, 2], index=["y", "x"]) 按标签 x=12、y=21、z=NaN

    z 变成 NaN 是设计如此，不是出错： 另一个表里根本没有 z 这个标签， 所以 pandas 无法告诉你 z 该加什么，它诚实地填了缺值。

    实践建议：

    • 与 ndarray 运算时要自己保证长度与顺序都对齐， pandas 帮不了你 —— 它会安静地按位置算。
    • 两个 Series 运算时要保证标签集合一致， 不能保证就先查 isna()，或先 fillna(0)。

    小结¶

    要记住的 为什么
    NumPy 同质、pandas 异构 混合类型塞进 ndarray 会被整表提升成字符串，数字就废了
    Series = 带标签的一维数组 index、values、name、dtype 四个属性先认全
    values 返回 ndarray pandas 与 NumPy 之间没有墙，可双向转换 ✓
    pandas 相加按标签，NumPy 按位置 顺序不同也能算对；顺序相同也可能因标签缺失出 NaN ⚠
    标签对不上就补 NaN，且不报错 最危险的静默错误，算完必须查 isna().sum() ⚠
    df[列] 给 Series，df[[列]] 给 DataFrame 多一个方括号，多一个维度 ⚠
    loc 切片含右端，iloc 不含右端 同一段 1:3，一个 3 行、一个 2 行，都不报错 ⚠
    at、iat 返回标量 取一个数就用它们，别用 loc 再取 [0] ✓
    链式赋值一定无效 df[...][...] = 值 改的是临时对象；赋值要用 df.loc[...] = 值 ⚠
    SettingWithCopyWarning 的意思是「你不确定改的是谁」 改原表用 loc，改副本先 .copy()
    默认方法都返回新表，不接住就白做 df = df.drop(...) 要成为条件反射 ✓
    drop(columns=...) 比 axis=1 易读 差一个数字的写法最容易看漏
    rename(columns=str.lower) 与 str.strip 一条命令统一列名大小写与空格 ✓
    reset_index(drop=True) 才能丢掉旧行标 不加 drop 会多出一列，后续分组、合并全被影响 ⚠
    sort_index 排标签，sort_values 排值 名字里已经写明了，别混
    别用 inplace=True，改成「返回新对象 + 重新赋值」 它常返回 None、切断方法链、新方法根本不支持 ⚠
    object 列的排序是字典序 数字被存成 object 后，"100" 会排在 "21.5" 前面 ⚠
    astype("int64") 是截断不是进位 21.5 会变成 21，要进位先 round(0) ⚠
    category 定顺序要同时给 categories 与 ordered=True 少一个，排序结果就不是你想要的那个顺序 ⚠
    造数据固定 rng = np.random.default_rng(42) 不固定就无法复现，输出也没法核对 ✓
    打印前先 head() 与 round() 长表会刷屏、浮点数尾巴会随环境变化 ✓

    这一页的终极目标其实只有一个： 看到一张表和一段取数代码，能立刻回答三个问题 —— 拿到的是 Series 还是 DataFrame、是按标签还是按位置、 改的是原表还是临时对象。

    这三个问题答得出来，pandas 里九成以上的 「改了不生效」「形状对不上」「莫名其妙多了 NaN」 都会在你写下那一行的当下被拦住， 而不是在三天后的结论里被发现
