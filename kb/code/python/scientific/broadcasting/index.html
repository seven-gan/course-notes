    03 广播与向量化¶

    这一页讲 NumPy 效率的真正来源：把「一个元素一个元素地做」改成「整体一起做」。

    学完这一页，你将能够：

    能力 具体表现
    写出向量化代码 把带 for 循环的数值计算改写成一行整体运算
    预测广播结果 看到两个形状，就能不运行代码说出结果形状
    读懂形状报错 见到「could not be broadcast」立刻知道是哪个维度对不上
    控制内存 知道什么时候广播会隐式复制大数组，怎么避免
    判断该不该向量化 知道哪些循环不该硬改成向量化

    这页最容易搞错的一点

    广播不会复制数据 —— 它只是在「读」的时候把某个维度重复使用。 真正会把内存撑爆的，是广播之后产生的那个新数组。

    所以看到 (3, 4) 与 (3, 1) 能相加，不要以为 NumPy 把 (3, 1) 复制成了 (3, 4)；它给自己的例子加了个「步长为 0」的维度， 反复读同一块内存

    这一页后面会用 view.strides 把这件事直接打印出来。

    一、为什么需要向量化¶

    1.1 先看一个真实的差别¶

    假设要把一串摄氏温度换成华氏温度。用最朴素的写法，你会写一个循环； 用 NumPy，你直接对整个数组做一次算术。

    import numpy as np

# ---------- 写法一：逐元素循环 ----------
temps_c = [-40.0, 0.0, 25.0, 37.5, 100.0]
temps_f = []
for t in temps_c:
    temps_f.append(t * 9 / 5 + 32)

# ---------- 写法二：整体运算（向量化） ----------
arr_c = np.array([-40.0, 0.0, 25.0, 37.5, 100.0])
arr_f = arr_c * 9 / 5 + 32

print("循环结果  :", [round(v, 2) for v in temps_f])
print("向量化结果:", arr_f.round(2))
print("两者一致吗:", np.allclose(temps_f, arr_f))

    循环结果  : [-40.0, 32.0, 77.0, 99.5, 212.0]
向量化结果: [-40.   32.   77.   99.5 212. ]
两者一致吗: True

    注意 arr_c * 9 / 5 + 32 这一行：没有任何循环， 但 NumPy 会对数组里的每一个元素做同样的运算。 这种「写成整体、作用到每个元素」的写法就叫向量化（vectorization）。

    它不只是少写几行，而是执行方式完全不同。

    1.2 为什么向量化快¶

    原因 说明
    循环在 C 里完成 那个「逐个元素做一次」的循环写在 NumPy 编译好的底层代码里，不是 Python 字节码
    没有解释器开销 Python 每执行一次循环体，都要「取字节码、判断类型、调用方法」；这部分开销在小运算上远超运算本身
    整块数据的类型是统一的 dtype 已知，不需要每个元素都去猜「它是什么类型」
    可以用 SIMD 指令 现代 CPU 一条指令能同时处理 4 个或 8 个浮点数，向量化运算能吃到这个好处
    内存访问连续，缓存友好 数组数据在一块连续内存里顺序读取，命中的是缓存而不是内存

    一句话：向量化把「一万次解释器往返」换成了「一次函数调用 + 一段紧凑的机器码」。

    import numpy as np
import time

n = 1_000_000
arr = np.arange(n, dtype=np.float64)

t0 = time.perf_counter()
vec_result = arr * 2.0 + 1.0
t_vec = time.perf_counter() - t0

t0 = time.perf_counter()
loop_result = [x * 2.0 + 1.0 for x in arr.tolist()]
t_loop = time.perf_counter() - t0

print("两种写法结果一致吗:", np.allclose(loop_result, vec_result))
print("向量化更快吗      :", t_vec < t_loop)

    别把「向量化更快」当成无条件真理

    只有在「运算本身很简单」时，向量化的优势才明显。

    如果每个元素要做的是「调一次网络请求」「写一个文件」「解析一段文本」， 那么快的那部分根本不是循环开销，向量化也救不了你， 反而会让代码更难读 ✗

    判断依据：运算本身很轻（几次算术/比较）→ 向量化收益大； 单元素工作量很重（I/O、复杂逻辑）→ 循环更清楚

    1.4 与列表推导式对比¶

    Python 的列表推导式已经比 for 循环快不少，但它仍然在 Python 层逐个元素执行。 NumPy 则把整个循环下推到 C 层。

    for 循环 列表推导式 NumPy 向量化
    代码长度 最长 较短 最短 ✓
    百万级数据速度 慢 比循环快 2~3 倍 比循环快 10~100 倍 ✓
    能处理的数据 任意对象 任意对象 数值、布尔、定长字符串
    复杂逻辑可读性 最好 ✓ 尚可 差
    内存 逐个生成 生成整个列表 生成整个数组（一次分配）

    选择依据，记住三句话：

    1. 数值数组 + 简单运算 → 一律向量化
    2. 对象不是数组（字典、类实例）或逻辑复杂 → 用循环
    3. 不确定时先写成循环跑通，再逐个替换成向量化 —— 不要一上来就追求炫技的写法。

    2.4 out 参数：原地写入，省一次内存分配¶

    每次 a + b 都会新建一个数组。在大数组上的循环里， 这些临时数组会反复申请、释放内存，既慢又占内存。 out= 让结果直接写进一块已经存在的内存。

b = np.array([10.0, 20.0, 30.0, 40.0])

total = np.empty_like(a)          # 先开好一块内存（形状、类型与 a 相同）
np.add(a, b, out=total)           # 结果写进 total，不新建数组
print("第一次写入:", total)

np.multiply(total, 2.0, out=total)   # 复用同一块内存：total = total * 2

    什么时候值得用 out：

    场景 是否建议用 out

    循环里累加到一个缓冲区（如 total += col） 建议 ✓
    一行代码、小数组 不必，可读性更重要
    结果需要保留原始输入时 不能用 ⚠ 会覆盖输入

    out 会覆盖原数据，而且 dtype 必须对得上

    np.multiply(a, 2, out=a) 是合法的，它会把 a 自己改掉。 如果你后面还要用原来的 a，就等着出 bug ✗

    另外，out 的 dtype 必须能容纳结果。把浮点数写进整数数组时， NumPy 默认会直接报错拦住你（这是好事）； 但如果图省事写了 casting="unsafe"，结果就会被静默截断 详见本页第九节的陷阱 3。

    三、广播的三条规则（重点）¶

    3.1 广播要解决什么问题¶

    (3, 4) 的数组要「每一行都加上同一个长度为 4 的向量」， 最笨的办法是手工把那个向量堆成 (3, 4)。广播（broadcasting） 让你不写这一步：NumPy 在计算时自动让形状兼容。

    但兼容是有规则的，规则只有三条。

    3.2 三条规则¶

        两个形状位数不同时，短的那个在左边补 1

        · 两边相等          → 直接对上
        · 其中一个是 1      → 把 1 「撑」成对方的大小

规则 3：不满足规则 2 的那一对维度 → 直接报错 ValueError
        （NumPy 不会猜你的意图）

    5.3 axis 与 keepdims 速查¶

    调用 结果形状 含义
    m.sum() 标量 全部元素之和
    m.sum(axis=0) (4,) 每一列求和（把行压掉）
    m.sum(axis=1) (3,) 每一行求和（把列压掉）
    m.sum(axis=0, keepdims=True) (1, 4) 每一列求和，形状仍是二维
    m.sum(axis=1, keepdims=True) (3, 1) 每一行求和，形状仍是二维

    axis 到底压掉哪一维（一句话记住）

    axis=k 表示「把第 k 维压掉」。

    数据 形状 axis=0 压掉的是 剩下
    一个班的成绩表 (学生数, 课程数) 学生维 每门课的统计 (课程数,)
    同上 同上 axis=1 压掉课程维 每个学生的统计 (学生数,)

    配上 keepdims=True，被压掉的维度会变成 1，位置不变 —— 于是「一维的结果」能正确地对齐回原数组

    情况 表现 建议

    九、易错点汇总¶

    陷阱 1：形状不匹配的报错怎么读

    报错长这样：

    1
    ValueError: operands could not be broadcast together with shapes (3,4) (3,)

    三步读法：

    步骤 做什么
    ① 找出括号里的两个形状，看位数是否相同（不同就先给短的左边补 1）
    ② 从右往左逐个比：相等或有一个是 1 就通过
    ③ 第一个不通过的维度就是原因；改形状（加 np.newaxis 或 reshape）而不是乱改代码

    最常见的原因是该用 (n, 1) 却写了 (n,)。

    陷阱 2：以为广播「复制了数据」

    说法 对不对
    「广播会把小数组复制成大数组再运算」 不对 ✗ 它用的是步长为 0 的视图
    「广播之后产生的那个结果数组不占内存」 也不对 ✗ 结果一定要分配内存
    「np.broadcast_to 得到的是只读视图，不复制」 对 ✓

    验证办法：看 .strides（出现 0 就是复用）和 .flags.writeable（视图是只读）。

    陷阱 3：忘记 keepdims，或忘记检查 dtype

    忘记 keepdims：聚合后维度少了一个，运气不好形状碰巧能广播， 结果算错却不报错 ⚠ 建议：只要聚合结果还要和原数组做运算， 就写 keepdims=True

    忘记检查 dtype：把浮点结果写进整数 out 时， NumPy 默认会拦下来报错；一旦你图省事写了 casting="unsafe"， 它就静默截断：

    import numpy as np

price = np.array([10.0, 20.0, 30.0, 40.0])            # (4,)
units = np.array([[2.0, 1.0, 0.0, 3.0],
                  [0.0, 5.0, 2.0, 1.0],
                  [4.0, 0.0, 1.0, 1.0]])               # (3, 4)

revenue = units * price          # (3, 4) 与 (4,) 广播 → 每列乘一个单价
print("销售额矩阵:\n", revenue.round(2))

daily = revenue.sum(axis=1)      # 每天汇总
item = revenue.sum(axis=0)       # 每件商品汇总
print("每天总销售额:", daily.round(2))
print("每件商品周销售额:", item.round(2))
print("总销售额:", revenue.sum().round(2))

weight = np.array([1.0, 1.0, 0.5]).reshape(3, 1)      # 每天一个权重
print("加权后总销售额:", (revenue * weight).sum().round(2))

    表达式 形状 含义
    units * price (3, 4) 每个「天 × 商品」的销售额
    revenue.sum(axis=1) (3,) 压掉商品维 → 每天合计
    revenue.sum(axis=0) (4,) 压掉天维 → 每件商品合计
    revenue * weight (3, 4) 每天的音入乘上当天权重

    要点：先用广播把「单价 × 数量」展开成矩阵， 再用 axis 选择汇总口径 —— 这是数据分析里最常见的两步组合

    小结¶

    要记住的 为什么
    向量化 = 把循环下推到 C 层 少了解释器往返，还能吃到 SIMD 与缓存的好处
    广播三条规则 从右对齐；相等或为 1 可广播；否则报错
    (n,) 是行、(n, 1) 是列 参与多维运算时方向完全不同，这是最常见的 bug
    聚合后还要和原数组运算 → keepdims=True 否则维度少一个，轻则报错、重则方向错
    axis=k 表示压掉第 k 维 配上 keepdims 就知道结果的形状
    广播不复制，结果数组才占内存 看 .strides 里的 0 与 .flags.writeable
    np.broadcast_to 得到只读视图 需要「假装很大」但不占内存时用它
    out= 省内存，where= 跳过无效位置 但 out 会覆盖输入，dtype 不匹配会静默截断
    np.max 与 np.maximum 不是一回事 一个整体求最大，一个逐元素取较大者
    需要 break、状态依赖、逻辑复杂时用循环 向量化不是目的，可读与正确才是
    形状报错的三步读法 看两个形状 → 从右往左比 → 第一个不通过的维度就是原因 ✓
