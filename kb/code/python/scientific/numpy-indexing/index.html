    02 索引与切片¶

    这一页解决一个问题：从一大块数据里，把真正要用的那一小部分取出来 —— 并且知道取出来的东西是不是原件本身。

    上一页把「一堆数」变成了一个能整体运算的对象。可是真实的数据分析里， 几乎没有一个操作是「对这一整块数据做点什么」。 你总是要挑出某一行、某一列、满足某个条件的那几条记录、 第 3 名到第 10 名之间的样本。这些动作全靠索引与切片。

    索引看起来简单——不就是方括号里写个数吗？难点不在语法，在两个后果：

    你可能没想到的后果 具体表现
    取出来的是视图还是副本 改一下「取出来的东西」，原数组悄悄跟着变了，或者你以为该变却没变
    各种索引方式混用时的形状 a[:, 1] 得到的不是一列，而是一个一维数组

    这两条加起来，构成了 NumPy 里最难查的一类 bug：不报错、结果却错。

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    切片 a[1:3] 与 花式索引 a[[1, 2]] 前者是视图，后者是副本 改了不生效，或者不该生效的地方生效了
    布尔索引与多条件 必须用 &，不能用 and；且每个条件必须加括号 报错，或悄悄算出完全错误的结果
    a[:, 1] 与 a[:, 1:2] 前者是一维，后者是二维 形状不匹配，或广播出意料之外的矩阵

    这三条都能靠两个动作当场查出来： 打印 shape，以及 打印 np.shares_memory(x, y)。 本页会把这两个自查手段用在每一个知识点上

    一、为什么需要索引与切片¶

    先看「不做索引」会怎样。假设手头有一个班的成绩表， 要回答下面几个问题：

    问题 需要的动作 用到的索引方式
    第 3 名学生的数学成绩是多少 取出一个位置的值 基本索引 a[2, 1]
    前 10 名学生的全部成绩 取出连续一段 切片 a[:10]
    所有高于 90 分的成绩 按条件取 布尔索引 a[a > 90]
    第 1、5、9 名的成绩 取出不连续的几个位置 花式索引 a[[0, 4, 8]]
    把负分（录错了）全改成 0 按条件改 布尔掩码赋值 a[a < 0] = 0

    这五种动作覆盖了实际项目里九成以上的数据提取需求， 它们是本页的主线。写法上它们都只用方括号，但行为差别很大：

    写法 结果形状 视图还是副本
    a[2, 1] 标量 取出的是值本身
    a[2] 一维 视图
    a[1:3] 与索引维度一致 视图 ⚠
    a[a > 90] 一维（长度未知） 副本 ⚠
    a[[0, 4, 8]] 与索引数组形状一致 副本 ⚠

    「视图还是副本」这一列就是本页的重点，因为它决定了 「我改了它，原数据会不会变」—— 这个问题在真实代码里经常是致命的。

    import numpy as np

scores = np.array([88, 92, 79, 95, 60, 73, 85, 91])

# 不用索引：手工写循环逐个判断
manual = []
for s in scores:
    if s >= 85:
        manual.append(s)
print("手工循环筛出:", manual)

# 用布尔索引：一行，且不需要 for
auto = scores[scores >= 85]
print("布尔索引筛出:", auto)
print("两者相同吗  :", np.array_equal(np.array(manual), auto))

    手工循环筛出: [88, 92, 95, 85, 91]
布尔索引筛出: [88 92 95 85 91]
两者相同吗  : True

    这一段的意义不在「少写几行」，而在于： 写得越短，能出错的地方越少，而且一旦数据量涨到百万级， 手工循环的写法会从「慢」变成「跑不动」。

a[1][2]         = 60  类型: int32

    两种写法结果一样，但过程差一步：

    写法 实际发生了什么 中间对象
    a[1, 2] 一次索引：直接定位到第 1 行第 2 列 无 ✓
    a[1][2] 两次索引：先取出第 1 行（造一个视图对象），再从这个视图里取第 2 个 多一个视图对象 ⚠

    为什么 a[i, j] 更高效：

    1
2
3
    a[1, 2]    一次方括号 → NumPy 在 C 层算一次偏移量 → 直接拿到元素
a[1][2]    两次方括号 → 第一次造一个「第 1 行」的视图对象（有形状、步长等元信息），
                       第二次再对这个视图做一次索引 → 拿到元素

    差别在于「多造了一个对象」： 每多一次方括号，就多一层 Python 函数调用、多一次边界检查、 多构造一个数组对象（哪怕只是个视图）。数据量大、循环里反复取值时， 这个开销会累积起来。

    把 a[i, j] 当默认写法，a[i][j] 当特例

    判断依据：

    情况 写法
    只是想取某个位置的值 a[i, j] ✓ 一次索引，最快
    确实需要「第 i 行」这个中间结果 (比如还要继续用它算别的) row = a[i] 先存下来，别写 a[i][j]
    一维数组 a[i]，这里没有第二种写法

    a[i][j] 唯一合理的用法是「我就是要那整行」—— 这时应当显式写成 row = a[i]，让别人一眼看出你是有意取整行的， 而不是无意中多索引了一次

    还有一个容易忽略的点：a[i][j] 能写成 a[i, j]， 但切片时不能随便拆。例如 a[:, 1] 不能写成 a[:][1] —— 后面会看到这两者的结果完全不同。

    五、视图与副本的完整规则（重点）¶

    5.1 速查表¶

    把这张表记住，能省掉大量排查时间：

    索引方式 例子 返回 改它会不会影响原数组
    基本索引（数字） a[2] 标量 不适用（要写 a[2] = ... 才改原数组）
    切片 a[1:5]、a[::2]、a[::-1] 视图 会 ⚠
    多维切片 a[:, 1:2] 视图 会 ⚠
    reshape / ravel / .T a.reshape(2, 3) 视图（能的话） 会 ⚠
    花式索引（整数数组） a[[0, 2, 4]] 副本 不会 ✓
    布尔索引 a[a > 0] 副本 不会 ✓
    np.take / np.compress np.take(a, [0, 2]) 副本 不会 ✓
    np.where(cond, x, y) 三参数形式 新数组 不会 ✓
    a.copy() —— 副本 不会 ✓

    怎么记这两组：「按位置规则取」是视图，「按内容挑」是副本。

    大类 判断依据 为什么
    视图 取出来的元素在原数组里位置规则、能用步长描述 只要「起点 + 步长」就能表达，不用复制 ✓
    副本 取出来的元素位置不规则（跳着挑、按条件挑） 步长描述不了，只能把值抄出来 ⚠

    区分「读」和「写」：x[mask] 是副本，x[mask] = v 是原地写

    同一个方括号，出现在等号左边和右边时含义完全不同：

    写法 语义 会不会改原数组
    y = x[mask] 读出满足条件的元素 不会（y 是副本）✓
    x[mask] = v 把符合条件的元素改成 v 会，改的就是原数组 ✓
    x[mask][:] = v 先读出副本，再改副本 不会，且是典型 bug ⚠
    y = x[mask]; y[:] = v 同上，改的是副本 不会，写法看着还更「认真」⚠

    口诀：「要改原数组，方括号必须在等号左边，并且只写一次。」

    ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()

    为什么报错：Python 的 and / or 要求参与运算的对象能整体判真假 （也就是能给出「这一个条件是 True 还是 False」）。 可 a > 0 是一个数组，里面有真有假， Python 没法替你决定「这算真还是算假」，于是直接报错

    这个报错其实是在保护你：如果它随便挑一个「反正非空就算真」， 你得到的就是完全错误但看起来正常的结果

    你想表达 NumPy 写法 Python 里的写法 用 and / or 会怎样

    为什么是这三个符号：它们本来是「按位与 / 按位或 / 按位非」， 但用在布尔数组上时，逐元素的运算结果和「且 / 或 / 非」完全一致 所以 NumPy 就直接借用了它们。

    还有一条容易忘的：每个条件都必须是数组比较。 a[(a > 0) & 25] 这种写法是错的 —— 25 不是布尔数组，& 会按整数位运算来算，结果无法预测

    d[[4, 0]] = [400, 999] 是这一节的要点： 赋值的顺序严格按索引数组的顺序，不做任何排序 —— 第 4 个位置拿 400，第 0 个位置拿 999 这一点和「先取出来、改完再写回去」的直觉不同，值得记住。

    长这样的一行是错的（重复下标在赋值里的行为和你以为的不一样）：

    1
    a[[1, 1]] = [10, 20]     最终 a[1] 是 10 —— 按顺序逐个写，后写的被覆盖 ⚠

    判断依据：赋值时别让同一个位置出现两次。 真需要「累加」这类语义，要用 np.add.at(a, idx, v)， 它会把重复位置的贡献累加起来，而不是互相覆盖

    「链式索引」在 NumPy 里基本都不可写 —— 一次索引到底

    什么是链式索引：连续写两次方括号，中间那次的结果是临时值。

    链式写法 结果 为什么
    a[1:3][0] = 9 生效 ✓ 切片是视图，视图的视图还是视图
    a[[0, 1]][0] = 9 不生效 ⚠ 花式索引给的是副本
    a[a > 3][0] = 9 不生效 ⚠ 布尔索引给的是副本
    a[mask][mask2] = 9 不生效 ⚠ 同上

    注意第一行：切片链恰好能生效 —— 正是这种「有时能」让人掉以轻心 ⚠

    统一的安全写法：

    1
2
3
4
    ✗  a[[0, 1]][0] = 9          链式，花式索引
✓  a[0] = 9                  直接写下标
✓  a[np.array([0, 1])[0]] = 9  把下标先算出来，再一次索引
✓  idx = [0, 1]; a[idx[0]] = 9  同上，可读性更好

    判断口诀：「方括号出现两次、中间没有赋值号，就要怀疑了。」

    真要两次取值，那就先把下标算出来，再一次索引到底：

    1
2
    idx = np.nonzero(a > 3)[0]      # 先算出下标数组
a[idx[0]] = 9                    # 再一次索引 → 原地写 ✓

    这样写既正确，又把「我在算什么」表达得很清楚

    1
2
3

    视图要能用「一小段元信息」描述整块取出来的数据，需要：
  起点偏移 + 形状 + 每维的步长

所以视图能表达的取法，只有「等间距」的那一类：
  切片 a[1:4]    起点=1，步长=1    ✓ 能表达

    小结¶

    要记住的 为什么
    a[i, j] 比 a[i][j] 高效 前者一次索引，后者要造一个中间视图对象
    切片是视图 改切片会影响原数组，这是无数 bug 的来源 ⚠
    花式索引、布尔索引是副本 改它们不影响原数组，「改了不生效」通常就是这个 ⚠
    方括号只能出现一次（在等号左边） x[mask] = v 生效，x[mask][:] = v 不生效 ⚠
    判断视图只信 np.shares_memory base 会对外层视图给出误导性的 False ⚠
    切片越界不报错，索引越界报 IndexError 切片会「夹」到合法范围，所以空结果是合法结果
    数字消维，切片保维 a[:, 1] 是 (3,)，a[:, 1:2] 才是 (3, 1) ⚠
    布尔索引结果永远是一维 行结构会丢，想保留就用 mask.any(axis=1) ✓
    多条件用 & / \| / ~，不能用 and / or 用后者要么报 ValueError，要么静默算错 ⚠
    每个条件必须加括号 不加会因优先级静默全选，且不报错 ⚠
    np.where 看参数个数分辨用法 三个参数选值，一个参数返位置元组（记得取 [0]）⚠
    np.select 条件要从最严到最松 先匹配上的赢，顺序错了结果就错 ⚠
    np.select 一定要给 default 不给会让整个结果被提升成字符串 ⚠
    带 arg 的返回下标，不带 arg 的返回值 argmax / argsort 是找位置与跟着排序的工具 ✓
    a.sort() 原地且返回 None 别写 a = a.sort()，会把 a 变成 None ⚠
    元组索引是基本索引，列表索引是花式索引 a[(0, 1)] 取一个元素，a[[0, 1]] 取两行 ⚠
    两个自查动作 print(x.shape) 与 print(np.shares_memory(x, y)) ✓
