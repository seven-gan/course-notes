    08 分组聚合与合并¶

    这一页解决两个问题：把一堆行「按某个键压成几行」（分组聚合）， 以及把几张表「按某个键接成一张表」（合并）。

    这两件事听起来不相干，其实是同一件事的两面： 分组是纵向压缩（多行变一行），合并是横向拼接（多列并过来）。 真实的数据分析几乎每一步都在做这两件事之一—— 算各班平均分是分组，把班级均分接回每个人是「分组 + 合并」。

    为什么这两件事值得单独一页：

    不做分组的后果 不做合并的后果
    只能算全体的均值，回答不了「哪一组更好」 信息散在几张表里，手工复制粘贴必然出错
    想看三个班的情况，就写三遍筛选 想补一个「大区」字段，就得用 VLOOKUP 或循环
    换一个分组维度（性别、月份）就得重写 改一次键名，两边的表就不再对齐 ⚠

    学完这一页，你将能够：

    能力 具体表现
    说清三阶段 能画出「拆分 → 应用 → 合并」的图，并指出每一步在做什么
    选对工具 知道什么时候用 agg、什么时候必须用 transform
    处理多级索引 看到多级列索引不慌，知道怎么取一列、怎么压平
    判断合并类型 看到两张表能预判合并后该有几行，并用 shape 验证
    避开行数陷阱 知道 merge 后行数变多的原因，并能查出是哪一行膨胀了
    分辨三种计数 分得清 value_counts、size、count 在缺失值上的差别

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    agg 与 transform 前者压缩成每组一行，后者广播回每行一行 想把组均值加回明细表时用了 agg，长度对不上，赋值全变 NaN
    count 与 size count 不数缺失值，size 数全部行 两个「人数」差一个，报表里没人看得出来 ⚠
    「一对多」合并 右表同一个键有多行，左表每行都会被复制多份 金额合计凭空翻倍，而且不报任何错 ⚠

    这三条本页都有实测代码，不用背，看一眼输出就明白

    本页需要的库：NumPy 与 pandas。 版本不必与示例一致，这里讲的行为在这个量级的版本上是稳定的。

    记住这张图的三个要点：

    阶段 关键动作 决定了什么
    ① 拆分 按一个或多个列的值把行分组 分组键选错，后面全错
    ② 应用 每组独立算一遍 用什么函数（mean / agg / transform / apply）决定结果形状
    ③ 合并 把每组结果摞起来 结果是「每组一行」还是「跟原来一样多行」，在这里定死

    SQL：
    SELECT 班级, AVG(语文) AS 语文均分
    FROM   成绩表
    GROUP BY 班级
    ORDER BY 班级;

pandas：
    df.groupby("班级")["语文"].mean()

对应关系：
    GROUP BY 班级          ←→  groupby("班级")
    AVG(语文)              ←→  ["语文"].mean()
    SELECT 班级            ←→  分组键自动成为结果的索引（或 as_index=False 变回列）
    ORDER BY 班级          ←→  groupby 默认 sort=True（结果按分组键排序）
    没有 GROUP BY 只有聚合 ←→  df["语文"].mean()（全体一个数）

    一句话对照：SQL 里「不写 GROUP BY 就只能得到全体一个数」， 在 pandas 里就是「不写 groupby 就只能得到全体一个数」。 你已经会的 SQL 直觉，可以整块搬过来。

    但有一个关键差别必须先说清：

    SQL pandas
    结果里能不能保留明细行 一般不能（除非用窗口函数） 能（用 transform，见第四节）
    分组键在结果里的位置 是一列 默认变成索引（不是列）⚠
    分组能做多复杂的事 受 SQL 表达能力限制 任意 Python 函数都能塞进去

def range_ratio(s):
    """极差除以中位数：衡量「组内差异相对于组内水平」的大小。"""
    mid = s.median()
    if mid == 0 or pd.isna(mid):
        return float("nan")
    return round((s.max() - s.min()) / mid, 3)

    六、apply：最灵活，也最慢¶

    apply 是「兜底工具」。 当 agg、transform、filter 都不够用时， 它能做几乎任何事——因为它把整张子表交给你的函数， 返回值是什么形状都由你决定。

    方法 你的函数收到 你的函数返回 结果形状

    要看的是倍数量级：apply 通常比内置方法慢一个数量级以上， 而返回 DataFrame / Series 的 apply 又要再慢一个数量级。

    判断口诀： 能用 agg / transform / filter 表达的，永远不要用 apply。

    apply 的另一个坑：分组列被「摸到」。

    新版 pandas 会对 apply 里能看到的列发出警告： 它认为你不应该在函数里读到分组列（因为下一版会把它去掉）。 所以更稳的写法是先选好要参与计算的列，再 apply：

    写法 状态
    df.groupby(k).apply(f) ⚠ 函数里能读到分组列，行为将来会变
    df.groupby(k, group_keys=False)[["a","b"]].apply(f) ✓ 明确选中参与计算的列
    df.groupby(k, include_groups=False).apply(f) ✓ 显式说明「分组列不参与」

    group_keys=False 解决另一个很烦的问题： 默认情况下 apply 会把分组键塞回索引里， 结果就变成一个多级索引的表。加上 group_keys=False， 结果的索引保持原样，看起来就像是「给原表做了个操作」

    apply 的正确使用清单：

    该用 不该用
    每组取前 N 行 / 后 N 行 求均值、求和（用 agg）
    每组拟合模型、做回归 广播组统计量（用 transform）
    每组按自定义规则算多个指标并组装成一行 整组留删（用 filter）
    每组返回形状完全不同（有的 1 行有的 5 行） 求组内排名（用 .rank()）

    最后一句总结： apply 是「能做一切」的那把瑞士军刀，但拧螺丝时请用螺丝刀。

    四种写法的含义与选择依据：

    how 中文常叫 保留哪些行 本例行数 什么时候用
    "inner" 内连接 两边都有的键 4 只要匹配成功的完整记录
    "left" 左连接 左表全部 5 给主表补充信息，不许丢行 ✓ 最常用
    "right" 右连接 右表全部 5 少见，通常交换左右表用 left 代替
    "outer" 外连接 两边全部 6 做「两边对照」，专门找不匹配的记录

    怎么读这四个行数（这是本节的第一个核心推论）：

    1
2
3
4
    left  5 行 = 左表 5 行（一行不落）✓   ← 因此「补信息」都用 left
inner 4 行 = 4 笔订单的城市能在右表查到（广州那条被丢了）
right 5 行 = inner 4 行 + 深圳 1 行（右表有、左表没有的键）
outer 6 行 = left 5 行 + 深圳 1 行 = 左表全部 + 右表全部 − 重复的键

    关键关系的记忆法：

    关系 恒成立吗
    inner 行数 ≤ left 行数 ✓（inner 就是 left 里匹配上的那部分）
    left 行数 ≤ outer 行数 ✓
    right 行数 ≤ outer 行数 ✓
    left 行数 == 左表行数 只有右表键唯一时才成立 ⚠

    最后一行是下一小节的伏笔：本例成立，是因为城市表里 每个城市只出现一次。如果右表同一个键有多行，left 的行数会超过左表

    「left 连接不会丢行」不等于「行数不变」

    说法 对不对
    left 保留了左表所有行 ✓ 对（左表每一行都能在结果里找到）
    left 结果的行数等于左表行数 ✗ 错，右表键不唯一时会变多 ⚠

    9.4 合并后行数变化：一对一 vs 一对多¶

    现在讲本页最重要的警报：merge 之后行数可能变多。

    关系 右表键 左表 1 行匹配到 结果行数 俗称

    遇到需求时，从这张表查，比回忆 API 快得多：

    你的需求 用 为什么
    每组一个数（均值、和、个数） groupby().mean() / .agg() 结果就是每组一行 ✓

    把组统计量贴回每一行 transform 长度与原表一致 ✓

    整组留或整组删 filter 只有它是组级布尔判断 ✓
    每组取前 N 行、拟合模型 apply 只有它能返回不同形状 ✓
    两列组合的频次表 crosstab 一行得到列联表 ✓
    二维的任意聚合 pivot_table 有 aggfunc / margins ✓
    已汇总的数据重排成宽表 pivot 不做聚合，最快 ✓
    给主表补充字段 merge(how="left") 不丢主表的行 ✓
    多张同结构的表堆起来 concat(axis=0, ignore_index=True) 直接拼，不做匹配 ✓

    小结¶

    要记住的 为什么
    groupby = 拆分 → 应用 → 合并 三个阶段分清了，后面所有 API 都能自己推出来 ✓
    等价于 SQL 的 GROUP BY 会 SQL 就能整块搬直觉
    结果默认要把分组键变成索引 这不是 bug，是设计；下游要用就 reset_index() 或 as_index=False ⚠
    默认 sort=True 按字符编码排 所以 三班 会排在 二班 前面，看起来像结果错了
    agg 压缩成每组一行，transform 广播成等长 两者差几个字母，但用错会静默得到整列 NaN ⚠
    count 不数缺失，size 数全部行 两个「人数」差一个，报表里没人看得出来 ⚠
    filter 的作用单位是组，不是行 它要么整组留、要么整组删；函数必须返回布尔值 ✓
    apply 最灵活也最慢 能用 agg/transform/filter 表达的就别用 apply ✓
    命名聚合适合出报表 列名你说了算、没有多级列索引、能对同一列算多次 ✓
    多级列索引取值要给元组键 t[("数学","max")]，写成 t["数学"] 会拿到一块表 ⚠
    结果离开 pandas 前先压平列名 否则 CSV 的列名是一堆括号逗号 ⚠
    crosstab 管频次与占比，pivot_table 管任意聚合 normalize 决定谁加起来等于 1
    pivot 不做聚合，重复组合会报错 明细数据一律用 pivot_table ✓
    merge 的 how 决定保留哪些行 补信息用 left；找缺口用 outer + indicator ✓
    merge 后行数可能膨胀（一对多） 金额合计会凭空翻倍，而且完全没有报错 ⚠
    合并后第一件事：打印 shape 并对比 这是唯一能当场发现膨胀的手段 ✓
    validate="one_to_one" 把静默错误变成报错 觉得键该唯一就加上它 ✓
    键不匹配会产生 NaN 用 indicator=True 查 left_only，再查空格/类型/大小写
    纵向堆叠用 ignore_index=True 否则索引重复，loc[0] 会返回多行 ⚠
    横向拼接是按索引对齐的 索引对不上就整块变 NaN，先 reset_index(drop=True) ✓
    NaN 在比较里永远是 False 缺考的人会被算进「不高于」，统计前先 dropna ⚠
    加一致性检查是流程的一部分 行数、合计、非空个数各打一行，十秒钟挡住最贵的错误 ✓
