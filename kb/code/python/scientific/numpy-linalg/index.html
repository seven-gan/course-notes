    04 线性代数与随机数¶

    这一页解决两个问题：把「矩阵运算」写成一行代码，以及把「随机」变成可复现的实验。

    上一页讲了广播与向量化：a + b、a * 2、a > 0 都是逐元素运算， 数组形状对了就一路顺畅。可是线性代数里真正的主角是矩阵乘法， 它不是逐元素的。a * b 与 a @ b 长得只差一个符号， 算出来的东西却完全不同；而 NumPy 对前者不会报错， 只会安静地把一个错误答案交给你。这是本页要拆的第一颗地雷。

    第二个问题是随机数。做数据分析、做仿真、做蒙特卡洛估计， 都要先「造一批随机数」。可随机数一旦不可复现，结论就没法被别人验证， 甚至没法被明天的自己验证。NumPy 给出的现代做法是 生成器对象 + 固定种子，本页会把「种子到可复现」这条链子完整走一遍。

    学完这一页，你将能够：

    能力 具体表现
    分清两种乘法 看到 * 与 @ 立刻知道是逐元素还是矩阵乘法
    选对乘法函数 在 dot / matmul / inner / outer 之间按输入维度做判断
    解方程组 唯一解用 solve，无解用 lstsq，无穷多解用 pinv
    做矩阵分解 会调用特征值、奇异值、QR、Cholesky，并知道各自的适用前提
    造随机数 用 default_rng 固定种子，让结果在任何时候都重现
    验证数值结果 用 np.allclose 而不是 == 判断两个浮点数组是否相等

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    a * b 与 a @ b 前者逐元素，后者矩阵乘法 形状可能一样，数值全错且不报错
    np.linalg.solve(A, b) 与 np.linalg.inv(A) @ b 前者直接解方程，后者先求逆再乘 病态矩阵下残差差出好几个数量级
    eig 与 eigh 前者通用，后者只接受对称矩阵 eig 不保证排序，也不保证正负号

    这三件事的共同点是：写错了不会立刻报错，只会在结果里悄悄出错。 本页每一项都配了能当场跑出差别的例子 ✓

    逐元素相乘（*）：对应位置的数各自相乘
   [a11 a12]   [b11 b12]   [a11*b11  a12*b12]
   [a21 a22] * [b21 b22] = [a21*b21  a22*b22]
                                   ↑ 位置对位置，互不干扰

矩阵乘法（@）：行与列做内积再求和
   [a11 a12]   [b11 b12]   [a11*b11+a12*b21  a11*b12+a12*b22]
   [a21 a22] @ [b21 b22] = [a21*b11+a22*b21  a21*b12+a22*b22]
                                   ↑ 整行乘整列，然后加起来

    一句话记住：* 看「位置」，@ 看「行列」。

    最高频的错误：把矩阵乘法写成了 *

    在做线性代数时（解方程、坐标变换、神经网络前向传播）， 你要的几乎永远是 @。 写成 * 会有两个结局：形状恰好兼容时静默给出错误答案； 形状不兼容时报 ValueError——后者反而是幸运的， 因为它逼你立刻发现问题。

    判断方法：如果这段代码的数学含义是「线性变换」「解方程」「加权求和」， 那它一定是 @。

    这就是「求平方和」时最常见的翻车现场： 想算 1² + 2² + 3²，顺手写了 v * v， 拿到的是一个长度为 3 的数组 [1 4 9]， 然后把这个数组当成「总能量」继续往下传，错误一路扩散。

    要算平方和，正确的写法有两种：

    目标 写法 结果
    每个元素各自平方 v * v 或 v ** 2 数组，长度不变
    平方之后求和 v @ v 或 np.dot(v, v) 或 (v ** 2).sum() 一个标量

    二、四个乘法函数：dot / matmul / inner / outer¶

    @ 是运算符，它背后对应的是 np.matmul。 NumPy 里做「乘法」的函数不止一个，它们在一维和二维输入下行为不同， 这是查文档时最容易看晕的地方。先给出总表：

    函数 一维 × 一维 二维 × 二维 一句话定位
    np.dot(a, b) 内积，返回标量 矩阵乘法 老牌通用函数，二维时等同 @
    np.matmul(a, b) 内积，返回标量 矩阵乘法 @ 运算符的真身，禁止标量参与
    np.inner(a, b) 内积，返回标量 a @ b.T 沿「最后一个轴」配对相乘再求和
    np.outer(a, b) 外积，返回二维矩阵 先展平，再算外积 只做「全部拆开两两相乘」

    二维那一行的差别是关键：dot 与 matmul 算的是矩阵乘法， 而 inner 算的是「先转置再乘」，得到的是完全不同的矩阵。

    import numpy as np

m = np.array([[1, 2], [3, 4]])

print("m @ m（矩阵乘法）：")

m @ m 与 np.inner(m, m) 相同? False

    结论很明确：做矩阵乘法时只考虑 @（或 np.matmul、np.dot）， 不要用 np.inner。 inner 的用途是「一批向量两两算相似度」这类场景， 不是线性代数里的矩阵乘法。

    np.outer 更是另一类东西：它把两个数组先展平，再让每一对元素相乘， 结果是一个二维矩阵，形状是（左长度，右长度）。

    想做的事 该用哪个 为什么
    矩阵乘法 a @ b 唯一符合线性代数定义、且维度规则清晰
    向量内积 a @ b 一维时 @ 就是内积，无需换函数
    一批向量两两内积 np.inner 它以最后一个轴为配对轴，正好是「两两」
    外积（笛卡尔式两两相乘） np.outer 只有它会展平输入再造二维矩阵

c = np.array([[1 + 2j, 3 - 1j], [1j, 4 + 0j]])

[[1.-2.j 0.-1.j]
 [3.+1.j 4.-0.j]]

实数矩阵的 .T 与 .conj().T 相同? True

    实数矩阵上两者没有区别，所以平时用 .T 就够了。 只有处理信号处理、量子力学那类复数矩阵时，才必须写 .conj().T， 否则你会得到「转置了但没有取共轭」的错误结果。

    3.2 维度规则：(m, n) @ (n, p) → (m, p)¶

    矩阵乘法能成立，只取决于一件事：左边矩阵的列数必须等于右边矩阵的行数。 中间的 n 必须相等，它会被「消掉」，剩下的前后数字就是结果的形状。

    左操作数形状 右操作数形状 能否相乘 结果形状 依据
    (2, 3) (3, 4) 可以 (2, 4) 中间的 3 相等，被消掉
    (2, 3) (2, 2) 不可以 —— 3 与 2 不等，报 ValueError
    (2, 3) (3,) 可以 (2,) 一维向量视为列向量
    (3,) (2, 3) 可以 (2,) 一维向量视为行向量
    (3,) (3,) 可以 标量 退化为内积

    把握住「中间的数字必须相等」这一条，你就能在写代码之前先把形状算出来， 而不是等报错再改。

    做法 何时该用 为什么
    np.linalg.solve(A, b) 默认就应该用这个 一步到位，误差小，速度快
    np.linalg.inv(A) @ b 几乎不该用 多一步求逆，误差被放大
    先算 A_inv = np.linalg.inv(A) 再循环乘多个 b 只在 A 良态且 b 很多时 省下重复分解，但要先确认 cond(A) 不大

    import numpy as np


def normalize_sign(vectors):
    """把每一列特征向量统一为「首个非零分量为正」。"""
    vectors = np.array(vectors, dtype=float, copy=True)
    for k in range(vectors.shape[1]):
        column = vectors[:, k]
        nonzero = np.flatnonzero(np.abs(column) > 1e-9)
        if nonzero.size and column[nonzero[0]] < 0:
            vectors[:, k] = -column
    return vectors

def normalize_sign(vectors):
    """每列统一为「首个非零分量为正」。"""
    vectors = np.array(vectors, dtype=float, copy=True)
    for k in range(vectors.shape[1]):
        column = vectors[:, k]

        if nonzero.size and column[nonzero[0]] < 0:

    return vectors

    Q2 为什么说「不要用 inv(A) @ b 解方程」？ 什么情况下用 inv 反而是合理的？

    提示

    从三方面想：中间多了一步求逆会带来什么误差； 求逆的计算量比直接分解大多少； 以及「需要逆矩阵本身」的场景与「只需要解 x」的场景有什么区别。

    解答

    原因有三条：

    1. 误差更大：求逆是一次完整的数值过程，误差会被放大并乘进结果。 病态矩阵（条件数 10¹⁰ 以上）下，误差可能与 solve 差好几个数量级。
    2. 更慢：解一个方程组的代价与矩阵分解相当， 而 inv 相当于做 n 次求解（每列一次），计算量更大。
    3. 不必要：你真正需要的通常是解 x，而不是逆矩阵。

    用 inv 合理的场景其实很局限：

    场景 是否该用 inv 说明
    只需要解 x 不该 用 solve
    需要逆矩阵本身（如做误差传递、协方差传播） 可以 这是真的需要这个矩阵
    同一个 A、很多个不同的 b 视情况 若 A 良态，可先分解一次重复使用
    A 奇异或非方阵 不该 用 pinv 或 lstsq

    第四行需要特别注意：inv 在奇异矩阵上不报错， 而是给出一个发散的、看似正常的结果，这是它最危险的地方。 遇到非方阵时它才会抛 LinAlgError。

    Q3 eig 与 eigh 有哪些区别？ 特征向量的符号为什么需要专门处理？

    提示

    从适用矩阵类型、速度、数值稳定性、特征值顺序四个方面比较。 符号问题要从特征向量的定义式出发想： 定义式里如果把 v 换成 -v，等式还成立吗？

    解答
    对比项 eig eigh
    适用矩阵 任意方阵 仅实对称 / 复 Hermitian
    速度 慢 快（利用对称性）
    稳定性 一般 好
    特征值顺序 不保证 保证升序
    特征值类型 可能复数 实对称时保证实数

    符号问题的根源：特征向量的定义是 A v = λ v。 把 v 换成 -v，左边变成 -A v，右边变成 -λ v， 等式依然成立。所以 v 与 -v 都是合法的特征向量， 数学上没有哪个「更对」。 但算法实现必须挑一个方向，挑法取决于底层数值库的实现细节， 于是不同机器、不同版本可能给出相反的结果。

    处理方式有两种：

    • 规范化：统一让每列首个非零分量为正（或统一为负）， 这样输出在任何环境下都一致。
    • 只验证关系式：断言 np.allclose(a @ v, v * w)， 不去比较向量本身的具体数值。

    除此之外，顺序也不稳定： eig 的返回顺序不保证，所以比较特征值时应当先 np.sort， 或者干脆用 eigh 拿「升序」这个确定的保证。

    小结¶

    要记住的 为什么
    * 逐元素，@ 矩阵乘法 两者形状可能一样，但数值完全不同，且 * 不会报错
    维度规则 (m, n) @ (n, p) → (m, p) 先在纸上算出形状，比等报错再改快得多
    做矩阵乘法只考虑 @、matmul、dot inner 是「最后一个轴配对」，不是矩阵乘法
    解方程用 solve，不要 inv(A) @ b 少一步求逆，误差小、速度快
    无解用 lstsq，多解用 pinv 两者都返回「最接近或最短」的解，且不会报错
    对称矩阵用 eigh 更快更稳，且特征值保证升序
    特征向量符号不保证，顺序也不保证 不同机器可能相反；只验证 A @ v ≈ λ * v
    svd 的 s 是向量不是矩阵 需要矩阵时用 np.diag(s)
    norm 的 ord 在向量与矩阵上含义不同 矩阵 1 范数看列，inf 看行，'fro' 才是元素平方和开根
    shuffle 原地修改且返回 None 要副本用 permutation
    用 default_rng(42) 固定种子 独立生成器不污染全局，结果可复现
    浮点比较用 np.allclose == 会在末位精度上误判
