    17 实战：回归建模¶

    前面十六页讲的是零件，这一页把它们装成一台机器。

    「拟合一条直线」这件事，任何库都是一行代码。 难的是它后面跟着的一串问题：

    一行拟合之后，必须回答的问题 靠什么回答
    这条直线该不该信 残差诊断
    系数到底是什么意思 量纲与因果的讨论
    两个特征几乎一样时会发生什么 条件数与共线性演示
    换一批没见过的数据，它还准吗 训练/测试划分与指标
    更复杂的模型是不是更好 过拟合的实测证据

    这一页不教新语法，只教判断顺序：先看图，再拟合； 拟合完先看残差，再谈评估；报指标之前先跟基线对比。

    读完之后，你应当能做到：拿到一组带噪声的数据， 走完从「看一眼」到「敢不敢用」的完整流程， 并且每一步都留下别人能复核的数字 ✓

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    「拟合得不错」与「模型有用」 前者说的是残差小，后者说的是比不知道强多少 不做基线对比，你永远不知道模型有没有贡献 ⚠
    「系数大」与「影响大」 系数带单位，量纲一变数字就变 直接凭系数大小给特征排序，常常排错
    「训练误差小」与「模型好」 参数足够多时训练误差可以压到 0 压到 0 往往意味着记住了噪声，换个点就崩 ⚠

    这三条在后面都有实测数字，不用背 ✓

    这页需要的库：NumPy、pandas、SciPy、Matplotlib。 版本不必与示例一致，行为在这个量级的版本上是稳定的。

    能力 具体表现
    造可控数据 用固定种子造出真值已知的数据，让「算得对不对」有确定答案
    先看再算 描述统计、相关系数、散点图，三个角度看同一组数据
    三路拟合 手算闭式解、lstsq、polyfit / linregress，互相印证
    解读系数 说得出斜率与截距的物理含义，并知道它不是因果效应
    读残差图 从「随机散布」与「有模式」的差别里判断模型是否漏了东西
    识别共线性 用条件数解释「系数为什么乱跳」，并知道怎么处理
    评估预测 划分训练/测试，算 \(R^2\)、RMSE、MAE，并跟基线比
    说出局限 讲得出 \(R^2\) 高不等于模型有意义、不同数据的 \(R^2\) 不能直接比
    工程化 说得出正则化、交叉验证、残差清单这些做法在真实项目里怎么用

    一、任务描述¶

    场景：手上有一组测量数据，一个特征 \(x\)、一个观测值 \(y\)， 任务是给出一个可用的预测模型，并回答一句附加的话：这个模型可信吗。

    报告要回答的问题 靠哪几步得到
    \(x\) 和 \(y\) 之间有没有关系、多强 描述统计 + 相关系数 + 散点图
    关系的具体形式（截距、斜率）是什么 三种方法拟合 + 互相印证
    这条直线的系数怎么解释 量纲分析 + 系数解读
    直线有没有漏掉数据的结构 残差分析
    特征之间是否互相干扰 条件数与共线性演示
    换一批数据还准不准 训练/测试划分 + 指标 + 基线对比
    复杂度该选到哪一档 过拟合实测

    为什么第一件事是「说清任务」：因为「模型好不好」没有绝对标准， 判据来自任务。

    任务 合理的判据 为什么
    解释关系（系数说了算） 系数稳定、能给出含义 系数随数据略微抖动没关系，符号和量级必须站得住 ✓
    预测新样本（误差说了算） 测试集 RMSE / MAE 只要预测准，某个系数具体是多少并不重要
    判断「有没有影响」 系数的符号与稳定性 这已经从拟合走到推断了，属于另一类问题 ⚠

    关键区分：本页做的是拟合与评估， 不做「这个斜率显著不为零吗」这类统计推断。 后者要看标准误、置信区间与假设检验， 在本模块的推断页里单独讲 ✓

    回归系数不是因果效应

    拟合出来的斜率先要过三关，才配谈「影响」：

    关卡 问题 不通过时的后果
    有没有漏掉共同原因 存在同时影响 \(x\) 与 \(y\) 的第三变量吗 斜率会把第三变量的一部分效应算到自己头上 ⚠
    方向假设对不对 是 \(x\) 影响 \(y\)，还是反过来 相关系数对称，回归不对称；拟合结果不会自动告诉你方向
    有没有选择偏差 数据是怎么被采集的 只在某个区间取样，会让斜率系统性偏大或偏小

    正确的表述是「\(x\) 每增加一个单位，样本中 \(y\) 平均变化多少」—— 描述你实际算出来的量，而不是断言作用机制 ✓

    二、构造一组「有标准答案」的数据¶

    为什么要自己造数据：真实数据没有标准答案， 你无法判断一次拟合「算对了没有」；而且真实数据每次都不同，输出无法复核。 造一组固定种子、真值已知的模拟数据， 既有噪声带来的真实感，又能保证每次运行完全一样， 还能拿拟合结果去跟真值对账 ✓

"""案例用的模拟数据模块。

make_data()  造一组「真实关系已知」的数据（固定种子，结果可复现）。
design()     给一维特征补上常数列，得到最小二乘用的设计矩阵。
fit_lstsq()  用 np.linalg.lstsq 拟合，返回系数与诊断用的量。
"""
import numpy as np

TRUE_INTERCEPT = 3.0          # 截距真值
TRUE_SLOPE = 2.0              # 斜率真值
NOISE_SD = 1.0                # 噪声标准差
N_SAMPLES = 60                # 样本量


def make_data(n=N_SAMPLES, seed=42):
    """返回 (x, y)：y = 3 + 2x + 噪声，噪声标准差为 1。"""
    rng = np.random.default_rng(seed)          # 固定种子，结果可复现
    x = rng.uniform(0.0, 10.0, n).round(4)
    noise = rng.normal(0.0, NOISE_SD, n)
    y = (TRUE_INTERCEPT + TRUE_SLOPE * x + noise).round(4)
    return x, y


def design(x):
    """把一维 x 变成 [1, x] 两列的设计矩阵（第一列是常数列，对应截距）。"""
    x = np.asarray(x, dtype=float)
    return np.column_stack([np.ones_like(x), x])


def fit_lstsq(x, y):
    """最小二乘拟合，返回 (系数, 残差平方和数组, 秩, 奇异值)。"""
    a = design(x)
    beta, ss_res, rank, singular = np.linalg.lstsq(
        a, np.asarray(y, dtype=float), rcond=None)
    return beta, ss_res, rank, singular


if __name__ == "__main__":
    xs, ys = make_data()
    coef, *_ = fit_lstsq(xs, ys)
    print("样本量        :", xs.size)
    print("真实截距/斜率 :", TRUE_INTERCEPT, TRUE_SLOPE)
    print("拟合截距/斜率 :", coef.round(4).tolist())

    四、拟合：三种方法，一条直线¶

    这一节是本页的重心，因为「最小二乘」四个字背后有一整套矩阵运算， 而绝大多数人只记住了调用哪一行代码。

    最小二乘在做什么：找一组系数 \(\beta\)， 让预测值 \(X\beta\) 与观测值 \(y\) 的残差平方和最小：

    \[\mathrm{RSS}(\beta) = \lVert y - X\beta \rVert^2 = \sum_{i=1}^{n}(y_i - \hat{y}_i)^2\]

    对 \(\beta\) 求导并令其为零，得到正规方程 \(X^{\mathsf T}X\beta = X^{\mathsf T}y\)， 于是闭式解为

    \[\hat{\beta} = (X^{\mathsf T}X)^{-1}X^{\mathsf T}y\]

    4.2 为什么实践中不要求逆¶

    上一节的 np.linalg.inv(xtx) 数学上正确，工程上却很危险。 危险不在公式，在浮点误差的放大倍数。

    5.1 斜率的含义¶

    说法 是否准确 说明
    「\(x\) 每增加 1，\(y\) 就增加 1.9948」 基本准确 补一句「在本样本的取值范围内」更严谨 ✓
    「\(x\) 越大 \(y\) 一定越大」 不准确 模型给的是平均趋势，单个点可以反向 ⚠
    「\(x\) 导致 \(y\) 增加」 不准确 这是因果断言，拟合结果不支持 ⚠
    「在本数据范围内，\(x\) 每增加 1 个单位，\(y\) 平均增加 1.9948」 准确 把范围、平均、单位都说清了 ✓

    现象 原因
    斜率准 斜率由 \(x\) 在整个区间上的变化决定，60 个点全在出力 ✓
    截距不稳 截距是 \(x=0\) 处的取值，而数据里 \(x=0\) 附近只有 2 个点 ⚠
    几何直觉 整条直线可以绕着数据中心微微转动；转一点，斜率变化很小，端点却移动很多 ✓

    这条经验可以推广：截距的可靠程度取决于数据离原点有多远。 本案例数据从 0.07 开始，截距还能估得住； 如果数据从 8 开始，截距就会变成一个纯粹的外推数字 ⚠

    x = 0 处的预测值 2.82 不能当成事实

    因为 x 最小只有 0.0736，x = 0 的预测是外推：

    说法 是否站得住
    「模型在数据范围内认为 \(x=0\) 时 \(y\) 约为 2.82」 站得住 ✓
    「\(x=0\) 时 \(y\) 就是 2.82」 不站得住 —— 那是把外推当观测 ⚠
    「\(x\) 取负数时 \(y\) 是多少」 完全不能答 —— 数据里根本没有负 \(x\) ⚠

    外推的代价随距离迅速上升： 模型里的直线假设在观测区间外没有任何验证， 而真实关系一旦弯曲，外推值就会错得很离谱 ✓

    两个教训：

    教训 具体含义
    系数依赖模型里放了什么 加一个变量、删一个变量，其它系数都可能变 ⚠
    因果结论需要设计，不是算法 随机化、对照组、工具变量这些是研究设计手段，拟合方法给不了 ✓

    六、残差分析：模型有没有漏掉东西¶

    为什么残差是这一页的重头戏： 前面所有的数字（系数、\(R^2\)）都只是摘要， 而摘要一定丢信息。残差是没被摘要吃掉的那部分， 它保留了「模型在哪一段偏高、哪一段偏低」的全部细节。

    残差的定义：残差 = 观测值 − 预测值，即 \(e_i = y_i - \hat{y}_i\)。

    别混 公式 能不能算
    残差 \(e_i\) \(y_i - \hat{y}_i\) 能，直接用观测值与预测值相减 ✓
    误差 \(\varepsilon_i\) \(y_i - (\beta_0 + \beta_1 x_i)\) 不能 —— 真系数未知 ⚠

    残差是误差的「可见替身」：我们永远看不到真误差， 只能用拟合出来的残差去猜误差长什么样。 诊断的全部逻辑就建立在这个替身上 ✓

    七、多重共线性：系数为什么会乱跳¶

    这是本页第二个重点，也是「条件数」这个概念第二次出场。 它的现象很反直觉：模型整体预测挺准，但每个系数都不可信。

    共线性是什么：两个（或多个）特征之间高度相关， 以至于它们在数据里几乎无法区分。

    为什么这会坏事：回归要给每个特征分配一个系数。 如果 \(x_1\) 和 \(x_2\) 几乎相同，那么「把系数给 \(x_1\)」和 「把系数给 \(x_2\)」在拟合误差上几乎没差别 —— 数据里没有任何信息能判出该给谁。 于是优化问题有一整个方向都近似平坦， 浮点误差、随机扰动都会让解在这个方向上滑很远 ⚠

    7.2 用条件数解释「系数不稳」¶

    条件数为什么能预测「系数有多不稳」： 条件数衡量的是「输入的相对扰动会被放大多少倍」。 把它套在正规方程 \(X^{\mathsf T}X\beta = X^{\mathsf T}y\) 上， 就得到系数相对误差的上界：

    \[\frac{\lVert \Delta\beta \rVert}{\lVert \beta \rVert} \;\lesssim\; \kappa(X^{\mathsf T}X)\cdot\frac{\lVert \Delta(X^{\mathsf T}y)\rVert} {\lVert X^{\mathsf T}y \rVert}\]

    读法：右边那个相对扰动再小，也会被 \(\kappa\) 倍放大。 \(\kappa = 10^6\) 意味着输入的第 6 位小数都会污染系数的第 1 位。

    共线性还有一个更直接的度量：方差膨胀因子

    「方差膨胀因子」（VIF）衡量的是「因为共线性， 某个系数的方差被放大了多少倍」。 它的定义出奇简单：把第 \(j\) 个特征当成因变量、 用其它特征去预测它，得到 \(R_j^2\)，则

    \[\mathrm{VIF}_j = \frac{1}{1 - R_j^2}\]

    本案例中 \(x_1\) 与 \(x_2\) 的 \(R^2\) 约为 0.9997578， 于是 \(\mathrm{VIF} \approx 4128.8\) —— 系数方差被放大了四千多倍，与条件数量级一致 ✓

    经验上 \(\mathrm{VIF}\) 超过 10 就该警惕。 它的好处是能定位到具体是哪个特征有问题， 而条件数只告诉你「这个矩阵整体有问题」✓

    共线性不影响预测，只影响解读

    这是最容易被误解的一点，值得单独说清：

    用途 共线性有多大影响
    预测新样本 几乎没有 —— 系数加起来还是那个和，预测值照样准 ✓
    解释单个系数 毁灭性 —— 系数可能变号、变动几十倍 ⚠
    判断「哪个特征更重要」 不可能 —— 数据里根本没有这个信息 ⚠

    所以任务决定了要不要处理共线性： 只想预测、不在乎每个系数含义，可以不管它； 想解释、想报告「\(x_1\) 的影响是多大」，就必须处理 ⚠

    处理手段按代价排序：

    手段 做法 代价
    删特征 留信息更完整的那个 丢掉一个变量的名字（信息没丢）✓
    合并特征 用主成分、或直接相加 新特征失去直观含义 ⚠
    正则化 Ridge 给所有系数加惩罚 系数被压缩，不再是无偏估计 ✓

    8.1 三个指标的公式与含义¶

    指标 公式 单位 读法
    \(R^2\) \(1 - \dfrac{\sum (y_i-\hat{y}_i)^2}{\sum (y_i-\bar{y})^2}\) 无量纲 相对「用均值预测」好多少 ✓
    RMSE \(\sqrt{\dfrac{1}{n}\sum (y_i-\hat{y}_i)^2}\) 同 \(y\) 平均误差量级，对大误差敏感 ✓
    MAE \(\dfrac{1}{n}\sum \lvert y_i-\hat{y}_i \rvert\) 同 \(y\) 平均误差量级，稳健 ✓

    三个指标各自的脾气：

    指标 优点 局限
    \(R^2\) 无量纲，能跨量纲比较 分母是样本方差，换个数据集就不可直接比 ⚠
    RMSE 与 \(y\) 同量纲，好解释 平方后放大异常点的影响 ⚠
    MAE 对异常点稳健 不可导，优化时不如平方方便 ✓

def metrics(y_true, y_pred):
    """返回 (R^2, RMSE, MAE)，三个指标一次算完。"""
    y_true = np.asarray(y_true, dtype=float)
    y_pred = np.asarray(y_pred, dtype=float)
    resid = y_true - y_pred
    ss_res = float((resid ** 2).sum())
    ss_tot = float(((y_true - y_true.mean()) ** 2).sum())
    r2 = 1.0 - ss_res / ss_tot
    rmse = float(np.sqrt((resid ** 2).mean()))
    mae = float(np.abs(resid).mean())
    return r2, rmse, mae

    局限一：\(R^2\) 可以很高，但模型毫无意义

    场景 会发生什么
    两个变量都有强烈的时间趋势 相关系数虚高，\(R^2\) 轻松到 0.95，但关系是「共同随时间上涨」 ⚠
    样本量极小 点少时任何直线都能穿过，\(R^2\) 必然偏高 ⚠
    特征数量逼近样本量 参数足够多就能插值所有点，\(R^2\) 被硬推到接近 1 ⚠

    局限二：不同数据集的 \(R^2\) 不可直接比

    \(R^2\) 的分母是该数据集自己的总平方和。 一批本身波动很小的数据（分母小），\(R^2\) 天然偏低； 一批跨好几个数量级的数据（分母大），\(R^2\) 容易偏高。 所以「\(A\) 模型 \(R^2\) 0.99，\(B\) 模型 0.90，\(A\) 更好」这种比较是错位的 ⚠

    局限三：\(R^2\) 大不代表误差小

    它只说明「相对本数据的波动，模型解释得多」。 如果 \(y\) 的波动本来就巨大，\(R^2\) 到 0.99 时 绝对误差仍可能大到不能接受。 必须同时报一个有量纲的指标（RMSE 或 MAE） ✓

    本案例的正确汇报方式： 「测试集 \(R^2\) 为 0.9838，RMSE 为 0.7083（约 \(y\) 均值的 5.10%）， 相比均值基线的 RMSE 降低 87.45%」—— 三句话分别回答了「解释了多少」「绝对误差多大」「比什么都不做强多少」✓

    9.2 抗过拟合的两件武器¶

    第一件是「选复杂度」：上面两张表都指向 3 次左右。 第二件是「正则化」：不减少参数个数，而是给系数加惩罚。

    Ridge 回归（也叫 L2 正则）最小化的是

    \[\lVert y - X\beta \rVert^2 + \alpha \lVert \beta \rVert^2\]

    多出来的 \(\alpha \lVert \beta \rVert^2\) 会把系数往 0 的方向压， 从而抑制「用巨大系数换一点点训练误差」的行为 ✓

    为什么正则化能治共线性：共线性让某些系数可以取任意大的值 而不影响拟合效果；加了惩罚之后， 「系数很大」本身就有代价，那个平坦方向被填上了 ✓

    Ridge 与 Lasso 的一句话区别

    两者都是「损失 + 惩罚」，区别只在惩罚的形式：

    名称 惩罚项 效果
    Ridge（L2） \(\alpha \sum \beta_j^2\) 系数被整体压缩，很少恰好为 0 ✓
    Lasso（L1） \(\alpha \sum \lvert \beta_j \rvert\) 一部分系数被压成 0，等于自动选特征 ✓

    共线性场景下 Ridge 是更常见的选择： 它把所有相关特征都留在模型里、平摊权重， 而 Lasso 会从一组高度相关的特征里随机挑一个留下、把其余清零—— 挑谁取决于噪声，结果不稳定 ⚠

    本案例 alpha = 10^{-3} 带来的测试误差改善并不惊人 （0.2010 → 0.1689），因为真正的病根是用 7 次多项式去拟合正弦。 正则化能缓解它，换模型才能治好它 ✓

    9 是否优于均值基线 与基线 RMSE 比 模型没有存在价值 ⚠
    10 外推区域是否有数据支撑 预测点是否落在观测范围内 结论超出证据范围 ⚠

    要做的事 具体做法 解决的问题

    数据情况 推荐做法 理由
    样本很多（上万） 单次留出 + 独立测试集 简单，测试误差已经很稳 ✓
    样本中等（几百） 5 折或 10 折交叉验证 每折都不至于太小 ✓
    样本很少（几十） 留一法（LOO）或重复交叉验证 每次尽可能多训练，但计算量上升 ⚠
    有时间顺序 按时间切分，不能随机打乱 打乱等于用未来预测过去，指标虚高 ⚠

    最后一条特别要注意： 本案例用随机置换划分是合理的，因为 60 个样本之间没有顺序关系。 但如果数据是「按天记录的」，随机打乱会让模型看到未来的数据， 测试误差会好看得不像话，上线后立刻崩 ⚠

    思路

    先想三件事：

    1. 分箱均值「两边高、中间低」是什么形状？直线模型能产生这种形状吗？
    2. 相关系数为什么是 0？它是必然为 0 还是碰巧为 0？ （提示：回忆第六节讲的恒等式）

    import numpy as np

def diagnose(x, y, label):

    beta, *_ = np.linalg.lstsq(design(x), y, rcond=None)
    y_hat = design(x) @ beta
    resid = y - y_hat
    bins = [float(resid[i].mean()) for i in
            np.array_split(np.argsort(y_hat), 5)]

        np.corrcoef(resid, y_hat)[0, 1]), 10))

    Q2 「用均值预测」的基线 \(R^2\) 应该是 0。 但实测里它有时是 0.0、有时是 −0.0316。 请说明这两次分别是怎么算的，以及为什么会出现负数。

    提示

    \(R^2\) 的公式是 \(1 - \mathrm{RSS}/\mathrm{TSS}\)， 其中 \(\mathrm{TSS} = \sum (y_i - \bar{y})^2\) 用的是哪个均值？

    基线预测又用的是哪个均值？ 这两个均值如果不同，会发生什么？

    如果两者取同一个均值，\(\mathrm{RSS}\) 与 \(\mathrm{TSS}\) 是什么关系？

    解答

    关键在「\(\bar{y}\) 取自哪里」：

    口径 基线预测值 TSS 用的均值 \(R^2\)
    用测试集自己的均值 \(\bar{y}_{\text{test}}\) \(\bar{y}_{\text{test}}\) 恰好 0.0 ✓

    resid = y_true - np.asarray(y_pred, dtype=float)
    tss = float(((y_true - y_true.mean()) ** 2).sum())

    Q3 一元回归的原始斜率是 1.9948， 把 \(x\) 与 \(y\) 都标准化之后再拟合，斜率变成 0.9912。 请说明这两个数各自是什么含义， 并解释它们之间为什么恰好差一个倍数 —— 这个倍数是什么？

    提示

    「标准化」是把两个变量各自变成「均值为 0、标准差为 1」。 那么标准化之后的斜率，是不是就等于某个早就见过的量？

    再想：原始斜率与标准化斜率之间， 是不是只差「两个变量标准差的比值」？

    如果想让两个特征的系数可以直接比较，应该标准化哪个？

    解答

    两个系数的含义完全不同：

    系数 值 含义
    原始斜率 1.9948 \(x\) 每增加 1 个原单位，\(y\) 平均变化 1.9948 个原单位 ✓
    标准化斜率 0.9912 \(x\) 每增加 1 个标准差，\(y\) 平均变化 0.9912 个标准差 ✓

    标准化斜率恰好等于相关系数 \(r = 0.9912\)，这不是巧合。 因为一元回归里 \(\hat{\beta}_1^{\text{std}} = r\)， 而原始斜率与之的关系是

    \[\hat{\beta}_1 = r \cdot \frac{s_y}{s_x}\]

    差的倍数就是两个标准差的比值 \(s_y / s_x\)：

    量 值
    \(s_x\) 2.8362
    \(s_y\) 5.7077
    \(s_y / s_x\) 2.012426
    原始斜率 / 标准化斜率 2.012426 ✓

    这就是第五节的结论「不能凭系数大小比较特征重要性」的数学根源： 系数等于「相关系数 × 量纲比」，量纲混在里面 ⚠

    小结¶

    这一页走完了一条完整的建模链： 造数据 → 看清数据 → 拟合 → 解读系数 → 诊断残差 → 检查共线性 → 划分验证 → 对比基线 → 防过拟合。

    要记住的 为什么
    先看图，再拟合 拟合不会因为「数据没直线关系」而拒绝你，它照样返回系数 ⚠
    lstsq 优先于 inv 条件数被平方：\(\kappa\) 变成 \(\kappa^2\)（实测 \(1.36\times10^{7}\) 变 \(1.84\times10^{14}\)）⚠
    inv 的解可能连自己的方程都没解对 求逆的残差平方和反而更大（33.8217 对 33.5505）⚠
    polyfit 高次项在前 顺序写反不报错，\(x=5\) 的预测偏了 3.30 ⚠
    四条路径应当一致 手算、lstsq、polyfit、linregress 结果差为 0 ✓
    斜率准、截距飘 截距可靠度取决于数据离原点有多远（本案例 0.26% 对 6.0%）✓
    系数带单位 单位缩小 1000 倍，斜率放大 1000 倍，模型其实没变 ✓
    系数不是因果 漏掉共同原因时，真实 2 的系数被估成 6.5412 ⚠
    残差与拟合值正交是必然 所以相关系数查不出 U 形模式：两组都是 0.0 ⚠
    看残差要分箱 分箱极差 0.7638 对 4.2963，这才是有效判据 ✓
    共线性只毁「可辨识量」 单系数在 −0.68 与 2.67 之间乱跳，两系数之和稳定在 1.9945 ✓
    条件数涨 457 倍是警报 从 161 到 73734，超过 \(10^4\) 就该去看一眼 ⚠
    删特征可验证共线 删掉后 RMSE 完全相同（差为 0），证明两个特征信息重复 ✓
    \(R^2\) 高不等于有用 必须跟均值基线比：RMSE 降低 87.45% 才叫有用 ✓
    \(R^2\) 可以为负 基线用训练集均值时是 −0.0316，因为它比测试集均值差 ✓
    训练误差下降没有意义 多项式从 1 次到 15 次，训练 RMSE 一路降到 0.0528 ⚠
    测试/训练之比是过拟合探针 从 0.68 涨到 115.33，1.0 附近就是分界 ✓
    正则化故意让训练变差 alpha 从 0 到 0.1，训练 RMSE 0.1302 升到 0.3307，测试却先降后升 ✓
    数据少就交叉验证 11 次的各折误差从 0.1638 到 9.4760，单次划分会骗人 ⚠
    外推要有依据 观测区间外的预测：真实 −3.50，直线给 16.45，只用前半段给 29.38 ⚠
    输出只留可核对的量 打印系数、残差统计量、图片里的点数与线条数；不打印路径 ✓

    这十件事可以收成三句话：

    1. 拟合是最后一步，不是第一步 —— 先看清数据的形状。
    2. 模型的证据在残差和留出数据里，不在训练误差里。
    3. 报任何指标之前，先回答「跟什么比」 ✓
