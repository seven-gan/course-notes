    01 NumPy 数组基础¶

    这一页解决一个问题：把「一堆数」变成「一个能整体运算的对象」。

    用 Python 的 list 存 100 万个数据也能存，但一旦要对它们做计算—— 求平均、做归一化、筛出异常值、算相关系数——你就得写循环， 而循环会慢到你怀疑人生。

    NumPy 给出另一种做法：把整堆数当成一个对象，a * 2 就是每个元素乘 2， 不需要写 for。这一页讲清这个对象是什么、怎么造、有哪些属性、 以及最容易在哪里掉坑。

    学完这一页，你将能够：

    能力 具体表现
    造数组 知道该用 array / zeros / arange / linspace 里的哪一个
    看懂形状 看到 (6,) 与 (6, 1) 立刻知道差别在哪
    控制类型 主动指定 dtype，并知道不指定会出什么事
    改变形状 reshape 与 flatten 混用不会搞错视图还是副本
    判断快慢 知道 NumPy 快的三个原因，从而知道什么时候它快不起来

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    arange(0, 1, 0.25) 与 linspace(0, 1, 5) 前者不含终点，后者含终点 采样点少一个，画图时曲线缺一截
    (6,) 与 (1, 6) 与 (6, 1) 是三个不同的形状 形状不匹配导致报错或悄悄算出错结果
    reshape 与 flatten 前者返回视图，后者返回副本 改了一个另一个跟着变，或该变却没变

    这三个坑都能靠「打印形状 + 打印 base」当场查出来， 本页会把这两种自查手段都教给你

    一、为什么需要 NumPy¶

    1.1 用 list 会怎样¶

    先看一个具体场景：给 200 万个数据求平方。

    用 list，你得写推导式或循环，逐个元素处理：

    list 的写法: [0, 1, 4, 9, 16]

    用 NumPy，一行搞定，没有任何 for：

    1.3 为什么快：三个原因¶

    原因 含义 直观理解
    C 实现 循环在编译好的 C 代码里跑，不是解释器逐行执行 你写的是一句，机器跑的是预先编译好的循环
    连续内存 数值排在一块连续内存里，CPU 缓存命中率高 从书架上顺序拿书，而不是满屋子找书
    SIMD 指令 一条 CPU 指令同时处理多个数（单指令多数据） 一台机器一次搬 4 箱，而不是一次 1 箱

    三者的内存布局差异是这样的：

    Python list：连续的是「指针」，数值分散在堆上
   [ptr][ptr][ptr][ptr]        ← list 本体只是一排指针（每个 8 字节）
     ↓    ↓    ↓    ↓
   int  int  int  int         ← 每个数值是独立对象，各占约 28 字节

NumPy ndarray：数值本身连续排布
   [ 8 字节 ][ 8 字节 ][ 8 字节 ][ 8 字节 ]  ← 一个挨一个，中间没有空隙
   ↑
   一个指针 + 一小段元信息（形状、类型、步长）指向整块内存

    关键差别：list 要取第 i 个数，得先读指针再去堆上找那个对象； ndarray 直接按偏移量算地址，一次内存访问拿到数值。 数据量越大，这个差别越明显。

    import sys

import numpy as np

py_list = list(range(1000))
arr = np.arange(1000, dtype=np.int64)

container = sys.getsizeof(py_list)
elements = sum(sys.getsizeof(x) for x in py_list)

print("list 里 1000 个 int 对象:", elements, "字节")

    为什么这么写：sys.getsizeof(py_list) 只算 list 容器本身（那一排指针）， 不含里面的 int 对象。所以要把每个元素的大小加起来才是真实开销。

    注意：sys.getsizeof 在代码块开头单独导入，而不是与 numpy 写在一行， 只是为了本页每个代码块都能独立运行。

    别把「快」理解成「无论怎么写都快」

    NumPy 快，前提是运算发生在数组整体上。

    写法 是否快 原因
    arr * 2 快 ✓ 整个数组交给 C 层
    arr[0] * 2 快，但没意义 单个元素本来就是标量运算
    [x * 2 for x in arr] 慢 ✗ 又回到 Python 循环，且逐个把数取出来装箱
    for i in range(len(arr)): arr[i] = arr[i] * 2 最慢 ✗ 每个下标都要做一次边界检查

    判断口诀：看到 for 循环遍历数组，先想一想能不能整体写。 （「怎么整体写」是下一章广播与向量化的主题。）

    1.5 list 与 ndarray 的完整对比¶

    Python list NumPy ndarray
    元素类型 可以混装（[1, "a", 3.5]） 必须同一种（同质）
    内存 指针数组 + 分散的对象 一整块连续内存

    3.6 linspace 与 arange 的关键区别¶

    一句话记住：arange 给步长，linspace 给个数

    请求的东西不同，所以「谁包含终点」也不同：

    np.arange np.linspace

    它算什么 算个数 算步长
    含终点吗 不含（stop 取不到）⚠ 含（stop 一定在里面）✓

    默认 dtype 整数参数给整数，有小数给浮点 一律 float64

    判断口诀： 「我要多少个点」→ linspace；「我要每隔多少取一个」→ arange。

    为什么这个区别很重要：

    四、dtype 详解¶

    dtype 决定了每个元素占几个字节、怎么解释这些字节。 它同时影响精度、内存和运算结果，是 NumPy 里最值得花时间理解的属性。

    4.3 默认整数类型取决于平台¶

    np.array([1, 2, 3]).dtype 在 Windows 与 Linux 上可能不同

    平台 np.array([1, 2, 3]).dtype

    4.4 显式指定 dtype 的重要性¶

    指定 dtype 有三个实在的好处：

    好处 说明 例子
    省内存 选宽度够用的类型 存 0-255 的像素用 uint8，是 float64 的 ⅛
    保精度 避免整数除法截断、避免溢出 计数的数组别用 int8
    跨平台一致 结果不随平台变化 用 float64 而不是默认整数

    最典型的一类 bug 是「精度不够」：

    1
2
3
4
    把金额存成 float32：
  1234567.89  →  1234567.9     （7 位有效数字之外的信息丢了）✗
存成 float64 或整数分：
  1234567.89  →  1234567.89    ✓

    另一类是「内存爆掉」：一个 20000×20000 的矩阵存 float64 要 3.2 GB， 存 float32 只要 1.6 GB —— 这可能就是「跑得动」和「跑不动」的区别。

    浮点精度不是「小数位」，而是「有效数字位」

    float32 与 float64 的差别不能理解成「小数少几位」：

    1
2
    float32：约 7 位有效数字   → 1234.567  还行，1234567.8  就只剩 7 位了
float64：约 16 位有效数字  → 日常工程计算基本够用

    另一个易错点：浮点数不能直接用 == 比较（本页第六节末尾演示）。 0.1 在二进制里是无限循环小数，存进去就已经是一个近似值

    1
2
3
4
    127 + 1  →  -128        走到头就绕回来
130      →  130 - 256 = -126
135      →  135 - 256 = -121

    注意它不报错、不警告、不抛异常，只是悄悄给你一个错数字。 如果你的实验数据是像素值、传感器计数、累计和，而 dtype 选小了， 结论可能整个是错的

    什么时候必须警惕溢出

    场景 风险 做法
    像素值 uint8 做加法（如提亮） 255 + 10 绕回 9 先 astype(np.int16) 再算，最后截断 ✓
    计数器、累计和用 int8/int16 累加几十次就绕回 用 int64 或 float64 ✓
    相乘两个大整数 平方后越界 np.arange(n, dtype=np.int64) ** 2 仍可能不够，必要时用 float64
    与 Python 整数混算 Python 整数是任意精度，不会溢出 别以为「Python 不会溢出，NumPy 也不会」⚠

    一个实用习惯：只要涉及乘法或累加， 默认用 int64 或 float64； 只有在明确知道范围且内存紧张时，才降到 int8/int16

    和 Python 对比一下：Python 的 int 是任意精度的， 2 ** 1000 能算出来；NumPy 的固定宽度整数不能。 这是「快」的代价 —— 要快就得让每个元素大小固定、能放在寄存器里

    1

    1

    为什么：(6, 1) 和 (6,) 相加时，NumPy 按广播规则 把 (6,) 补成 (1, 6)，于是变成 (6,1) 与 (1,6) 逐元素运算 → 得到 (6, 6)。 它不报错，只是给你一个 36 个元素的矩阵，而你以为是 6 个

    自查办法：只要结果形状不符合预期，先打印两边形状：

    1

    import numpy as np

a = np.arange(6)             # (6,)
b = a.reshape(6, 1)          # (6, 1)

print(a.shape, b.shape, (a + b).shape)     # 一眼看出谁被广播了

    (6,) (6, 1) (6, 6)

    (6, 6) 就是证据：两边的长度本来都是 6， 结果却变成了 6 行 6 列，说明 a 被当成了行向量去和列向量配对

    • .T 返回视图，不复制数据 ✓（np.shares_memory 打出 True）

    transpose 视图有个容易踩的后果： 转置后的数组内存顺序不再是行优先，做运算时 CPU 缓存不友好， 可能比预期的慢。需要连续内存时用 np.ascontiguousarray(a.T)

    a.ravel() a.flatten()
    返回 视图（内存允许时） 总是副本

    import numpy as np

scores = np.array([
    [88, 92, 79],
    [73, 65, 81],
    [95, 98, 90],
    [60, 72, 68],
], dtype=np.float64)

# 输出容器：形状与类型自动照抄输入
z = np.zeros_like(scores)

    col = scores[:, j]
    z[:, j] = (col - col.mean()) / col.std()

print("输入形状:", scores.shape, " 输出形状:", z.shape)
print("输出 dtype:", z.dtype)
print("每列均值（取绝对值后应接近 0）:", np.abs(z.mean(axis=0)).round(10))

每列标准差（应为 1）: [1. 1. 1.]

    为什么要加 np.abs：浮点算出来的均值可能是 -0.0， 打印时会带一个负号（[ 0. -0. 0.]）， 而这个负号出现不出现取决于具体的舍入过程，不好保证稳定。 取绝对值之后一定是 [0. 0. 0.]， 既读起来干净，也让这段输出在任何机器上都一致

    为什么用 zeros_like 而不是 np.zeros((4, 3))：

    np.zeros((4, 3)) np.zeros_like(scores)
    形状写死 是 ⚠ 自动跟随 ✓
    以后数据变成 40 行 要改代码，漏改就错 ⚠ 不用改 ✓
    dtype 默认 float64（可能不匹配） 与输入一致 ✓

    「形状和类型从数据里来」是一个非常好的习惯 —— 它让代码自动适应输入规模，少了整整一类「忘记同步改两处」的 bug

    例题 1：给一列分数做标准化¶

    题目：给定 8 名学生的分数 [88, 92, 79, 95, 60, 73, 85, 91]，做标准化 （减均值、除标准差），并验证结果。 要求：数组类型显式指定，输出保留 3 位小数。

    思路

    标准化的公式是 \((x - \mu) / \sigma\)，其中 \(\mu\) 是均值、\(\sigma\) 是标准差。

    思考三件事：

    1. mean() 和 std() 直接作用在整个数组上就可以吗？
    2. 结果应该是多少个数？形状和输入一样吗？
    3. 标准化之后，均值应该接近什么值？标准差应该接近什么值？

    （第 3 点是验证的关键 —— 没有验证的代码不算写完。）

    解答

    思路：标准化是逐元素运算，可以整体做，不需要循环。

    1

    每列均值  [ 0. -0.  0.]     ← 三列都标准化了 ✓

    什么情况下必须用 flatten()：

    场景 为什么
    函数内部要改数组，且不能影响调用方 ravel 会污染调用方的数据 ⚠
    打算把结果返回或存起来 视图会随原数组一起变，副本才稳定 ✓

    大数组（几百 MB 以上） flatten 可能直接 MemoryError ⚠
    就是要通过它修改原数组 ravel 正好能当「另一个视角」用 ✓

    import numpy as np


def normalize(arr):
    """返回归一化结果，不修改传入的数组。"""
    flat = arr.flatten()              # 副本：后面可以放心改
    flat = (flat - flat.min()) / (flat.max() - flat.min())
    return flat.reshape(arr.shape)    # reshape 回原形状


data = np.array([[3.0, 7.0], [5.0, 11.0]])

print("归一化结果:")

    对照着看更清楚：

    数组 ravel 返回 原因
    连续（a） 视图 内存本来就按顺序排，不用复制 ✓
    不连续（a.T） 副本 顺序不对，只能复制 ⚠
    任意 flatten 一律副本 它定义为「总是复制」 ✓

    不确定 copy() 最保险，意图也最清楚 ✓

    小结¶

    要记住的 为什么
    ndarray = 同质 + 定长 + 连续内存 这三条决定了它为什么快、为什么不能 append
    NumPy 快在 C 实现、连续内存、SIMD 所以「用 for 遍历数组」就把优势全丢了
    没逗号 = 数组，有逗号 = list 打印结果一眼分辨类型
    (6,) ≠ (1, 6) ≠ (6, 1) 形状 bug 的头号来源，且往往不报错
    结果可疑时第一件事打印 shape 比读代码快得多
    要个数用 linspace，要步长用 arange 浮点步长的 arange 个数不可靠
    linspace 含终点，arange 不含 采样点少一个，曲线就缺一截
    默认整数类型随平台变化 别断言 int64，用 dtype.kind 或显式指定
    固定宽度整数会溢出且不报错 涉及乘法/累加时默认用 int64/float64
    float64 是默认浮点，float32 省一半内存 精度约 7 位 vs 16 位
    浮点不要用 == 用 np.isclose / np.allclose
    reshape/ravel 是视图，flatten/copy 是副本 改视图会连带改原数组
    判断共享内存信 np.shares_memory 比看 base 更可靠
    np.empty 的内容不可预测 不确定就用 np.zeros
    set_printoptions 只改显示，不改数据 真要改值用 .round()
