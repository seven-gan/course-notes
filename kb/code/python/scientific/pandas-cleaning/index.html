    这一页解决一个问题：把一份「能用但不能信」的表，变成一份「敢拿去做结论」的表。

    真实数据几乎从来不是干净的。从 Excel 导出、从数据库拉、从别人手里接过来的表， 几乎必然带着这几样东西：空的格子、被读成文本的数字、重复录入的行、 以及「填了值但明显不可能」的记录。

    它们不会报错。代码照样跑完，图照样画出来， 错的是你从中读出的结论 —— 这才是不清洗最危险的地方。

    清完一遍以后，你应当能对每一格数据回答三个问题：

    问题 为什么要能回答
    这个格子为什么是空的？ 「没测」与「测了是 0」是两件事，填错方向全错 ⚠
    这个值是怎么来的？ 找出录入、单位、小数点、口径这些系统性原因 ✓
    我的处理会让结论变吗？ 换个填充方式结论就翻盘，说明这条结论本来就不稳 ⚠

    学完这一页，你将能够：

    能力 具体表现
    看清脏在哪 拿到表先跑一遍体检，说出「哪一列、脏成什么样」而不是「感觉脏」
    判断缺失类型 知道该填均值、中位数还是前后值，并说得出代价
    修正类型 一眼看出「数字被读成字符串」，用 to_numeric 修好且不丢信息
    处理重复 分清「真重复」与「同名不同人」，会用 keep 控制保留哪一条
    识别异常 会用描述统计、IQR 法则、Z-score、业务规则四种方法交叉验证
    不敢乱删 知道「删除」是最后手段，优先选择截断、替换或单独标注
    写成函数 把整套步骤封装成可复用函数，同一份数据每次清洗结果一致
    交付前后对照 用 shape、缺失数、dtypes 三张对照表证明自己确实清洗过

    这一页的主线

    本页的骨架是先让问题显形，再逐个处理。第二节到第七节各处理一类问题（缺失、类型、重复、异常、文本、列名）， 每一类都走同一个三步：检测 → 决定怎么处理 → 留下理由。

    前四类（缺失、类型、重复、异常）是主干，读完可以停下；第八节把它们封装成一个可复用的函数，第九节做清洗前后对照。

    这页最容易搞错的五件事

    看起来差不多 实际差别 后果
    dropna() 与 dropna(how="all") 前者删任何含缺失的行，后者只删整行全空 默认写法可能一下子删掉三分之一的数据 ⚠
    fillna(df.mean()) 与 fillna(df[col].median()) 前者按列算，后者按单列算 写错一个词就填了完全无关的列
    均值填充与中位数填充 有异常值时均值被拉走，中位数不动 一条 999 分能把全班填成本科水平不可能的成绩 ⚠
    astype(int) 与 to_numeric(errors="coerce") 前者遇错直接崩，后者把错值变缺失 一个交给你处理，一个把问题藏起来——两者都需要，看场景
    inplace=True 与链式调用 inplace=True 返回 None，链式必崩 报 AttributeError: 'NoneType'，且原表可能已被改动一半 ⚠

    这五条后面都有实跑代码验证，不用背

    一、为什么必须清洗¶

    1.1 四类问题一张表看清¶

    先把「脏」拆成四类。每一类的检测手段和处理手段都不一样， 所以第一步永远是把问题分对类：

    问题现象 后果 检测方法 处理策略
    缺失：该有值的地方是空的 求均值时被跳过，样本量悄悄变少；求合计时整行变空 ⚠ isna()、isna().sum()、isna().mean() 删除、固定值填充、统计量填充、前后值填充、插值
    类型错：数字被读成字符串 整列不能参与算术；比大小变成字典序（"100" 排在 "99" 前面）⚠ dtypes、info()、试做一次列加法 to_numeric、astype、to_datetime、to_timedelta
    重复：同一条记录进来了两次 计数、求和、求平均全部被多算一遍，且人数跟着虚高 ⚠ duplicated()、duplicated().sum() 先查清重复原因，再 drop_duplicates()（别加 inplace）
    异常值：填了值但明显不合理 均值和标准差被一两个值拖着走，模型跟着学偏 ⚠ describe()、IQR 法则、Z-score、业务规则 删除、截断、替换、单独标注（推荐从这条开始）

    注意这四类的排序不是随意的：缺失和类型错会互相伪装。 一列数字如果混进一个 "缺考"，整列就被读成字符串， isna().sum() 报 0 —— 看起来一个缺失都没有，实际上缺了一个人 这就是为什么后面的清洗顺序里，类型转换必须排在缺失统计之前。

    df = build_dirty()

    df.columns = df.columns.str.strip()                       # ① 列名去空格
    df["姓名"] = df["姓名"].str.strip()                        # ② 文本列去空格

    2.2 NaN、None、pd.NA 的区别¶

    pandas 里有三种表示「空」的写法，来自三个不同的来源：

    写法 来自哪里 放在数值列会怎样 典型场景
    np.nan NumPy 的浮点缺失值（IEEE 754 定义） 保持 float64，本身就是浮点数 数值列默认缺的就是它
    None Python 语言自带的空对象 会被 pandas 转成 NaN，整数列因此变 float64 从 Python 字典、列表构造表时带进来
    pd.NA pandas 自己的缺失值 配合 Int64 / boolean / string 等可空类型使用，不会把整数挤成浮点 想要「整数列缺值也还是整数」时

    三者的共同点：pd.isna() 都认定为缺失，isna() 也都报 True。 所以检测时永远用 pd.isna() / isna()，不要用 == None 或 == np.nan。

    填均值/中位数最隐蔽的后果是「缩小方差」： 填入的值全挤在中心，样本看起来比真实情况更一致。 如果下游要做置信区间、做检验，这把方差人为压低会产生「显著」的假结论 稳妥做法：填完之后，同时报出填充比例 （「本列 12% 由中位数填充」），让读者知道这列数据里有多少是估算的

  ffill(limit=1): [1.0, 1.0, nan, nan, 5.0]  ← 只补 1 个

    适用场景：顺序有意义，且「保持不变」是最合理的假设。

    场景 为什么适合 注意事项
    每日库存快照 没登记的日子多半就是没变化 停业日会误填成「还在营业」⚠
    传感器缺失点 短时间内的读数接近 长段缺失不能一路填下去 ⚠
    按顺序排列的台账 同一批次的属性相同 一定要先确认这个假设，别默认成立 ⚠

    代价：

    • 最危险的是「一条值填到底」：如果缺失连续 200 行， ffill() 会把第 1 行的值灌满 200 行，而正确值可能早就变了
    • 首尾两端的缺失填不上：ffill() 处理不了开头， bfill() 处理不了结尾（要两头都补就 ffill().bfill()）
    • 会人为造出连续段，让方差看起来更小

    对策：一定配合 limit，明确「最多允许连着填几个」：

    写法 含义 建议
    ffill() 不限长度 只在缺失极稀疏时用 ⚠
    ffill(limit=1) 最多补 1 个 稀疏缺失的安全默认值 ✓
    ffill(limit=3) 最多补 3 个 按物理意义决定，例如「3 天内读数相近」✓
    超过限制的仍缺失 保留为缺失，后面用别的策略 明确区分「可接受的外推」与「不能外推」✓

    • 趋势不是线性时，线性插值会系统性偏高或偏低

    插值前记下 isna() 的掩码 后面任何分析都能区分真实值与插值 ✓
    在报告里写「本列 8% 为插值」 读者知道结论里有多少是估算的 ✓
    对长缺失段设 limit 避免「一路插到底」⚠

    2.9 五种策略的适用场景与代价对比¶

    策略 代码 适用场景 代价 / 风险 何时不该用
    删除 dropna(subset=..., how=...) 缺失极少（<1%）、且缺失行本就该排除 样本量下降，可能引入选择偏差 ⚠ 缺失超过 1%；缺失非随机（集中在某群体）⚠
    固定值 fillna(0) 缺失在业务上就是「没有」 把「没测」与「测到 0」混为一谈 ⚠ 0 是合法值且含义不同
    统计量 fillna(df.median()) 缺失随机、次要列、样本量不小 缩小方差，人为造出一批中心值 ⚠ 有异常值时用均值；列间差异大时用全局值 ⚠

    插值 interpolate(method="time") 时序数据、变化平滑、缺失成段 「造」出从未观测的值，且看起来很像真的 ⚠ 趋势非线性；缺失段过长 ⚠
    单独标注 加一列 是否是填充值 任何拿不准的情况 不损失信息，但后续代码要显式处理缺失 下游必须拿到无缺失矩阵时 ⚠

    选策略的三句话判断法

    顺序问自己三个问题，答案会直接落到某一行：

    问题 是 否
    缺失是不是随机分布的？（按缺失与否分组比一比） 可以放心填 ✓ 先弄清原因，别急着填 ⚠
    这一列的缺失有没有时间顺序？ 用 ffill / interpolate ✓ 用统计量或标注 ✓
    我敢不敢在报告里写明用了哪种填充？ 就按这个方案做 ✓ 改成「单独标注」，不要填 ⚠

    第三问是最实用的自检。一个不敢写进报告的填充方案，就是不该用的方案。

    五种策略就到这里。 第五节还会回来处理「越界值置空后怎么填」， 因为「越界」和「本来就缺」不是同一类问题，处理顺序也不同。

    四、重复值¶

    4.1 先分清两种「重复」¶

    「有重复行」这句话本身不够精确，必须先说是按什么判定的：

    类型 判定依据 本页脏表里的例子 处理方式
    完全重复 所有列的值都一模一样 王芳那一条被整行录入两遍 直接删，几乎不会误删 ✓
    按列重复 只看某一列（或几列）相同 "李娜" 与 "李娜 "（带空格） 先做文本清洗，再判断；否则漏掉一个 ⚠

    IQR（四分位距）法是箱线图背后的规则。它只用位置信息，不假设数据服从正态分布， 所以比 Z-score 更稳健：

    步骤 公式 含义
    ① 算四分位数 Q1（25% 分位）、Q3（75% 分位） 中间 50% 数据的上下边
    ② 算四分位距 IQR = Q3 - Q1 中间 50% 数据跨越的宽度
    ③ 算上下界 下界 Q1 - 1.5 × IQR、上界 Q3 + 1.5 × IQR 界外即标记为疑似异常
    ④ 筛选 落在界外的行全部标出 只是标记，不是判决 ⚠

    系数 含义 标记出的比例（正态数据） 用途
    1.5 × IQR 标准箱线图须长 约 0.7% 默认选择 ✓

    IQR 法的两个优点：

    优点 为什么重要
    不假设分布 分数、收入、响应时间这些都不是正态分布，Z-score 会误判 ✓
    不会被异常值本身拉动 Q1/Q3 是位置量，一个 999 不会把它们带偏 ✓

    IQR 是「标记法则」，不是「删除法则」

    上界算出来是 111，1.5×IQR 的规则「标记」了 999 和 -5。 但标记不等于该删：

    情况 该怎么做
    明显不可能的值（999 分、-5 分） 按业务规则处理：置空、截断或替换 ✓
    罕见但合法的值（身高 2.1 米、单笔大额订单） 保留，它可能正是你研究的对象 ⚠
    数据量很小（比如只有 13 行） Q1/Q3 本身就不稳，界值不可信 ⚠
    分布本身严重偏斜（如收入） 右尾全被判为异常，删完就只剩低收入的 ⚠

    一句话：IQR 帮你找到「值得看一眼的值」， 「要不要动它」取决于业务含义，不取决于公式

    Z-score 的前提与两个致命弱点

    前提 / 弱点 说明

    弱点二：样本太小时阈值不可信 13 个值算出的标准差本身波动巨大 ⚠
    对策一：改用稳健版 Z-score 用中位数代替均值、用 1.4826 × MAD 代替标准差，|z| > 3.5 ✓
    对策二：别只看阈值 把 describe()、IQR、业务规则、直方图放在一起交叉验证 ✓

    稳健版 Z-score（MAD 法）的写法：

    量 公式 为什么稳健
    中心 中位数 不受极端值影响 ✓
    尺度 1.4826 × median(|x - 中位数|) 乘以 1.4826 是为了在正态下与标准差可比 ✓
    判据 |x - 中位数| / 尺度 > 3.5 阈值通常用 3.5 而不是 3 ✓

def clean_scores(df, score_range=(0, 100), dup_key="登记编号",
                 fill="median", verbose=False):
    """按固定顺序清洗成绩表，返回新的 DataFrame（不修改传入的 df）。

    参数
    ----
    df          : 原始表（脏数据）
    score_range : 业务规则允许的分数区间 (下界, 上界)
    dup_key     : 判断重复用的唯一键列名
    fill        : 缺失填充方式，"median" / "mean" / "zero"
    verbose     : 是否打印每一步的变化
    """
    df = df.copy()                       # 第一步永远是复制，不动原表
    log = []

    # ① 列名去空格
    df.columns = df.columns.str.strip()

    # ② 文本列去空格（姓名里带空格会让同一个人被算成两个）
    for col in df.columns:
        if df[col].dtype == object:
            df[col] = df[col].str.strip()

    # ③ 类型转换：所有成绩列转数值，转不了的值变成缺失
    subj = [c for c in df.columns if c in ("语文", "数学", "英语")]
    for col in subj:
        before = int(df[col].isna().sum())
        df[col] = pd.to_numeric(df[col], errors="coerce")
        log.append("类型转换 %s：被 coerce 掉 %d 个"
                   % (col, int(df[col].isna().sum()) - before))

    # ④ 日期列转真正的时间类型
    if "登记时间" in df.columns:
        df["登记时间"] = pd.to_datetime(df["登记时间"],
                                        format="mixed", errors="coerce")

    # ⑤ 去重（按唯一键）
    if dup_key in df.columns:
        before_n = len(df)
        df = df.drop_duplicates(subset=[dup_key], keep="first")
        df = df.reset_index(drop=True)
        log.append("去重：%d 行 → %d 行" % (before_n, len(df)))

    # ⑥ 业务规则：越界分数记成缺失，并保留标记列
    lo, hi = score_range
    for col in subj:
        bad = (df[col] < lo) | (df[col] > hi)
        if bad.any():
            log.append("业务规则 %s：%d 个越界值已置空" % (col, int(bad.sum())))
        df[col + "_越界"] = bad.astype(int)
        df[col] = df[col].mask(bad)

    # ⑦ 缺失填充
    for col in subj:
        n_na = int(df[col].isna().sum())
        if n_na == 0:
            continue
        if fill == "median":
            filler = df[col].median()
        elif fill == "mean":
            filler = df[col].mean()
        elif fill == "zero":
            filler = 0
        else:
            raise ValueError("不支持的填充方式: %r" % (fill,))
        df[col] = df[col].fillna(filler)
        log.append("填充 %s：%d 个缺失用 %s = %.2f 填充"
                   % (col, n_na, fill, filler))

    if verbose:
        for line in log:
            print("   ", line)
    return df, log

def summarize(df, name):
    """把一张表的体检结果整理成三张对照表。"""
    shape = pd.DataFrame({"行数": [df.shape[0]], "列数": [df.shape[1]]})
    shape.insert(0, "表", [name])
    na = df.isna().sum().rename("缺失数").to_frame()
    na["缺失比例"] = (df.isna().mean() * 100).round(2).astype(str) + "%"
    dt = df.dtypes.rename("dtype").astype(str).to_frame()
    return shape, na, dt

    表一 · 规模：

    变化 含义 该不该接受
    行数减少 去重删掉了重复记录 减少的条数必须等于 duplicated().sum() ✓

    行数减少过多 误用了 dropna() 立刻回查，这是最危险的一类变化 ⚠

    表二 · 缺失数：

    变化 含义 判断依据
    缺失数上升 to_numeric(..., errors="coerce") 或 to_datetime 把脏值转成了缺失 ⚠ 上升多少 = 被 coerce 掉多少，必须能对上✓

    缺失数与预期不符 有一个环节和你想的不一样 这时才真正需要逐块查 ⚠

    表三 · 类型：

    变化 期望结果
    object → float64 成绩列转换成功 ✓
    object → datetime64[ns] 日期列转换成功 ✓
    object → object（没变） 说明转换失败或者没做 ⚠

    越界值处理必须在填充之前 均值被异常值污染，填进去的值也是错的 ⚠

    小结¶

    要记住的 为什么
    四类问题：缺失、类型错、重复、异常值 每类的检测与处理手段都不同，先分类再动手 ✓
    类型错会伪装成「零缺失」 一格 "缺考" 让整列变成文本，isna() 报 0 ⚠
    清洗顺序不能换 列名 → 文本 → 类型 → 去重 → 规则 → 填充，换了就错 ⚠
    isna().mean() 比 isna().sum() 更该看 缺失比例才是判断「填还是删」的依据 ✓
    NaN / None / pd.NA 用 pd.isna() 判断 nan == nan 是 False；== 判断会静默失败 ⚠
    整数列里放一个 None 会变成 float64 整数类型没有「空」的位置 ✓
    dropna() 默认 how="any"，删整行 5 行的表可能只剩 1 行，且不报错 ⚠
    fillna(df.mean()) 是按列算的 写成 df["某列"].mean() 就会把那个值填到所有列 ⚠
    有异常值时用中位数，不用均值 均值被极端值拉动，中位数不动 ✓
    均值填充会缩小方差 做检验时可能造出假的「显著」结论 ⚠
    ffill 一定配 limit 否则一条值会灌满整段缺失 ⚠
    插值会造出从未观测的值 图上看起来最平滑，也最容易被误当真值 ⚠
    每种填充都要报「填充比例」 「本列 12% 为填充」比只报均值诚实得多 ✓
    to_numeric(..., errors="coerce") 前后各记一次缺失数 差值就是被 coerce 掉的个数，必须能对上 ⚠
    "88" + "92" 是 "8892"，不报错 文本列 .sum() 同理；只有 .mean() 会报错 ⚠
    日期转完必须查 dtype 打印出来的样子很像，只有 datetime64[ns] 才真转成功 ⚠
    category 是只读优化 后面还要改写这一列时，先别转 ✓
    duplicated() 的三种 keep first/last 各标 2 条，False 标 4 条 —— False 删得最多 ⚠
    「什么算重复」是业务定义 只按姓名去重会合并同名不同人 ⚠
    文本清洗必须排在去重之前 带空格的名字会让 duplicated() 漏判 ⚠
    去重后 reset_index(drop=True) 否则索引带洞，iloc 按位置取会取错 ⚠
    异常值不报错、也查不出 isna() 看不见它，只有描述统计、IQR、Z-score、业务规则能发现 ⚠
    mean 与 50% 差得远 = 有异常值 这是 describe() 里最该一起看的两行 ✓
    IQR = Q1 - 1.5×IQR 到 Q3 + 1.5×IQR 不假设分布，也不被异常值本身拉动 ✓
    Z-score 会被异常值自己污染 异常值同时抬高均值和标准差，把自己「藏」起来 ⚠
    业务规则法优先于统计方法 「分数必须在 0~100」不需要讨论，违反的直接处理 ✓
    IQR 是标记法则，不是删除法则 标出后必须先查业务含义 ⚠
    删除是最后手段 删行丢的是整行所有字段，且无法回滚 ⚠
    优先「单独标注」 零信息损失，唯一代价是后续要显式筛选 ✓
    clip 会造出看似正常的假值 截断后无声，下游看不出哪里被动过 ⚠
    别用被污染的均值去替换异常值 先剔异常 → 再算参考值 → 最后替换 ✓
    .str 自动跳过缺失 这也是「不要用 map(lambda) 代替 .str」的理由 ✓
    contains 不加 na=False 时 dtype 不是 bool 缺失位会变成缺失，后续布尔筛选会漏行 ⚠
    str.len() 的 0 与 NaN 含义不同 0 是「有值但为空串」，NaN 是「没值」⚠
    str.extract 不匹配 → 静默变缺失 抽取后立刻 isna().sum() ✓
    列名去空格要赋值回去 df.columns.str.strip() 单独写一行不生效 ⚠
    rename 后查重名 重名会让 df["列名"] 返回 DataFrame 而不是 Series ⚠
    清洗封装成函数并返回日志 参数集中、结果可复现、过程可复核 ✓
    inplace=True 一律不用 链式调用必崩；切片上还静默失效 ⚠
    前后对照三张表：shape / isna / dtypes 唯一能抓住「悄悄发生的改动」的手段 ✓
    「多出来的缺失」每一个都要能解释 对不上就说明有一步的行为和你想的不一样 ⚠
    报告里写「没做什么」和「遗留局限」 这是结论可复核的关键 ✓
