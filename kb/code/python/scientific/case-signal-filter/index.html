    15 实战：信号去噪¶

    前面十几页讲的是零件，这一页把它们装成一条完整的处理链。

    数据清洗那一页处理的是「不听话的表格」：格子空着、类型错了、数值荒谬。 这一页换一种脏法 —— 数据本身是连续的、格式完全正确的， 但它被噪声盖住了，而你手里没有任何一个格子是明显错的。

    这类问题的难点不在语法，在判断顺序： 先看时域还是先看频域？截断频率定在哪？窗口取多长？ 怎么证明「我真的去掉了噪声」而不是「我把信号也一起削掉了」？

    所以这一页的每条代码前面都有一句「为什么这么做」。 读完你应当能做到：拿到一段被噪声污染的测量信号， 按固定顺序把它变成一段可以用的信号， 并且用数字说明自己做到了什么程度、付出了什么代价。

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    「波形变光滑了」与「噪声真的少了」 前者靠眼睛，后者要算功率 平滑过头会把信号一起削掉，波形还是很漂亮 ⚠
    「提高 SNR」与「保持保真」 SNR 只看噪声剩下多少，保真还要看信号被改了多少 一个把信号也滤掉的方案，SNR 可以很高 ⚠
    「时域滤波」与「频域滤波」 数学上是同一件事的两种坐标 两者能做的事其实一样，差别只在代价算在哪一头

    这三条在后面都有实测代码验证，不用背

    这页需要的库：NumPy、Matplotlib，末尾一个小节用到 SciPy。 版本不必与示例一致，行为在这个量级的版本上是稳定的。

    能力 具体表现
    造带答案的数据 用固定种子生成「真实信号 + 噪声」，使每一步都有东西可比对
    说清采样条件 采样率、时长、点数、Nyquist 频率、频率分辨率之间的关系能一口说清
    看懂时域的局限 知道为什么「波形更乱」这句话无法作为判断依据
    频域定位 用 np.fft.rfft 与 np.fft.rfftfreq 拿到频谱，并从峰上读出信号频率
    设计滤波 写出频域截断与时域移动平均两种方案，并说得出各自的副作用
    量化效果 用 dB 计算 SNR，同时给出与真实信号的均方误差
    评估代价 说得出平滑度与失真度的取舍，并演示相位延迟
    画图核对 一张四联图，输出里只留可核对的数字
    讲清假设 说得出哪些结论依赖「噪声是高斯白噪声」这个前提

    一、任务描述¶

    场景：从测量设备里拿到一段一维时间序列。 设备本身工作正常，但信号很微弱，采集过程中混进了大量噪声， 波形在屏幕上看起来「毛刺很多」，看不出原来的形状。

    任务只有三句话：

    要回答的问题 靠哪几步得到
    真实信号长什么样 频域定位 + 重建
    怎么把它恢复出来 设计一个滤波器
    恢复得有多好 SNR 与均方误差两个指标

    为什么这个任务值得单独做一页：

    因为「信号处理」和「数据清洗」有一个根本区别 —— 表格里的异常值是孤立的（某一格是 999）， 而噪声是遍布每一个采样点的。

    数据清洗（表格） 信号去噪（本页）
    脏在哪 少数几个格子 每一个点都被污染了
    判断依据 业务规则（分数不能超过 100） 统计假设（噪声是白噪声、与信号不相关）
    手段 置空、填充、去重 滤波（在频率或时间上做运算）
    有没有标准答案 没有，口径靠自己定 有 —— 我们自己造的数据，知道真实信号
    怎么评价 报告里说清改了几处 算 SNR 与均方误差 ✓

    「有没有标准答案」这一条是本页最大的便利： 表格案例里我们永远不知道缺失的那个分数本来是多少； 而这一页的噪声是我们自己加的，所以每一步都能算出真实误差。 这就是为什么实战练习要先造数据 —— 没有标准答案，就无法评价方法好坏

    「看起来平滑了」不是证据

    把一段含噪信号做任何形式的平均，它都会变平滑。 平滑是低通滤波的定义，不是成功的证据。

    现象 可能的原因
    波形变平滑了 高频被削掉了 —— 而高频里既有噪声，也可能有信号 ⚠
    毛刺少了 同上，无法区分削掉的是谁
    曲线更「像样」了 视觉偏好不等于物理正确 ⚠

    所以本页从头到尾都只认两个数字： 与真实信号的均方误差（越小越保真）、 以及 SNR（越大越干净）。 眼睛只用来做最后一道「有没有离谱」的检查

    二、构造一个「有标准答案」的信号¶

    2.1 为什么自己造信号¶

    真实测量信号涉及设备、场地、隐私，不能放进教学材料； 而且真实信号每次采集都不一样，输出无法复核，结论也无法比较。

    造一段模拟信号的三个好处：

    好处 具体表现
    知道真实信号 每一步都能算「我偏离真值多少」
    可复现 固定随机种子之后，每一次运行的数字完全相同 ✓
    可调参数 想试「噪声大 10 倍会怎样」「采样率减半会怎样」，改一个数就行 ✓

    信号怎么造：用两个不同频率的正弦叠加。

    为什么是正弦？因为正弦是最「干净」的信号 —— 它的能量全部集中在一个频率上，在频谱里是一个尖峰。 这让「信号在哪里、噪声在哪里」这件事变得答案明确， 从而把注意力集中在流程上，而不是纠结信号本身长什么样 ✓

    成分 频率 幅度 在频谱里的样子
    低频分量 5 Hz 1.0 5 Hz 处一根尖峰
    高频分量 20 Hz 0.5 20 Hz 处一根尖峰
    噪声 全频段 标准差 0.5 通铺在所有频率上的一份「底噪」 ✓

    注意最后一行：噪声不是集中在一个频率上， 而是在每一个频率上都有一点点。这是理解整个去噪思路的关键， 后文还会专门算一次

"""案例用的模拟信号模块。

make_signal() 生成「两个正弦 + 高斯白噪声」的测量信号，
固定种子 → 每次运行完全相同，输出才敢写死。
"""
import numpy as np

FS = 1000.0            # 采样率（Hz）
DURATION = 1.0         # 观测时长（秒）
F1, F2 = 5.0, 20.0     # 两个正弦分量的频率（Hz）
A1, A2 = 1.0, 0.5      # 两个分量的幅度
NOISE_STD = 0.5        # 高斯白噪声的标准差


def make_signal(fs=FS, duration=DURATION, noise_std=NOISE_STD, seed=42):
    """返回 (时间轴, 真实信号, 含噪信号)。"""
    rng = np.random.default_rng(seed)          # 固定种子 → 可复现
    n = int(round(fs * duration))
    t = np.arange(n) / fs
    clean = A1 * np.sin(2 * np.pi * F1 * t) + A2 * np.sin(2 * np.pi * F2 * t)
    noisy = clean + rng.normal(0.0, noise_std, n)
    return t, clean, noisy


if __name__ == "__main__":
    t, clean, noisy = make_signal()
    print("采样点数      :", len(t))
    print("时间轴步长    :", round(float(t[1] - t[0]), 4), "秒")
    print("真实信号标准差:", round(float(clean.std()), 4))
    print("含噪信号标准差:", round(float(noisy.std()), 4))

    误解 事实

    「点数越多，分辨率一定越高」 只有时长变长才会。点数变多但采样率同时变高，分辨率不变 ⚠
    「采样率只要大于信号频率就行」 必须大于两倍最高频率，否则会混叠 ⚠

    为什么采样率必须大于两倍最高频率： 本案例最高频率是 20 Hz，采样率 1000 Hz，比 40 Hz 高出很多 —— 每个 20 Hz 周期被采到 50 个点，波形轮廓非常清楚

    反过来，如果采样率只是「刚刚好」，会出现什么？ 这正是例题 4 的内容：那时候波形不但会失真， 频谱上还会出现根本不存在的频率成分

    注意 True 这一行：它是一句断言，不是装饰。 如果哪天把 20 Hz 改成 800 Hz，这一行会立刻变成 False， 提醒你「后面的频谱分析已经没有意义了」—— 这比事后盯着一个诡异的频谱图猜半天要便宜得多

probe[0] = 0.0
peaks = []
for _ in range(4):
    k = int(probe.argmax())
    peaks.append((round(float(freq[k]), 3), round(float(amp[k]), 3)))
    probe[max(0, k - 1):k + 2] = 0.0

for f, a in peaks:
    print("   %8.3f Hz   幅度 %.3f" % (f, a))

# ---------- 用 Parseval 关系把功率拆到两个频段 ----------
power = np.zeros_like(amp)
power[0] = amp[0] ** 2                 # 直流项不折半
power[-1] = amp[-1] ** 2               # Nyquist 点不折半
power[1:-1] = amp[1:-1] ** 2 / 2       # 正弦分量的平均功率 = 幅度^2 / 2

low = freq <= 50.0
print()
print("总平均功率（谱求和）    :", round(float(power.sum()), 4))
print("总平均功率（时域平方均值）:", round(float(np.mean(noisy ** 2)), 4))
print("50 Hz 以下功率占比      :", round(float(power[low].sum() / power.sum()), 4))
print("50 Hz 以上功率占比      :", round(float(power[~low].sum() / power.sum()), 4))
print("50 Hz 以上的最大幅度    :", round(float(amp[~low].max()), 4), "（噪声，无峰）")
print("50 Hz 以下的最大幅度    :", round(float(amp[low].max()), 4), "（信号，有峰）")

    两根假峰（171 Hz、82 Hz）的幅度在 0.077 上下， 而两根真峰是 0.983 与 0.502 —— 差了 6 到 12 倍。

    判据 信号峰 噪声峰
    幅度 远高于周围 与周围草地差不多 ✓
    位置 每次运行都在同一处 每次运行换地方 ⚠
    数量 很少（本案例 2 个） 到处都是

    最可靠的判据是最后一条：重跑一遍看峰在不在原位。

    本案例的数据是模拟的，所以在同一段信号里没法「重跑」； 但真实项目里可以换一段采集数据做同样的频谱 —— 真信号的峰会稳稳待在原地，噪声峰则会到处乱跑

    4.4 50 Hz 这条线画在哪里¶

    上表里 22 Hz 看起来最优，但不要直接照抄这个数。

    为什么不能照抄 说明
    它依赖信号频率 换个信号，最优点就变了 ⚠
    它依赖噪声带宽 本案例噪声铺满整个频段；若噪声只在低频，结论完全不同 ⚠
    它是事后算出来的 现实中你不知道真实信号，算不出 MSE ⚠

    真实项目里的做法：画出频谱，从峰的位置往两边找余地， 选一个「离信号峰足够远、离噪声带也足够远」的值， 而不是去搜索一个评价值的最优解 —— 因为你手上没有评价值（没有真实信号可以比）

    那怎么知道选得对不对？靠两条：

    手段 能发现什么

    换不同截止频率各跑一遍，看结果稳不稳 结论是否依赖某一个神奇参数 ✓

    本页能做后者，是因为我们自己造了数据。 这件事本身就是「模拟练习」的价值所在

    整段的最大偏差比两端都大 —— 说明最大偏差出现在中间某处， 而不是边界。这正是 FFT 滤波（隐含周期延拓）的一种表现： 它假设信号两端接得上，接不上就会在接缝处出问题

    5.2 「砖墙滤波」的副作用：振铃¶

    为什么叫「砖墙」：这个滤波器的频率响应是一个理想的矩形 —— 通带内增益严格为 1，阻带内严格为 0，中间没有任何过渡。

    问题出在那个「没有任何过渡」上。 时域与频域是互补的：频域里越陡峭的边沿，时域里对应的就越「拖尾」。

    怎么把这件事演示清楚：不去看含噪信号， 而是喂给它一个阶跃信号（前半段是 0，后半段是 1）。 理想情况下滤波后仍然是一个干净的台阶； 但实际会在跳变点附近冒出多余的上下起伏 —— 这就是振铃

    振铃不是「数值误差」，是砖墙滤波的固有代价

    很多人以为 8.87% 的过冲是浮点误差或者代码写错了，于是到处找 bug。 不是。这是理想低通滤波器在数学上的必然结果。

    事实 含义
    砖墙的频率响应是矩形 它的时域冲击响应是 sinc 函数，无限延伸且上下摆动 ⚠
    把 sinc 和阶跃做卷积 必然在跳变处产生过冲与下冲 ⚠
    加大点数不能消除它 过冲始终是 8.87% 量级（这是信号处理里的经典结论）⚠

    怎么减轻：

    手段 代价
    把截止频率降低 过冲变宽但幅度不一定变小；同时更容易切到信号 ⚠
    用有过渡带的滤波器（如 Butterworth） 需要设计阶数，且会引入相位延迟 ✓
    用加窗的时域滤波器设计 振铃变小，但通带会略有波纹

    最重要的是先知道它存在： 本案例的信号是连续正弦，没有突变， 所以振铃表现在 5.1 节那个「整段最大偏差 0.4373」上 —— 它不像阶跃例子那么刺眼，但确实是同一件事

    「输出标准差低于真实标准差」就是信号被削掉的信号： 噪声和信号叠加时标准差会偏大（0.9239）， 如果去噪得当，它应该趋近 0.7906； 一旦掉到明显低于 0.7906，说明不只是噪声被去掉， 信号本身的起伏也被抹平了

    只报 SNR 只报 MSE

    原因是两个指标的参照物不同：

    指标 分子 / 分母 回答
    SNR 真实信号功率 ÷ (输出 − 真实信号) 的功率 剩下的东西有多干净
    MSE 输出与真实信号差多少 结果有多接近真值

    注意这里用了一个技巧： 计算 SNR 时，把「输出 − 真实信号」当作噪声。 这在教学里可行（因为我们知道真实信号）， 而在真实项目里做不到 —— 后面 9.2 节会讲替代办法

    六、量化去噪效果¶

    6.1 SNR 的定义与读法¶

    定义（本页统一用这一个）：

    1
    SNR（dB） = 10 * log10( 信号功率 / 噪声功率 )

    为什么取对数： 功率比可以从 0.001 到 1000 跨越六个数量级， 取对数之后压缩到 −30 到 +30 这一段，好读也好比

    为什么乘 10 而不是 20： 这里比的是功率（幅度的平方）。 如果比的是幅度，才用 20。 两者并不矛盾 —— \(20\log_{10}\sqrt{P} = 10\log_{10}P\)

    dB 值怎么快速估：

    SNR 直观含义
    0 dB 信号和噪声功率一样大，基本没戏 ⚠
    3 dB 信号功率是噪声的 2 倍
    10 dB 信号功率是噪声的 10 倍，看起来已经比较干净 ✓
    20 dB 功率比 100 倍，噪声几乎看不出来 ✓
    负数 噪声比信号还强 ⚠

    本案例含噪信号是 4.074 dB —— 也就是说噪声功率大约是信号的一半。 这属于「很脏但还能救」的区间

    所以本页每个表都同时给 MSE。 MSE 对幅度错误是敏感的，而 SNR 只在「信噪比」这个意义上有意义

    要点：SNR 管「干净不干净」，MSE 管「像不像」，两个都要报。

    七、信号与系统的呼应¶

    7.1 滤波的代价：没有免费的低通¶

    滤波这件事在数学上只有一个动作： 把信号的频谱乘上一个「频率的函数」（叫频率响应 \(H(f)\)）。

    滤波类型 \(H(f)\) 的形状 保留 去掉
    低通 低频为 1，高频为 0 缓慢变化 快速变化
    高通 低频为 0，高频为 1 快速变化 缓慢变化
    带通 只有中间一段为 1 某个频段 其余全部

    关键认识：\(H(f)\) 不知道哪部分是噪声。 它只知道频率。所以「把高频置零」这个动作 必然同时削掉高频里的噪声和高频里的信号

    这就是滤波的代价：噪声抑制与信号保真， 由同一个动作同时决定，无法分开选择

    本案例为什么能成功：因为运气好 —— 信号恰好只在低频（5、20 Hz），噪声恰好铺满全频段。 换个信号（比如信号的频段和噪声完全重叠），低通就没用了

    判断「低通滤波能不能用」只看一件事

    信号的能量和噪声的能量，在频率轴上分得开吗？

    情况 能不能用简单低通
    信号集中低频，噪声铺满全频段 能，低通正合适 ✓
    信号和噪声频段完全重叠 不能，低通会一起削掉 ⚠
    信号在高频（如调制载波） 要用带通，不是低通 ⚠
    噪声是窄带的（如 50 Hz 工频干扰） 用陷波（只切那一条），比低通更省 ✓

    做法顺序永远是：先画频谱 → 看两者在频率上分不分得开 → 再决定用哪种滤波器。 反过来（先定滤波器再看信号）会把明明能救的数据判成没救

    最实用的一条：把「去噪前 − 去噪后」当作估计出来的噪声， 检查它是不是像白噪声（频谱平坦、自相关接近零）。 如果残差里还有明显的周期成分，说明信号被一起削掉了

from numpy.lib.stride_tricks import sliding_window_view

from signal_case import FS, F1, F2, make_signal

n = 1000
t = np.arange(n) / FS
clean = np.sin(2 * np.pi * F1 * t) + 0.5 * np.sin(2 * np.pi * F2 * t)

rng = np.random.default_rng(42)

spiky[idx] += rng.choice([-1.0, 1.0], size=20) * 5.0


def snr_db(x):
    return 10 * np.log10(np.sum(clean ** 2) / np.sum((x - clean) ** 2))


def move_avg(x, k):
    return np.convolve(x, np.ones(k) / k, mode="same")


def med_filt(x, k):
    """中值滤波：每个点换成它邻域里 k 个点的中位数。"""
    pad = k // 2
    win = sliding_window_view(np.pad(x, (pad, pad), mode="edge"), k)
    return np.median(win, axis=-1)

for name, x in (("原始（含脉冲）", spiky),

    噪声的分布 该用 为什么

    为什么 20 Hz 会「整段消失」： 采样率 40 Hz 时，采样时刻是 0, 1/40, 2/40, … 秒。 20 Hz 的正弦在这些时刻的值是：

    1
    sin(2π × 20 × k/40) = sin(π k) = 0      对所有整数 k

    每一个采样点都恰好落在零点上 也就是说，采样后这段信号看起来就是一条 0 线， 连「里面有个 20 Hz 分量」这个事实都记录不下来

    这就是 Nyquist 条件的真实含义： 「采样率必须大于两倍最高频率」里的「大于」不是大于等于。 刚好等于时，正弦正好踩在零点上（或正好踩在极值上，取决于相位）， 信息完全丢失，且无法从数据里恢复

    还有第二重损失，与 Nyquist 无关：

    问题 数值
    采样点数只有 40 个 频谱只有 21 个频点
    6 Hz 与 9 Hz 的频谱 只能挤在同一个频点里 ⚠
    5 Hz 会被相邻噪声干扰 上面测到 1.0431 而不是 1.0 ⚠

    所以「调低采样率」是双重损失： 上限（Nyquist）变低 + 分辨率（fs/n）变差 —— 而在本案例里，分辨率恰好没差（还是 1 Hz，因为时长也变成了 1 秒）， 真正致命的是 Nyquist 这一条

    规矩 理由
    采样率明显大于两倍最高频率 临界值附近信息会丢 ⚠

    采样前先做抗混叠低通 硬件层面挡掉超限的高频，不然会混叠成假信号 ⚠

    20 * log10(功率比) 把功率比当成幅度比 8.1484 dB 错，恰好翻倍 ⚠
    20 * log10(幅度比) 两个幅度之比 4.0742 dB 对 ✓

    小结¶

    要记住的 为什么
    先造出「有标准答案」的数据 没有真值就只能靠眼睛判断，而眼睛分不清噪声和信号 ✓
    np.random.default_rng(42) 固定种子 输出才能写成固定文本、结论才能被别人复核 ✓
    采样率必须大于两倍最高频率 等于时信号会整段消失，低于时会出现混叠 ⚠
    频率分辨率只看 T = n/fs 提高采样率不会提高分辨率，只有延长时间才会 ✓
    时域分不开「信号」与「噪声」 两者逐点相加，没有任何局部特征可区分 ⚠
    白噪声铺满全频段 这是「低通能去噪」的物理前提 ✓
    rfft 只算正频率半边 实信号频谱共轭对称，输出长度是 n//2 + 1 ✓
    频率轴用 rfftfreq(n, 1/fs) 漏掉第二个参数会让单位变成「每周几个采样点」⚠
    幅度谱要 *2/n（直流与 Nyquist 不折半） 不乘 2 会让所有幅度整体矮一半 ⚠
    截止频率画在「离信号峰和噪声带都远」的地方 靠搜索最优点在真实项目里做不到（没有真值）⚠
    砖墙滤波必然振铃 矩形频响对应 sinc 冲击响应，过冲是数学结论 ⚠
    移动平均的通带也不平 窗口越长，信号自己也被压得越扁 ✓
    窗口长度的取舍看 MSE 本案例 k = 21 附近最好，k = 201 时是负收益 ⚠
    因果滤波必然有 (k-1)/2 点延迟 实时系统用不了未来的点，延迟只能接受或补偿 ✓
    SNR 与 MSE 必须同时报 SNR 管干净、MSE 管保真；只报一个会掩盖系统偏差 ⚠
    比功率用 10，比幅度用 20 写错会整体翻倍，且排序不变、很难发现 ⚠
    irfft 一定要写 n= 不写时长度默认成 2*(len-1)，而且不报错 ⚠
    卷积核必须先归一化 np.ones(k) 的和是 k，会让输出放大 k 倍 ⚠
    spec[...] = 0 之前先 copy() 否则原频谱被就地改掉，后续没法再比 ✓
    脉冲噪声要用中值滤波 均值会被单个极端值拉偏，中位数不会 ✓（实测好 20.6 dB）
    去噪不能凭空造信息 含噪 −16 dB 时，低通再削 9.6 dB 也救不回来 ⚠
    改善量是常数，不是「越脏越好救」 线性滤波的降噪比例只由频谱形状决定 ✓
    真实项目要另找 SNR 的替代判据 手上没有真值，只能看残差像不像白噪声 ✓
    离线用 filtfilt，在线用 lfilter 前者零相位但需要整段数据，后者有延迟 ✓
