    这一页解决一个问题：从「能画出图」走到「能画出可以交给别人看的图」。

    上一页讲的是折线、散点、柱状、直方图这四种基本图形，加上标题、图例、网格、 中文字体和保存。那一页画出来的图，自己看够用；但一旦要放进报告、论文、 答辩幻灯片，或者交给合作者判断结论，就会立刻遇到一批新问题：

    你会遇到的麻烦 这一页给的答案
    一张图上要放四个小图，手动调位置调不准 子图布局与自动布局引擎
    温度是摄氏度、功率是千瓦，量纲不同没法画在一张图上 双坐标轴

    想一眼看出「哪个格子最热」 热力图与色标
    点的第三个属性没地方放 颜色映射与点大小
    数据跨了好几个数量级，线性坐标挤成一团 对数坐标
    图上五颜六色，打印出来黑白一片 配色的分类与选择

    学完这一页，你将能够：

    能力 具体表现

    两个量纲画一张图 会用 twinx，并且知道为什么图例会「丢一半」
    表达不确定性 会用 errorbar，并说清误差棒代表的是标准差还是标准误
    展示分布 会用 boxplot 与 violinplot，知道各自能看到什么、看不到什么

    选配色 会按「连续 / 发散 / 分类」三类选色板，知道为什么避开彩虹色

    这页最容易搞错的三件事

    看起来没问题 实际埋的坑 后果
    fig, axes = plt.subplots(1, 3) 然后写 axes.plot(...) 单行/单列时 axes 仍然是数组 报 AttributeError，或者你以为拿到了轴其实是数组
    ax1.twinx() 之后只写 ax1.legend() 图例只收集自己那个轴上的曲线 右轴的曲线在图上，但图例里没有它
    imshow 不写 origin 默认把第 0 行画在最上面 热力图上下颠倒，与矩阵写法相反

    这三件事都不报错，只是悄悄给你一张错的图 —— 本页会把它们逐个钉死

    一、子图布局¶

    1.1 为什么需要子图¶

    用 plot() 画图时，Matplotlib 会自动给你造一个图（figure）和一个绘图区 （axes）。这在只画一条曲线时很方便，但真实的分析往往要在一张图里并排放 好几张子图：

    • 同一批数据换三种处理方式的结果对比
    • 「原始数据 → 处理后 → 残差」的纵向流程
    • 左边一张大图配右边两个小注释图

    这时就需要显式创建多个绘图区，并且决定它们怎么排。

    1.2 subplots 返回的到底是什么¶

    plt.subplots(nrows, ncols, ...) 是最常用的入口。它的返回值是两个东西： 图对象 fig 和绘图区容器 axes。

    关键在于：axes 是数组还是单个对象，取决于你请求了几个子图。

matplotlib.use("Agg")
import matplotlib.pyplot as plt
import numpy as np

# 请求 1 行 3 列
fig, axes = plt.subplots(1, 3, figsize=(6, 2))
print("subplots(1, 3) 的返回类型:", type(axes).__name__)
print("axes 的形状:", np.shape(axes), "，元素个数:", len(axes))
print("axes[0] 的类型:", type(axes[0]).__name__)

# 请求 2 行 2 列
fig, axes2 = plt.subplots(2, 2, figsize=(4, 4))
print("subplots(2, 2) 的形状:", axes2.shape)
print("axes2[0] 的类型:", type(axes2[0]).__name__, "（一整行，不是单个轴）")
print("axes2[0, 1] 的类型:", type(axes2[0, 1]).__name__, "（这才是单个轴）")

# 只请求 1 个子图
fig, ax = plt.subplots(1, 1, figsize=(3, 2))
print("subplots(1, 1) 的返回类型:", type(ax).__name__)
print("它是数组吗:", isinstance(ax, np.ndarray))

    单行或单列时 axes 仍然是数组，不能直接当轴用

    这是新手最常撞的一堵墙。规律可以直接背下来：

    你请求的形状 axes 的类型 怎么访问某个轴
    1 x 1 单个 Axes 直接用 axes（不要加下标）
    1 x N（单行） 一维数组，形状 (N,) axes[0]、axes[1]
    N x 1（单列） 一维数组，形状 (N,) axes[0]、axes[1]
    M x N（都大于 1） 二维数组，形状 (M, N) axes[0, 1]

    一维与二维的索引写法完全不同，这是写通用代码时的雷区：

    1

4
    axes[i]        只对一维数组成立；二维数组会返回一整行，不是单个轴
axes[i, j]     只对二维数组成立；一维数组会报「太多下标」
axes.ravel()   无论几维都压成一维，遍历时最省心
axes.flat      同上，是迭代器写法

    最稳的写法是两种情况都不猜：

    目标 写法
    只画一张图 fig, ax = plt.subplots()，变量名用单数 ax
    循环生成、数量不定 fig, axes = plt.subplots(1, n, squeeze=False)，统一写 axes[0, i]
    行列数固定且都大于 1 直接 axes[i, j]，最直观

    squeeze=False 的作用就是禁止自动压缩维度： 哪怕你只要了 1 x 1，它也返回形状 (1, 1) 的二维数组

    判断依据：代码里如果需要按索引取轴，就加 squeeze=False， 从此别再关心「这一行是不是单行」；如果只是顺序遍历一遍， 用 axes.ravel() 把维度问题一次抹平。

    误用 后果 正确做法
    用 add_subplot(gs[0, :]) 却以为自己在用 subplots 统计子图个数时少了 axes 数组，遍历不到 用 fig.axes 拿到全部子图
    让两个子图占重叠的格子 后者盖住前者，看起来像「某个子图没画出来」 先在纸上画格子，确认每格只被占一次
    忘记 constrained_layout=True 跨行的图与旁边的图共享边界时容易压住标签 用 add_gridspec 时就把约束布局打开

    2.3 twinx 的使用边界¶

    twinx 很强，但不是越多越好。

    情况 该用什么
    两个量纲，一个自变量 twinx ✓
    三个以上量纲 拆成多张子图，一张图最多两个纵轴
    两个量纲而且数量级相同 干脆归一化后画在同一根轴上，不需要双轴
    两条曲线但单位不同、同量纲 用一张轴 + 图例里注明单位即可

    三条实用原则：

    原则 理由
    一图最多两个纵轴 三条纵轴时，读者的眼睛要在三套刻度之间来回找，认知负担过高
    必须标注哪个轴对应哪条线 靠颜色区分，不要靠读者自己猜
    不要让两条曲线交叉点暗示因果关系 双轴图上「两线相交」的横坐标没有任何数学意义，只是缩放比造成的巧合

    最后一条尤其重要：双轴图的两条曲线相交的位置完全由两个纵轴的范围决定， 你把范围改一下，交点就跑到别处去了

    换个思路：能归一化就别开双轴

    双轴图的本质困难是「两条曲线的相对高低没有意义」， 因为你可以通过改范围让任意一条看起来更高。

    如果两个量确实同量纲（比如都是浓度），只是数值范围不同， 那么把它们归一化到同一个尺度，画在同一根轴上往往更好：

    做法 优点 缺点
    twinx 双轴 各自保留原单位，读数直接 相对高低无意义，容易误导
    归一化到 \([0, 1]\) 相对高低有意义，可对比 轴上的数字不再等于原始量
    画成两个上下子图（sharex） 最不容易误读 ✓ 占版面更多

    判断依据：如果你希望读者关心「两条线的相对变化」， 用归一化或上下子图；如果你希望读者读出「各自的绝对数值」， 才用 twinx，并且必须在图注里说明 ✓

    三、误差棒：不确定性的画法¶

    3.1 为什么科研图必须有误差棒¶

    一次测量的数字本身没有意义，它的「不确定程度」才有意义。

    没有误差棒 有误差棒
    读者看到两个点，一个高一个低，以为「高的那个确实更大」 读者看到误差棒重叠，知道「这点差别在测量误差之内」
    结论看起来比实际证据更强 结论的强度与证据匹配

    这不是「画得好看不好看」的问题，而是图有没有如实反映结论强度的问题。 一张没有误差棒的实验曲线，如果两个条件的差别小于测量误差， 它就在暗示一个不存在的效应。

import matplotlib.pyplot as plt
import numpy as np

days = np.arange(1, 7)
mean = np.array([5.2, 6.8, 6.1, 7.9, 8.4, 7.2])

# 不对称误差：第 0 行向下，第 1 行向上
lower = np.array([0.2, 0.3, 0.2, 0.4, 0.3, 0.4])
upper = np.array([0.6, 0.9, 0.4, 1.1, 0.8, 1.0])

    3.4 误差棒的常见错误¶

    错误 后果 正确做法
    误差棒的含义没写在图注里 读者无法判断结论是否站得住 图注写明「± 标准误（n = 6）」
    同一张图上混用标准差和标准误 不同组的「不确定性」不可比 全图统一口径
    用很小字号的 capsize 两端横杠太小，看不出棒到哪里结束 一般取 3 ~ 6
    误差棒盖住了相邻的数据点 图变糊，趋势看不出 加点横向偏移，或错开画不同组
    把标准差当成「测量误差」 标准差反映的是个体差异，可能与测量精度无关 想清楚你算的这个量代表什么
    误差棒画得比数据点还粗 视觉上误差成了主角 让误差棒用细线、浅色

    最后一条容易忽略但很重要：yerr 里的数字从哪来？ 它可能是重复测量的标准差、仪器的标称精度、拟合参数的置信区间、 或者不同批次的波动。不同的来源代表不同的东西， 所以在写图注之前，先问自己一句「这个数代表什么不确定性」

    四、箱线图：一次看清整个分布¶

    4.1 五数概括：箱线图的五个关键数¶

    箱线图（box plot，也叫盒须图）只用五个数概括一整列数据：

    位置 名称 含义
    箱体下边 下四分位数 Q1 有 25% 的数据小于它
    箱体中间线 中位数 Q2 一半数据在它下面、一半在上面
    箱体上边 上四分位数 Q3 有 75% 的数据小于它
    上须顶端 上界内最大值 仍在 1.5 倍 IQR 之内的最大观测值
    下须底端 下界内最小值 同上，向下的那一端

    其中最重要的一个量是四分位距：

    1
    IQR = Q3 - Q1        箱体的高度，中间 50% 数据所在的范围

    须（whisker）画到哪里，规则是：

    1
2
    上界 = Q3 + 1.5 × IQR
下界 = Q1 - 1.5 × IQR

    超过上界的点，一个都不画在须上，而是单独用标记点表示 —— 这就是异常点。

    为什么用 1.5 倍 IQR，而不是「超过 3 倍标准差」

    两种判据的适用条件不同：

    判据 假设 适合
    均值 ± 3 倍标准差 默认数据大致对称、近似正态 已经知道分布形状时
    Q3 + 1.5 × IQR 不需要任何分布假设 默认选它 ✓

    四分位数只依赖「排序后第几个数」，而均值与标准差会被极端值本身拉偏。 用含异常值的量去判断谁是异常值，逻辑上是循环的

    所以「1.5 倍 IQR」这条经验规则的特点是：它自己不会被异常值污染

    4.4 箱线图比柱状图多给了什么¶

    这是本节最值得记住的一个对比。

    能看出偏斜吗 ✗ ✓ 中位线偏离箱体中心即偏斜

    箱线图也不是万能的：它藏得住「双峰」

    箱线图只用五个数，所以任何五个数相同但形状不同的分布，画出来一模一样。

    每个个体 散点图 / 蜂群图 ✓

    实用做法：箱线图 + 数据点叠画。 在箱体上把小样本的每个观测点也画出来（stripplot 式的小抖动点）， 这样既保留了五数概括，又能看出个体在哪、有没有分堆

matplotlib.use("Agg")
import matplotlib.pyplot as plt
import numpy as np
from scipy import stats

rng = np.random.default_rng(3)
normal = rng.normal(50, 5, 200)
bimodal = np.concatenate([rng.normal(40, 3, 100), rng.normal(60, 3, 100)])
skewed = rng.gamma(2.0, 5.0, 200) + 20
groups = [normal, bimodal, skewed]
names = ["正态", "双峰", "偏态"]


def peaks_of(g, bw="scott"):
    """用核密度估计数峰：返回 (峰个数, 峰位置列表)。"""
    grid = np.linspace(g.min() - 3, g.max() + 3, 800)
    dens = stats.gaussian_kde(g, bw_method=bw)(grid)
    idx = np.where((dens[1:-1] > dens[:-2]) & (dens[1:-1] > dens[2:]))[0] + 1
    idx = idx[np.argsort(dens[idx])[::-1]]
    return len(idx), np.round(grid[idx], 2).tolist()


fig, ax = plt.subplots(figsize=(5, 3))
vp = ax.violinplot(groups, showmeans=True, showmedians=True)
print("violinplot 返回的字典键:", sorted(vp.keys()))
print("小提琴个数:", len(vp["bodies"]))
print("每把小提琴的轮廓顶点数（核密度曲线的采样点数）:",
      len(vp["bodies"][0].get_paths()[0].vertices))
print("中位数线的 y 坐标:",
      [round(float(s[0][1]), 3) for s in vp["cmedians"].get_segments()])

print()

for name, g in zip(names, groups):
    q1, med, q3 = np.percentile(g, [25, 50, 75])

    5.2 什么时候用它、什么时候别用¶

    情况 建议
    样本量很大（每组几百以上） ✓ 小提琴图能画出可靠的密度形状
    样本量很小（每组十来个） ✗ 密度估计全是噪声，看起来有很多峰其实没有
    组数多、要紧凑对比 箱线图更省地方
    想强调「有没有双峰」 ✓ 小提琴图
    要在论文里快速说明位置与离散 箱线图更常见、审稿人更熟悉

    小提琴图的形状受两个主观设定影响

    影响形状的设定 后果
    带宽（bw_method） 带宽太大 → 两个峰被抹成一个；太小 → 画出很多假峰
    采样点数 太少则轮廓是折线，看起来有棱角

    实测里同一份双峰数据：

    1
2
3
4
    带宽 0.15 → 2 个峰
带宽 0.30 → 2 个峰
带宽 0.60 → 2 个峰
带宽 1.20 → 1 个峰        ← 双峰被抹平了！

    结论：小提琴图的形状不是数据本身，而是「数据 + 你的带宽选择」。 报告图上的「有几个峰」时，要么固定一个公认的带宽， 要么同时给出直方图作为佐证，不要只凭小提琴的鼓包下结论

    另外，小提琴图的轮廓面积也不代表样本量 —— 每组都会被归一化成同样的最大宽度， 所以 10 个点和 10000 个点画出来的小提琴一样「胖」

    六、热力图：把矩阵画成颜色¶

    6.1 什么时候需要它¶

    origin 第 0 行画在哪一端 默认 'upper'，即画在最上面 ⚠
    extent 数据在第 0 行/列外侧的坐标范围 用来把格子对齐到真实坐标
    aspect 每个格子的宽高比 默认 'equal'，格子是正方形
    clim 色标映射的范围 用 vmin / vmax 指定，用 get_clim() 读回

    origin 默认是左上角，与数学习惯的纵轴向上恰好相反

    这是热力图最容易出错的地方，必须单独讲清。

    origin 第 0 行画在 纵轴方向 对应什么习惯
    'upper'（默认） 最上面 向下增大 图像显示（第 0 行是屏幕最上方）
    'lower' 最下面 向上增大 数学/矩阵写法（原点在左下）

    实测两种设置下 extent 的值是不同的：

    1
2
    origin='upper'  →  extent = [-0.5, 2.5, 1.5, -0.5]
origin='lower'  →  extent = [-0.5, 2.5, -0.5, 1.5]

    看最后两个数的顺序：upper 是「从 1.5 到 -0.5」， 也就是纵轴从上往下排；lower 是「从 -0.5 到 1.5」， 也就是从下往上排

    后果：如果你把矩阵当作数学习惯的表格（第 0 行在第 0 行位置）， 却用了默认的 origin，那么整张图会上下颠倒， 而行列标签还是按 0、1、2 顺序摆的 —— 于是你读出来的每一行都串了位置

    判断依据：

    你的数据来源 该用什么
    图像像素（如相机拍的照片） origin='upper'（默认）✓
    矩阵、相关系数表、混淆矩阵 origin='lower' ✓
    已经明确知道「行从下往上」 origin='lower' ✓

    一个稳妥的习惯：画热力图时永远显式写出 origin， 不要依赖默认值，这样读代码的人（包括未来的你）不用去猜

    7.3 用点大小表示第四维¶

    scatter 的 s 参数控制点的大小 —— 但这里有个必须知道的细节：

    s 是点的「面积」，不是半径。

    1
    s 翻倍  →  面积翻倍  →  半径只增大 根号2 ≈ 1.414 倍
    你以为 实际 后果
    s 是直径，翻倍就是直径翻倍 s 是面积，直径只增大 1.414 倍 视觉上「大点」不够大，对比被压缩

    点大小使用上的三条实用原则：

    原则 理由
    s 必须是正数 面积不能为负；有 0 值时点会消失
    大点要降低不透明度（alpha） 否则大点会把下面的小点全盖住
    给个大小图例 读者不知道「多大的点代表多少」
    别用大小表达太精细的量 面积感知的精度很低，只能表达数量级差异

    大小图例的做法：从数据范围里挑几个有代表性的值， 用 ax.scatter([], [], s=..., label=...) 画几个空点当图例条目， 再用 ax.legend() 把它们显示出来

    7.4 什么时候不该硬塞第四维¶

    情况 更好的做法
    有 5 个以上的属性 分成多张子图（分面），每张画两三个属性
    第四维是类别且有 10 类 不要用形状，改成不同的子图
    点特别多（几万个） 用 hexbin 或二维直方图，散点会糊成一片
    第四维与横纵坐标强相关 也许根本不需要画，直接看相关系数

    判断依据：颜色和大小都是「弱通道」 —— 人眼能精确比较位置（横纵坐标），但只能粗略估计颜色和面积。 所以：重要的量放坐标轴，次要的量放颜色和大小

    八、对数坐标¶

    8.1 什么时候该用¶

    线性坐标默认「相等的数值差对应相等的距离」。 这个假设在两种情况下会失效：

    情况 线性坐标下的表现 对数坐标下的表现
    数据跨多个数量级（如 0.001 到 1000） 小值全挤在原点附近，糊成一片 每段数量级占同样的宽度 ✓
    数据按指数增长（如细菌繁殖、复利） 是一条陡峭的曲线，看不出增长率 变成直线，斜率就是增长率 ✓
    数据按幂律变化（如 \(y = a x^b\)） 曲线，难以判断指数 双对数下变成直线，斜率就是指数 ✓
    数据本来就在线性尺度上 正常 反而会把均匀的数据挤歪 ✗

    两条判断口诀：

    1
2
    要看「差多少」→ 线性坐标（如温度从 20 到 25 度）
要看「差几倍」→ 对数坐标（如浓度从 1e-6 到 1e-2）

    为什么不该用 jet / rainbow 表示连续量

    有三个独立的原因，每条单独看都足够说服人。

    原因一：同一个灰度对应两个数值。

    jet 的亮度在色板 64% 的位置达到最高，两端都偏暗。 于是「亮」这个视觉特征在中间段表示「数值大」， 在两端的同一张图里却表示「数值小」。

    直接后果：图打印成黑白、或被红绿色盲读者看时， 一个灰色可能对应两个完全不同的数值，读图会系统性出错

    原因二：亮度不均匀，会制造「假边界」。

    jet 在青蓝交界处亮度变化很陡，于是数据里一个平缓的过渡 会被画成一条看起来很明显分界的边。 观察者会以为数据在这里有突变，实际上什么都没有 —— 这是在数据里看到了不存在的结构

    原因三：对色盲读者不可靠。

    色觉类型 大约占比 jet 的问题
    红绿色盲 男性约 8% 红端与绿端难以区分
    蓝黄色盲 更少见 蓝端与青端难以区分

    靠色相（红/绿/蓝）区分时，色盲读者会看到多段颜色糊在一起。 而 viridis 的区分主要靠亮度，亮度感知与色觉类型无关

    用途 首选 备选

    发散量 coolwarm、RdBu BrBG、PiYG
    分类量（少类别） tab10、Set2 Paired、Dark2
    黑白打印 Greys viridis（灰度化后仍单调）

    其中 cividis 是专门为色盲设计的，viridis 也表现良好， 两者作为默认选择几乎不会出错

    曲线数量 一张图塞 12 条线 超过 5 条就考虑拆图，或只突出要讲的那两条
    颜色数 8 条线用 tab10 注意配色只提供约 10 种可区分色，会循环重复
    图例位置 压在数据上 loc="best" 或放到图外 bbox_to_anchor
    字号 缩到单栏宽后看不清 见下表
    信息密度 一张图讲五件事 一张图讲一件事，其它拆到别的图

    10.2 字号与尺寸的建议值¶

    元素 建议最小字号 说明
    图标题 10 磅 与正文同号或略大
    轴标签 9 磅 不能小于刻度字号
    刻度数字 8 磅 再小就认不清了
    图例 8 磅 项目多时宁可放图外
    图注（caption） 正文同号 图注是给读者读的，不能缩

    为什么强调「缩到单栏宽」：论文排版会把图缩放到栏宽 （常见是 3.5 英寸量级）。你按 8 英寸画的图缩小一半后， 原本 8 磅的字会变成视觉上的 4 磅，基本看不清

    所以更好的做法是：一开始就按最终显示的宽度画（figsize=(3.5, 2.5) 量级）， 字号按上面的表设置，这样所见即所得，不会缩出问题。

    10.3 一张图只讲一件事¶

    这是最难做到、也最能拉开差距的一条。

    反例 问题 拆法
    一张图里有折线、柱状、散点、文字标注 读者不知道眼睛该看哪儿 拆成两三张子图
    标题写「结果分析」 没有结论，读者要自己猜 换成一句话结论
    图上有 6 组数据、3 个纵轴 认知负担过载 挑出最重要的对比单独画

    自查的一句话测试

    出图前问自己：「如果这张图配一句说明，那句说明是什么？」

    • 如果你能立刻说出一句话（如「乙组的波动明显大于甲组」）， 那这句话就应该是标题
    • 如果你想了半天说不出来，或者要说出三句话， 说明这张图还没想清楚要表达什么 —— 先拆图，再画

    这条测试比任何格式规范都管用，因为它逼你先想「结论」再想「画法」。

    11.2 dpi 到底在控制什么¶

    概念 含义
    figsize（英寸） 图的物理尺寸，如 3.5 × 2.5 英寸
    dpi（每英寸点数） 每英寸塞多少个像素
    像素尺寸 = figsize × dpi 实测：3.5 英寸 × 300 = 1050 像素 ✓

    所以要分清两种需求：

    用途 目标 该调什么
    期刊投稿（PNG/TIFF） 足够多的像素，要求 dpi ≥ 300 提高 dpi ✓
    期刊投稿（PDF/SVG） 矢量，无分辨率问题 不用管 dpi ✓
    网页展示 文件别太大 dpi=150 通常够
    幻灯片 屏幕像素即可 dpi=200 足够清晰

    bbox_inches='tight' 能自动裁掉多余白边

    1
    fig.savefig("fig.pdf", bbox_inches="tight")

    默认情况下，figsize 里的四周会留下固定留白。 加上 bbox_inches="tight" 后，Matplotlib 会按实际内容裁剪， 把外侧空白去掉，图看起来更饱满

    但要注意两个副作用：

    副作用 说明
    输出尺寸不再等于 figsize 因为白边被裁了，宽高比可能变化
    多张图并排时尺寸可能不一致 每张图裁掉的白边多少不同

    所以如果要求多张图尺寸严格一致（比如排版成对齐的两列）， 就不要用 bbox_inches="tight"，而是靠 constrained_layout 把内容摆好，让 figsize 说了算

    12.1 子图重叠¶

    症状：x 轴标签被下面的图压住、总标题被顶掉、纵轴标签被切掉。

    修法 写法 说明
    首选 plt.subplots(..., constrained_layout=True) 每次绘制都重算，后续改动也自动跟随 ✓
    次选 画完调 fig.tight_layout() 只算一次，之后再改就失效
    给总标题留位置 fig.tight_layout(rect=[0, 0, 1, 0.95]) 上方留 5% 给 suptitle
    手动微调 fig.subplots_adjust(hspace=0.4, wspace=0.3) 只在非要精确控制时用

    实测数据：未开自动布局时下排子图底边在 0.11， 调用 tight_layout() 后被抬到 0.1557，上抬了约 0.046， 腾出来的正是 x 轴标签要占的地方

    12.2 twinx 后图例丢失¶

    症状：右轴的曲线在图上看得见，图例里却没有它。

    原因：legend() 只收集自己所属轴上的 artist， twinx 造出的第二个轴不在第一个轴的清单里。

    修法 写法
    合并句柄（推荐） lines = l1 + l2; ax1.legend(lines, [ln.get_label() for ln in lines])
    等效写法 把合并后的句柄交给 ax2.legend(...)
    不要两个轴都调 legend() 会出现两套重复图例

    12.3 热力图行列标签与数据不对齐¶

    症状：标签整体偏半格、最后一行的标签缺失、上下颠倒。

    症状 根因 修法
    标签整体偏半格 刻度用了 1..N 改成 np.arange(N)，从 0 开始 ✓
    最后一行/列没标签 刻度个数 ≠ 数据维度 刻度个数必须等于列数（x）与行数（y）
    上下颠倒 用了默认 origin='upper' 改成 origin='lower' ✓
    标签位置对但内容错 数据与标签的顺序没对应上 挑一个角落的格子核对数值

    extent 与 xticks 的配合：extent 描述的是 格子边界在数据坐标下的范围，写成 [左, 右, 下, 上]。 它会影响坐标轴的方向与范围，但不会自动帮你摆刻度 —— 刻度仍然要用 set_xticks 显式指定。 所以「改了 extent 但没改 xticks」也会造成标签错位

    12.4 imshow 的 origin¶

    这是本页反复强调的一点，因为它最容易出错、后果又最隐蔽：

    数据来源 正确设置
    图像（相机、扫描） origin='upper'（默认）
    矩阵、相关系数、混淆矩阵 origin='lower' ✓

    另一个等价但不太推荐的做法：imshow(mat[::-1]) （先把矩阵上下翻转）。它画出来的结果与 origin='lower' 相同， 但改动了数据本身 —— 之后如果要从图上取回数据、或者要标数值， 就得记得再翻一次，容易错。用 origin 参数更干净 ✓

def peaks_of(g, bw="scott"):
    """用核密度估计数峰：返回 (峰个数, 峰位置列表)。"""
    grid = np.linspace(g.min() - 3, g.max() + 3, 800)
    dens = stats.gaussian_kde(g, bw_method=bw)(grid)
    idx = np.where((dens[1:-1] > dens[:-2]) & (dens[1:-1] > dens[2:]))[0] + 1
    idx = idx[np.argsort(dens[idx])[::-1]]
    return len(idx), np.round(grid[idx], 2).tolist()

  乙 组 Q1=45.079 中位=50.696 Q3=58.563，IQR=13.484
两组的三分位数都很接近：中位数只差 0.529，IQR 只差 3.544
→ 只看箱线图，会以为两组分布差不多

换成小提琴图（核密度估计），差别立刻出现：
  甲 组 KDE 峰个数 1，峰位置 [51.0]
  乙 组 KDE 峰个数 2，峰位置 [58.48, 45.12]
甲组是单峰，乙组是双峰 —— 这个结构只有密度曲线看得出来
箱线图只用五个数概括分布，给不出「有几个峰」

但要小心：小提琴的形状受带宽影响
  bw_method=0.30 → 峰个数 2，峰位置 [58.55, 45.09]
  bw_method=0.60 → 峰个数 2，峰位置 [58.22, 45.35]
  bw_method=1.20 → 峰个数 1，峰位置 [51.84]
带宽加大到 1.2 时，双峰被抹成了单峰

最稳的做法：箱线图 + 原始数据点叠画，或用直方图做旁证

    输出里的对照：

    组 箱线图给出的量 小提琴图额外给出的量
    甲 Q1/Q2/Q3 与乙很接近 KDE 只有 1 个峰
    乙 中位数只差 0.53 KDE 有 2 个峰，分别在约 45 与 58

    结论：

    问题 答案
    箱线图漏了什么 峰的个数与位置（分布形状）
    为什么漏了 它只用五个数概括，任何五数相同的分布画出来一样
    补救办法 在小提琴/箱线图上叠画每个观测点（加一点横向抖动），或并排给一张直方图
    另一个提醒 小提琴图的形状受带宽影响，实测带宽从 0.3 加大到 1.2 时，双峰被抹成单峰 ⚠

    所以最稳的做法是「箱线图 + 原始数据点」： 箱线图负责位置与离散，数据点负责暴露个体结构， 两者叠在一起才既能看总体、又不会被概括骗过

    小结¶

    要记住的 为什么
    subplots 的返回值取决于你要了几个子图 单行/单列时是数组，1 x 1 时是单个轴；用 squeeze=False 统一成二维
    sharey 才是「能否对比」的关键 不共享纵轴时，两组量级不同的数据会被自动缩放成看起来一样高
    constrained_layout=True 优于事后 tight_layout() 前者每次绘制都重算，后面的改动会自动跟随
    gridspec 就是「先划格子，再用切片占格」 跨行跨列与 NumPy 切片写法一致，会切片就会写
    twinx 之后必须手动合并图例 legend() 只收集自己所属轴上的 artist
    一图最多两个纵轴 三套刻度会让读者在刻度之间来回找，认知负担过高
    双轴图上的曲线交点没有意义 交点位置完全由两个轴的范围决定，改范围交点就跑了
    科研图必须有误差棒 没有误差棒的图会暗示一个可能存在也可能不存在的效应
    误差棒的含义必须写进图注 标准差、标准误、置信区间画出来长度差好几倍
    箱线图给五数概括 + 离群点，但不给形状 双峰分布会被压成一个平平无奇的箱子
    小提琴图给形状，但形状受带宽影响 带宽从 0.3 改到 1.2，双峰能被抹成单峰
    imshow 的 origin 默认是左上角 与数学习惯相反，所以画矩阵永远显式写 origin='lower'
    pcolormesh 适合不等距坐标，且 Z 比 X、Y 各少一维 它接收的是格子边界，不是格心
    多图对比时必须固定 vmin / vmax 否则各自的极值不同，10 倍差距被颜色抹平
    热力图的行列标签要「个数等于维度、位置从 0 起」 常见的「偏半格」与「缺最后一行」都源于此
    颜色可以表示第三维，大小表示第四维 但两者都是弱通道：重要量放坐标轴，次要量放颜色和大小
    s 是点的面积不是半径 面积翻倍时半径只放大 1.414 倍
    跨数量级用对数坐标，看倍数而非差值 幂律在双对数下变直线，斜率就是指数
    对数轴会静默丢掉 0 与负数 不报错、不警告，图看起来正常但少了一个点；画之前先查 (x > 0).all()
    配色分三类：连续 / 发散 / 分类 选错类型会丢掉「有序」这个信息
    不要用 jet / rainbow 表示连续量 亮度折返，同一个灰色对应两个数值，还会制造假边界
    发散色板的中心要落在有意义的中间值 [-2, 6] 会让白色落在 2，0 被误读成负值
    标题说结论，轴带单位 「如果这张图配一句说明，那句说明就是标题」
    论文图优先矢量格式 放大不糊，还能在矢量软件里继续改
    dpi ≥ 300 是位图投稿的通行要求 像素尺寸 = figsize × dpi，figsize 决定物理尺寸
    中文字体要在画图之前设，并在列表末尾放兜底字体 字体名写错会静默退回默认字体，中文全变方块
