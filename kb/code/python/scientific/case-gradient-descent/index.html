    前面几页讲的是「怎么读数据」，这一页讲「怎么找一个最小值」。

    优化器在工程里几乎是黑盒：调一个参数、看损失降不降。 但黑盒用久了会形成一种危险的直觉 —— 以为「学习率」是一个可以随便设的数字，以为「收敛慢」是机器的问题。

    这一页不给现成优化器。自己用 NumPy 手写梯度下降， 把一个二次函数当靶子，实测两件事：

    要实测的问题 靠哪个实验回答
    学习率调大调小，到底会发生什么 实验一：固定条件数，扫学习率
    为什么同样的算法换个问题就慢十倍 实验二：固定学习率，扫条件数
    有没有「一步到位」的办法，代价是什么 实验三：与牛顿法对比

    读完你应当能做到：拿到一个优化问题，先估算它的条件数， 再据此判断「这个学习率大概能有多快」，而不是靠试。

    这一页的主线

    本页的主线是用两个参数把「优化为什么会变慢」拆开：学习率与条件数。

    第二节定义靶子函数，第三节手写梯度下降，第四、五节各固定一个、扫另一个， 第六节用牛顿法做对照，第七节把收敛过程画出来。三个实验是主体，第四节读完就能理解「学习率不能再大」的边界在哪。

    这页最容易搞错的三件事

    看起来差不多 实际差别 后果
    「学习率太大」与「学习率超过上界」 前者只是震荡，后者每步放大 只看最后一步的损失，可能还以为在缓慢下降
    「收敛慢」与「步数多」 慢是每步的有效进展小 前期下降 40%、后期下降 0.1%，看前几步会误判成很快
    「牛顿法更快」与「牛顿法更便宜」 它是一个更贵的每步换更少的步数 规模一大，解方程的代价直接吃掉所有收益

    这三条后面都有实测数字，不用背

    本页与数学优化模块的关系： 梯度下降的推导、为什么沿负梯度方向走、步长的几何直觉， 在 梯度下降 那一页已经讲过。 这一页不重复推导，只做一件事：把那里的结论跑出来、量出来。

    这页需要的库：NumPy，画图用 Matplotlib，最后一节用 SciPy 做交叉验证。 版本不必与示例一致，行为在这个量级的版本上是稳定的。

    能力 具体表现
    手写迭代 不用现成优化器，自己写出 x ← x - lr * grad 并记录全过程
    用解析解校准 二次函数有闭式解，能精确判断「到底收敛了没有」
    判断稳定性 会算 2/λ_max，能说出「这个学习率安全还是危险」
    判断快慢 会算条件数与收敛因子，能预测大概多少步
    看清代价 说得出牛顿法一步为什么要解方程组，以及代价怎么随规模涨
    画图核对 图画得出来，且输出里只留可核对的数字
    讲清结论 能说「为什么深度学习不用牛顿法」，而只答「因为太慢」

    一、任务描述¶

    场景：要在一批数据上拟合一个模型，最终归结为「找一个使损失最小的参数」。 现成的优化器能一行调用，但调用之前有三件事必须想清楚：

    必须回答的问题 为什么非回答不可
    学习率取多少 取错不是慢一点，是训练直接崩掉
    大概要迭代多少轮 决定算力预算、决定要不要换方法
    换个问题会不会变慢 决定这套超参数能不能复用

    为什么不用现成优化器： 调用 minimize 或 fit 当然能得到一个解， 但它把「中间发生了什么」全藏起来了 —— 你看不到误差是在指数增长还是在缓慢爬行， 也看不到「第 3 步就已经到了，后面 100 步都在浪费」。

    所以这一页的规则是：所有迭代都自己写，每一步都留下记录。

    「用现成优化器」和「自己写」学到的不是同一件事

    做法 你得到 你学不到
    minimize(f, x0) 一行调用 一个解，和一句 success: True 为什么这个解可信、换组参数会不会崩 ⚠
    手写迭代 + 记录误差 一条误差曲线 + 每一步的中间量 —— 本页采用 ✓
    手写迭代但只打印最后结果 一个数 发散、震荡、停滞、收敛，这四种命运看起来一模一样 ⚠

    判断依据：要「拿到答案」用现成库； 要「搞懂这个问题的脾气」，必须自己写，而且必须记录全过程。

    任务拆成四步，每一步都要有可运行的代码和真实输出：

    步骤 要拿到什么
    定义目标函数 一个已知解析最优解的函数，这样才有「标准答案」可以对
    手写梯度下降 一个能返回轨迹、函数值、误差序列的迭代器
    扫参数做实验 学习率、条件数各自单独变化，其余量固定
    交叉验证 用解析解和现成优化器两条独立路径确认自己的实现没错

    注意最后一步为什么必要： 自己写的迭代器如果有个下标错误， 它照样能跑出一条「看起来很收敛」的曲线 —— 因为它可能在解一个与你以为的不一样的问题。 所以必须留一条独立的核对路径 ✓

    二、定义目标函数¶

    2.1 为什么选二次函数¶

    要研究「收敛」，前提是知道正确答案。 二次函数 f(x) = 0.5 * x^T A x（A 对称正定）恰好满足这个前提：

    性质 二次函数的表现 对实验的价值
    最优解 梯度 ∇f = A x 是一次式，令它为零即可解出 有闭式标准答案，误差可以精确算 ✓
    收敛判据 可以明确说「误差小于多少就算收敛」 不同参数的迭代次数可比 ✓
    条件数 就是 A 的最大与最小特征值之比 一个数就能控制问题的「病态程度」 ✓
    梯度下降的表现 有完整的理论收敛因子 实测值可以和理论值对上 ✓

    最关键的是第三行：条件数 κ 可以人为控制。 现实问题的条件数是你拿到的，而教学实验的条件数应当是你设的 —— 否则你就不知道「变慢」到底是不是条件数造成的。

    为什么不用更「真实」的函数

    很多人第一反应是拿神经网络当例子。但那样做会同时变动一大堆东西： 非凸、随机梯度、批量大小、初始化…… 最后测出来的差异归因不到任何单一因素。

    本页的策略是一次只动一个旋钮： 先固定条件数扫学习率，再固定学习率扫条件数。 真实的深度学习是这些效应叠加的结果， 但叠加之前，得先看清每一层各是什么

    2.2 用对角矩阵控制条件数¶

    取 A 为对角矩阵 diag(λ₁, …, λₙ)，对角元从 λ_max / κ 均匀排到 λ_max。 对角矩阵的特征值就是它的对角元，所以：

    1
    条件数 κ = λ_max / λ_min        （对角矩阵的情形，一眼可见）

    为什么"对角"这个限制是重要的：对一般矩阵， 特征值要解特征方程才能得到，而「条件数」这个词在非对称矩阵上还有别的含义。 对角矩阵把这件事变得完全透明 —— 你能看着 np.diag(A) 就说出条件数

"""梯度下降实验用的工具模块（本页所有代码块共用）。"""
import numpy as np


def make_A(kappa, n=20, lam_max=10.0):
    """构造对角正定矩阵：对角元从 lam_max/kappa 排到 lam_max。

    对角矩阵的特征值就是对角元，所以条件数恰好等于 kappa。
    """
    return np.diag(np.linspace(lam_max / kappa, lam_max, n))


def f(A, x):
    """目标函数 f(x) = 0.5 * x^T A x。"""
    return float(0.5 * (x @ (A @ x)))


def grad(A, x):
    """梯度 nabla f(x) = A x —— 二次函数的梯度是一次式，没有近似。"""
    return A @ x


def gd(A, x0, lr, tol=1e-6, max_steps=50000):
    """手写梯度下降：x = x - lr * A x，最优解是零向量。

    返回 (轨迹, f 序列, 相对误差序列, 状态字典)。
    """
    x = np.array(x0, dtype=float)
    scale = float(np.linalg.norm(x))
    xs, fs, errs = [x.copy()], [f(A, x)], [1.0]
    for k in range(1, max_steps + 1):
        x = x - lr * grad(A, x)
        xs.append(x.copy())
        fs.append(f(A, x))
        e = float(np.linalg.norm(x)) / scale
        errs.append(e)
        if not np.isfinite(e) or e > 1e12:
            return xs, fs, errs, {"iters": None, "status": "发散", "ran": k}
        if e <= tol:
            return xs, fs, errs, {"iters": k, "status": "已收敛", "ran": k}
        if k >= 500 and errs[k - 500] <= errs[k]:
            return xs, fs, errs, {"iters": None, "status": "停滞", "ran": k}
    return xs, fs, errs, {"iters": None, "status": "未收敛", "ran": max_steps}


def gd_momentum(A, x0, lr, beta, tol=1e-6, max_steps=50000):
    """带动量的梯度下降：v = beta*v - lr*grad, x = x + v。"""
    x = np.array(x0, dtype=float)
    v = np.zeros_like(x)
    scale = float(np.linalg.norm(x))
    errs = [1.0]
    for k in range(1, max_steps + 1):
        v = beta * v - lr * grad(A, x)
        x = x + v
        e = float(np.linalg.norm(x)) / scale
        errs.append(e)
        if not np.isfinite(e) or e > 1e12:
            return errs, {"iters": None, "status": "发散", "ran": k}
        if e <= tol:
            return errs, {"iters": k, "status": "已收敛", "ran": k}
    return errs, {"iters": None, "status": "未收敛", "ran": max_steps}

    原因是收敛因子不是单调的：

    学习率 收敛因子 ρ 含义
    0.002 0.998 太接近 1，缩得极慢
    0.1818 0.8182 最小 → 最快 ✓
    0.19 0.9 又往回涨了
    0.2 1.0 完全不缩
    0.21 1.1 大于 1 → 放大 → 发散 ⚠

    ρ 先随学习率增大而降（步子变大，缩得快）， 到 2/(λ_max+λ_min) 触底，然后回升： 因为此时最慢方向虽然在加速，但最快方向已经开始震荡，把整体拖了回去。 再大一点，1 - lr·λ_max 变成负数、绝对值超过 1，游戏就结束了

    「学习率越大越快」只在很窄的一段里成立

    区间 行为 判断依据
    0 < lr < 2/(λ_max+λ_min) 越大越快 ✓ 最快方向还没开始震荡
    lr = 2/(λ_max+λ_min) 最快 两个方向的收敛速度恰好相等
    2/(λ_max+λ_min) < lr < 2/λ_max 越大越慢 ⚠ 最快方向在震荡，抵消了收益

    「牛顿法一步收敛」只对二次函数成立

    本节的结论非常干净，但它的成立条件很窄，必须说清：

    目标函数 牛顿法的表现 原因
    二次函数（本例） 一步精确 Hessian 是常数，二阶模型与函数完全一致 ✓
    一般凸函数 局部二阶收敛（快但仍要好几步） 二阶泰勒展开只是近似 ⚠
    非凸函数 可能收敛到鞍点或极大点 牛顿法会朝 H⁻¹∇f = 0 的任一点走 ⚠
    Hessian 不正定 方向可能上升 H⁻¹ 不再是下降方向 ⚠

    另外还有两个实际障碍： H 要存 n² 个数（n = 1e6 时是 1e12 个数）， 而且解方程组的数值稳定性在病态问题上很差

    判断依据：参数少、Hessian 便宜且正定 → 牛顿法值得考虑； 参数多、非凸、只能用随机梯度 → 老老实实用一阶方法

# 旋转过的二次型：特征值 50 与 1，条件数 50，主方向与坐标轴成 45 度
LAM_FAST, LAM_SLOW = 50.0, 1.0
ang = np.pi / 4.0
rot = np.array([[np.cos(ang), -np.sin(ang)],
                [np.sin(ang), np.cos(ang)]])
A = rot @ np.diag([LAM_FAST, LAM_SLOW]) @ rot.T
x0 = np.array([1.0, 0.0])
upper = 2.0 / LAM_FAST                   # 稳定上界
u_fast = rot[:, 0]                       # 对应 lambda = 50 的方向


def run_gd(lr, tol=1e-6, max_steps=200000):
    """在 A 上跑梯度下降，返回整条轨迹与步数。"""
    x = np.array(x0, dtype=float)
    xs = [x.copy()]
    for k in range(1, max_steps + 1):
        x = x - lr * (A @ x)
        xs.append(x.copy())
        if float(np.linalg.norm(x)) <= tol:
            return np.array(xs), k
    return np.array(xs), None


def flips(path):
    """穿「慢方向」直线的次数 = 快方向分量的符号翻转次数（锯齿的证据）。"""
    proj = path @ u_fast
    proj = proj[np.abs(proj) > 1e-12]
    return int(np.sum(np.sign(proj[1:]) != np.sign(proj[:-1])))

    输出 图上对应什么 说明
    符号翻转: 0（上界 50%） 一条平滑的折线，不穿过中间那条对角线 快方向一步就被压掉，规规矩矩往里走 ✓
    符号翻转: 258（上界 95%） 轨迹反复来回穿过对角线，像拉链 快方向每步都过冲一次，来回震荡 ⚠

    「符号翻转」就是「锯齿」的量化定义： 它在数「轨迹穿过慢方向直线的次数」。 一条平滑下降的轨迹只会穿 0 次或 1 次， 而锯齿状轨迹会穿几十上百次 —— 这个数字把「图上看起来抖」变成了「可以核对的事实」

    为什么会抖：看「快方向因子」这一列。 梯度下降在快方向上的每步缩放因子是 1 - lr·λ_max： lr 取上界的 50% 时它是 0（一步归零，完全不抖）； 取 95% 时它是 -0.9 —— 负号意味着每步都翻方向， |-0.9| = 0.9 意味着每步只缩 10%，于是要来回抖很多次才消掉

    这正是「学习率接近上界」和「学习率只是偏大」的分界： 前者在快方向上反复过冲（因子接近 -1）， 后者只是步子大一点（因子是个小的正数）。 两条曲线的步数也印证了这件事： 95% 那条只用了 348 步，比 50% 那条的 667 步还少 —— 接近上界的锯齿轨迹其实更快， 代价是它对问题的任何变化都极其敏感，稍微再大一点就发散

    所以「锯齿」不是一个必须消灭的坏事： 它是「学习率用得很满」的外在表现。 看到锯齿，意味着你正走在稳定边界的边缘： 再想提高 lr 已经没有空间，要更快只能改问题本身（换坐标、上动量）

    8.1 为什么深度学习不用牛顿法¶

    前面已经算过：牛顿法一步的运算量是 O(n³)，梯度下降是 O(n²)。 把这条结论放到真实规模上：

    场景 参数量级 牛顿法每步运算量 可行吗
    本页实验 20 8e3 完全可行 ✓
    小型回归 1e3 1e9 勉强可行
    中等模型 1e6 1e18 不可能 ⚠
    大模型 1e9 1e27 完全不可能 ⚠

    除了运算量，还有四个更硬的障碍：

    障碍 说明
    Hessian 存不下 n × n 个浮点数：n = 1e6 时需要 1e12 个数，约 8 TB ⚠
    算不出来 二阶导有 n² 个，反向传播只算一阶就已经很贵了 ⚠
    不正定 非凸问题的 Hessian 可能不正定，H⁻¹ 给出的不是下降方向 ⚠
    随机梯度 每次只看一小批样本，H 的估计噪声极大 ⚠

    所以工程上的选择是：保留牛顿法的想法（利用曲率信息加快收敛）， 放弃它的做法（显式构造并求逆 Hessian）。 准牛顿法（如 BFGS）用「历史梯度差」逼近 H⁻¹， 省掉了二阶导，但内存仍是 O(n²)； 到了大模型连这个都受不了，只能回到一阶方法加一堆技巧

    这就是「知道原理」和「知道怎么用」的分界： 原理告诉你「曲率信息有用」， 工程约束告诉你「不能直接用它」， 中间的每一层折中，都是在两个事实之间找位置

import numpy as np

from gd_lab import make_A


def gd_decay(A, x0, lr0, decay, tol=1e-6, max_steps=100000):
    """学习率按 lr0 / (1 + decay * k) 逐轮衰减。"""
    x = np.array(x0, dtype=float)
    scale = float(np.linalg.norm(x))
    errs = [1.0]
    for k in range(1, max_steps + 1):
        lr = lr0 / (1.0 + decay * k)
        x = x - lr * (A @ x)
        e = float(np.linalg.norm(x)) / scale
        errs.append(e)
        if not np.isfinite(e) or e > 1e12:
            return errs, {"iters": None, "status": "发散", "ran": k}
        if e <= tol:
            return errs, {"iters": k, "status": "已收敛", "ran": k}
    return errs, {"iters": None, "status": "未收敛", "ran": max_steps}

    正确的顺序：先诊断条件数（是不是量纲不一致导致的）， 能通过标准化修的就标准化； 标准化之后剩下的病态，才交给调度与自适应方法

import numpy as np
from scipy.optimize import minimize


def condition_number(A):
    """对称正定矩阵的条件数（最大/最小特征值之比）。"""
    ev = np.linalg.eigvalsh(A)
    return float(ev.max() / ev.min())


def standardize(A, b):
    """对角预条件：让 A 的对角元全部变成 1。

    返回缩放后的 (A', b') 与坐标变换矩阵 D。
    这一步只会改善「量纲不一致」造成的病态，不会消除相关性。
    """
    d = np.diag(A)
    D = np.diag(1.0 / np.sqrt(d))
    return D @ A @ D, D @ b, D


def lam_bounds(A):
    """最小与最大特征值（对称正定矩阵）。"""
    ev = np.linalg.eigvalsh(A)
    return float(ev.min()), float(ev.max())


def run_experiment(A, b, lr=None, tol=1e-6, max_steps=200000):
    """跑一次梯度下降；返回 (解, 记录)。lr 为 None 时按 1/lam_max 估。"""
    lam_min, lam_max = lam_bounds(A)
    lr = (1.0 / lam_max) if lr is None else lr
    log = {"条件数": round(condition_number(A), 4),
           "lam_min": round(lam_min, 4),
           "lam_max": round(lam_max, 4),
           "稳定上界": round(2.0 / lam_max, 4),
           "学习率": round(lr, 6)}

    x = np.zeros_like(b)
    x_star = np.linalg.solve(A, b)
    history = []
    k = 0
    for k in range(1, max_steps + 1):
        x = x - lr * (A @ x - b)
        err = float(np.linalg.norm(x - x_star))
        history.append(err)
        if err <= tol:
            log["达到容差于第几步"] = k
            break
    log["最终误差"] = "%.3e" % err
    log["迭代步数"] = k
    log["误差单调下降"] = bool(np.all(np.diff(np.array(history)) <= 0))
    return x, log

import numpy as np


def run_quad(x0, lr, steps=300):
    """二次函数 f = x^2/2：梯度 x，Hessian 恒为 1 ⇒ 上界 2/1 = 2。"""
    x = float(x0)
    for _ in range(steps):
        x = x - lr * x
        if not np.isfinite(x) or abs(x) > 1e6:
            return float("nan")
    return x


def run_quart(x0, lr, steps=300):
    """非二次函数 f = x^4/4 + x^2/2：梯度 x^3+x，Hessian = 3x^2+1。"""

    for _ in range(steps):
        x = x - lr * (x ** 3 + x)
        if not np.isfinite(x) or abs(x) > 1e6:

    return x

import numpy as np

from gd_lab import gd

TOL = 1e-6
lam = np.linspace(1.0, 1000.0, 20)

# 情形 A：对角矩阵，「两个方向的量纲」差了 1000 倍
A_diag = np.diag(lam)
n_diag = gd(A_diag, np.ones(20), lr=1.0 / lam.max(), tol=TOL)[3]["iters"]
print("情形 A（对角，条件数 %s）: GD 需要 %d 步"
      % (round(float(np.linalg.cond(A_diag)), 4), n_diag))

D = np.diag(1.0 / np.sqrt(np.diag(A_diag)))    # 让对角元全部变成 1
A_s = D @ A_diag @ D
n_s = gd(A_s, D @ np.ones(20),
         lr=1.0 / float(np.linalg.eigvalsh(A_s).max()), tol=TOL)[3]["iters"]
print("  对角缩放后：对角元全为", bool(np.allclose(np.diag(A_s), 1.0)),
      "，条件数", round(float(np.linalg.cond(A_s)), 4))
print("  → 缩放后 %d 步，加速 %s 倍" % (n_s, round(n_diag / n_s, 4)))

print()
# 情形 B：把同一个对角矩阵旋转一下，特征值一个都没变
rng = np.random.default_rng(0)
Q, _ = np.linalg.qr(rng.normal(size=(20, 20)))
A_rot = Q @ np.diag(lam) @ Q.T
n_rot = gd(A_rot, np.ones(20), lr=1.0 / lam.max(), tol=TOL)[3]["iters"]
print("情形 B（旋转，特征值完全相同，条件数 %s）: GD 需要 %d 步"
      % (round(float(np.linalg.cond(A_rot)), 4), n_rot))

D2 = np.diag(1.0 / np.sqrt(np.diag(A_rot)))
A_r2 = D2 @ A_rot @ D2
n_r2 = gd(A_r2, D2 @ np.ones(20),
          lr=1.0 / float(np.linalg.eigvalsh(A_r2).max()), tol=TOL)[3]["iters"]

    例题 3：学习率衰减能不能救回发散的训练¶

    题目：正文实验一里，lr = 0.21 直接发散。 如果在训练过程中让学习率逐渐变小，能不能把这个设置救回来？ 请实测并说明：什么样的发散能救，什么样的救不回来。

    思路

    注意两个事实：

    1. 发散是每步放大造成的，而放大的倍数取决于当前的学习率。
    2. 衰减是渐进的：第 k 步的学习率是 lr0 / (1 + decay·k)。

    把这两件事放在一起想：如果第一步就放大得足够多， 后面衰减到安全值还来得及吗？

    实测时至少要试三档起始学习率（略超、超 50%、超 150%）， 每档再配两档衰减系数，才能看出边界在哪。

    0.30 150% 发散 ⚠ 发散 ⚠ 收敛（115 步）✓
    0.50 250% 发散 ⚠ 发散 ⚠ 发散 ⚠

    关键数字是衰减后第 1 步的学习率：

    起始 lr decay = 0.01 时第 1 步的 lr 与上界 0.2 之比 结果
    0.21 0.21 / 1.01 = 0.2079 1.04 倍 收敛 ✓
    0.30 0.30 / 1.01 = 0.2970 1.49 倍 仍要更多步衰减

import numpy as np

from gd_lab import make_A


def gd_exact(A, x0, tol=1e-6, max_steps=200000):
    """每步用解析最优步长 eta* = (g'g)/(g'Ag) 走。"""
    x = np.array(x0, dtype=float)
    scale = float(np.linalg.norm(x))
    errs, etas = [1.0], []
    for k in range(1, max_steps + 1):
        g = A @ x
        eta = float(g @ g) / float(g @ (A @ g))
        x = x - eta * g
        etas.append(eta)
        e = float(np.linalg.norm(x)) / scale
        errs.append(e)
        if e <= tol:
            return errs, etas, {"iters": k, "status": "已收敛"}
    return errs, etas, {"iters": None, "status": "未收敛"}


def gd_fixed(A, x0, lr, tol=1e-6, max_steps=200000):
    """固定步长版本，用作对照。"""
    x = np.array(x0, dtype=float)
    scale = float(np.linalg.norm(x))
    errs = [1.0]
    for k in range(1, max_steps + 1):
        x = x - lr * (A @ x)
        e = float(np.linalg.norm(x)) / scale
        errs.append(e)
        if e <= tol:
            return errs, {"iters": k}
    return errs, {"iters": None}

    tol 步数 比上一行增加
    1e-2 30 ——
    1e-3 52 +22
    1e-4 74 +22
    1e-6 117 +22（跨两位 → +43，即两次 +21.5）
    1e-9 183 +22 / 每十进制位

    每一步都是 +22 左右，是一个常数： 从 1e-2 到 1e-9 跨了 7 个数量级， 步数从 30 涨到 183 —— 增加了 153 步，153 / 7 ≈ 21.9

    理论推导：误差按 errs[k] ≈ ρ^k 衰减， 要 errs[k] ≤ tol，就要：

    1

    ρ^k ≤ tol
k · ln(ρ) ≤ ln(tol)              （ρ < 1，ln ρ < 0，两边除以它要变号）
k ≥ ln(tol) / ln(ρ)

    k 与 ln(tol) 是线性关系 —— 这就是常数增量的来源：

    规律 表达式 本页的值
    每缩小 10 倍需要的额外步数 ln(10) / \|ln ρ\| 2.3026 / 0.1054 ≈ 21.85 ✓
    只与收敛因子有关 与 tol 的具体值无关 ✓ ——
    与条件数的关系 ρ = 1 - 1/κ，κ 越大这个常数越大 κ = 1000 时约 1100 步/位 ⚠

    理论值与实测值对得上：21.85 与实测的约 22 只差 0.15 步， 而且表里四个「差值」都是 14～15 —— 说明理论模型在这个问题上是准确的

    为什么表里的「差值」是常数 14～15： 那是「理论上界」与「实测步数」的差， 来自「实测用的是全方向误差范数、理论上界用的是最坏方向」这个口径差（5.1 节解释过）。 它也是常数，同样印证了模型正确

    这条规律在工程上怎么用：

    你要做的事 代价
    把收敛精度提高 1 位（如 1e-4 → 1e-5） 固定多约 22 步 ✓
    提高 3 位 固定多约 66 步 ✓
    在条件数差的问题上提高 1 位 代价同步放大（κ 越大，每位的步数越多）⚠

    好消息是「代价是线性的」： 精度每加一位只多一个固定的步数，不会指数爆炸。 坏消息是这个「固定值」本身与条件数挂钩 —— κ = 1000 时每提高一位要多上千步
