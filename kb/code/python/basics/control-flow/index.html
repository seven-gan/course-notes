    07 条件与循环¶

    前面六页讲的是「数据怎么存」，从这一页开始讲「程序怎么动」。

    到上一页为止，你写的代码都是从上往下一路平推的：第一行做完做第二行， 第二行做完做第三行，一行不落、一行不跳。真实的程序不能这样 —— 它必须能根据情况选择走哪条路，也必须能把同一段逻辑重复执行很多遍。

    这两件事分别叫条件（branch）与循环（loop）， 它们加上顺序，就是结构化程序设计里的全部三种控制结构。

    这一页学完，你将能够：

    能力 具体表现
    让程序做选择 用 if / elif / else 写出多分支判断，并排对分支顺序
    看懂「真假」 说清 0、""、[]、None 为什么是假，不再被空值坑到
    写出安全的判断 用链式比较与短路求值，避免「先取下标再判空」这类崩溃
    重复执行 用 while 与 for 覆盖「次数已知」和「次数未知」两类场景
    优雅地遍历 用 enumerate / zip / reversed / sorted 代替手写下标
    提前结束与跳过 分清 break / continue / pass，并会用 for...else
    写得更快 用 sum / max / any / all 换掉手写累加循环

    这页最容易搞错的三件事

    第一件：真值判断不是「必须写 == 0」。

    Python 允许直接把任何值放进条件位置，if data: 与 if len(data) > 0: 都能判断列表非空。但两者的适用边界不同 —— 关键在于 「0 或空串在你的业务里算不算合法数据」。

    第二件：and / or 返回的不是布尔值。

    1
2
    1 and 2      → 2        （不是 True）
"" or "默认" → '默认'    （不是 True）

    它们返回的是某个操作数本身。「返回布尔值」的只有 not。

    第三件：循环里的 else 不是「否则」。

    for...else 的 else 意思是「循环没有被 break 中断，正常走完了」， 与循环前面的 if 没有任何关系 ✓

    一、为什么需要它¶

    没有条件与循环会怎样¶

    假设要处理一批成绩，做三件事：给每条成绩分级、找出最高分、统计及格人数。

    如果代码只能顺序执行，你唯一能做的重复手段就是复制粘贴：

    1
    判断第 1 条成绩……复制一份判断第 2 条……再复制一份判断第 3 条……

    这段代码有三个致命问题：

    问题 后果
    数据条数一变就要改代码 从 50 条变成 5000 条，代码没法用 ✗
    修改规则要改很多处 及格线从 60 改成 70，漏改一处就是静默错误 ✗
    逻辑稍复杂就写不下去 「一直读直到读完整个文件」根本没法用复制粘贴表达 ✗

    条件与循环把「重复」从「手工复制」变成「语法结构」。 有了它们，「对每条数据做同一件事」只需要写一遍：

    两种循环各管一类问题¶

    循环 什么时候用 判断依据
    for 遍历一个已有的集合（列表、字符串、字典、文件……） 「对每个元素做一次」
    while 重复到某个条件不再成立 「还不知道要做几次」

    判断依据只有一句话： 「我是在遍历一堆东西，还是在等一个条件变假？」

    • 遍历一堆东西 → for
    • 等条件变假 → while

score = 78

    这段代码有三个必须记住的语法点：

    语法点 规则 为什么
    冒号 每个 if / elif / else 后面都要有 : 冒号表示「条件写完了，下面是它的身体」
    缩进 属于这个分支的语句要统一缩进 Python 用缩进表示从属关系，不用大括号
    elif 不是 else if 写成一个词，不带空格 Python 的固定关键字

    if / elif / else 三者最多只有一个分支会执行， 且执行的是从上往下第一个条件为真的那个。

    2.3 多分支是有顺序的：第一个为真的胜出¶

    这是条件语句最容易被忽视、后果又最严重的一点。

    elif 不是「所有条件都检查一遍再挑最好的」， 而是从上往下依次检查，命中第一个就执行并跳出整条链。 所以分支的顺序本身携带语义。

# ✗ 顺序写反：第一个条件太宽松，后面的分支永远轮不到
if score >= 60:
    print("先命中「及格」")
elif score >= 90:
    print("这一行永远执行不到")

# ✓ 从严格到宽松排列
if score >= 90:
    print("先命中「优秀」")
elif score >= 60:
    print("只有 60 ~ 89 才会到这里")

    先命中「及格」
先命中「优秀」

    看第一个版本：95 确实大于等于 60，所以第一个分支被命中并执行， elif score >= 90 连检查的机会都没有 —— 它写成 elif score > 100 也一样，因为它永远不会被求值。

    判断依据： 多分支的区间必须「互斥」，而互斥要靠排序实现。

    场景 正确顺序 原因
    分数分档 从高分到低分 ✓ 高分条件更严格，必须排在前面
    折扣分档 从大折扣到小折扣 ✓ 同上
    错误码匹配 从具体到宽泛 ✓ 先匹配特例，再用兜底
    类型分发 从子类到父类 ✓ 子类更具体，先判它

    反过来的写法是：每个条件都写全区间。

    写法 优点 缺点 什么时候选
    只写下界 + 排序 简短，改边界时只改一处 ✓ 依赖顺序，打乱就出错 ⚠ 分档类似、边界连续
    写全上下界 顺序无关，自解释 ✓ 边界值要写两遍，容易写不一致 区间相互独立、可能重叠

    elif 里的条件要写在「前面所有分支都不成立」的前提下

    三、真值判断：哪些值是「假」¶

    这一节是整页最"反直觉"、也最有工程价值的部分。

    把任意值放进 if 的位置，Python 都会先把它转成布尔值。 问题在于：转换规则里，非 False 的值也可能是「假」。

    3.1 用 bool() 逐个验证¶

    bool(x) 就是那个转换函数 —— 它是查看真值的唯一权威手段， 不要靠猜，直接跑一遍。

    「假」的规律只有三条，背下来就够用了：

    规律 覆盖的对象 例子

    容器长度为零 所有容器类型 ""、[]、{}、()、set()、range(0)
    它就是 None 空值对象 None
    （特例）False 布尔类型本身 False

    除了这三类，其余一切值都是「真」 —— 这一点比上面更重要， 因为真正会坑人的是「看起来像假、其实是真」的那些。

    5.2 返回值规则：and / or 不是「布尔运算」¶

    这是初学者最常踩的一个认知坑：and / or 的返回值不是布尔值， 而是参与运算的某个操作数本身。

    表达式 结果 规则
    1 and 2 2 左边为真 → 返回右边
    1 and 0 0 左边为真 → 返回右边
    0 and 2 0 左边为假 → 返回左边
    0 or 2 2 左边为假 → 返回右边
    "" or "默认值" '默认值' 左边为假 → 返回右边
    "有值" or "默认值" '有值' 左边为真 → 返回左边
    not 0 True 只有 not 真的产出布尔值

    一句话总结：

    • and：遇到假就返回它；一路为真则返回最后一个操作数
    • or：遇到真就返回它；一路为假则返回最后一个操作数

    写成公式就是：

    1

    写 while 时，必须能指出「哪一行让条件最终变假」

    如果指不出来，那它就是死循环（infinite loop） —— 程序会一直转下去，直到你强制中断。

    下面就是「忘了更新 i」的死循环。 它加了安全计数器 guard，转够 3 圈就主动退出 —— 否则这一段会一直跑下去，页面验证也会卡死：

     1

# 直接跑会一直转下去，所以加一个安全计数器 guard，
# 转够 3 圈就主动退出 —— 验证脚本也就不会超时。

    print(f"第 {guard} 轮：i 还是 {i}（它从没被更新过）")

    2. 哪一行会改这些变量？
    3. 改了以后，条件真的可能变假吗？（例如 i *= 2 从 0 开始就永远出不去 ✗）

    七、for 循环与可迭代对象¶

    7.1 for 不数数，它「遍历」¶

    很多人把 for 当成「计数循环」。Python 的 for 不是 —— 它是遍历循环：

    1
2
    for 变量 in 可迭代对象:
    循环体

    每一轮，把「可迭代对象」给出的下一个元素赋给变量，然后执行循环体。

    要理解 for，必须先理解可迭代对象（iterable）： 只要一个对象能「一个接一个地给出它的元素」，它就是可迭代的。

    可迭代对象 每一轮拿到什么
    列表 每一项
    元组 每一项
    字符串 每个字符
    字典 每个键（不是键值对）⚠
    集合 每个元素（顺序不固定）⚠
    文件对象 每一行（含行尾换行符）⚠
    range 每个整数
    生成器 按需算出的每个值

    这张表解释了 for 的威力： 同一套语法能遍历这么多不同的东西，因为它们遵守同一个约定。 所以后面学新类型时，你只要问一句「它可迭代吗」， 就立刻知道能不能用 for ✓
