    一、为什么把「数字」单独作为一页¶

    很多人觉得数字是最简单的东西 —— 加减乘除，谁不会？

    问题在于：Python 里的数字有两套完全不同的实现机制。

    类别 例子 存储方式 特点
    整数 int 42 任意精度（要多长有多长） 精确，永远不会溢出
    浮点数 float 3.14 固定 64 位二进制（近似表示） 快，但不精确

    这两套机制的存在，直接导致了下面前三种「反直觉」：

    1
2
3
    整数精确 → 所以 2 ** 100 能算出一个 31 位的大数
浮点近似 → 所以 0.1 + 0.2 得不到 0.3
两者混用 → 所以 7 / 2 一定得到浮点数 3.5，而不是整数

    还有第四种反直觉在等着你：True 居然能当数字用 —— True + True 等于 2。

    它看起来荒谬，但它是上面那张表的一个直接推论，也是理解 「Python 里类型关系」的绝佳入口。这一页会把它讲清楚。

    这一页的正确用法¶

    不要背结论。这一页里每个结论后面都跟着一段可运行的代码和它的真实输出。 建议的做法是：

    1. 先看结论，猜一下输出会是什么
    2. 再往下看真实输出，对一下自己的猜测
    3. 猜错的地方就是你要重点记的地方

    二、三种数值类型¶

    Python 内置三种数值类型。它们都是类（class）， 创建出来的值就是这些类的实例。

    类型 中文名 字面量写法 例子
    int 整数 直接写数字 42、-7、0
    float 浮点数（小数） 带小数点，或带指数 3.14、1e20、2.0
    complex 复数 数字后跟 j 2 + 3j、1j

    三个小细节

    • float 的字面量必须带小数点或指数：2 是整数，2.0 才是浮点数。 这两个值在数学上相等，但在 Python 里是不同的类型。
    • 虚数单位写成 j 而不是 i：1j 就是一个虚数单位。 这一点沿用了工程（电气）领域的习惯，因为 i 常被用作循环变量。
    • 整数没有小数部分也照样精确：10 ** 20 是精确的， 而 1e20 只是一串浮点近似值的十进制显示。

    2.1 判断类型的三种写法¶

    写法 得到 什么时候用
    type(x) 类型对象本身，如 <class 'int'> 打印出来给调试看
    type(x).__name__ 类型名字符串，如 'int' 拼进提示信息里最方便
    isinstance(x, int) True / False 判断「是不是某类」的首选

    为什么优先用 isinstance 而不是 type(x) is int： isinstance 会顺着继承关系往上找，而 type(x) is int 要求类型完全一致。 马上要讲的 bool 就是最好的例子 —— 它是 int 的子类， 于是 isinstance(True, int) 是 True，而 type(True) is int 是 False。

    __mro__ 是「方法解析顺序」（method resolution order）， 它列出了查找一个方法时依次经过的类。 bool 找到的第一个父类就是 int —— 这就是「bool 是 int 的子类」的直接证据。

    这个特性带来的实用写法：

    1
    count = sum(x > 0 for x in values)     # 数有几个正数

    x > 0 的取值就是 True / False，求和时自动当 1 / 0 用 —— 一句话完成「条件计数」，不需要写 if 累加。这是 Python 里非常常见的写法。

    「能当数字用」不等于「应该当数字用」

    True 能算成 1，但不要真的这么写。对比一下：

    写法 评价
    total = total + is_valid ✗ 读代码的人要停下来想「is_valid 是数字还是开关」
    if is_valid: 判断，再 total += 1 ✓ 意图清楚

    判断依据：True 当数字用只在两种场合可接受 —— 一是「条件计数」（sum(条件 for ...)），二是与 int 相关的位运算。 其他地方老老实实用 if。

    同样注意反向的坑：bool 只认「空」与「零」为假。

    值 bool(值) 容易误判的地方
    0、0.0、0j False 数值零为假
    ""、[]、{} False 空容器为假
    None False 空值为假
    "0" True 非空字符串永远为真，即使内容是 0
    "False" True 同上，字符串内容不影响真假
    -1 True 只要不是 0，无论正负都是真

    最后三行是最常踩的：从文件或键盘读进来的是字符串， bool("0") 得到 True，bool("False") 也得到 True。 要判断「用户填的数是不是零」，必须先转成数字：

    1
2

    4.1 结合性：2 ** 3 ** 2 到底怎么算¶

    「结合性」指同一优先级的运算符，从哪一头开始算。

    运算符 结合性 验证
    ** 右结合（从右往左） 2 ** 3 ** 2 等于 2 ** (3 ** 2) 等于 512
    + - * / // % 左结合（从左往右） 10 - 3 - 2 等于 (10 - 3) - 2 等于 5

    为什么幂要反着来：数学上的乘方记号 a^b^c 通常理解为 a^(b^c)， Python 沿用了这个惯例。

    建议：像 2 ** 3 ** 2 这种写法一律加括号 2 ** (3 ** 2)。 少打两个字符，换来的可读性非常划算 —— 读代码的人不需要停下来回忆结合性。

    4.2 一元负号的位置很讲究¶

    一元负号（-x）与减法用的是同一个符号，所以有些写法会让人看错：

    写法 读作 建议
    -x 取 x 的相反数 正常写法
    a - -b a 减「负 b」 ✗ 别看错成 a - b，写成 a - (-b) 或 a + b
    -2 ** 2 -(2 ** 2) 等于 -4 ✗ 极易看错，注意下一节的优先级表

    结论：一元负号和幂混在一起时，一定加括号把意图写清楚。

    5.2 规则二：% 的符号跟随「除数」¶

    这是最反直觉的一条，但也是最好记的一条：

    表达式 除数符号 余数 余数符号

    -7 % -2 负 -1 负

    余数的符号永远与除数的符号一致，与被除数的符号无关。

    为什么必须这样：为了让下面这个恒等式永远成立：

    1
    a = (a // b) * b + (a % b)

    上面的输出里，四组数都打印了 -> True，说明这个等式在四种符号组合下都不破。 如果 % 的符号跟着被除数走，这个恒等式就会失效。 Python 选择了保住恒等式 —— 因为很多算法依赖它。

    附带结论（也很好用）：既然符号跟着除数走，那么 x % n 的结果一定落在 0 到 n - 1 之间（n 为正数时）。 这正是「取余」在编程里最常用的场景：把任意整数折进一个固定范围。

    6.1 原因：十进制小数无法用二进制精确表示¶

    问题的根源只有一句话：我们写的是十进制，机器存的是二进制。

    十进制的 0.1 表示「十分之一」。而在二进制里，小数位分别是 1/2、1/4、1/8、1/16…… 用这些分数的和去拼 1/10， 永远拼不精确，只能无限逼近：

    1

    float 只有 64 位，存不下无限循环的二进制小数， 于是在第 53 个有效位处被截断 —— 这就是误差的来源。

    12.1 nan != nan —— 必须记住的陷阱¶

    看第 2 行输出：

    表达式 结果 说明
    nan == nan False nan 不等于它自己！

    这不是 Python 的 bug，而是 IEEE 754 浮点标准的规定： nan 表示「一个未知的数值结果」。 既然不知道第一个 nan 是什么数、第二个 nan 又是什么数， 就不能说它们相等。

    这个规定的直接后果：

    写法 结果 评价
    x == x 判断「不是 nan」 能用 太隐晦，不推荐
    math.isnan(x) True / False ✓ 唯一推荐的写法
    x == float("nan") 永远 False ✗ 写错了也发现不了
    x != x 判断「是 nan」 能用 可读性差

    另外注意第 7 行：nan in [nan] 得到 True，[nan] == [nan] 也得到 True。 为什么 == 在列表里又成立了： 列表的相等判断是先比长度，再逐个用「同一性」快速通道比较元素 —— 同一个 nan 对象会被判定为「同一个东西」，于是相等。

    结论：nan 的相等判断在不同容器里有不同表现， 不要依赖它。判断 nan 一律用 math.isnan()。

def to_base(n, base):
    """把整数 n 转成 base 进制字符串（base 取 2 到 36）。"""
    if n == 0:
        return "0"
    sign = "-" if n < 0 else ""
    n = abs(n)
    out = []
    while n > 0:
        n, r = divmod(n, base)
        out.append(DIGITS[r])
    return sign + "".join(reversed(out))

print("负数:", to_base(-255, 16))

    比较会静默失效 if x > 阈值: 遇到 nan 直接跳过，数据悄悄丢失

    处理含 nan 数据的标准流程：

    步骤 做法
    1. 检测 math.isnan(x)（数组用 numpy.isnan）
    2. 决策 丢掉、填 0、填均值/中位数
    3. 再统计 绝不留着 nan 去求和或取平均

    顺带认识另一个特殊值：math.isinf(x) 判断是否无穷大。 浮点溢出不会报错，只会变成 inf 并一路传播 —— 所以计算完成后主动检查一次 isinf / isnan， 比事后对着一个奇怪的最终结果反推要快得多 ✓

    小结¶

    要记住的 为什么
    bool 是 int 的子类 所以 True + True == 2，isinstance(True, int) 为真
    / 的结果一定是浮点 即使 8 / 2 也得到 4.0
    // 是向下取整 所以 -7 // 2 是 -4，不是 -3
    % 的符号跟随除数 为保住 a = (a // b) * b + (a % b) 恒成立
    divmod(a, b) 一次拿到商与余数；时间换算、进制转换都靠它
    0.1 + 0.2 不等于 0.3 十进制小数在二进制里是无限循环，只能截断近似
    浮点比较用 math.isclose 精确比较 == 在浮点上是不可用的
    比零要加 abs_tol 相对容差在接近 0 时失效
    round() 是银行家舍入 round(0.5) 得 0、round(2.5) 得 2
    金额用 decimal.Decimal 必须用字符串构造，并显式写 ROUND_HALF_UP
    int 没有上限 2 ** 100、100! 都精确；溢出的是 float
    float 溢出成 inf 且不报错 所以要用 math.isinf 主动检查
    nan != nan 为真 判断一律用 math.isnan()；nan 会污染求和
    0b / 0o / 0x 与 bin / oct / hex 字面量与函数成对；f-string 的 :b :x 不带前缀
    int() 向零截断，math.floor() 向下取整 正数相同，负数不同，这是隐藏 bug 的高发区
    int("3.5") 报 ValueError 先 float() 再 int()；脏数据先清洗再转换
    ** 右结合且优先级高于一元负号 -2 ** 2 是 -4；拿不准就加括号
    不确定就打印 print(repr(x), type(x).__name__) 能解决绝大多数「数算错了」
    出错时先分层 先看类型对不对（TypeError），再看值合不合法（ValueError）
