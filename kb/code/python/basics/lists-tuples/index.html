    05 列表与元组¶

    这一页解决一个问题：把「一堆数据」当成一个整体来管理。

    前面几页里，一个变量只能装一个值。可是真实的数据几乎从不只有一个： 一次实验测了 8 个温度、一份名单有 40 个名字、一段轨迹有上万个坐标。 没有「容器」就没法写程序 —— 你不可能给每个温度都起一个名字。

    这一页学完，你将能够：

    能力 具体表现
    建与取 用 4 种方式造出列表，用下标和切片拿到任意一段
    增删改查 记住 append / extend / insert / remove / pop / del 各自干什么
    排序 分清 sort() 与 sorted()，会用 key 做多级排序
    看穿引用 知道 b = a 不是复制，分清浅拷贝与深拷贝
    选对类型 知道什么时候该用列表，什么时候该用元组

    这页的重点

    最容易踩的两个坑，都和「到底是同一个对象，还是新对象」有关：

    坑 后果
    b = a 以为复制了一份 改 b 把 a 也改了，还不报错
    lst.sort() 以为返回排好序的列表 拿到的是 None，后面全崩

    第二个坑的麻烦之处在于：它不在这里报错，而是在很远的后面才报错。 所以这一页会反复用 is、id()、type() 把这些「看不见的关系」显形

    一、为什么需要它¶

    1.1 没有容器会怎样¶

    假设你要记录一周每天的最高气温。用已学的知识，只能这样写：

    1
2
3
    temp_mon = 26.5
temp_tue = 27.1
temp_wed = 25.8

    三天还行，三十天就写不下去了。更致命的是没法循环处理：

    1
2
3
    想算平均值 → 要把 30 个变量名都列出来相加   ✗ 又长又容易漏
想找最大值 → 只能两两比较，写一大串 if      ✗
想排序     → 根本没地方存排序结果           ✗

    问题的根源不是「数据太多」，而是数据没有被组织成一个整体。 列表要解决的正是这件事：用一个名字，管住一组有顺序的数据。

    1.3 列表和元组差不多，为什么还要两个¶

    这是初学时的共同困惑。一句话回答：

    类型 一句话定位
    列表 「会变的清单」 —— 记录会增删改的数据，如待办、采样点、结果集
    元组 「一次定型的记录」 —— 描述一个不再改动的组合，如坐标 (3, 4)、一行固定记录

    选择依据不是「哪个更快」，而是语义：这份数据在程序运行中该不该被改。 讲完列表的全部操作之后（第九节），我们会把两者的取舍讲透。

    四条写法的分工：

    写法 什么时候用
    [] 手写已知的少量元素，或先建空列表待填
    list(可迭代对象) 把别的东西转成列表（字符串、元组、range、字典的键…）
    list(range(n)) 造 0 到 n-1 的整数序列
    推导式 由已有数据批量算出新元素（本页第十二节会用到）

    list("abc") 得到的是字符列表，不是单词列表

    这是中文使用者最容易误会的一处：

    1
2
    print(list("abc"))
print(list("苹果"))

    ['a', 'b', 'c']
['苹', '果']

    它按「字符」拆，不是按「词」拆 —— list("苹果") 得到两个汉字元素，而不是一个 "苹果"。

    想要 ["苹果"] 就直接写 ["苹果"]； 想把一句话按空格拆成词，要用字符串的 split（第 04 页讲过）：

    1
2
3
    text = "红苹果 绿香蕉 黄柠檬"
print(text.split())          # 按空白拆：得到「词」
print(list(text))            # 按字符拆：得到「字」

    ['红苹果', '绿香蕉', '黄柠檬']
['红', '苹', '果', ' ', '绿', '香', '蕉', ' ', '黄', '柠', '檬']

    三种常见的 key 写法：

    写法 排序依据 典型场景
    key=len 元素的长度 按词长排、按列表长度排

    key 里能写什么

    key 要的是一个参数的函数。三种给法都可以：

    1

    key 也能直接用内置函数，比如 abs（取绝对值）： 这解决的是「不看正负号，只比大小」的排序需求。

    key 参数可以直接用的三种东西

    写法 什么时候用 例子

    lambda x: ... 规则要临时写一个表达式 key=lambda x: x[1] ✓
    命名函数 规则复杂、要复用或测试 def score_of(s): ... → key=score_of

    判断依据： 能用现成的内置函数就别写 lambda —— key=abs 比 key=lambda x: abs(x) 更短、更快、意图更清楚

    「可哈希」到底是什么：能算出一个在程序运行期间不变的整数（哈希值）， 从而可以放进字典或集合这种「按下标查找」的结构里。

    类型 可变吗 可哈希吗 能当字典的键吗
    int / float / str 不可变 可哈希 能 ✓
    tuple（元素都可哈希） 不可变 可哈希 能 ✓
    list 可变 不可哈希 不能 ⚠
    dict / set 可变 不可哈希 不能 ⚠

    规律：不可变的才能哈希。因为键必须在「放进字典之后保持不变」， 否则就再也找不回来了

    12.1 [[0] * 3] * 2 的共享引用问题¶

    写法 内层是否共享 能用吗
    [[0] * 3] * 2 共享 ⚠ 只读浏览可以，一改就错
    [[0] * 3 for _ in range(2)] 各自独立 ✓ 推荐
    [0] * 3（一维） 元素是数字，不可变 安全 ✓
    [[]] * 3 共享 ⚠ 危险

    为什么 4 会漏掉？ 因为遍历用的是内部下标：

    1

3
4

                    ↑ 下标 1 现在指向 3，于是 4 被跳过了 ⚠

    删掉一个元素会让后面所有元素前移一位， 而遍历的下标照常加一 —— 于是紧跟在被删元素后面的那个被跳过 ✗

    两种正确写法：

    1

    if x % 2 == 0:
        nums.remove(x)

    遍历副本后: [1, 3, 5]

    1

    nums = [1, 2, 3, 4, 5, 6]

# 写法二：列表推导式重建（更推荐，一行完成，意图清楚）

    推导式重建后: [1, 3, 5]

    1

3
4
5
6
7
    nums = [1, 2, 3, 4, 5, 6]

# 写法三：倒着遍历（下标从大到小，删元素不影响还没访问的下标）
for i in range(len(nums) - 1, -1, -1):
    if nums[i] % 2 == 0:
        del nums[i]
print("倒序遍历后:", nums)

    倒序遍历后: [1, 3, 5]

    三种写法的取舍

    写法 优点 缺点 什么时候用
    列表推导式重建 一行、意图清楚、最快 需要额外一份内存 默认首选 ✓
    遍历副本 for x in nums[:] 保留原列表对象（别名也生效） 要额外复制一份 别处还持有这个列表的引用时
    倒序遍历删 不额外占内存 下标容易写错 数据很大、内存紧张时

    判断依据：如果别的地方还拿着这个列表对象（比如字典里存了它）， 就不能用「重建」，要用「遍历副本」或「倒序删」 —— 因为重建会把列表换成另一个对象，原来持有它的人看到的还是旧数据

    例题 1：为什么列表变成了「列表套列表」¶

    下面的代码想把 [3, 4] 加进 data，让 data 变成 [1, 2, 3, 4]， 但结果不对。找出原因并给出两种修法。

    1
2
3
4
    data = [1, 2]

print("结果:", data)
print("长度:", len(data))

    结果: [1, 2, [3, 4]]
长度: 3

    思路

    看看 append 到底把什么塞进去了。被塞进去的东西是一个元素， 还是一批元素？想一想哪个方法的作用是「把元素逐个加进去」。

    解答

    原因：append 的作用是「在末尾追加一个元素」。 传进去的 [3, 4] 被当成一个整体，于是 data 变成 [1, 2, [3, 4]] —— 长度只增加了 1，最后一个元素是一个列表 ✗

    修法一：改用 extend（追加一批）

    1
2
3
4
    data = [1, 2]
data.extend([3, 4])
print("extend 的结果:", data)
print("长度:", len(data))

    extend 的结果: [1, 2, 3, 4]
长度: 4

    修法二：用 + 拼出新列表

    1
2
3
4
    data = [1, 2]
data = data + [3, 4]
print("相加的结果:", data)
print("长度:", len(data))

    相加的结果: [1, 2, 3, 4]
长度: 4

    两种修法的差别：

    修法 原列表对象 适用
    data.extend([3, 4]) 不变（原地扩展） 别处还持有 data 的引用时 ✓
    data = data + [3, 4] 换成了新对象 需要保留旧数据时

    判断依据：append 与 extend 的区别不在参数类型， 而在「参数是被当成一个元素，还是被摊开成若干元素」

    例题 2：多级排序¶

    给定一批学生成绩，要求按分数从高到低排；分数相同时按姓名升序排。请写出排序代码。

    1
    students = [("小明", 90), ("小红", 85), ("小刚", 90), ("小丽", 85), ("小安", 60)]
    思路

    两个关键字：分数要降序，姓名要升序。 但 reverse=True 会把两个关键字一起反转。 能不能让 key 返回一个元组，同时把「降序」这件事塞进 key 里？

    解答

    思路：让 key 返回 (-分数, 姓名) 这个元组。 分数取负号之后，「分数大的」就变成「负数小的」，排在最前； 而姓名保持升序

for i, (name, score) in enumerate(ranked, 1):
    print("%d. %s %d" % (i, name, score))

    1. 小刚 90
2. 小明 90
3. 小丽 85
4. 小红 85

    对照：如果错误地使用 reverse=True 会怎样

    1

print("reverse 的结果:", [x[0] for x in wrong])
print("分数相同的两人姓名变成降序了 ✗")

    reverse 的结果: ['小明', '小刚', '小红', '小丽', '小安']
分数相同的两人姓名变成降序了 ✗

    对照表：

    写法 分数 姓名 符合要求吗
    key=lambda x: (-x[1], x[0]) 降序 升序 ✓
    key=lambda x: (x[1], x[0]), reverse=True 降序 降序 ✗

    关键认识：reverse=True 是「整体反转」， 而「各关键字方向不同」必须靠 key 里的表达式实现。 数值可以取负号；字符串不行，只能靠多趟排序（利用稳定性）

    例题 3：浅拷贝导致的「神秘改动」¶

    下面的代码里，original 在没有被直接赋值的情况下变了。请解释原因，并给出两种修法。

    用 * n 重复一个「可变对象」，得到的是 n 个指向同一处的引用。

    小结¶

    要记住的 为什么
    列表 = 有序 + 可变 + 可重复 + 类型可混 后面所有的行为都从这四条推出来
    append 加一个，extend 加一批 用错就得到「列表套列表」，长度也不对
    + 建新列表，+= 原地扩展 有别名时结果不同，是隐蔽 bug 的来源
    切片越界不报错，下标越界报错 切片出错时静默返回短列表，要用 len 检查
    列表切片给新对象，数组切片给视图 从 Python 转到科学计算时最容易翻车
    sort() 返回 None，sorted() 返回新列表 接错返回值会在很远的地方才报错
    key 返回元组 = 多级排序 各关键字方向不同时，靠 key 里的负号解决
    排序是稳定的 可以利用「多趟排序」，但用元组 key 更简洁
    b = a 不是复制 两个名字，一个对象
    浅拷贝只护外层 嵌套结构必须 deepcopy
    元组的本质是逗号 (1) 是整数，(1,) 才是元组
    不可变的东西才能哈希 所以元组能当字典键，列表不能
    别用 * n 造嵌套列表 得到的是共享引用，一改全改
    别边遍历边删元素 元素前移 + 下标递增 = 跳过元素
