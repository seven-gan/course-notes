    08 函数¶

    这一页解决一个问题：把一段代码变成一个「有名字的功能」。

    前面七页讲的是「数据长什么样」和「程序怎么走」。但真实的程序不能只靠 一行行往下推 —— 同一套算法会反复用到，一个程序会长到没人能整段读完。 函数就是用来把「一段逻辑」打包起来、起个名字、随时调用的工具。

    这一页学完，你将能够：

    能力 具体表现
    把重复代码收成一处 同一段算法只写一遍，改的时候只改一个地方
    写出有说明书的函数 用 docstring 让 help() 能讲清参数和返回值
    灵活收参数 位置、关键字、默认值、*args、**kwargs 五形态随手用
    避开最隐蔽的坑 「可变默认值会累积」「函数内赋值变成局部变量」
    看懂变量的来源 用 LEGB 规则判断一个名字到底取自哪一层
    把函数当数据用 传参、返回、lambda、闭包、装饰器
    给参数贴类型标签 用类型标注让编辑器和读者都不猜

    这页的重点

    函数里有两个坑最值得先记住，因为它们都不报错，只是结果悄悄不对：

    1
2
3
4
    def f(x, items=[])   ← 默认值只创建一次，所有调用共享它，会越攒越多
def g():
    total = 0        ← 这一赋值让 total 变成「局部变量」
    ...              ← 于是上面读 total 就报 UnboundLocalError

    第一个坑的修法是「默认写 None，函数里再建列表」； 第二个坑的修法是「先想清楚这个名字属于哪一层」。

    其余内容都围绕一句话展开：函数不只是「把代码包起来」， 它是 Python 里一种可以传来传去的普通对象

    一、为什么需要函数¶

    1.1 先看不写函数会怎样¶

    假设要算几组数据的平均值。最直接的写法就是把同一套逻辑抄几遍：

    temps = [25.4, 26.1, 24.8]

total = 0
for t in temps:
    total = total + t
avg_temp = round(total / len(temps), 2)
print("平均温度:", avg_temp)

readings = [101.5, 99.8, 100.4]

for t in readings:
    total = total + t
avg_read = round(total / len(readings), 2)
print("平均读数:", avg_read)

    平均温度: 25.43
平均读数: 100.57

    这段代码能跑，也能得出正确结果，但它有三个问题：

    问题 具体表现
    重复 同一套「累加再除」抄了两遍，第三组数据就要抄第三遍
    改不动 想把「先四舍五入到两位」改成「保留三位」，得找遍每一处副本
    没法单独验证 想知道「空列表会怎样」，只能把整段代码复制出来改，很别扭

    1.2 用函数收成一处¶

    把那段逻辑起个名字，写一次，之后就只写「调用」：

    1
2

    def average(numbers):
    """返回一组数字的平均值。"""
    return sum(numbers) / len(numbers)


print("平均温度:", round(average([25.4, 26.1, 24.8]), 2))
print("平均读数:", round(average([101.5, 99.8, 100.4]), 2))
print("只有一个数:", average([10]))
print("整数也会得到浮点:", average([2, 4]))

    平均温度: 25.43
平均读数: 100.57
只有一个数: 10.0
整数也会得到浮点: 3.0

    对比一下两段代码：

    维度 不用函数 用函数
    算法写了几遍 每组数据一遍 ✗ 永远只有一遍 ✓
    再加一组数据 复制粘贴，改动一处要同步多处 多写一行调用 ✓
    算法有 bug 要逐个副本都改 改定义那一处 ✓
    代码在讲什么 读者要读循环才能明白这是求平均 average(...) 一眼就懂 ✓

    1.3 三个好处，值得分别记住¶

    好处一：复用（写一次，用很多次）

    函数把「一段逻辑」变成了一个可重复调用的名字。 上面 average 写在文件里一次，之后 3 组、30 组数据都是一行调用。

    好处二：抽象（让读者不必读细节）

    average(numbers) 这个名字本身就是说明书。 读代码的人不必关心「是先累加还是先用 sum」，只要知道它返回平均值。 这正是函数最容易被低估的价值：它让上层代码变短、变清楚。

    1
2
    不用函数：  读者看到   循环 + 累加 + 除法 + 取长度        → 需要推理
用函数：    读者看到   average(data)                      → 立刻明白 ✓

    好处三：可测试（能单独喂边界值）

    函数可以被单独调用，所以能立刻拿边界情况去试。 下面这段故意给平均函数喂一个空列表：

    1
2
3
4
5
6
    # @expect-error
def average(numbers):
    return sum(numbers) / len(numbers)


average([])

    ZeroDivisionError: division by zero

    这个报错是好事：它说明函数能在「单独测试」时立刻暴露边界问题。 如果不写函数，同一段逻辑散在三处， 你要发现「空输入会崩」就得挨个复制出来试。

    判断「该不该抽成函数」的三个信号

    信号 该怎么做
    同一段逻辑出现第二次 抽成函数 ✓
    一段代码需要写注释才能看懂 抽成函数，把注释改写成函数名和 docstring ✓
    想单独试它一下 抽成函数，才试得了 ✓

    反过来，只用一次、只有两三行、名字比代码还长的逻辑， 硬抽成函数反而更难读 —— 判断依据是「是否重复」和「是否需要一个名字」

    几个术语先对齐（后面会反复用到）：

    六、作用域与 LEGB 规则¶

    6.1 一个名字，去哪儿找¶

    作用域（scope）就是「一个名字在哪些地方能被用」的范围。 查找顺序固定四层，缩写为 LEGB：

    1
2
3
    Local → Enclosing → Global → Builtin
  ↑        ↑          ↑         ↑
函数内   外层函数    模块级    内置名字

    规则一句话：从里往外找，找到第一个就停

    层 英文 指什么 例子
    L Local 当前函数内部 函数里赋值的 x
    E Enclosing 外层函数（闭包） 嵌套函数的外层变量
    G Global 模块（整个文件）级 文件顶部定义的 x
    B Builtin 内置命名空间 len、print、sum

def traced(func):
    """记录每一次调用的参数与返回值。"""
    calls = []

    @functools.wraps(func)

        return result

    wrapper.calls = calls
    return wrapper

        n = n + 1
        print(f"{func.__name__} 被调用了，参数是 {args} {kwargs}（第 {n} 次）")
        return func(*args, **kwargs)

    return wrapper

    小结¶

    要记住的 为什么
    函数的三个好处：复用、抽象、可测试 同一逻辑出现第二次就该抽函数 ✓
    def 定义时不执行，调用时才执行 区分「定义」与「调用」是读代码的基本功
    docstring 用 """..."""，help() 能读 第一行字符串自动成为 __doc__
    没写 docstring 时 __doc__ 是 None 判断用 is None，不要用 == None
    参数五形态：位置 / 关键字 / 默认 / *args / **kwargs 决定调用者能怎么传值
    *args 得到元组，**kwargs 得到字典 一个 * 对元组，两个 * 对字典 ✓
    参数顺序：位置 → 默认 → *args → 仅关键字 → **kwargs 顺序写错是 SyntaxError（定义）或 TypeError（调用）
    默认参数只在定义时创建一次 所以 def f(x, items=[]) 会累积 ✗
    可变默认值的修法：默认 None，函数内 if items is None: items = [] 这是社区标准写法 ✓
    没有 return 就返回 None print 不等于 return
    返回多个值实际是返回元组 所以能解包：a, b = f()
    提前 return 写卫语句 主逻辑留在最外层，缩进不会越写越深 ✓
    LEGB：Local → Enclosing → Global → Builtin 从里往外找，找到第一个就停
    函数内一赋值就是局部变量 赋值前读取 → UnboundLocalError ⚠
    global 改模块级，nonlocal 改外层函数 但优先用「参数 + 返回值」代替 global ✓
    函数是对象：可赋值、可传参、可返回 这是 lambda、闭包、装饰器的基础
    lambda 适合 key= 这类「一行小规则」 需要多步逻辑或复用时改用具名函数 ✓
    闭包 = 内层函数 + 它记住的外层变量 用 __closure__[0].cell_contents 可验证
    装饰器 = 收函数、返回新函数的函数；@ 是语法糖 @d + def f 等价于 f = d(f)
    装饰器必须加 @functools.wraps(func) 否则 __name__ / __doc__ / __wrapped__ 全丢 ✗
    类型标注是元数据，运行时不检查 主要给编辑器和静态检查工具用 ✓
    计时类示例的输出不稳定，只能示意 毫秒数取决于机器与负载，不能写死
