    01 环境与工具¶

    这一页解决一个问题：让你的代码跑起来。

    听起来简单，但初学者放弃编程最常见的原因就卡在这一步 —— 代码明明是从书上抄的，一运行就报错，而报错信息又看不懂。

    这一页学完，你将能够：

    能力 具体表现
    装好环境 有 Python，有编辑器，能装库
    跑通代码 三种运行方式，知道该用哪个
    看懂报错 看到红字不慌，能定位到「哪一行、什么错、为什么」
    自查环境 出了问题知道先查什么

    为什么把「环境」单独作为第一页

    因为环境问题的表现具有极强的误导性：

    现象 学生的第一反应 真实原因
    No module named 'numpy' 「我代码写错了」 编辑器选错了解释器
    中文变成乱码 「Python 不支持中文」 编码设置不对
    跑了没反应 「程序卡死了」 后台在等输入，或弹窗被挡住
    输出和书上不一样 「Python 版本不对」 可能是正常的版本差异

    这一页的目的就是把这类困惑一次性解决掉

    一、Python 是什么：解释器与脚本¶

    先建立一个准确的心智模型

    Python 是一门语言，而你装的是它的「解释器」。

    你写的 .py 文件是纯文本，计算机不能直接执行。 需要「解释器」一行一行读进去、翻译成机器能做的事：

    1
2
3
4
5
    你写的源代码 (hello.py)
        ↓
   Python 解释器（读一行、执行一行）
        ↓
    计算机真正干活

    这解释了三件常见困惑：

    困惑 原因
    为什么改完代码要重新运行？ 解释器每次都重新读文件
    为什么报错说到「第几行」？ 它就是逐行执行的，执行到哪行出错就在哪行停
    为什么装了 Python 还不能算矩阵？ 解释器只带标准库，科学计算库要另装

    所以「装好环境」= 装解释器 + 装上你要用的库

    选哪一套：三条路¶

    方式 适合 优点 代价
    Anaconda 发行版 科研 / 初学者 ✓ 科学计算库全都预装，一条龙 体积大（数 GB）
    官方 Python + pip 想自己掌控 干净、体积小 需逐个装库
    系统自带 / 应用商店 不建议 ✗ 来得快 常缺库、版本杂、难以管理

    推荐 Anaconda：它把 Python 与科学计算生态打包在一起， 装一次就够，省掉「逐个装库、互相冲突」的大量麻烦

    装完之后先做两件事¶

    第一件：确认 Python 能跑。

    打开终端，输入：

    python --version

    应当看到类似输出（具体小版本号不必一致）：

    1
    Python 3.12.7

    若提示「不是内部或外部命令」或 command not found

    说明 Python 没被加进系统的搜索路径（PATH）。

    系统 解决
    Windows 重新运行安装程序，勾选 Add Python to PATH；或用 Anaconda 自带的命令行
    macOS / Linux 试试 python3 --version；或把 Python 的 bin 目录加进 PATH

    Windows 上最省事的做法：用 Anaconda 安装时附带的 「Anaconda Prompt」终端 —— 它已经配好了路径

    第二件：确认库能导入。

    输入：

    python -c "import numpy, pandas, matplotlib; print('库就绪')"
    • 打印 库就绪 → 环境可用，可以直接往下学
    • 报 No module named 'numpy' → 装库（下一节）

    二、装库：pip 与 conda¶

    两个包管理器，用哪个都行

    工具 来自 特点
    pip Python 官方 通用，任何 Python 环境都有 ✓
    conda Anaconda 能装非 Python 的依赖（如编译器、C 库）

    建议：

    • 用 Anaconda → 优先 conda install（依赖处理更稳）
    • 其他情况 → 用 pip install

    不要混用太频繁 —— 偶尔可以，但同一个库别一会儿 pip 一会儿 conda， 容易造成版本混乱

    pip 的常用命令¶

    pip install numpy                    # 装一个库
pip install numpy pandas matplotlib  # 一次装多个
pip install --upgrade numpy          # 升级
pip uninstall numpy                  # 卸载
pip list                             # 看已装了哪些
pip show numpy                       # 看某个库的详细信息

    网络慢时换国内镜像源：

    pip install numpy -i https://pypi.tuna.tsinghua.edu.cn/simple

    conda 的常用命令¶

    conda install numpy
conda install numpy pandas matplotlib
conda update numpy
conda list

    装库时最容易犯的三个错

    错误 1：装到了另一个 Python 上 ✗

    pip install numpy          # 装给了「命令行里的那个 python」

    但你的编辑器可能用的是另一个 Python —— 于是编辑器里仍然 报 No module named 'numpy'。

    正确做法：先确认当前用的是哪个 Python，再装：

    python -c "import sys; print(sys.executable)"
pip -V                     # 看 pip 属于哪个 Python

    两者的路径应当指向同一个 Python

    错误 2：权限不足

    现象 解决
    Permission denied / 拒绝访问 加 --user 装到用户目录：pip install --user numpy
    用 sudo 装到了系统 Python 改用虚拟环境（见第 12 页）✓

    错误 3：大小写与拼写

    pip install Numpy      # ✗ 包名一般不区分大小写，但要拼对
pip install numpi      # ✗ 拼错会报 Could not find a version

    记住：报 Could not find a version that satisfies the requirement → 先检查包名拼写，再检查网络

    三、编辑器：把代码写在哪里¶

    三档选择，按需求挑

    类型 例子 适合
    代码编辑器 VS Code、PyCharm 日常写脚本、做项目 ✓
    交互式笔记本 Jupyter Notebook 探索数据、写实验记录
    纯文本编辑器 记事本、vim 应急

    推荐 VS Code：免费、跨平台、Python 支持好、 有断点调试与变量面板 —— 后面对调试很有用

    让编辑器用对解释器（关键一步）¶

    这是新手最容易卡住的地方：机器上往往不止一个 Python。

    位置 特点
    Anaconda 的 科学计算库齐全 ✓
    系统里原有的 可能一个库都没有 ✗

    编辑器默认可能选中后者 → 代码没错，却报 No module named 'numpy'。

    以 VS Code 为例，三种做法：

    做法 操作
    命令面板 Ctrl+Shift+P → 输入 Python: Select Interpreter → 选带库的那个
    状态栏 点右下角的 Python 版本号 → 从列表里选
    配置文件 在项目里建 .vscode/settings.json

    写进配置文件最省事（换项目也不用重选）：

    1
2
3
    {
  "python.defaultInterpreterPath": "在这里填入你的 Python 路径"
}

    路径怎么查？在正确的终端里运行：

    python -c "import sys; print(sys.executable)"

    把输出那一串粘进去即可

    怎么确认「编辑器用对了」¶

    新建一个文件 check.py：

    1
2
3
4
5
6
7
8
9
    import sys

print("当前解释器:", sys.executable)

try:
    import numpy
    print("numpy 版本:", numpy.__version__)
except ImportError:
    print("numpy 不可用 —— 解释器选错了，或库没装")

    （上面这段的输出会因机器而异，所以这里不给固定输出。 运行它，看属于下面哪种情况：）

    输出 结论
    打印出路径 + numpy 版本 配置正确 ✓
    打印「numpy 不可用」 回到上一节，重选解释器

    这一步花 1 分钟，能省掉后面无数次莫名其妙的报错

    判断口诀：报「找不到模块」时，先查解释器，再查代码

    四、运行代码：三种方式¶

    方式一：编辑器里直接运行（最常用）¶

    操作 效果 适用
    Ctrl+F5（VS Code） 直接运行当前文件 日常首选 ✓
    右键 → Run Python File 同上 鼠标操作
    F5 调试模式：在断点处停下 排查逻辑错误 ✓

    Ctrl+F5 与 F5 的区别值得记住：

    键 行为 什么时候用
    Ctrl+F5 一直跑到结束，打印输出 只想看结果
    F5 停在断点，能逐行看变量 结果不对、要查原因 ✓

    建议：养成每写几行就运行一次的习惯。 一次写 200 行再运行，出错时要查的地方太多 ✗

    方式二：终端里跑¶

    python hello.py

    适合：

    • 需要传命令行参数时：python train.py --lr 0.01
    • 在服务器上运行（没有图形界面）
    • 想用管道/重定向：python run.py > out.txt

    方式三：交互式解释器（REPL）¶

    在终端直接输入 python（不带文件名），会进入交互模式：

    1
2

4
5
6
7
8
    python
Python 3.12.7
>>> 2 + 3
5

    六、读懂报错（这一节最重要）¶

    报错是信息，不是失败

    初学者的最大误区：看到一堆红字就慌了，开始乱改代码。

    事实：Python 的报错信息写得相当好 —— 它会明确告诉你在哪一行、什么类型的错误、为什么。

    报错的结构¶

    假设 demo.py 只有三行，第一行是 print("开始")， 第二行是 scores = [88, 92]，第三行是 print(scores[10])：

    1
2
3
4

print(scores[10])

    运行后会看到：

    开始
IndexError: list index out of range

    真实的报错还包含 Traceback 与文件行号等内容。 上面为便于阅读只保留了关键一行 —— 而「最后一行」正是最该先看的那一行。

    读报错的顺序：从下往上¶

    1
2
3
4
5
    Traceback (most recent call last):
  File "demo.py", line 3, in <module>       ← ③ 出错的文件与行号
    print(scores[10])                       ← ② 出错的那行代码
          ~~~~~~^^^^
IndexError: list index out of range          ← ① 错误类型 + 原因
    顺序 看什么 作用
    ① 最后一行 IndexError: list index out of range 错误类型 + 原因 ✓
    ② 倒数第二段 print(scores[10]) 出错的具体代码
    ③ 中间 File "demo.py", line 3 文件名 + 行号

    口诀：先看最后一行，再看行号

    五种必会的错误类型¶

    报错 含义 典型原因

    TypeError 类型不对 字符串加数字
    IndexError 下标越界 访问 lst[len(lst)]
    KeyError 字典没有这个键 键名拼错
    ValueError 值不合法 int("abc")

    七、编码问题：中文乱码怎么办¶

    乱码几乎总是「读写两端用了不同编码」

    现象：文件里明明是中文，读出来变成 锟斤拷、Ã¤Â¸Â 这类怪字符。

    原因：Python 3 内部统一用 UTF-8， 但操作系统默认编码可能不同（中文 Windows 历史上是 GBK）。

    解决办法：显式指定 UTF-8。

    场景 写法
    读写文件 open(path, encoding="utf-8") ✓
    命令行输出 设环境变量 PYTHONIOENCODING=utf-8
    Windows 终端 用 chcp 65001 切到 UTF-8，或用新版终端

    读写文件必须写 encoding：

    不写 encoding 会发生什么：Python 用「系统默认编码」去解码， 在中文 Windows 上遇到 UTF-8 的中文就可能报 UnicodeDecodeError，或者读出乱码 ✗

    判断口诀：读写中文，永远显式写 encoding="utf-8" ✓

    例题 4：设计一个自检流程¶

    某同学运行代码报 No module named 'pandas'。 请给出三步排查方案，说明每步看什么、得出什么结论。

    思路

    报「找不到模块」可能是「没装」，也可能是「装到了别的 Python 上」。 怎么区分这两种情况？

    解答

    三步排查，从最可能的原因开始：

    步骤 命令 / 操作 看什么 结论
    1 在编辑器里运行 print(sys.executable) 打印的路径 记住这个路径 A
    2 在终端运行 python -c "import sys; print(sys.executable)" 打印的路径 得到路径 B
    3 比较 A 与 B 是否相同 不同 → 找对原因了 ✓

    判断：

    情况 含义 解决
    A ≠ B 编辑器用的不是终端那个 Python 在编辑器里切换解释器（第三节）✓
    A = B 是同一个 Python，那么确实没装 终端执行 pip install pandas

    第 4 步（可选）：确认 pip 装到哪去了

    pip -V

    输出里的路径应当与路径 A/B 一致

    这套流程为什么有效：

    1
2
3
4
5
6
    报「找不到模块」
    ↓
先分清是「环境不对」还是「真没装」
    ↓
环境不对 → 切换解释器（最常见）
真没装   → pip install

    核心思想：不要立刻去装库。 先确认「编辑器到底在用哪个 Python」，因为装错地方是最常见的原因

    """安全除法：除数为 0 时给出提示而不是崩溃。"""
    if b == 0:
