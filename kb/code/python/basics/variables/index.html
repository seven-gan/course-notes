    02 变量与类型¶

    这一页讲一个看似简单、但决定你后面能不能少踩坑的问题：

    Python 里的「变量」到底是什么？

    如果你把它理解成「装东西的盒子」，那么遇到下面这些现象时就会完全想不通：

    现象 「盒子」模型会怎么想 实际情况
    改了一个列表，另一个列表也变了 「我明明只改了 b」 两个名字指向同一个对象
    函数里改了参数，外面的列表也变了 「参数不是复制一份吗」 传的是引用，不是副本
    a = 1 后 b = a，改 b 不影响 a 「所以赋值总是复制？」 数字不可变，改的是绑定
    x 指向列表时 x += [1] 改了原列表，指向数字时 x += 1 没改 「+= 到底是原地还是新建？」 取决于对象是否可变

    这一页就是把「名字、对象、可变性」这三件事讲清楚。 理解之后，上面四个现象就都能一眼看穿。

    一句话概括（但请读完这一页再回来看）

    Python 的变量是「贴在对象上的名字」，不是「装对象的盒子」。

    赋值 a = 1 的含义是「让名字 a 指向这个整数对象」， 而不是「把 1 放进 a 这个盒子」。

    一、变量是「名字绑定到对象」¶

    赋值时发生了什么¶

    1
2
3
    x = 42
print(x)
print(type(x))

    42
<class 'int'>

    关于「绑定」，可以先建立一个可观察的事实：同一个对象可以被多个名字指向。

    1
2
3
4
5
6
    a = [1, 2, 3]
b = a

print("a 的值:", a)
print("b 的值:", b)
print("a 与 b 是同一个对象吗:", a is b)

    a 的值: [1, 2, 3]
b 的值: [1, 2, 3]
a 与 b 是同一个对象吗: True

    注意 a is b 的结果是 True —— 这说明 a 和 b 不是两个独立的列表， 而是两个名字指向同一个列表对象。

    为什么用 is 而不是 == 来验证

    运算符 比较什么 例子
    == 值是否相等 [1,2] == [1,2] → True
    is 是不是同一个对象 [1,2] is [1,2] → False

    要验证「两个名字是否指向同一对象」，必须用 is ✓

    id() 也能看身份（同一个对象 id 相同）， 但 id() 的具体数字每次运行都不同、也随实现变化， 所以本页用 is 来做判断，而不打印 id 的数值

    用图示理解¶

    执行 a = [1, 2, 3] 之后：

    a ──────►  ┌─────────────┐

               └─────────────┘

执行 b = a 之后（注意：没有创建新列表！）：

            ├──►  ┌─────────────┐
    b ──────┘     │  [1, 2, 3]  │

    所以通过 b 修改，a 看到的当然也变了 —— 因为本来就是同一个对象。

    这是新手最容易踩的坑之一

    「我明明只改了 b，为什么 a 也变了？」

    因为 b = a 从来不复制对象，它只让 b 也指向那个对象。

    你以为的 实际的
    b = a 复制了一份 b 和 a 指向同一对象 ✗

print("a is b:", a is b)


    a = [1, 2, 3]
b = [1, 2, 3, 4]

    现在 a 不受影响了

    二、重新赋值是「改绑定」，不是「改对象」¶

    1
2
3
4
5
6
7
8
9
    x = 1
print("x =", x)

x = 2
print("x =", x)

x = "现在变成字符串了"
print("x =", x)
print("x 的类型:", type(x))

    x = 1
x = 2
x = 现在变成字符串了
x 的类型: <class 'str'>

    同一个名字 x 先后指向了三个不同的对象（整数 1、整数 2、字符串）。

    注意关键点：x = 2 不是「把 1 改成 2」， 而是「让 x 改指向一个新的整数对象 2」。 原来的整数对象 1 依然存在（如果有别的名字还指向它）。

    「重新赋值」与「原地修改」是两件不同的事

    操作 含义 原来的对象
    x = 新值 改绑定：让名字指向别的对象 不变 ✓
    x.append(...) / x[0] = ... 原地修改：改对象内部 被改了 ⚠

    这两者的区别在下一节（可变性）里会有更直观的例子。

    动态类型：优点与代价¶

    Python 是动态类型语言：变量不需要声明类型，类型属于对象，不属于名字。

    1
2
3
4
5
6
7
8
    value = 18
print(type(value).__name__)

value = "十八"
print(type(value).__name__)

value = [1, 2]
print(type(value).__name__)

    int
str
list
    优点 代价
    写得快、灵活，不用先设计类型 ✓ 类型错误要到运行时才暴露 ✗
    适合原型探索与数据处理 大型项目容易出现隐蔽 bug

    实践上的三条缓解措施：

    措施 作用
    类型标注 def f(x: int) -> str: 让 IDE 实时提示类型问题
    单元测试 覆盖关键路径，提前发现问题
    print(type(x)) 排查时最直接的手段 ✓

    排查类型问题时，repr 比 print 更有用

    1
2
3
4
5
    v1 = 88
v2 = "88"

print(v1, v2)              # 看不出区别
print(repr(v1), repr(v2))  # 一眼看出哪个是字符串


    88 88
88 '88'

    repr 会显示引号，所以字符串 '88' 和整数 88 立刻区分开了

    三、可变与不可变：理解一切差异的钥匙¶

    Python 的对象分两类：

    类别 类型 能否原地修改
    不可变 int、float、str、tuple、bool、frozenset 不能 ✗
    可变 list、dict、set 能 ✓

    这个区别解释了大量「反直觉」的现象。

    例子：+= 在不同类型上的行为不同¶

    先看不可变的数字：

    1
2
3
4
5
6
7
8
    a = 1
b = a

a += 1          # 等价于 a = a + 1

print("a =", a)
print("b =", b)
print("a is b:", a is b)

    a = 2
b = 1
a is b: False

    再看可变的列表：

    1
2
3
4
5
6
7
8
    a = [1, 2]
b = a

a += [3]        # 对列表来说，+= 是「原地扩展」

print("a =", a)
print("b =", b)
print("a is b:", a is b)

    a = [1, 2, 3]
b = [1, 2, 3]
a is b: True

    同一个 +=，两种完全不同的行为 —— 这是本页最该记住的一处

    对比两者的结果：

    类型 a += ... 之后 a is b 原因
    数字（不可变） b 不受影响 False a 改指向新对象
    列表（可变） b 跟着变了 True 原地修改了同一个对象 ⚠

    为什么会这样：

    • 不可变对象没法原地改，所以 a += 1 只能新建一个对象让 a 指过去
    • 可变对象可以原地改，所以 a += [3] 直接改了自己，b 看到的就是改后的

    这个差异在真实代码里的后果：函数收到一个列表参数、 在里面 += 拼接，会把调用方的列表也改掉 ✗

    不可变的另一面：字符串的「修改」其实是新建¶

    1
2
3
4
5
6
7
8
    s = "abc"
t = s

s = s + "d"          # 字符串不可变 → 这是新建了一个字符串

print("s =", s)
print("t =", t)
print("s is t:", s is t)

    s = abcd
t = abc
s is t: False

    字符串所有看起来「修改」的方法，都返回新字符串，原字符串不变：

    1
2
3
4
5
6

    """把成绩加入列表（每次调用都用新列表）。"""
    if scores is None:
        scores = []
    scores.append(score)
    return scores


print("第一次:", add_score(88))
print("第二次:", add_score(92))
print("第三次:", add_score(79))


    第一次: [88]
第二次: [92]
第三次: [79]

    通用规则：默认参数只用不可变对象（None、数字、字符串、元组）

    函数收到的 lst 是一个新列表，还是指向同一个列表？ 回忆「变量是名字绑定到对象」。

    解答

    输出 [1, 2, 3, 999]。

    [1, 2, 3, 999]

    lst.append(999)
    return lst

print("data   =", data)
print("result =", result)


    data   = [1, 2, 3]
result = [1, 2, 3, 999]

    取舍：

    需求 写法
    就是要原地修改（如排序、追加） 直接改 ✓
    不想影响调用方 进函数先 copy() ✓
    数据是嵌套的 用 deepcopy()

    例题 2：+= 与 + 的区别¶

    下面两段代码结果不同，为什么？

    1

    1

    思路

    a + [3] 会创建新列表吗？a += [3] 对列表来说是原地操作吗？

    解答
    片段 a b 原因
    A（a = a + [3]） [1, 2, 3] [1, 2] + 新建列表，a 改指向新对象
    B（a += [3]） [1, 2, 3] [1, 2, 3] 列表的 += 是原地扩展（等价 extend）⚠

     1

    例题 3：嵌套列表的深拷贝¶

    下面代码想复制一份矩阵并只改副本，但失败了。为什么？怎么修？

print("内层是同一对象吗    —— shallow:", matrix[0] is shallow[0], " deep:", matrix[0] is deep[0])


    外层是同一对象吗    —— shallow: False  deep: False

    浅拷贝：外层是新的，内层共享；深拷贝：层层都是新的

        items = []
    items.append(x)

    规则：默认参数不要用可变对象（[]、{}、set()） 要用可变容器时，用 None 作默认值、在函数内创建。

    小结¶

    要记住的 为什么
    变量是「名字」，不是「盒子」 b = a 不复制，只让两个名字指向同一对象
    == 比较值，is 比较身份 判 None 用 is None；值比较用 ==
    int/str/tuple 不可变，list/dict/set 可变 决定操作是「新建」还是「原地改」
    可变对象的 += 是原地操作 会连带改掉其他引用，是最隐蔽的 bug 来源
    copy() 是浅拷贝 嵌套结构要用 deepcopy()
    默认参数不要用可变对象 默认值只创建一次，会被所有调用共享
    a = b = [] 两个名字指向同一列表 要独立就分别创建
    不要用 list/sum 等内置名做变量名 会覆盖内置函数
    小整数缓存是实现细节 不要用 is 比较数值
