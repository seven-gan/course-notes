    13 类与对象¶

    这一页解决一个问题：当「数据」和「操作数据的函数」变多之后，怎么把它们组织到一起。

    前面几页里，数据装在字典、列表里，函数单独写在文件里 —— 这在脚本短的时候完全够用。可一旦程序长大，你会发现 同一个东西的字段名和函数散落在各处：改个字段名要全局搜索， 漏改一处也不会报错，只会在运行时悄悄出错。

    类（class）就是为了把这两半粘在一起而存在的机制。 这一页学完，你将能够：

    能力 具体表现
    把数据和方法绑在一起 定义一个类，让「记录」自己知道怎么描述自己、怎么判断自己是否正常
    分清两种属性 知道「实例属性」和「类属性」各自存在哪里，不再被共享陷阱咬到
    挑对方法类型 实例方法 / 类方法 / 静态方法 / 属性，四种各有各的用场
    让对象融入语言 用魔术方法让自定义对象能 print、能 ==、能排序、能 for 遍历
    复用与扩展 用继承和 super() 扩展已有行为，也知道什么时候不该用继承
    少写样板代码 用 dataclasses 把几十行样板压成几行

    这页的重点

    最反直觉的一点：给实例「赋值」不会改到类，但「就地修改可变类属性」会波及所有实例。

    1
2
    class Team:
    members = []        ← 类属性；所有实例共用同一个列表对象

    写成上面这样，t1.members.append(...) 之后 t2.members 里也会出现这个东西 —— 而且全程不报错。正确写法是在 __init__ 里写 self.members = []。

    第二个重点：实例方法忘了写 self 时，报错信息说的是「参数个数不对」， 而不是「你忘了写 self」。看懂这条信息，能省下很多排查时间 ✓

    1.2 这种写法什么时候撑不住¶

    字典的「字段名」只是字符串，编译器完全看不见它。 写错一个字母，程序照样能启动，只在真正取用那一刻才炸：

    字典写法的三个真实痛点

    痛点 表现 后果
    字段名靠字符串拼 rec["koce"] 检查不出来 运行时才 KeyError
    数据和函数分家 describe 和字典是两回事，谁都能改 换个人接手就不知道有哪些配套函数
    没有类型可言 type(rec) 永远是 dict 一堆不同的记录看起来一模一样

    第三个痛点最隐蔽：三类完全不同的数据如果都用字典装， 调试时看到 dict 两个字母，等于什么都没看到 ⚠

class Reading:
    def __init__(self, code, value, unit, status):

        self.value = value
        self.unit = unit

    1.4 两版对比¶

    维度 字典 + 函数 类
    字段名检查 字符串，拼错不报错 ⚠ 属性，取不到就 AttributeError
    配套函数在哪 散在文件里，靠命名约定 写在类里，dir() 一列就看到 ✓
    type() 看到什么 一律 dict 具体的类名 ✓
    能否加校验 得自己记得先调校验函数 可在 __init__ 里强制校验
    能否参与语言机制 只能用手写的函数 可重载 ==、<、len 等 ✓
    上手成本 极低，立刻能用 要先想清楚有哪些字段和方法
    适合场景 临时的、一次性的数据 长期存在、反复使用的概念 ✓

    判断依据：

    • 只是把几个值临时打包传一传 → 用字典，别上类 ✓
    • 这个东西在程序里有名字、有行为、会被反复创建 → 用类 ✓

    class Point:
    """二维平面上的一个点。"""

    def __init__(self, x, y):
        self.x = x
        self.y = y

    def length_sq(self):
        """到原点距离的平方（避免开方）。"""
        return self.x ** 2 + self.y ** 2

    class Version:
    def __init__(self, major, minor):
        self.major = major
        self.minor = minor

    def __repr__(self):

    def __lt__(self, other):
        return self._key() < other._key()

    class Vec:

        self.y = y

    A 只是需要用到 B 的能力？ 组合 ✓
    我想在运行时换掉这部分能力？ 组合 ✓
    我其实只是想复用 B 的几行代码？ 组合（或抽成函数）✓

    原因：一旦你自定义了 __eq__， Python 会认为原来那个「按身份哈希」的方案不再成立， 于是把 __hash__ 设为 None —— 对象变成不可哈希 ⚠

    小结¶

    要记住的 为什么
    类 = 数据 + 操作数据的函数 字段名和配套方法绑在一起，type() 也能看出是什么
    实例属性写在 __init__ 里，类属性写在类体里 前者每个实例一份，后者所有实例共享
    可变对象绝对不能当类属性（items = []） 一个实例改了全部实例跟着变，且不报错 ⚠
    属性查找：先实例字典，再类字典 给实例赋值只是「遮蔽」，类属性一个字节没动
    self 是方法的第一个参数 漏写时报的是「参数个数不对」，不是「忘了 self」
    __init__ 里别写 x = x 那是自赋值；构造不报错，读属性时才 AttributeError
    实例方法 / 类方法 / 静态方法 / 属性 看它要用哪一层：self / cls / 都不用 / 想当属性读
    @classmethod 做替代构造函数 返回 cls(...)，子类继承后自动造出子类 ✓
    @property + setter 做校验 非法值根本进不来，而不是事后才发现 ✗
    __repr__ 面向调试，__str__ 面向用户 print 和 f-string 走 __str__；容器里一律走 __repr__
    至少写一个 __repr__ 它同时管调试显示；不写就只能看到内存地址
    __eq__ 和 __hash__ 要一起想 只写 __eq__ 会让对象不可哈希，进不了 set
    继承表达「是一种」，组合表达「有一个」 拿不准时先用组合，耦合更松 ✓
    子类 __init__ 要调 super().__init__(...) 不调的话，父类那部分数据压根不存在
    MRO 就是方法查找顺序 有疑问时 print(Cls.__mro__) 一眼看清
    _name 是约定，__name 是改名 Python 没有真私有，靠约定 + 名称改写
    dataclass 自动生成 __init__ / __repr__ / __eq__ 手写类十几行的事，四行搞定 ✓
    field(default_factory=list) 可变默认值必须用它，否则每次构造都共用同一个对象
    frozen=True 顺带可哈希 能进 set、能当字典键；代价是不能改
    想让人一看就懂 vars(obj) 所有实例属性都在 __init__ 里初始化 ✓
