    04 字符串¶

    这一页解决一个问题：把文本当成「可以精确操作的数据」。

    程序里最多的数据就是文本 —— 名字、地址、日志、网页、CSV 文件、 用户输入，全都是字符串。会不会处理字符串，直接决定你能不能写实用脚本。

    这一页学完，你将能够：

    能力 具体表现
    取出想要的片段 用索引与切片精确拿到任意一段文字
    判断与清洗 把脏数据（多余空格、大小写不一、全角字符）弄干净
    组装输出 用 f-string 把数字、变量、表达式排成整齐的报告
    看穿隐藏字符 用 repr 发现换行、制表符、全角空格这类「看不见的东西」
    处理中文 分清「字符数」与「字节数」，不再被编码问题卡住

    这页的重点

    字符串最反直觉的一点是「不可变」（immutable）：

    1
    s.upper()      ← 它返回一个新字符串，并没有改变 s

    忘了这一点，就会写出「调用了方法但结果不见了」的代码， 而且不报错 —— 这是最难受的一类 bug。

    第二个重点：调试文本问题时，永远用 repr() 而不是 print()， 因为它能把「看不见的字符」显示出来 ✓

    一、为什么需要它¶

    没有字符串处理能力会怎样¶

    假设你从一份实验记录里读出这样一行：

    1
      编号: A-001,  温度: 25.4 C , 备注: 正常

    你想拿到编号、温度、备注三个值。如果没有字符串方法，你只能：

    • 靠数位置硬算下标 —— 字段一长一短就错 ✗
    • 靠眼睛找 —— 几百行根本做不到 ✗

    有了字符串方法，一行代码就能拆开：

    1
2
3
    line = "  编号: A-001,  温度: 25.4 C , 备注: 正常"
parts = [p.strip() for p in line.split(",")]
print(parts)

    ['编号: A-001', '温度: 25.4 C', '备注: 正常']

    字符串在真实工作里的比重¶

    场景 具体做什么 用到的能力
    读数据 解析 CSV、日志、配置文件 split / strip / 切片
    存数据 生成报表、JSON、文件名 f-string / join
    洗数据 去空格、统一大小写、去全角 strip / lower / translate
    查数据 判断关键字、提取编号 in / find / 切片 / 正则
    排错 看清到底是 "5" 还是 5，是空格还是空串 repr / len

    你会发现：科学计算也好，爬虫也好，写前端也好 —— 绝大部分工作量其实花在「把文本弄成正确的形状」上 ✓

    二、字符串是什么：不可变的 Unicode 字符序列¶

    官方定义是三个词：不可变（immutable）、Unicode、序列（sequence）。 逐个拆开讲。

    2.1 它是「序列」：可以用下标取¶

    「序列」意味着：有顺序、有长度、能用下标访问、能切片。

    1
2
3
4
5
    s = "Python"
print("长度:", len(s))
print("第 0 个:", s[0])
print("第 5 个:", s[5])
print("最后一个:", s[-1])

    长度: 6
第 0 个: P
第 5 个: n
最后一个: n

    下表把「序列」的能力列全（列表、元组也通用，第 05 页会再讲一遍）：

    操作 写法 适用于字符串？
    求长度 len(s) 是
    按下标取 s[i] 是
    切片 s[a:b] 是
    遍历 for ch in s: 是
    判断包含 "a" in s 是
    拼接 s1 + s2 是
    重复 s * 3 是
    逐个赋值 s[0] = "H" 否（不可变） ✗

    2.2 它是「Unicode」：一个元素是「一个字符」而不是「一个字节」¶

    Python 3 的字符串内部按 Unicode 码点存放， 所以对中文、日文、emoji 都是一个长度单位：

    1
2
3
4
    words = "中文ok"
print(len(words))
print(words[0], words[1], words[2], words[3])
print("表情也算一个字符:", len("🙂"))

    4
中 文 o k
表情也算一个字符: 1

    这一点和历史语言（如 C 的 char*）完全不同： 在 C 里中文一个字占好几个字节，下标会取到半个字； 在 Python 3 里 "中文"[0] 就是 "中" ✓

    2.3 它是「不可变」：创建之后内容永远不变¶

    这是全页最重要的一个概念。

    1
2
3
4
5
6
7
    s = "hello"

t = s.upper()            # 返回一个新的字符串
print("s 还是:", s)       # s 没变
print("t 是  :", t)       # 新字符串

print("它们是同一个对象吗:", s is t)

    s 还是: hello
t 是  : HELLO
它们是同一个对象吗: False

    2.4 「不可变」到底禁止了什么¶

    它禁止的是「原地修改」，不是「重新赋值」。

    1
2
3
    # @expect-error
s = "hello"
s[0] = "H"          # 想原地改一个字符

    TypeError: 'str' object does not support item assignment

    报错说得非常清楚：str 不支持「按下标赋值」。

    「不可变」不等于「变量不能改」

    这两句话听起来像，但完全不同：

    写法 合法吗 发生了什么
    s[0] = "H" 不合法 ✗ 想改字符串对象内部的内容
    s = "Hello" 合法 让名字 s 指向一个新对象 
    1
2
3
4
5
    s = "hello"
old_id = id(s)
s = s.upper()        # 不是改 s，而是让 s 指向新对象
print(s)
print("地址变了吗:", old_id != id(s))

    HELLO
地址变了吗: True

    记忆诀窍： 不可变说的是「那个东西」不能改，不是「这个名字」不能改 ✓

    2.5 不可变带来什么好处¶

    好处 说明
    能当字典的键 字典要求键「可哈希」，而可哈希的前提是内容不变
    能放进集合去重 同上，set 也要求可哈希
    可以安全共享 两个变量指向同一个字符串，谁都不会偷偷改掉它
    便于缓存与优化 解释器可以复用相同内容的字符串，省内存
    少一类 bug 函数收到一个字符串参数，不必担心被改掉 
    1
2
3
4
    # 不可变 → 可哈希 → 能当字典键
codes = {"A-001": "正常", "A-002": "异常"}
print(codes["A-001"])
print("能放进集合:", len({"a", "b", "a"}))

    正常
能放进集合: 2

    对比一下：列表是可变的，所以不能当字典的键 —— 这一点在第 05、06 页会反复用到 ✓

    3.1 引号该用哪种¶

    Python 不区分单引号和双引号 —— 两者完全等价，只有编码风格差别。

    情况 建议
    文本里有单引号 外面用双引号："it's"
    文本里有双引号 外面用单引号：'他说"好"'
    两种都有 用转义，或三引号
    无特殊字符 随便，团队内统一即可

    判断依据只有一个：选能让你少写转义符的那个。

    三引号字符串会把「缩进」也一起收进去

    缩进是为了让代码好看，但 Python 会原样把它放进字符串：

    1

    三种修法，按场景选：

    修法 写法 适用

    用 str.strip() 逐行处理 join + 推导式 需要精细控制

    最省事的做法是让内容顶格：
